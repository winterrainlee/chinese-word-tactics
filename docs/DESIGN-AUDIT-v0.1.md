# 전체 디자인 감사 v0.1

작성: 2026-10-05. 대상: **따라온 단어들 전체 경험**. 랜딩·월드맵·방을 학습 화면과 동등하게 점검한다.
상태: 구조 조사·대표 화면 시각 감사·공통 DNA·수정 우선순위를 정리했다. **UI 개선 구현과 iPhone 최종 승인은 아직 하지 않았다.**
공통 기준: [디자인 원칙 v0.3](DESIGN-PRINCIPLES-v0.3.md). 이번 작업은 새 디자인 시스템이나 전역 CSS 교체가 아니다.

## 1. 결론

이 앱의 공통 DNA는 **조용한 여행 세계 안에서 필요한 말과 변화가 또렷하게 드러나는 것**이다. 다른 일을 하는 화면을 같은 모양으로 만드는 것은 목표가 아니다. 랜딩은 초대하고, 지도는 장소를 고르게 하고, 방은 머무르게 하며, 플레이는 의미를 행동으로 쓰게 하고, 기록은 경험을 다시 연결한다.

문제는 디자인 철학의 부재보다 **화면 사이의 접점과 보조 도구에서 공통 계약이 빠진 것**에 가깝다. 전술판·학술탑·단어장의 목적별 위계는 보존할 만하다. 우선 바꿀 것은 화풍이나 팔레트가 아니라 작은 의뢰 버튼, 실행보다 강한 닫기, 잠금 표식의 의미, 복귀와 상태에 맞지 않는 안내다.

## 2. 확인 방법과 범위

### 기준 소스와 증거

- 실제 앱 코드의 기준은 `8ad45b41b6fe40d59265350f8f5d43b6a0179c46`이다. 그 뒤 `a56ef00`과 `7c74990`은 수집 도구·워크플로만 바꾸며 `src/`, `index.html`, 게임 데이터와 자산을 바꾸지 않았다.
- 기존 배포 검사 `37294532156`의 `ux-screenshots` 아티팩트에서 360개의 PNG를 확보했다. 지역별 플레이의 대표 진입·선택·결과와 학술탑·단어장 화면을 골라 시각 비교했다. **360장을 모두 수동 정밀 검수했다는 뜻은 아니다.**
- 새 수집기 `tools/capture_design_audit.py`는 네 viewport의 비학습·읽기 화면에서 정지 스크린샷과 최종 적용 geometry를 수집한다. 원자료는 `manifest.json`과 `inventory.json`이다. 실행 결과와 재현 방법은 아래 §8에 기록한다.
- 시각 감사에서는 랜딩→지도→방, 이야기→번역→메뉴, 게시판→장소→학술탑 허브, 여정→단어장→설정을 묶어 비교했다. 플레이는 길목 G7·장인골 W7·장터 M7/M8·숲 F8·학술탑 작업대의 서로 다른 역할을 대조했다.

### 과장하지 않는 검수 경계

수집에는 실제 사용자 저장이 아닌 독립된 합성 진행 상태를 사용했다. 클릭과 화면 호출을 섞어 필요한 상태를 직접 열었다. 새 게임부터 모든 분기를 통과한 완주 테스트가 아니다. `tower-hub-new`는 본편 완료·탑 입구 이야기 이전의 강제 허브 조회이므로 잠금된 연구가 보인다는 사실을 자연 진입의 결함으로 판단하지 않는다. 경로별 통행패를 만드는 `stageOutcomes`는 비어 있어 두 통행패 동시 배치의 실제 타격 영역은 이번에 확인하지 않았다.

Chromium 모바일 크기 검수이며 iPhone Safari 실기기 검수가 아니다. 가상 키보드·실제 safe-area·브라우저 도구막대·VoiceOver·reduced-motion의 실제 경험과 신규 사용자 이해도는 별도 확인이 필요하다. 전체 접근성 적합성 인증을 뜻하지 않는다.

측정기는 input의 클릭 가능한 label을 반영하지만 가상 요소의 확장 타격 영역, 겹침, SVG의 실제 painted hit area를 모두 판정하지 않는다. `smallTargets`는 **후보 목록**이지 자동 위반 목록이 아니다. 스크롤 아래에 있는 요소도 목록에 포함된다. 전체 페이지 PNG는 첫 viewport와 같지 않으므로 좌표·높이와 함께 읽는다.

## 3. 저장소와 화면의 책임

`index.html`의 8개 주요 화면과 동적으로 생성하는 소년의 방을 중심으로 동작한다. `src/`에는 JS 61개, CSS 28개가 있으며 기본 콘텐츠 42개 스테이지는 튜토리얼 6·길목 7·장인골 7·장터 8·숲 8·탑 6으로 나뉜다. 파일 수는 디자인 복잡도 점수가 아니다.

| 책임 | 주된 코드 | 감사의 초점 |
|---|---|---|
| 시작·화면 전환·복귀 | `index.html`, `app.js`, `flow-runtime.js` | 현재 목적과 다음 이동을 구별한다. |
| 랜딩 | `landing.css`, `flow-runtime.js` | 처음 방문·재방문의 초점, 여백, 보조 진입을 확인한다. |
| 지도·장소·게시판 | `world-runtime.js`, `world-inn-runtime.js`, `north-forest-world-runtime.js`, 관련 CSS | 장소와 상태가 읽히며 실제 행동이 충분히 드러나는지 본다. |
| 소년의 방·기념물 | `world-inn-runtime.js`, `inn-keepsakes-runtime.js`, 관련 CSS·방 자산 | 생활 공간을 보존하면서 사물 조회·귀환을 확인한다. |
| 공통 플레이와 지역별 기믹 | `styles.css`, `ux-play.*`, 각 지역 `*-runtime.*` | 안정된 판, 선택·가능 행동·결과의 공통 문법을 확인한다. |
| 학술탑 | `academic-tower-*` | 연구실·작업대·전체 여정의 역할을 분리한다. |
| 읽기·기록·설정 | `story-*`, `journey-*`, `lexicon-*`, `settings-*` | 읽는 순서, 도움, 상태별 문구, 안전한 도구와 복귀를 확인한다. |

`ux-play.css`에는 공통 목표·피드백 외에 장터 전용 높이와 패널 규칙도 있다. `index.html`의 스타일 로딩 순서와 최종 계산값까지 확인해야 한다. 단일 파일의 첫 선언이나 파일 이름을 최종 디자인 책임으로 오인하지 않는다.

## 4. 보존할 좋은 사례

| 화면 | 보존할 디자인 | DNA와의 연결 |
|---|---|---|
| 랜딩 | 제목·풍경·한 가지 시작 행동과 넉넉한 여백을 유지한다. | D1·D6. 기능 안내판이 아니라 여행의 입구다. |
| 지도 | 장소가 하나의 지형에 연결된 풍경을 유지한다. | D1. 이동 목적지를 카드 격자로 바꾸지 않는다. |
| 방 | 생활 장면과 사물, 여행에서 실제로 받은 물건을 유지한다. | D1·D4. 수집률이나 의무 목표를 붙이지 않는다. |
| 이야기 | 중국어 대사와 요청 시 번역, 안정된 읽기 면을 유지한다. | D2·D5. 이 면은 의미 있는 컨테이너이며 일괄 제거 대상이 아니다. |
| 전술·장치·거래 | 판은 다르지만 목표어, 현재 상황, 결과, 되돌리기의 역할을 이어간다. | D3·D4. 동일한 미니게임보다 의미에 맞는 행동이 중요하다. |
| 학술탑 | 원본/작업 면, 타공판·레일, 본선과 작은 옆방, 완료 체크를 유지한다. | D2·D6. 지역의 개성과 정보 구조가 함께 작동한다. |
| 단어장 | 문서·색인형 배열과 비교할 중국어의 큰 표제를 유지한다. | D2·D5. 단어마다 상품 카드처럼 만들지 않는다. |
| 설정 | 저장 위치, 오류, 복원 미리보기와 파괴적 행동 설명을 유지한다. | D3·D5. 안전에 필요한 설명은 단순화 대상이 아니다. |

랜딩의 평면적인 그림과 지도·방의 회화적인 그림 차이는 그 자체로 결함이 아니다. 현재는 글자·밝은 면·조작 문법의 연결을 먼저 정리하는 편이 낫다. 새 팔레트나 자산 전면 교체는 제안하지 않는다.

## 5. 개선 목록

P1은 조작 의미·접근성의 직접 문제, P2는 이해·탐색 비용, P3는 검수 후 결정할 미세 조정이다. 확인 사실과 디자이너의 판단을 구분한다. 아래 크기는 주로 375×640 CSS px에서 반올림한 값이며 원값은 원자료에 남긴다.

### A01 · P1 · 작은 보조 버튼에도 동일한 터치 계약이 필요하다

**확인:** 의뢰 게시판의 `의뢰 확인` 버튼은 약 84.5×27px, 랜딩의 `여정` 보조 버튼은 40×44px, 첫 자유 의뢰 제안의 `한국어 뜻 보기`는 약 85.2×38px이다. 해당 버튼의 코드에는 방 기념물처럼 타격 영역을 넓히는 가상 요소나 클릭 가능한 부모 label이 없다. 기준은 프로젝트의 44×44px이다.

**문제:** 자주 쓰는 목적지·의뢰·도움의 진입이 전술판의 작은 칸보다 누르기 어렵다. 시각적 절제와 작은 터치 영역을 혼동한 경우다.

**변경 방향:** 현재 글자 크기와 조용한 표현은 유지하고 실제 버튼의 최소 폭·높이를 확보한다. 게시판은 동등한 의뢰를 동등하게 선택하게 하고 큰 카드로 확대하지 않는다.

**근거:** `quest-board-new-375x640.png`, `landing-returning-375x640.png`, `inn-first-offer-375x640.png`; `north-forest-world-runtime.js`, `landing.css`, `first-free-quest-world-runtime.js` 및 관련 스타일.

**완료 기준:** 네 viewport에서 실제 클릭 영역이 44×44px 이상이고 인접 행동과 겹치지 않는다. 글자만 키워 문제를 우회하지 않는다. D3·D5.

### A02 · P1 · 잠긴 장소와 잠금 이유를 여는 버튼을 구분해야 한다

**확인:** `world-runtime.js`는 잠긴 장소의 버튼에 `aria-disabled="true"`를 주면서 접근성 이름에는 `눌러서 조건 확인`을 넣고 클릭 시 정보 창을 연다. 최초 수집에서도 Playwright의 일반 클릭이 이 상태를 비활성으로 판단했다.

**문제:** ‘장소에 들어갈 수 없다’와 ‘이 설명을 열 수 없다’가 같은 비활성 의미로 표현된다. 이것을 모든 기기에서 터치가 막힌다는 주장으로 확대하지 않는다.

**변경 방향:** 정보 창을 여는 지도 표식은 사용 가능한 버튼으로 두고 장소의 잠금 상태를 별도 문구·표식으로 표현한다. 실제 입장 행동만 조건에 따라 비활성으로 둔다. 미구현 장소와 아직 조건을 못 채운 장소도 같은 안내로 합치지 않는다.

**근거:** `src/world-runtime.js:185–189`, 첫 수집 run `37298008651`의 manifest. 수정 수집기는 정보 내용을 보기 위해 이 표식에만 `dispatch_event('click')`을 사용한다. 이는 정상 포인터 조작이나 보조기술 사용성 통과가 아니다.

**완료 기준:** 잠금 설명은 일반 클릭·키보드·VoiceOver로 접근하고, 조건 불충족 상태에서 입장 자체는 열리지 않는다. D3·D6.

### A03 · P2 · 실행과 닫기의 시각적 우선순위가 뒤집힌다

**확인:** 게시판은 작은 기본 버튼으로 의뢰를 고르는 반면 하단 `닫기`는 넓은 짙은 녹색 버튼이다. 일반 메뉴도 이동 행보다 닫기가 더 강한 채움색을 가진다.

**판단:** 같은 녹색 채움이 랜딩에서는 여행 시작을, 다른 곳에서는 창을 닫는 행동을 가장 강하게 권한다. 단독 확인 창의 닫기와 여러 선택을 제공하는 창의 닫기를 구분해야 한다.

**변경 방향:** `.sheetactions button`의 일괄 기본값을 전면 변경하기 전에 게시판과 게임 메뉴에서 실행·보조·닫기 세 역할을 정의한다. 동등한 의뢰 가운데 하나를 임의 추천색으로 만들지 않는다.

**근거:** `quest-board-new-375x640.png`, `menu-from-story-375x640.png`, `src/styles.css`의 `.sheetactions`.

**완료 기준:** 창의 목적 행동을 먼저 발견하고 닫기 역시 쉽게 찾는다. 취소·복원·초기화의 역할을 별도 회귀한다. D3.

### A04 · P2 · 지도는 줄이지 말고 탐색의 진입 위치를 검토한다

**확인:** 375×640에서 도착 직후 지도 문서 높이는 858px, 본편 완료 뒤는 803px이다. 하단 월드맵·여정·단어장 진입은 첫 viewport 아래에 위치한다.

**판단:** 지도를 스크롤한다는 사실은 오류가 아니다. 다만 세계의 지형을 보는 행동과 공통 메뉴에 접근하는 행동을 같은 긴 이동 뒤에 두는 것이 적절한지 검토할 필요가 있다.

**변경 방향:** 상시 사용법·중복 이동 표현부터 검토하고, 지형을 과도하게 축소하지 않는 탐색 배치를 대표 시안으로 비교한다. 고정 하단 바를 바로 확정하지 않는다. 그림을 가리는지와 safe-area를 먼저 확인한다.

**근거:** `world-arrival-375x640.png`, `world-chapter-complete-375x640.png`, inventory의 document/targets 좌표.

**완료 기준:** 지명과 장소 관계를 유지하면서 공통 탐색을 쉽게 찾는다. 전체 페이지를 620px로 압축하지 않는다. D1·D2·D3.

### A05 · P2 · 돌아가기는 진입 위치와 읽던 위치를 보존해야 한다

**코드 확인:** 단어장 `exit()`는 월드맵·여정을 제외한 진입 위치에서 `GameFlow.resume()`를 호출한다. 랜딩에서 단어장을 열었을 때 ‘이전 화면’이 랜딩 복귀가 아니라 여행 재개가 되는 경로가 있다. 또한 내부 history는 view 상태만 저장하고 `render()`가 항상 `scrollTo(0,0)`를 실행한다.

**변경 방향:** 실제 이전 화면으로 돌아가기와 여행을 이어가기를 분리한다. 단어장 내부 목록의 스크롤·검색어·초점을 저장하고, 여정에서 세부 항목을 열었다 돌아올 때도 같은 계약을 적용한다.

**근거:** `src/lexicon-runtime.js:265–293,331–344`, `src/flow-runtime.js:226–239`. 이 항목은 코드 경로 확인이며 새 수집기의 전체 왕복 행동 검증 항목은 아니다.

**완료 기준:** 랜딩→단어장→뒤로는 랜딩으로, 긴 목록→단어→뒤로는 읽던 목록 위치로 돌아온다. 첫 플레이·재플레이의 저장 위치를 변경하지 않는다. D3·D5.

### A06 · P2 · 상태가 바뀌면 운영 설명도 바뀌어야 한다

**확인:** 여정의 상단 버튼이 `월드맵으로`인 완료 상태에도 `본편은 이어서 여행하기로 진행해`라는 안내가 그대로 남는다. 펼침 목록이 짧을 때 하단의 `여정 초기화`도 바로 눈에 들어온다.

**판단:** 안내가 현재 화면과 다른 조작을 가리키고, 회고 공간에 운영 설명과 파괴적 도구가 함께 남는다. 다만 초기화는 확인 단계가 있으므로 즉시 삭제된다는 뜻은 아니다.

**변경 방향:** 필요한 진행 상태에서만 짧은 안내를 두고, 재플레이의 저장 분리는 해당 행동 가까운 도움으로 옮긴다. 초기화의 주 진입은 설정으로 모으는 안을 검토한다. 기록 계층 자체는 유지한다.

**근거:** `journey-first-quest-complete-375x640.png`, `journey-tower-focus-375x640.png`; `index.html`의 고정 `.flowNote`, `journey-runtime.js`의 reset 행.

**완료 기준:** 안내에 적힌 행동이 실제 화면에 존재하고, 삭제·복원은 예측 가능한 도구 위치에서 제공된다. D2·D3·D5.

### A07 · P2 검증 대기 · 방의 작은 그림과 실제 타격 영역을 분리해서 확인한다

**확인:** 375px 폭에서 길잡이패 버튼 자체의 회전 후 경계는 약 38.7×26.7px, 수리패는 37.2×26.4px, 관찰 카드는 46.5×32.3px이다. **그러나 `inn-keepsakes.css`의 `::before { inset:-8px }`가 타격 영역을 확장하므로 이 수치를 실제 터치 크기로 단정하면 안 된다.**

**변경 방향:** 그림은 지금 크기로 보존한다. 확장된 영역의 가장자리와 다른 사물과의 겹침을 실제 포인터로 측정한 뒤 필요한 것만 조정한다. 두 통행패가 함께 놓인 경우도 추가한다. 관찰 카드를 ‘32px라서 기준 미달’로 자동 분류하지 않는다.

**완료 기준:** 사물마다 충분한 실제 입력 영역이 있고 다른 물건을 잘못 열지 않는다. 장면 전체에 큰 버튼 외곽선을 덧씌우지 않는다. D1·D3.

### A08 · P2 · 공통 CSS와 검수의 책임을 좁고 분명하게 한다

**확인:** 공통 UX 파일에 장터 전용 패널·높이 예외가 있고, 기존 정적 UX 감사에는 CSS 문자열과 DOM 순서로 판정하는 부분이 있다.

**판단:** 화면 하나의 수정이 다른 역할의 화면에 퍼질 위험이 있다. 이것을 CSS 파일 수가 많다는 이유만으로 전면 재작성할 근거로 삼지 않는다.

**변경 방향:** A01/A03에 필요한 버튼·보조 창 역할부터 실제 두 사용처를 묶고, 지역 전용 규칙은 변경하는 범위에서만 구분한다. 최종 계산값·상태별 캡처·복귀 검사를 함께 둔다.

**완료 기준:** 선언이 있다는 이유로 통과하지 않고 실제 표시와 hit area를 확인한다. 공통 변경 후 전술·탑·단어장·설정에 회귀가 없다. D2·D3·D6.

## 6. 결함으로 확정하지 않은 항목

랜딩의 과거 캡처에는 시작 버튼이 희미하게 보이는 순간이 있으나, CSS의 유한 등장 애니메이션이 끝난 새 캡처에서는 정상적으로 선명하다. 이것을 최종 대비 결함으로 기록하지 않는다. 애니메이션 중 상호작용과 reduced-motion은 별도 검수로 남긴다.

설정 switch 자체는 48×28px이지만 클릭 가능한 전체 label이 더 크다. 수정 수집기는 label을 effective target으로 계산하며 28px만으로 터치 위반을 만들지 않는다.

설정·단어장·여정의 긴 문서와 탑의 내부 읽기 스크롤은 목적에 따라 허용한다. 전술 화면의 무스크롤 핵심 예산을 모든 화면에 강제하지 않는다. 학술탑 연구실의 상단·하단 복귀도 단순 중복이라는 이유만으로 삭제하지 않고 실제 접근 위치를 함께 판단한다.

## 8. 재현과 검증 기록

수집기는 `python tools/capture_design_audit.py`로 실행한다. Python Playwright와 Chromium이 필요하며 `TEST_OUTPUT`, 선택적인 `CHROMIUM_PATH`를 받는다. `.github/workflows/design-audit.yml`은 수동 실행 또는 수집기·워크플로 변경 시 실행한다. 기본 배포 검사를 대체하지 않는다.

새 수집의 아티팩트 이름은 `design-audit-snapshots`이며 30일 보관한다. `inventory.json`의 `id`와 같은 PNG 이름으로 증거를 찾는다. 원자료의 `smallTargets`는 자동 실패가 아니며 §2와 A07의 한계를 함께 읽는다. 향후 잘못된 버튼을 코드로 강제 클릭해 사용성 검사를 통과시키지 않는다. 잠금 정보의 프로그램 호출은 내용 관찰 전용이다.

새 수집 실행 `37298955082`(커밋 `7c74990`)은 성공했으며 **40개 화면 상태 × 4 viewport = 160개 캡처, 수집 오류 0개**를 남겼다. 아티팩트 ID는 `11339419944`다. 160개 상태의 문서 폭에서 가로 넘침은 관찰되지 않았다. 이는 모든 내부 요소의 겹침·클리핑이 없다는 보장은 아니다.

# 재사용 가능한 게임 규칙·기믹 도감 v0.2

> 작성·실제 코드 대조: 2026-10-27 (Asia/Taipei)
> 범위: 튜토리얼 6판, 길목 G1~G7, 장인골 W1~W7, 장터 M1~M8, 북쪽 숲 F1~F8, 학술탑 본선 01~05·03A·03B, 여관 방 MVP
> 성격: **실제로 구현된 의미 행동의 재사용 색인**. 이번 개정은 문서 작업이며 새로운 기능·테스트·배포·iPhone 실기기 승인을 뜻하지 않는다.
> 이력 보존: [v0.1](REUSABLE-MECHANICS-v0.1.md)은 초기 튜토리얼/G1 및 2026-10-25~27 학술탑 추가 기록을 그대로 보존한다.

관련 기준: [게임 전체 구조](GAME-CONTENT-FRAMEWORK-v0.1.md), [지역·스테이지 개발 표준](REGION-STAGE-DEVELOPMENT-STANDARD-v0.1.md), [디자인 원칙 v0.3](DESIGN-PRINCIPLES-v0.3.md), [개발 상황판](DEVELOPMENT-STATUS.md).

**새 스테이지를 만들 때 “이 의미를 플레이어가 직접 경험하려면, 이미 있는 어떤 판정을 어떻게 조합할까?”라는 질문에 답하기 위한 도감**이다. 스테이지의 사건·대사·원문·정답까지 이 문서로 옮기지 않는다. 그 책임은 지역 상세 설계 문서에 남긴다.

## 0. 기본 모델·재사용 상태·작성 원칙

### 0.1 도감의 최소 단위

`단어·구문의 의미 → 플레이어가 겪는 관계·상태 → 모바일 입력 → 조건 판정 → 실제 상태 변화 → 중국어/시각 피드백`

- **판정:** 거리·수량·일치·조건·경로처럼 참/거짓 또는 상태값을 결정하는 규칙.
- **기믹:** 플레이어가 그 판정을 이해해서 직접 대상을 조사·이동·선택·수정하는 경험.
- **조작:** 칸 탭, 직접 대상 선택, 값 조절, 구절 연결, 빈칸 메뉴 등. 조작법 자체를 단어의 뜻으로 취급하지 않는다.
- **지역 표현:** 같은 거리 판정도 길목의 격자, 숲의 흔적, 학술탑의 근거 범위처럼 서로 다르게 보여 줄 수 있다.
- **진행 계약:** 최초 본편, 재플레이, 중단·재개, 저장, 이야기 전환에서 유지할 상태와 결과.

기본 기술은 `trigger → predicate → state delta → feedback → win`이다. 학술탑도 `자료 선택 → 관계 판정 → 원본을 보존한 작업 기록 변경 → 근거 피드백`으로 설명할 수 있다.

### 0.2 재사용 수준과 검증 수준은 다르다

| 상태 | 실제 뜻 | 다음 스테이지에서 |
|---|---|---|
| **C · 공용** | 코드로 분리된 공통 판정 또는 복수 사용처의 공유 흐름 | 지원하는 데이터·화면 범위를 확인해 재사용한다. *모든 지역 UI에서 바로 작동한다는 뜻은 아니다* |
| **R · 지역 공통** | 같은 지역의 여러 판에서 사용하는 상태·런타임 | 지역 안에서는 데이터 조합 우선. 다른 지역에서는 어댑터 필요 여부 확인 |
| **S · 전용** | 한 판/연구에서 구현·검증됐지만 범용 API는 없음 | 실제 두 번째 사용처에서 필요한 만큼만 일반화 |
| **P · 미구현** | 설계·아이디어만 있음 | 실제로 작동하는 기믹으로 표기하지 않음 |

검증은 별도로 **코드 존재 → Node 단위검사 → 브라우저·모바일 검사 → Pages 배포 → iPhone Safari G6 실기기 승인**을 남긴다. C여도 G6가 미완료일 수 있다. S여도 해당 스테이지는 자동검사를 통과했을 수 있다.

2026-10-27 학술탑 03B 빈칸 직접 드롭다운은 빌드 `2026-10-27-tower-03b-dropdown-v5`, Node **337개**와 네 모바일 뷰포트 브라우저 검사·Pages 성공 이력이 있다([v0.1 §13](REUSABLE-MECHANICS-v0.1.md), [03B 상세 설계 §13](ACADEMIC-TOWER-RAN-REVISIT-03B-DETAIL-v0.1.md)). **03B의 G6 검수는 2026-10-27 사용자 완료 확인으로 마감됐다**. 별도 실검수 수행일·세부 체크리스트는 전달되지 않았으며 학술탑 본선 01~05·선택 03A의 기기 승인과는 구분한다. 다른 지역의 기기 승인은 [개발 상황판](DEVELOPMENT-STATUS.md)과 해당 구현 기록을 따른다.

### 0.3 일곱 공통 원칙

1. `避開` 버튼으로 위험을 지우지 않고 이동으로 피한다. `出現` 버튼을 누르지 않고 상태를 맞춰 현상이 나타나게 한다. 단어는 세계의 **관계와 변화**로 보인다.
2. 단어 카드·대상 정보 조회는 페널티 없이 허용한다. 조회만으로 목표를 완료할지는 그 학습 목적에 맞게 따로 정한다.
3. 위험한 이동·충돌·잘못된 목적지는 가능하면 확정 전에 막는다. 틀린 의미 판단은 지우지 말고 근거를 되짚게 한다.
4. 판에서 보이는 정보를 같은 상태줄·카드·완료 문구에 반복하지 않는다. 피드백에는 **새로 생긴 정보**를 적는다.
5. 의미상 가능하면 복수 해법·조작 순서를 허용한다. 정해진 순서 자체를 가르칠 때만 순서를 강제한다.
6. 정답을 외운 뒤에도 단어가 가리키는 관계를 다시 확인하는 활동이 남아야 한다. 의미 판단 없는 재배열·확인 클릭은 없앤다.
7. 직접 선택/실행/닫기/되돌리기를 예측 가능하게 만든다. 44px 터치 목표와 세로 375×812·375×667·375×640·360×640을 고려한다.

**기믹 카드 — SP07:** G5에선 수레를 직접 옮겼지만 G6에선 소년만 이동해 수레가 따라온다. 소년이 좁은 지름길에 들어가는 것은 막지 않고 수레만 멈춰 이유를 보여 준다. 플레이어가 다시 길을 찾아 수레 가까이 돌아가면 회복할 수 있다. G7에서는 같은 추종 판단을 두 수레로 확장한다. 이는 `跟隨/帶領`의 **주체 차이**를 조작으로 보여 주는 사례다.

## 2. 상태·수치·조건·인과 (`ST`)

장인골은 `장치 상태 관찰 → 일부 조작 → 다른 상태 변화 확인 → 조건 만족`이 중심이다. `src/workshop-runtime.js`의 `WorkshopMechanic`와 `src/workshop-late-runtime.js`를 사용한다.

| ID | 의미 행동 | 사용처·수준 | 피해야 할 오용 |
|---|---|---|---|
| **ST01 바꾸기/유지하기** | 한 수문만 변경하고 다른 것은 유지한다 | W1·W7 · **R** | 무조건 다 바꾸지 않는다. `保持`가 필요한 상태를 읽게 한다 |
| **ST02 증가·감소·조절** | 불·바람 등 값의 크기를 높이거나 낮춰 목표에 맞춘다 | W2·W5·W7 · **R** | `增加/減少`는 변화의 방향, `調整`은 목표를 맞추는 일이다 |
| **ST03 연결·분리·상태 전파** | 연결된 축이 다른 장치에 영향을 주게 한다 | W3·W7 · **R** | 연결 표시뿐 아니라 다른 요소의 회전·정지를 보여 준다 |
| **ST04 여러 조건을 함께 만족** | 물·연결·화덕 상태를 동시에 맞춘다 | W4·W7 · **R** | 장인골 `conditionMet/predicates`는 지역 API다. 전역 predicate registry로 오인하지 않는다 |
| **ST05 파생 현상 출현·소멸** | 값을 조정한 결과로 푸른 불꽃이 나타나거나 사라진다 | W5·W7 · **R** | `出現/消失` 직접 실행 버튼을 만들지 않는다 |
| **ST06 손상 조사·수리·기능 회복** | 고장 난 톱니를 확인하고 수리해 장치 기능을 되돌린다 | W6·W7 · **R** | `損壞` 상태, `修復` 행동, `恢復` 결과를 구분한다 |
| **ST07 복합 장치 종합** | 유지·조절·연결·수리를 자유로운 순서로 조합 | W7 · **R** | `남은 이상 수`는 실제 조건 배열에서 파생한다. 조작값과 파생 결과를 중복 저장·표시하지 않는다 |

**조합 예:** W5는 `ST02 → ST05`이고 W7은 여러 `ST` 판정을 새 버튼 없이 결합한다. 장터에도 조건 평가 함수가 있지만 **장인골과 장터의 `conditionMet`는 서로 다른 지역 함수**다.

## 3. 수량·자원·거래·선택 (`RS`)

장터는 이동 경로보다 물건·수량·돈·용량의 변화가 핵심이다. `src/market-runtime.js`의 `MarketMechanic`와 `src/market-inference-runtime.js`를 따른다.

| ID | 의미 행동 | 사용처·수준 | 재사용 조건 |
|---|---|---|---|
| **RS01 필요·부족·충분** | `need`와 현재 `stock`으로 부족 여부를 판단 | M1·M7·M8 · **R** | `不足/足夠`는 파생 상태다 |
| **RS02 수량·잔여량·운반 한도** | 가져간 뒤 남은 수량과 운반 가능량을 읽는다 | M2·M5·M6·M8 · **R** | 계산보다 다음 행동 가능성이 중요하다 |
| **RS03 가져가기·놓기·보충·분배** | 출발지 수량 감소→소지 증가→목적지 수량 증가 | M1·M7·M8 · **R** | 한 행동에서 양쪽 수량을 일관되게 바꾸고 잘못된 목적지는 차단한다 |
| **RS04 교환·획득** | 물건을 내주고 다른 물건을 받는다 | M3·M8 · **R** | `交換`은 방법, `獲得`은 결과 |
| **RS05 구매·판매·가격** | 돈을 지불하고 물건과 좌판 수량을 바꾼다 | M4·M8 · **R** | `買/賣`는 같은 거래의 다른 주체 관점 |
| **RS06 선택·대가·보류** | 다른 운반 도구를 비교하고 이번에 싣지 않을 것을 남긴다 | M5·M6 · **R** | M6의 `放棄`는 물건 삭제가 아니라 이번 운반 **보류** |
| **RS07 자원 흐름 종합** | 교환·구매·보충·분배를 여러 순서로 수행 | M8 · **R** | 정해진 처리 순서보다 실제 최종 자원 상태로 완료 판정 |
| **RS08 자료 확인 뒤 남은 양 추론** | 보이지 않는 잔여량을 자료로 판단하고 가능한 구매 확인 | 일부 장터 난이도 보정 · **S/R** | `market-inference-runtime.js`의 스테이지별 조건과 저장을 확인하고 적용 |

**기믹 카드 — RS03:** `take → 출발지 stock 감소 + inventory 증가 → 운반/부족 상태 변동 → put → 목적지 stock 증가 → 목표 충분 상태 → 완료`. 거래와 수량 이동은 되돌리기로 원자적으로 복원돼야 한다. 장터 `conditionMet`의 `all/any`·위치별 수량·소지·조사·선택 조건은 **장터 지역의 판정**이지 장인골과 공유하는 전역 조건 언어가 아니다.

## 4. 관찰·특징 비교·흔적 추적 (`OB`)

### 같은 공통 작업대 안에서도 다른 문제를 만든다

- **01 卻:** 첫 기록은 기대와 실제의 어긋남을 읽는다. 둘째 기록은 오래된 장치에 대한 점검 메모 중 **잘못된 추론**만 고친다. ‘앞뒤 사실을 둘 다 유지한다’만으로 축소하지 않는다.
- **02 然而:** 뒤 기록을 근거로 기존 보고의 어느 판단 범위를 제한해야 할지 직접 연결한다.
- **03 果然/竟然:** 긍정·부정과 별개로 예상과 실제가 맞는지를 판정한다.
- **04 反而:** 첫 기록은 사라진 예상/실제 연결, 둘째는 결과와 反而를 고정한 채 그에 반하는 **이전 예상 추론**이다.
- **05 종합:** 이어지는 기록의 문맥·조건을 읽고 남길 판단을 선택한다.
- **03A 然:** 관찰 단계에선 구성 글자와 뜻을 읽고, 마지막 적용에서 필요한 문장 관계만 조작한다.

### 03B에서 검증된 패턴을 옮길 때

03B의 흐름은 `도입 이야기 → 의미 작업 → 필요할 때 중간 인물 이야기 → 다음 판단 → 공동 기록 → 결말`이다. **이야기 화면은 인물의 사건과 관계를, 작업대는 플레이어의 판단을 맡는다.** 단계마다 정답 뒤 인물 대사를 끼우지 않는다.

- `仍然`: 옛 지도와 현재 경험에서 계속 남은 사실을 확인한다.
- `當然`: 익명 쪽지 작성자의 확신이 **두 사람의 결론이 아님**을 표시한다.
- `固然`: 연구원의 앞부분을 인정하면서 소년의 현재 정보를 이어 쓴다.
- `不盡然`: 옛 지도의 쓸모를 지나치게 단정한 평가 부분만 고친다.
- `突然`: 실제 사건 속에서 경험하며 별도 오지선다를 의무로 만들지 않는다.
- **T6:** 연구실 사건/익명 인용/공동 해설의 서로 다른 문장에 다섯 표현을 복원한다. 모든 칸을 채운 뒤 `기록 검토`를 누른다. 틀린 칸을 지우지 않고 근거를 다시 보게 한다.

**현재 v5의 입력 계약:** 빈칸 자체(44px 이상)를 누르면 **그 문장 아래** 표현 선택 메뉴가 열린다. 한 표현을 다른 빈칸에서 선택하면 기존 배치와 교환·이동한다. 단순히 메뉴를 열었다 닫는 동작으로 이전 판정이 사라지지 않는다. 실제 배치가 바뀔 때만 다시 검토하게 한다. 드롭다운 열림·선택 위치·단어 순서·오답·새로고침 후 복구를 검증한다.

**일반화 금지:** `renderVillageMeaning`, `renderVillageCloze`, `villageResearch`, 내부 중간 장면 분기는 **03B 전용**이다. 다른 연구에 옮길 때는 슬롯 수·중복 가능 여부·정답/오답·선택지·장면 조건·저장을 별도 결정한다. v4의 **하단 공용 단어 은행**은 이력으로만 남으며, 현행은 v5의 직접 드롭다운이다.

### 8.2 일반화 대기 — 실제 두 번째 사용처가 나타날 때

| 항목 | 현행 판정 | 필요한 최소 공통화 |

## 1. 이번 첫 구간에서 플레이어가 경험할 변화

> **예전과 같은 장소로 돌아왔는데, 그곳에서 무엇을 알 수 있고 아직 무엇을 알 수 없는지가 달라져 있다.**

1장에서는 소년이 앞에 있는 장치·수레·짐의 상태를 직접 바꿨다. 2장 첫 구간에서는 **서로 다른 출처로 얻은 정보를 오해 없이 모으고, 아직 판단할 수 없는 부분을 남기는 행동**이 중심이야.

플레이는 한 가지 필수 조사 순서로 이어지지 않아.

~~~text
1장 방 결말 → 《큰비가 내리던 밤》 (기존 구현)
                     │
               비가 그친 월드맵
                     │
  ┌──────────────────┼─────────────────────┐
  길목 첫 풍경       장터 첫 풍경          장인골 첫 풍경
  (선택)             (선택)                (선택)
  └───────┬──────────┴─────────────────────┘
          │  첫 풍경 세 개를 다 봐야 할 의무 없음
     ┌────┴────────────────┐
  회의소 첫 회의           끝마을 통행 조사
  (독립 시작)             (독립 시작)
     └──────────┬──────────┘
            후속 합동 회의
            (별도 다음 설계)
~~~

- **여관**은 이미 구현된 2장 도입 장소·생활 거점이야. 큰비가 끝날 때 C08 첫 자유 의뢰를 그대로 진행할 수 있어.
- **학술탑 04A와 북쪽 숲**은 상설·자유 콘텐츠야. 2장의 필수 선수로 바꾸지 않아.
- 회의소를 먼저 다녀온 소년은 끝마을 현장 확인이 왜 필요한지 알고 갈 수 있어. 끝마을을 먼저 다녀온 소년은 자신이 본 공고를 회의에서 전달할 수 있어. **방문 순서는 결론을 달라지게 하지 않고 대사·출처의 정확도에만 영향을 준다.**
- 첫 회의는 의견을 듣고 **현장 확인·임시 조치**를 정하는 데서 마쳐. 복구 순위·최종 해결은 후속 합동 회의에서 다뤄.

## 2. G3로 이미 아는 것과 이번에 처음 확인할 것을 구분한다

**G3는 이미 같은 세계 목록을 읽을 수 있지만, 우천 뒤의 실제 지역 관측·공고를 저장하고 판정하는 G4 엔진은 아니다.** \`WorldSpatialContext.planningRule('scenario:post-rain-border-travel').active\`는 지금 \`false\`이고, 승인된 이야기 설정을 현재 통행 제한으로 곧바로 적용하면 안 돼.

| 정보 | 이미 확정·구현된 근거 | 소년이 첫 구간에서 접하는 방식 | 함부로 단정할 수 없는 것 |
|---|---|---|---|
| 1장 이후 한 차례 큰비 | \`JourneyProgress.hasRainPassed\` · 기존 도입 | 비가 그친 현재를 공통 시점으로 삼아 | 1장의 사건이 큰비 때문에 발생함 |
| 길목→끝마을 방면 | G2 \`relation:gate-to-border\` | 안내·경로의 이야기 관계를 재사용 | 실제 도로 edge·막힌 위치·다리 손상 |
| 장터→회의소 | G2 \`relation:market-to-council\` | 장터지기의 관심이 회의소와 이어짐 | 장터 방문이 회의소 입장 선수라는 해석 |
| 장인골→학술탑 | G2 \`relation:workshop-to-tower\` | 장인골의 수로 점검 관심을 별도로 전달 | 학술탑 04A 완료가 이번 본편의 선수라는 해석 |

| 회의소의 의견 차이 | 2장 스토리라인·회의소 학습 초안 | 각 화자의 발언을 그 사람의 의견으로 기록 | 주민의 주장=측량으로 검증된 사실 |
| 끝마을 너머 운반 제한 | G2 \`scenario:post-rain-border-travel\` (향후 승인 조건) | **끝마을에서 공고를 직접 본 경우**만 소년의 기록에 추가하는 것을 제안 | 끝마을 자체 진입 금지·구체 구간·원인·해제 시각 |
| 04A 측벽 인공 통로 D | G2 \`observation:04a-side-outlet\` | \`openingFound\` 또는 04A 완료로 실제 발견한 경우에만 아는 정보 | 종착지·제작자·목적·불법 취수·이번 도로 피해와 인과 |

### 정적 사실·현재 사건·소년의 지식·발언 출처의 네 층

이번 첫 구간에서 필요한 최소 정보 모델은 네 층을 구별해.

1. **정적 세계 사실**: 지역 ID·소속·서사적 관계·미확정 연결. 기존 G2 JSON을 재사용해.
2. **현재 사건 상태**: 큰비가 이미 지남. 큰비 전 W7 수리·M8 분배의 완료 상태는 보존해. 구체 우천 피해 좌표는 여전히 미확정이야.
3. **소년의 지식**: 해당 현장을 실제 조사했는지, 공고를 읽었는지, 회의에서 특정 화자의 말을 들었는지를 *기존 진행 기록으로부터* 파생해.
4. **발언/문서 출처**: 누가 주장했는지, 누가 작성했는지, 어느 시점에 해당하는지. ‘누군가 걱정했다’는 기록을 ‘피해가 확인됐다’로 자동 올리지 않아.

차후 구현 후보 예시(현재 데이터가 아님):

~~~js
{
  evidenceId: 'evidence:chapter2-market-next-shipment',
  placeId: 'market-town',
  eventId: 'chapter2-rain',
  source: { type: 'speaker', id: 'marketkeeper' },
  observedWhen: 'post-rain-first-visit',
  report: 'next-shipment-delayed',
  status: 'attributed-report',          // 소년의 직접 측량 기록 아님
  knownAfter: 'story:chapter2-market-first-look',
  cause: 'unknown',
  coordinates: null
}
~~~

\`observedWhen\`과 \`knownAfter\`는 반드시 다른 필드로 둬. **사건이 발생한 시점**과 **소년이 알게 된 시점**을 혼동하지 않기 위해서야. 위 구조·ID는 설명용 후보로, 승인 없이 \`data/world-spatial-catalog-v0.1.json\`의 확정 지형에 추가하지 않아.

## 3. 먼저 들를 수 있는 세 갈래 — 선택형 첫 풍경

이 세 장면은 1장 스테이지를 재플레이시키지 않고, **한 장소를 다시 보면서 달라진 정보를 하나씩 구별**하는 1회성 이야기·짧은 조사 후보야. 첫 방문 순서 자유, 전부 완료할 의무 없음. 첫 플레이 후에는 여정에서 다시 읽을 수 있어.

| 장소 | 기존 사실 | 새 관찰·발언 후보 | 조작과 보이는 결과 | 다음 이야기의 다리 |
|---|---|---|---|---|
| 길목 | G7 소년의 길안내·통행패는 유효 | 길 가장자리의 진흙·자갈, 관리인의 재점검 | 길가 흔적을 눌러 **눈으로 본 것**과 **아직 통행 가능 여부를 판단하지 않은 것**을 다른 기록 칸에 놓는다 | 끝마을의 공고와 실제 제한을 다시 확인 |
| 장터 | M8 물자 분배는 끝남 | 새로 들어올 물자가 아직 도착하지 않았다는 말 | **지난 물자**와 **새 물자**를 탭해 구분한다. 새로운 물류 지연이 과거 분배 실패로 표시되지 않아 | 회의소에서 물자 확인 요청의 출처를 보존 |
| 장인골 | W7 수차·공방 장치는 고쳐짐 | 수차는 움직이고, 큰비 뒤 수로는 점검할 필요가 있다는 설명 | **작동 확인**과 **추가 점검 필요**를 각각 다른 상태로 표시한다 | 학술탑의 관측 역할을 알되 04A 비밀은 공개하지 않음 |

모바일 공통 원칙은 ‘원본 장면의 사물·주민을 누른다 → 아래에 짧은 번체 중국어와 근거가 나타난다 → 내가 확인한 한 줄만 남긴다’야. 이미 구현한 여관의 하단 조사 패턴을 **필요한 만큼만** 참고하되, 모든 장소에 여관 C 그림을 복제하지 않아.

학습 역할은 기존 어휘의 의미를 **재사용**하는 데 둬. 길목은 \`位置 / 周圍 / 障礙\`, 장터는 \`分配 / 補充\`, 장인골은 \`保持 / 改變\`의 관계를 새 상황에서 활용할 수 있어. 이 단계에서 새로운 목표어를 각각 필수 추가하지 않아. 짧은 감상 장면이라면 억지 정답 판정 없이 끝내도 돼.

**정보 누출 방지:** 소년이 장터에 안 갔는데 시장의 진술을 ‘내 현장 관찰’로 기록하면 안 돼. 회의소에서 듣게 된다면 ‘장터 대표가 그렇게 말했다’는 증언으로 구분해.

## 4. 본편의 자유로운 두 출발점

둘은 독립적인 첫 플레이 구간이야. **하나를 먼저 했다고 다른 쪽이 잠기지 않아.** 각자 짧은 도입 이야기 → 의미 행동 한 판 → 결과 이야기로 이어지는 형태를 기본 후보로 잡아.

### 4.1 회의소 01 — 《누가 무엇을 말했을까》

**상황:** 큰비 뒤 사람들은 길 보수·수로 점검·물가 안전을 서로 다른 이유로 걱정한다. 소년은 회의의 우선순위를 혼자 정하지 않고 **각 사람의 요구를 정확하게 회의록 초안에 옮기는 일**을 맡아.

**학습 목표 후보:** \`該 + 명사\`, \`本 + 명사\`의 **재지칭 대상과 기록 작성자의 관점**. 기존 \`但是 / 先 / 再\`는 재등장어로 사용해. 2장 첫 판에 여러 지시 표현을 한꺼번에 넣지 않으며, \`因此 / 其 / 前者 / 後者\`는 후속 회의록 후보로 남겨.

**자료 후보(번체 윤문·주음·TBCL 검증 전 창작 초안):**

| 출처 | 발언/기록의 내용 | 소년이 남길 것 |
|---|---|---|
| 장터 쪽 발언자 | \`新一批貨還沒到。我們想先確認運送的情況。\` | 새 물자 도착 지연에 대한 발언 + 운반 상황 확인 요청 |
| 장인골 쪽 발언자 | \`水車還在轉，但水道也需要重新檢查。\` | 수차는 작동함 + 수로는 점검이 필요하다는 입장 |
| 물가 주민 | \`我們擔心下次再下大雨時，住在低處的人怎麼辦。\` | 다음 큰비 대비에 대한 **걱정**, 현재 침수 피해 확정 아님 |
| 회의록 작성자 | \`本鎮還沒有決定修繕順序。\` | \`本鎮\`은 기록의 작성 주체인 三溪鎮, **보수 순위 미확정** |
| 회의록 작성자 | \`先確認該批貨的運送情況。\` | \`該批貨\`는 앞에서 특정한 **새로 들어올 물자** |

**한 판의 모바일 의미 조작:**

1. 한 사람의 발언을 듣고, 하단의 **‘화자 · 말한 사실/걱정 · 요청한 점검’** 칸에 맞는 내용을 탭해 임시로 붙인다. 다음 발언을 듣기 전에 첫 답을 확정할 필요는 없어.
2. 짧은 회의록이 나타나면 \`該批貨\`를 탭해 원래 발언의 대상인 **새 물자**에 연결하고, \`本鎮\`을 누르면 회의록 작성자·마을 이름을 먼저 확인한 뒤 **물길마을**에 연결한다.
3. 마지막에는 **확인할 현장과 당장 가능한 임시 조치**를 기록한다. 어떤 보수를 먼저 할지 정답으로 고르게 하거나, 회의에서 실제로 정하지 않은 우선순위를 기록하지 않아.

**판정 기준:** 발언자의 주장과 확인한 사실을 뒤섞지 않았고, 두 지시 표현의 대상이 정확하며, **미확정인 보수 우선순위를 결론이라고 작성하지 않으면** 완료야. 플레이어 개인의 정책 선호는 정답/오답이 아니야.

**대표 오해와 복구:** \`수차가 고장 났다\`를 기록하려 하면 ‘수차는 돌고 있지만 **수로 점검을 요청**한 말’이라는 원문 근거를 다시 보여줘. \`該批貨\`를 지난번 M8 분배 물자로 연결하려 하면 새 물자와 완료된 분배를 나란히 보여줘. 오답은 초기화·벌점 대신 **틀린 연결 한 줄만 다시 선택**하게 해.

**결과:** 첫 회의가 할 수 있는 임시 확인과 담당자 전달 범위를 정하는 데서 끝나. 소년에게 마을 전체의 보수 책임이나 결정 권한을 주지 않아. 다음 합동 회의의 순위·대도시 지원 요청은 이번 판에서 끝내지 않아.

### 4.2 끝마을 01 — 《막힌 것은 어느 길일까》

**상황:** 소년은 1장 G7에서 익힌 북쪽 길을 따라 끝마을에 도착한다. 마을 자체로 오는 길이 막힌 것은 아니지만, **그 너머 외부와 이어지는 일부 구간**에는 통행 제한이 있다.

**학습 목표 후보:** \`目前\`, \`暫時\`, \`限制\`. 시점·적용 범위·대상 차이를 읽고 실제 가능한 선택을 갱신한다. \`通過 / 經由 / 允許\`는 이전 학습을 재사용해. 수량·적재중량의 임의 수치를 만들지 않아.

**공고 후보(번체 윤문·공고 표현/대상 교정 전 창작 초안):**

> \`目前，通往外地的部分路段暫時限制載重較大的貨車雙向通行。行人仍可通過；輕型手推車須先確認通行條件。\`

이는 이야기의 **정해진 통행 조건을 표현하는 예문 후보**이지 현재 지도에서 통행을 제한하는 실제 규칙이나 지정된 도로 좌표가 아니야.

**한 판의 모바일 의미 조작:**

1. 기존 길목에서 익힌 경로 정보와 **끝마을 현장의 공고**를 구별해. 공고에서 \`目前 / 暫時\`를 눌러 ‘현재 적용되는 임시 제한’임을 확인하고, 제한 대상이 **어느 길 전체가 아니라 외부행 일부 구간**인지 잡는다.
2. 세 이동 방식(보행·조건 확인이 필요한 가벼운 손수레·무거운 짐수레)을 각각 탭해 **현재 가능 / 확인이 먼저 필요 / 양방향 임시 제한**으로 분류한다. 모두 막혔다거나 가벼운 손수레는 무조건 허용된다고 처리하면 다시 문구를 보게 해.
3. 누군가 ‘전부 막혔대’라고 전하더라도, 그 말과 공식 공고를 **별도의 출처**로 놓는다. 소문만 보고 길을 열거나 닫지 않아. 소년은 자신이 확인한 제한 조건과 **모르는 구간·원인**을 기록해.

**판정 기준:** 보행 가능, 가벼운 손수레 조건부, 무거운 수레 양방향 임시 제한을 구분하고 **끝마을 접근 가능**을 유지하면 완료야. 이용자에게 통행을 허가하거나 실제 정비 공사를 지시하는 권한을 주지 않아.

**대표 오해와 복구:** \`暫時\`를 영구 폐쇄로 처리하거나, 소문 때문에 모든 길을 폐쇄하면 공고의 **시점·대상·적용 범위**만 다시 강조하고 분류표를 수정하게 해.

**결과:** 소년은 장터의 물자 문제, 연구원의 큰 장비, 가족·친지의 왕래가 **왜 같은 제한 아래에서도 서로 다른 부담**을 받는지 알기 시작해. 그러나 운반량·해제 시점·실제 도로 파손 원인은 아직 모른다고 기록해.

## 5. 두 출발점의 순서가 바뀌어도 모순되지 않는 정보

| 진행 순서 | 회의소에서 소년이 말할 수 있는 것 | 끝마을에서 소년이 알고 갈 수 있는 것 |
|---|---|---|
| 회의소 먼저 | ‘장터·장인골·물가 주민이 **이렇게 말했다**’는 출처별 기록. **공고 확인 전**에는 끝마을의 특정 제한을 직접 봤다고 말하지 않음 | 회의에서 **현장 확인이 필요하다**는 말을 들었고, 공고는 아직 읽지 않음 |
| 끝마을 먼저 | 공고를 직접 읽은 뒤라면 ‘외부행 일부 구간에서 **이런 임시 제한을 확인했다**’고 말할 수 있음. 그 원인·해제 시각은 모름 | 자기 눈으로 공고를 읽고 조건부/제한 대상을 분류했지만 회의에서 어떤 임시 조치를 정했는지는 아직 모름 |
| 두 곳 모두 다녀옴 | 주민의 걱정·요청과 실제 확인한 공고를 **출처별로 구별**해 전달 가능 | 후속 합동 회의에서 정보를 모을 근거가 마련됨. 첫 회의의 결론을 과거로 바꾸지 않음 |
| 04A 선택 연구만 완료 | 측벽 D 관측은 **소년이 확인한 선택 연구 사실**일 뿐, 모두가 알고 있는 정보나 도로 제한의 원인 아님 | D의 제작자·목적·종착지가 여전히 미확정이며 2장 필수 진입 조건과 무관 |

**중요:** 먼저 플레이한 콘텐츠가 나중 회의의 *한두 문장*을 바꿀 수는 있어. 하지만 완료 후 다시 플레이한다고 당시 처음 알았던 정보가 소급하여 재작성되면 안 돼. **최초 결과 이야기의 정보 기준은 진입 시점에 고정**하는 편이 안전해. G2 상세 구현에서는 첫 진입 스냅샷과 replay를 분리해.

## 6. 제안하는 G0 안정 ID·여정·진입 경계 (아직 코드 예약 아님)

현재 실제 \`chapter-2-after-rain\` 장에는 \`chapter2-rain-opening\` 이야기 노드만 존재해. 아래 ID는 **충돌 방지를 위해 먼저 제안하는 신규 이름**이며 실제 \`JourneyContent\`나 저장에는 추가하지 않았어.

| 역할 | 제안 ID | \`entryRegionId\` / 반환 |
|---|---|---|
| 길목 첫 풍경 story | \`chapter2-gate-first-look\` | \`gate-town\` → 월드 |
| 장터 첫 풍경 story | \`chapter2-market-first-look\` | \`market-town\` → 월드 |
| 장인골 첫 풍경 story | \`chapter2-workshop-first-look\` | \`workshop-town\` → 월드 |
| 회의소 도입 story | \`chapter2-council-first-intro\` | \`council-town\` → 다음 stage |
| 회의소 01 stage | \`council-stage-01-minutes\` | \`council-town\` → 결과 story |
| 회의소 결과 story | \`chapter2-council-first-result\` | 월드 복귀 |
| 끝마을 도입 story | \`chapter2-border-first-intro\` | \`border-village\` → 다음 stage |
| 끝마을 01 stage | \`border-stage-01-notice\` | \`border-village\` → 결과 story |
| 끝마을 결과 story | \`chapter2-border-first-result\` | 월드 복귀 |

- 기존 \`chapter-2-after-rain\` 아래에 **서로 독립적인 section**으로 넣어. 1장 섹션에서 무조건 다음 2장 섹션으로 진행하는 \`nextSectionId\`나 첫 풍경 3개를 순차 강제하는 연결을 만들지 않아.
- 신규 2장 **첫 시작**은 \`JourneyProgress.hasRainPassed(progress)\`를 의미상 기준으로 해. 정상 \`chapter2-rain-passed\` 및 **큰비를 이미 경험한 구형 저장**을 포함해야 하므로 \`seenStories.includes('chapter2-rain-opening')\` 하나만 강제하지 않아. 기존 \`requiresRainPassed\`와 \`revealAfterRain\`의 실제 적용 위치는 G3 구현 전 계약 테스트로 확인해.
- 각 첫 풍경은 **선택**이므로 회의소·끝마을 입장의 선수로 두지 않아. 03B·04A·숲 F1~F8 완료도 요구하지 않아.
- 기존 지도 마커의 \`gate-core / workshop-core / market-core\` 완료 시 ‘다시 연습하기’ 버튼은 그대로 둬. 새 풍경을 접근 가능하게 하려면 **기존 장소 시트에 별도 ‘비가 그친 뒤 살펴보기’ 진입점**을 조용히 추가하거나 여정에서 직접 선택하도록 설계해야 해. 월드맵 그림·아이콘 위치를 바꾸지 않는 게 기본이야.
- 회의소·끝마을은 기존 지도 마커를 사용해. 현재는 \`hasJourneyContent=false\`라 ‘의뢰 준비 중’이지만, 실제 story/stage를 연결한 뒤에는 독립 진입하도록 해야 해. 이때 **권장 방문 관계**(market→council, gate→border)를 **잠금 조건**으로 바꾸지 않아.
- \`STAGES\` 배열 끝에 신규 stage를 추가하고 \`JourneyContent\` 여정 노드로 표시 순서를 정해. 과거 인덱스·ID는 유지해.
- 첫 풍경은 읽은 경우에만 \`seenStories\`에 저장하고, 의미 행동 stage는 최초 완료만 \`completedStages\` 및 필요한 경우 \`stageOutcomes\`에 저장해. **새 전역 저장 키·백업 버전은 우선 불필요**하며, 도중 중단 저장이 필요하면 기존 전술 저장을 먼저 검토해.
- \`G3 WorldSpatialContext.storyBindings\`에는 **최종 확정된 story ID만** 명시해서 추가해. 배경 이미지·장소 이름으로 자동 연결하지 않아. 출처·소년 지식의 진행별 변형은 \`WorldSpatialContext.planningRule\`의 \`active:false\`와 혼동하지 않는 후속 조회·사건 파생층을 따로 설계해.

## 8. 첫 플레이·오답·중단·재플레이·모바일 검수 조건

- **첫 방문:** 큰비를 겪은 뒤 어떤 장소부터 들어가도 자연스러운 설명이 나온다. 회의소에 먼저 와도 장터 조사부터 요구하지 않고, 끝마을에 먼저 와도 회의소 기록을 요구하지 않아.
- **분기:** council-first / border-first / 두 곳 모두 방문 / 세 풍경 하나도 안 본 경우 / 04A 완료·미완료 각각에서 소년의 대사가 아는 정보와 일치해야 해.
- **오답·복구:** 의미를 오해하면 사실 출처·시점·대상을 다시 보여 주고 해당 연결만 수정할 수 있어. 시간·별점·목숨·반복 정답 파밍을 추가하지 않아.
- **답 외우기 방지:** 회의 발언의 도착 순서, 기록 후보의 배열 위치, 공고 분류 버튼 위치는 바꿀 수 있으나 **문장 의미·출처·시점은 변하면 안 돼**. 반복 플레이의 익숙함이 문장 이해로 이어지게 해.
- **저장:** 1장의 G7/W7/M8 완료·여관·C08·숲 F1~F8·탑 03B/04A·방문 순서·백업을 회수하지 않아. 빈 저장부터 1장→방→큰비→회/끝 양 순서의 종단 회귀가 필요해.
- **구형 저장:** 이미 자유 의뢰·04A를 진행해 큰비가 ‘과거 사건’인 저장에서 비 장면을 다시 발생시키거나 첫인상 기록을 허위 완료 처리하지 않아. 사용자가 직접 선택하면 새 장면을 **당시 첫 확인**으로 자연스럽게 읽도록 시점을 맞춰.
- **재플레이:** 저장된 최초 완료·선택·화자 기록을 덮어쓰지 않아. 다른 순서로 재열람해도 다른 지역의 이미 확정된 최초 발언이 바뀌지 않아.
- **모바일:** iPhone 13 mini의 375×640·375×812 중심으로, 원본 자료와 내가 연결할 기록을 동시에 구별할 수 있어야 해. 모든 탭 44×44px 이상, 큰 문장 재열람·주음·뜻 보기 무료, 빠른 반응이 아닌 의미 이해로 완료해야 해. 길게 누르기·정밀 드래그는 필수 아님.
- **G3 회귀:** \`WorldSpatialContext\` JSON 읽기가 실패해도 2장 본편 콘텐츠를 막지 않아. 플레이어에게 숨겨야 하는 관찰을 DOM/로그/기본 목록에 단정형으로 표시하지 않아. ‘미확정’을 빈 문자열로 덮지 않아.

## 9. 다음 구현 단위와 아직 남은 결정

권장 구현 순서는 다음과 같아.

1. **P1 — 세 갈래의 짧은 첫 풍경**과 회의소·끝마을 입장 연결의 공통 조건 검증. 지도는 그대로 두고, 첫 풍경·재열람·C08/상설 콘텐츠가 양립하는지 먼저 확인해.
2. **P2 — 회의소 01과 끝마을 01의 독립적인 첫 플레이**를 같은 개방 상태로 제공해. 두 갈래를 **둘 다 실제 플레이 가능**하게 한 뒤 첫 구간의 자유 방문 계약을 검수해. 한 쪽만 개발 시험에 먼저 올리는 경우 다른 쪽을 잠갔다고 표시하지 말고 미구현 상태를 구별해.
3. **P3 — 출처/소년 지식 공통 조회**와 첫 회의/끝마을의 정보 상호참조를 붙이고, 처음·역순·재플레이·구형 저장·공식 공고 우선성 검사까지 마쳐.
4. **후속 별도 설계:** 두 첫 이야기에서 나온 자료를 모아 **합동 회의**로 수렴한다. 실제 수리 우선순위·요청서·대도시 이동은 이 문서에서 확정하지 않아.

**구현 전 반드시 확인·닫을 항목:** (a) 위 신규 ID 최종 승인·story/stage 수, (b) 회의 참석자의 대사·번체 문체·주음·TBCL 출처 검증, (c) P1 첫 풍경을 상호작용형으로 만들지 순수 이야기로 마칠지, (d) 회의소/끝마을 원본자료와 작업 화면의 최종 모바일 배치, (e) 초반 stage의 진행 중 저장을 기존 전술 저장으로 충족할지, (f) ‘처음 회의에 참석한 상태의 지식’을 이후 재플레이에 어떻게 고정할지.

완료 기준은 **상세 설계 문서가 다음 구현에서 근거 없는 세계 사실·새 잠금을 만들지 않고 G3의 확정 정보/관찰 출처를 재사용할 수 있는 것**이야. 이번 문서 자체는 실제 새 스테이지·일러스트·세계관의 추가 확정·Pages 배포를 뜻하지 않아.

## 11. 2026-11-03 · P2 구현 사양

§6의 두 장소별 후보 ID 여섯 개를 그대로 사용한다. 정상 큰비와 구형 저장의 해금 판정은 모두 `hasRainPassed`를 따른다. 두 장소는 2장에 각자 한 section으로 등록한다.

회의소는 장터·장인골·물가 발언과 마을 회의록을 원본으로 삼는다. 플레이어는 발언 쪽지를 화자·증언·요청·걱정 칸에 붙이고, 마지막 두 줄에서 該批貨와 本鎮을 원래 대상에 연결한다. 끝마을은 현장 공고와 행상의 말을 따로 읽고 제한 구간·시점·세 이동 방식·출처를 조사표에 넣는다. 같은 칸을 다시 누르면 쪽지를 떼며, 기록 목록에서 이미 작성한 줄을 고쳐도 된다. 대조에 실패하면 해당 원문으로 돌아간다. 목표어를 누르면 주음·뜻이 바로 열린다.

기존 journey 저장 안의 선택 필드 `fieldDrafts[stageId]`에 도입 당시 상대 장소 원문을 본 적이 있는지와 현재 줄·임시 연결을 보존한다. 최초 결과는 `stageOutcomes[stageId]`에 발언/공고 출처 키와 줄별 확정 연결을 남긴다. 재플레이는 별도 메모리에서 시작한다. 각 원문의 출처·귀속은 `src/chapter2-field-content.js`가 소유하며 세계 도로 상태를 변경하지 않는다.

다섯 목표어를 지역 단어장과 생애주기 목록에 등록했다. TBCL은 2025-04 공식 표제 수준이며 개별 문법 용법 등급은 추정하지 않는다. 本은 1, 目前은 4, 暫時와 限制/限은 4*, 該는 5다. 출처는 [國教院 공식 목록](https://coct.naer.edu.tw/file/files/14452%E8%A9%9E%E8%AA%9E%E8%A1%A8202504.pdf)이다.

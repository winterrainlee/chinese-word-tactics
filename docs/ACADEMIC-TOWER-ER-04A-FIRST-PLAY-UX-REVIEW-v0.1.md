## 1. 첫 플레이 동선과 역할 분담

S0 이야기(학술탑 밖 우연한 만남) → T1 A의 증거 추가 → T2 B/C의 판단 → I1 점검길에서 다른 물소리를 들음 → T3 숨은 D 탐색과 유출 방향 확인 → I2 연구원이 원래 도면을 펼침 → T4 인공 흔적과 판단 범위 구분 → T5 조사 기록 완성·다음 질문 선택 → S1 결말 이야기.

T1~T5는 **한 개의 04A 전역 스테이지 안에 들어가는 다섯 의미 작업**이다. 전역 STAGES의 새 항목 다섯 개도, 03B의 다섯 빈칸 복원도 아니다. 본선 04만 필수 선수이며 03A·03B·05는 선수가 아니다.

처음 읽는 화면에 필요한 사실은 주되, 정답 결론을 미리 고백하지 않는다. 다음 구획은 항상 출처를 명시한다.

- 공통 이야기 화면: 인물의 행동·감정·사건. 중간의 인물 대사를 작업대 안에서 다시 반복하지 않는다.
- 관측/원본 영역: 플레이어가 이미 확인한 시각·문장·관리 기록, 관측 시점과 소유자.
- 작업 영역: **소년의 관찰 메모 / 연구원과 함께 검토할 메모 / 소년과 연구원의 조사 기록**처럼 실제 작성자를 표시한다.
- 확인/완료: 선택은 미리보기일 뿐이다. 확정 뒤 성공·오답을 알려 주며 원본은 고치지 않는다.
- 결말: D 발견과 후속 질문 한 개가 성과이지, 절도·제작자·불법·최종 유출 지점·정확한 유량 감소를 해결한 게 아니다.

## 3. S0 도입 — 비가 그친 탑 앞

이야기 화면. 소년은 별 목적 없이 젖은 산책길을 지나가다 외출 준비를 마친 연구원과 우연히 만난다. 연구원은 “올해는 비의 양상이 평소와 달라서 직접 수문과 물길을 살펴보려 한다”고 말한다. 고장·누출·샛구멍의 존재를 미리 말하지 않는다. 소년은 안전한 관측로에서만 동행한다. 03B를 완료했다면 친근한 인사 한두 줄 정도만 변형하고, 03B의 도시락·05의 관찰 카드는 미완료 사용자에게 전제하지 않는다.

플레이어가 이어서 할 일은 상류 수위 눈금을 보는 것. 우연한 만남을 위해 월드맵 랜덤 인카운터·새 POI를 만들지 않는다.

## 4. T1 — 《남은 흔적》 · 而且

### 첫 화면

상단: 학술탑 04A / 남은 흔적.

관측 영역: A 상류의 낡은 수위 눈금, 최근의 높은 수위 흔적, 지금 수위가 그 흔적보다 낮다는 **시점 구분**.

작업 영역: **소년의 상류 관찰 메모**.
- 이미 쓰인 첫 사실: 「石壁上有新留下的高水痕。」
- 질문: **“이 물 자국과 함께 기록할 다른 흔적은?”**

이미 본 물 자국을 플레이어에게 다시 탭해 확인시키지 않는다.

### 조작·즉시 변화

선택 대상은 **글자/물건의 역할**을 구별하도록 만든다.

- a-grass-high: 높은 석틈에 걸린 풀잎. 같은 큰비 흔적과 관련 있는 추가 관찰. **통과 후보**
- a-current-level: 현재의 낮아진 수위. **유효한 사실**이지만 지난 높은 수위의 별도 직접 증거가 아니라 다른 시점의 정보. 정답/오답의 문제보다 *이 작업의 추가 근거로는 범주가 다름*을 설명한다.
- a-gate-failure-theory: 수문이 고장 났을 것이다. 이미 확인한 사실이 아닌 추측이다.

선택 즉시 메모가 미리보기로 바뀌고 성공 표시는 없다. 선택한 추가 근거를 확인하면 문장 후보 「石壁上有新留下的高水痕，而且高處的石縫裡還卡著被水沖上來的草葉。」가 나타나며, **서로 다른 증거 두 개를 더한 기록**이라는 점을 짧게 설명한다.

‘메모 남기기’ 한 번으로 완료한다. T1이 가르치는 것은 물건 클릭이 아니라 관측 근거의 *추가*와 과거 흔적/현재 수위/추측의 구분이다. 而且 단어 조회는 무료지만 해당 판의 정답을 미리 넣어 보여 주지 않는다.

## 5. T2 — 《예상과 다른 물》 · 然而

### 첫 화면

관측/원본 영역은 한 장으로 모은다. 출처는 분리한다.

- B 관리자 기록: 「管理人員在雨後調整了進水口，現在仍有水流入工坊水道。」
- C 현장 관측: 「工坊水道下段的水流，比少年原先想的弱。」
- 소년의 이전 예상: 「下過這麼大的雨，下段的水流也會很急吧？」

서로 다른 위치에서 동일한 기준으로 측정한 유량 수치라는 **가상의 그래프/숫자**는 사용하지 않는다. “C가 평소보다 낮다”는 정보도 제공하지 않는다.

작업 면: **연구원과 함께 검토할 점검 메모**.
질문: **“이 두 관측으로 어디를 더 살펴봐야 할까?”**

### 판정 하나로 압축

- check-between-b-c: B의 현재 유입은 사실이고 C의 흐름은 소년 예상보다 약하다. 원인을 확정하지 말고 **두 지점 사이를 더 확인**한다. (통과)
- deny-b-intake: C가 약하니 B에는 물이 들어오지 않는다고 적는다. (B 관찰과 모순)
- conclude-gate-broken: 수문이 틀림없이 고장 났다고 적는다. (근거를 넘는 단정)

선택 직후 내용만 미리보기. 확인 뒤 두 사실을 보존한 문장 후보 「進水口仍有水流入工坊水道。然而，下段的水流沒有少年預想的那麼急。」와 **B~C 재점검** 결정이 남는다.

**중요:** 연구원이 ‘수문은 반드시 고장났다’는 오답을 이미 써 놓은 것처럼 보여 주지 않는다. 잘못된 선택은 가능성/오독이며, 확정된 인물의 판단이 아니다. 여기에 새 정정 버튼을 한 번 더 붙이지 않는다.

T2 완료 뒤 중간 이야기 I1. B 기록만으로 중간 구간의 흐름을 다 보았다는 뜻은 아니지만, D의 유출이 이미 입증된 것도 아니다.

## 6. I1 — 다음 구간의 물소리

공통 인물 이야기.

연구원은 점검길로 돌아가자고 제안한다. 소년은 평소의 수로 소리와 다른 방향에서 물소리를 듣는다. “저쪽에서도 물소리가 나요.” 정도의 관찰을 먼저 말한다.

소년은 **검증되지 않은 예상**으로 “수풀 쪽의 빗물이 수로로 들어오는 걸까요?”라고 추측한다. 예상이 실제와 반대라는 것은 **T3 관측 뒤** 알게 된다. I1에서 D의 위치·네모 입구·유출 방향·도구 자국·도면 미표시 사실을 미리 설명하지 않는다.

## 7. T3 — 《물소리의 방향》 · 反而 (핵심)

### 상태 0: 아직 구멍을 발견하지 못함

- 관찰 화면 이름은 ‘현장 관찰 · B~C 점검길’. 원래 사료라고 꾸미지 않는다.
- 위→아래 B→C로 흐르는 공방 수로, 양옆 둑과 안전한 점검길만 단순 개념도로 보여 준다. 실제 WORLD 지도 좌표나 수문학적 북쪽 아님.
- 수풀 쪽에서 다른 소리가 난다는 단서. **D 핀, 구멍, 정답 화살표 없음**.
- 44×44px 이상의 안전한 관측 구역 탭. 예: ‘상류 돌벽’, ‘수풀 가까운 둑’, ‘수차 쪽’.

다른 구역을 조사하면 ‘여기는 보통의 수로 소리’ 같은 **추가 정보**만 얻고 무한 실패·목숨·시간 손실은 없다. 수풀 가까운 둑을 조사하면 **좁은 네모 입구**가 드러나고 다음 관측으로 이동한다. 어린 소년이 위험한 물가에 내려가거나 구멍 속에 들어가지는 않는다. 음성만 들을 수 있어야 진행되는 장치도 쓰지 않는다.

### 상태 1: 틈은 찾았지만 방향은 아직 모름

- 드러난 틈과 물결·수면의 잎이 움직이는 **관측 단서**가 나타난다.
- 관측 사실에 접근할 수 있도록, 그림을 보지 못하는 사람에게도 ‘잎이 수로 가운데에서 벽의 틈 쪽으로 움직여’라는 동등한 짧은 설명을 제공한다.
- 정답을 미리 표시한 화살표는 **없다**. 선택한 화살표는 선택 *미리보기*임을 보여 준다.
- 질문: **“물은 어느 쪽으로 흐르고 있지?”**
  - flow-out: 수로 안 → 측벽의 틈 → 수풀 아래 (관찰과 일치)
  - flow-in: 수풀 아래 → 측벽의 틈 → 수로 안 (소년의 기대이지만 관찰과 불일치)
- 틀린 방향을 고르면 이미 찾은 구멍은 유지한 채 관찰 근거만 다시 보게 한다. ‘아직 모르겠다’며 잠시 관찰 상태로 머무르는 것은 허용하되 단계 완료는 관측 방향 확정 뒤에만 일어난다.

### 상태 2: 유출 방향 확정

- **소년의 예상(점선): 유입 / 실제(실선): 유출**이 나란히 기록된다.
- 번체 문장 후보: 「我原以為草叢裡的水會流進水道，結果水反而從水道流向草叢。」
- 학습 피드백: **이때는 방향이 반대**인 사건이지만, 反而 자체를 ‘반대 방향’으로 외우게 하지 않는다. 본선 04와 마찬가지로 *기대한 결과 대신 일어난 실제 결과*를 드러낸다.
- 구멍 위치와 현재 유출만 확정한다. **인공 공사/원래 도면 미표시/누가 팠는지/종착지**는 아직 밝히지 않는다.

**상태 전이 계약:** hidden → opening-found → flow-preview → flow-confirmed. 탐색 클릭 자체는 관찰이며 정답 판정이 아니다. 핵심 학습 판정은 **소년의 예상과 관측 실제 관계**다. ‘누른 뒤 보이는 방향’과 ‘사용자가 선택한 방향’을 혼동하지 않는다.

## 8. I2와 T4 — 《도면에 없는 길》 · 不是……而是…… / 而已

### I2 이야기

T3에서 구멍과 유출을 발견한 뒤 연구원이 **자신이 가진 원래 설계도**를 꺼낸다. 아직 인공 도구 흔적, 불법 여부, 제작 의도는 설명하지 않는다. T4가 판단할 부분을 이야기 대사가 먼저 해결하지 않아야 한다.

### T4의 첫 행동 — 인공 흔적으로 정정

관측 영역: 작은 네모 입구 확대, 정돈된 돌의 모서리, 반복된 도구 자국.
작업 영역: **소년의 의문을 검토하는 메모**.
소년 질문: 「是大雨把石壁沖壞了嗎？」

- artificial-passage: 반복된 가공 흔적을 근거로 **자연 균열보다 인공적으로 낸 통로**로 정정. (통과)
- natural-crack: 자연적 훼손이라는 가설의 근거가 반복된 도구 자국과 맞지 않는다는 안내. (다시 비교)

결과 문장 후보: 「這不是大雨沖出的裂縫，而是有人鑿出的通道。」
인공 통로라는 판단은 **누가/왜/적법하게** 팠는지의 결론이 아니다.

### T4의 둘째 행동 — 도면의 범위 한정

원본 설계도의 해당 지점에는 D가 그려져 있지 않다. 그러나 **이후 변경된 별도의 기록이 존재하는지** 아직 조사하지 않았다.

소년이 “그러면 누가 몰래 물을 가져가는 건가요?”라고 **질문**한다. 연구원이 근거 없이 절도를 확정한 보고를 이미 써 둔 설정으로 바꾸지 않는다.

작업 질문: **“이 원래 설계도 하나로 무엇을 말할 수 있지?”**

- scope-original-only: 원래 도면에 D가 미표시. 이후 변경·허가·용도는 미확인. (통과)
- scope-all-records-missing: 원래 도면에 없으니 이후 어떤 기록도 없다. (범위를 넘음)
- scope-theft-certain: 물이 나가니 절도다. (범위를 넘음)

**而已는 도면 한 장의 증명 범위를 제한**하는 데 쓴다. 다른 관측 사실(T3의 유출, T4의 인공 흔적)까지 삭제하지 않는다.

번체 문장 후보: 「單看這張原圖，我們只知道圖上沒標這個孔而已；後來有沒有改建紀錄，還得再查。」
언어적 자연스러움·문장 선택은 최종 윤문 단계에서 확정한다.

T4 완료 기록: 확인한 것(인공 구멍, 실제 유출, 원래 도면 미표시)과 미확인(제작자·허가·목적·종착지·영향량)을 구별한 연구원의 도면 대조 메모. 원본은 수정하지 않는다.

## 9. T5 — 《다음 질문》 · 從而 / 因而 / 進而

독립 퀴즈 세 개를 연속으로 푸는 것처럼 보이지 않게 **소년과 연구원이 함께 남기는 현장 조사 기록 한 장**에 다음 내용을 정리한다. 03B의 다섯 빈칸·단어 사용 횟수 제약을 복제하지 않는다.

1. **조사 방법 → 실제로 확인한 결과 (從而).** D 위치를 직접 관찰하고 원래 도면과 비교했다는 실제 방법을, 도면에 없는 통로를 **현장에서 확인했다**는 범위의 결과와 잇는다. ‘모든 변경 도면이 없다’, ‘범인을 찾았다’는 식의 허위 결과는 배제.
2. **확인된 발견 → 필요한 조치 (因而).** 시설 관리자에게 인공 분기와 현재 유출을 정확히 알리고, 관리/변경 기록의 확인을 요청한다. 임의로 수문을 조작하거나 구멍을 막는 행동은 허용하지 않는다.
3. **오늘의 기록 → 새로운 질문 (進而).** 둘 중 하나를 택한다. inquiry-records = 나중의 보수/변경 기록이 있는지 찾아보기. inquiry-outlet = 관리자 안전 확인 뒤 하류 출구 관측 계획하기. **두 선택 모두 통과**, 둘 다 계획일 뿐 결과를 본 것은 아니다.

세 부분은 각각 다른 작업 행위(근거와 결과 연결 / 조치 선정 / 후속 질문 선택)이며, 모두 선택한 뒤 **‘현장 기록 마무리’ 한 번**으로 확정한다. 앞에서 맞춘 내용을 뒤 입력이 지우지 않는다. 빈칸에 因而·從而·進而를 각각 한 번 넣는 일은 하지 않는다.

번체 문장 후보(윤문 전):
- 「我們把現場看到的孔口和原圖對照，從而確認這裡有一條原圖沒有標出的通道。」
- 「這個出水口沒有標在原圖上，因而有必要通知管理人員，再核對相關紀錄。」
- 「先記下孔口的位置和水流方向，進而查閱後來的修繕紀錄。」
- 「先記下孔口的位置和水流方向，進而安排在確認安全後觀察下游出口。」

**채점 경계:** 因而·從而가 뜻상 겹치는 문장을 하나씩 독점 정답으로 분류하지 않는다. 확인된 결과, 필요한 조치, 미실행 계획의 범위를 판정한다. 다음 질문 선택을 world state의 후속 사건으로 자동 확정하지 않는다.

## 10. 결과 이야기와 첫 완료

연구원과 소년은 **추가된 물의 갈래 하나를 정확히 발견했다**는 작은 성과로 돌아간다. 담당자에게 알릴 사실을 정리했고, 선택한 다음 질문은 기록에 남았다. 실제로 변경 서류를 발견했거나 하류 출구를 찾은 것은 아니다.

첫 완료 시 새 전역 stageId 하나만 완료 처리한다. inquiry-records 또는 inquiry-outlet 첫 선택이 **영구 결과에 남고**, 결과 이야기에서는 선택에 맞는 한 줄의 언급은 가능하다. 완료 후 연습/재플레이에서 다른 조사를 골라도 처음 기록을 덮지 않는다. 별도 보상·관찰 카드 재지급·새 milestone·강제 후속 퀘스트 없음.

## 11. 작은 화면에서의 우선순위

- 헤더는 제목·현재 작업 중심. 여덟 표현의 상시 대형 목록, 상시 T1~T5 대시보드는 넣지 않는다.
- 큰 구획: **원본/현장 관찰 → 실제 작성 주체가 있는 작업 면**. 문장마다 카드·테두리를 늘리지 않는다.
- T3의 정적 도식은 관측 자료 영역에 놓고 안전한 관측 지점의 터치 영역을 최소 44×44 CSS px로 확보한다. 작은 구멍 자체를 정밀하게 터치하는 게임은 만들지 않는다.
- 세로 스크롤을 허용하고 핵심 버튼은 가리거나 중첩되지 않게 한다. 검사 크기: 360×640, 375×640, 375×667, 375×812.
- 정답 전 화살표는 **선택 미리보기**이며 성공 표시가 아니다. 관측 사실의 텍스트 대안·접근성 이름을 제공한다. 음성/정밀 드래그가 없어도 같은 결과를 얻는다.
- 정답은 짧은 상태 변화와 꼭 필요한 설명 한 개만. 이미 선택된 근거를 다른 카드에서 다시 장황하게 반복하지 않는다.
- 잘못된 답은 원본을 지우지 않고 해당 주장/해석만 수정한다. 조회는 무료이며 작업 진행을 바꾸지 않는다.

현행 코드는 일반 전술 저장 **마지막 한 개의 stage 스냅샷**을 쓰며, TacticalGame.playStage가 진입 시 resetStage를 호출한다. 따라서 04A의 독립 재개는 현재 구현됐다고 간주할 수 없다. 설계에서는 기존 journey 진행에 선택적인 04A progress를 붙이는 방향을 검토하되, 실제 phase·ID 유효성 검사·옛 저장 호환/백업 검증까지 확정한 후에 구현한다.

또한 첫 nextInquiryId를 journey.stageOutcomes에 기록하려면 현재 GameFlow.recordStageComplete가 조회하는 **stageOutcome 제공 경로**를 명확히 연결해야 한다. 기존에 자동으로 기록된다고 간주하지 않는다.

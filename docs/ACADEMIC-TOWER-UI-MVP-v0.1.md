# 학술탑 전용 UI 원칙과 01·04 MVP 계획 v0.1

작성: 2026-10-05 (Asia/Taipei)
상태: 🧪 01·04 구현·자동검사 완료, 기기 승인 전. 사용자 플레이 뒤 확장 여부를 결정한다.

## 목적과 별도 원칙

[전체 설계](GAME-CONTENT-FRAMEWORK-v0.1.md)의 의미→행동→모바일 조작 원칙을 학술탑에 적용한다. 다른 지역에서는 물건·위치·수량이 조작 대상이지만 학술탑에서는 구절·관계·기록에서 내린 판단이 대상이다. 원문이 판이므로 목표/단어/판/결과를 모두 별도 고정 영역에 두지 않는다.

1. 중국어 원문을 주 작업면으로 유지한다. 앞뒤 사실을 지우지 않고 판단과 연결을 바꾼다.
2. 목표어는 원문 또는 작업 제목 가까이에서 무료 조회한다. 번역은 필요할 때 열며 위치를 유지한다.
3. 선택은 미리 적용하고, 확정은 의미 판정을 한다. 틀린 선택도 그대로 보며 수정한다.
4. 결과와 피드백은 작업한 기록 가까이에 둔다. 빈 상태창을 상시 확보하지 않는다.
5. 정밀 드래그 없이 탭으로 조작한다. 터치 영역 44px, 본문 19px를 기본으로 한다.
6. 같은 기록에서 선택·번역 조회 뒤 포커스와 읽던 위치를 보존한다. 새 기록은 처음부터 보여준다.
7. 완료 결과를 자동으로 덮지 않는다. 완성 기록을 읽은 뒤 직접 이야기로 이어간다.
8. 도움은 정답을 자동 표시하지 않는다. 적용 문제는 의미를 읽어야 해결할 수 있어야 한다.

## MVP 범위와 동작

기존 ID, 어휘, 선수 관계, 저장 판정, 첫 플레이/재플레이 구분을 보존한다. 초기 MVP는 01·04의 UI만 바꾼다. 2026-10-05 사용자 확장 요청 이후의 02·03·05 및 선택 연구 03A는 [확장 기록](ACADEMIC-TOWER-UI-EXPANSION-v0.1.md)을 따른다.

### 01 — 원문과 검토 메모

원문을 한 문장으로 연결해 보여주고 卻를 눌러 뜻을 조회한다. 첫 기록은 검토 메모의 주장들을 직접 선택해 고칠 대상을 찾는다. 이어 메모를 펼쳐 수정안을 고르면 바로 메모에 임시 반영한다. 확정 전 다른 수정안으로 바꿀 수 있다. 적용 기록에서는 같은 작업대에서 중국어 수정문을 선택한다. 원문 번역과 수정안 번역은 필요할 때 연다. 정답 뒤에도 원문과 완성 메모가 같은 위치에 남는다.

### 04 — 원문 구절을 관계에 놓기

01·02 모두 채울 칸을 탭한 뒤 예상 기록과 실제 기록의 구절을 탭한다. 두 칸은 순서 없이 자유롭게 채우고 다시 바꿀 수 있다. 두 칸을 모두 채워야 ‘두 결과 검토’를 누를 수 있으며 한 번에 판정한다. 틀렸을 때는 배치를 유지하고 고칠 칸을 설명한다. 적용 기록에서는 연결어 네 개를 접힘 없이 표시하며, 선택하면 완성 문장에 미리 들어간다. 단순 긍정/부정 화살표로 정답을 노출하지 않는다.

MVP에서는 원문에 실제로 존재하는 구절을 직접 고른다. 기록에 없는 결과를 따로 보기로 제시하던 단계는 표시하지 않는다. 조건 구절과 예상/실제 구절의 구별은 유지한다. 완성 연결문은 기존 검증된 문장을 사용한다.

## 공통 화면과 구현 경계

상단 연구 이름, 스크롤되는 원문 작업대, 하단 되돌리기/확정으로 구성한다. 기존 공통 목표·단어·상태 영역은 두 MVP 판에서만 대체한다. 설명과 번역은 펼침 UI에 둔다. 04의 저장 스키마는 2로 올리며, 이전 스키마의 현재 문제·확정한 칸·미확정 선택·완료 기록을 자동으로 옮긴다. 01의 스키마는 유지한다. 미확정 선택도 기존 저장 규칙을 따른다. 펼침 상태와 스크롤은 같은 기록에서 보존하며 브라우저 재시작 후 복구는 범위 밖이다.

## 구현 검증 기록

04의 두 결과 검토에서 틀린 칸을 자동으로 활성화하고 키보드 포커스와 화면 위치를 해당 칸으로 옮긴다. 둘 다 틀리면 첫 번째인 예상 칸을 우선한다. 선택해 둔 두 결과는 그대로 보존한다.

2026-10-05 후속 조정: 04-01·02 모두 두 결과를 자유롭게 배치한 뒤 한 번에 검토한다. 04-02의 연결어는 접힘 UI를 제거해 항상 표시하며, 연결어 단계에 들어가면 해당 위치로 이동한다. 이전 자동 펼침 패치는 서버 배포 성공을 확인했지만 사용자의 기기에서 동일하게 보인 원인은 확정하지 못했다.

초기 빌드: `2026-10-05-academic-tower-ui-mvp1`. 두 칸 동시 검토 개정 빌드: `2026-10-05-academic-tower-pair1`.

- `node tools/verify-content.cjs --browser`가 300개 테스트와 전체 브라우저 회귀를 통과했다.
- `smoke_academic_tower_mvp.py`에서 선택 미리보기·뜻 조회 후 포커스·펼침 유지·되돌리기·수동 완료·기존 UI 복귀를 확인했다.

사용자는 01의 수정안 선택과 미리보기 왕복, 04의 원문 구절 선택과 관계 배치, 긴 기록의 스크롤, 마지막 기록을 읽고 계속하는 흐름을 확인한다. 통과 전 다른 판으로 확대하지 않는다.

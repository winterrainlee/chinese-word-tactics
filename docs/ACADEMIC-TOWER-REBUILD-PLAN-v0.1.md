## 1. 다음 세션의 시작점

최신 원격 `main`과 작업 트리를 먼저 확인한다. 이 문서 작성 이후의 변경을 보존하고, 사용자 변경이 있으면 덮어쓰지 말고 별도 작업 트리 등으로 격리한다. 특정 과거 커밋으로 되돌려 구현하지 않는다.

다음 순서로 읽는다.

1. `AGENTS.md` 및 실제 수정 경로에 적용되는 하위 지침을 읽는다.
2. [전체 디자인 원칙](DESIGN-PRINCIPLES-v0.3.md)의 '답을 기억한 뒤에도 의미를 다시 사용한다'를 읽는다.
3. [학술탑 UI 가이드](ACADEMIC-TOWER-UI-GUIDE-v0.1.md)의 문장 방향 조작·반복 사용 원칙을 읽는다.
4. [첫 연구 묶음 §10](ACADEMIC-TOWER-FIRST-RESEARCH-BUNDLE-v0.1.md)의 방별 배치와 05 변경 범위를 읽는다.
5. [곁가지 로드맵](ACADEMIC-TOWER-SIDE-RESEARCH-ROADMAP-v0.1.md)과 [개발 표준](REGION-STAGE-DEVELOPMENT-STANDARD-v0.1.md)을 읽는다.
6. 현재 `src/academic-tower-content.js`, `src/save-data.js`, `index.html`과 실제로 로드되는 학술탑 런타임·CSS·테스트·배포 설정을 조사한다. 파일 이름만으로 최종 동작을 추정하지 않는다.

문서 책임은 전체 원칙 → 지역 UI 계약 → 첫 묶음의 의미·방별 설계 → 이 실행 계획의 순서다. 기존 MVP·확장 문서는 현행 구현의 기준선이다. §10에서 명시한 새 조작과 충돌하면 다음 구현에는 새 설계를 적용하고, 현재 동작과 변경 이유를 구현 기록에 남긴다.

## 2. 핵심 성공 기준

> **정답을 이미 아는 사람이 풀어도 무엇을 한 번 더 경험하는가?**

답을 외우는 것을 막는 것이 이번 작업의 목표가 아니다. 정답을 기억하더라도 원문의 대상·구절·조건을 직접 다루어 단어의 의미 관계를 다시 만들도록 한다.

| 기준 | 통과하는 예 | 피할 예 |
|---|---|---|
| 의미 행동이 남는다. | 卻 앞뒤 구절을 연결하고 두 사실을 보존한다. | 卻를 보고 언제나 같은 화살표 버튼만 누른다. |
| 적용 대상을 직접 고른다. | 예상·실제 구절을 각각 놓는다. | '예상 밖' 버튼만 누르면 자동으로 전부 배치된다. |
| 입력 결과가 의미를 보여 준다. | 不然 뒤 결과가 '묶지 않음'에 연결된다. | 관계와 무관한 정답 체크만 뜬다. |
| 반복이 불필요한 클릭은 아니다. | 연결 자체로 관계 선택을 수행한다. | 같은 뜻을 기호·문법명·번역으로 세 번 답한다. |
| 익숙함과 전이를 구분한다. | 익숙한 사례 뒤에 검토된 다른 사례를 적용한다. | 반복 성공 횟수를 숙달 점수로 표시한다. |

기계적 반복을 완전히 막는다고 주장하지 않는다. 탭만으로 실제 독해를 입증할 수 없다. 익숙한 문장을 의미에 맞게 다룰 기회를 보존하고, 새 문장에서 이해가 이어지는지 별도로 관찰한다.

사용자는 세 기믹 모두 단어의 역할 이해에 좋다고 평가했다. 1·2는 직관적이었으며 세 방식 모두 한국어 서술어가 어색했고 특히 3은 문구 개선이 필요했다. 이는 대화 속 예시 체험의 피드백이며 실제 재구축 게임·긴 문장·듣기 효과의 승인 기록은 아니다.

## 4. 작업 단위

### R0 — 현재 코드와 첫 구현 사양 확인

현행 source → event handler → 상태 전이 → 렌더 → 저장 → 검사 흐름을 추적한다. 현재 정상·오답·재진입의 기준선을 확보한다. 기존 도구를 이용하며 새 검수 기능 제작으로 작업 범위를 넓히지 않는다.

각 작업의 G2 표에는 안정 task ID, 원문 구절 ID, 연결 가능한 대상, 허용 관계·해석, 대표 오답, 입력 직후 변화, 확인 시점, 되돌리기, 완료 조건, 저장 revision을 적는다. 필드·revision 숫자는 최신 코드를 확인한 뒤 확정한다. 구조만 있는 범용 엔진부터 만들지 않는다.

01·03의 G2를 먼저 닫고 R1으로 진행한다. 나머지는 해당 작업 착수 전에 같은 기준으로 보완한다. 승인된 제품 방향의 반복 확인을 요구하지 않고, 새로운 제품 결정이나 충돌이 있을 때만 구체적인 쟁점을 남긴다.

완료 증거: 현재 코드 책임 목록, 기존 검사 결과, 01·03의 정상·오답·복구·저장 사양.

### R1 — 01·03의 기본 조작

**01: 관계 붙이기.** 짧음과 우천 위험의 두 구절을 직접 연결한다. 원본 두 사실을 지우지 않고 내 메모의 성급한 이용 판단만 수정한다. 첫 사례는 관계 조작을 안내하고 기존의 오래된 장치/정상 작동 사례로 적용한다. 새 연결 문제와 옛 선택지 전체를 중첩하지 않는다.

**03: 예상과 실제.** 예상·실제 구절을 각각 놓아 점선과 실선의 관계를 만든다. 결과의 좋고 나쁨과 일치·이탈 네 조합을 유지한다. 원문에 정답 표제나 기본 관계를 미리 배치하지 않는다. 실제 결과 하나 선택만으로 관계 판정을 마치지 않는다.

첫 의미 행동을 만든 뒤 무료 조회·되돌리기·확정·저장·완료 이야기까지 이어지는 작은 수직 단위로 마친다. 함수는 실제 두 사용처의 공통 책임이 확인됐을 때만 추출한다.

완료 증거: 두 방 정상·오답·무료 조회·재개·재플레이 통과, 원본 보존, 네 예상 사례, 기존 다른 방 회귀.

### R2 — 02·04로 관계 범위 확장

**02:** 뒤 점검 기록을 앞의 보고에서 고쳐야 할 판단에 붙인다. '수량 증가'와 '전체 정상'을 구분한다. 원문 사실과 내 추론을 시각적으로 분리하고 기존 보고 문장 직접 선택을 재사용한다. 卻/然而의 모든 용법을 문장 길이만으로 나누지 않는다.

**04:** R1의 예상·실제 표시를 재사용한다. 생기지 않은 예상과 대신 나타난 실제 결과를 모두 짚고 대비를 만든다. 두 결과의 원문 직접 선택과 문맥별 연결어 판정을 유지한다. 竟然의 뜻밖이라는 평가도 가능함을 인정하고, 이번에는 두 결과의 대비를 남기는 과제라고 설명한다.

완료 증거: 원본 사실 취소·과잉 추론·예상/실제 혼동·조건 구절 오선택을 구분하는 피드백, 긍정/부정 결과 모두 통과, 연결 변경·되돌리기 통과.

### R3 — 03A의 공통 한자 관찰

공통 然 발견을 유지하고 기존 일곱 표현의 관계명 선택을 짧은 의미 조작으로 바꾼다.

| 표현 | 답을 기억해도 해야 하는 일 |
|---|---|
| 然而 | 두 사실을 남겨 연결한다. |
| 果然／竟然 | 예상과 실제를 직접 비교한다. |
| 然後 | 점검 다음에 수량 조절을 잇는다. |
| 雖然 | 앞 사실을 남기고 뒤의 卻와 연결한다. |
| 既然 | 받아들인 전제에서 다음 판단을 잇는다. |
| 不然 | 결과를 '앞 행동을 하지 않는 경우'에 붙인다. |

전제·조건 UI는 이때 필요한 만큼 구현한다. 既然은 받아들인 전제, 如果는 조건 제시라는 관점으로 다루며 '如果=항상 모르는 사실'로 단순화하지 않는다. 不然의 결과를 '묶은 다음'에 연결하는 오독을 잡는다.

완료 후 조작 결과를 관찰 메모로 돌아볼 수 있게 한다. 모든 표현을 한 화면에 압축하지 않는다. 신규 목표어는 기존 既然·不然을 유지하고 새 후보를 필수로 넣지 않는다.

완료 증거: 03A 생략 본선 진행, 본선 05 전후 방문, 중단·재개, 공통 글자 선노출 없음, 일곱 표현의 의미 행동, 아이템 중복 지급 없음.

### R4 — 05의 종합 읽기

기존 일곱 빈칸을 작업 수로 고정하지 않는다. 다루던 의미 관계는 보존하며 다음의 흐름으로 재구성한다.

| 기록 | 의미 행동 |
|---|---|
| 기록 1 | 예상과 실제의 일치를 연결한다. |
| 기록 2 | 예상과 다른 사실을 읽고 뜻밖이라는 평가를 구분한다. |
| 기록 3 | 일반적 효과와 이번 결과를 대조하고 기대 대신 나타난 손상을 연결한다. |
| 안전 기록 | 앞 효과를 남긴 채 안전 범위 초과 조건에 손상 가능성을 붙인다. |
| 전체 재독 | 완전한 중국어 원문을 끊김 없이 다시 읽는다. |
| 전달 판단 | 적정 수량을 확정하지 않고 추가 확인이 필요하다는 기존 판단을 남긴다. |

일부는 남아 있는 표현을 읽고 관계를 만들고, 일부는 흐려진 표현을 복원한다. 매 지점에서 두 과제를 중복하지 않는다. 태스크와 허용 해석 목록은 변경 전에 G2에 명시하고 구형 빈칸 완료 수를 새 완료로 기계적으로 치환하지 않는다.

안전문의 `如果`와 `可能`은 실제 사건으로 확정하지 않는다. 가능한 손상을 실제 사건용 실선으로 표시하지 않는다. 순차 공개 중 뒤 내용을 맞히게 하지 않고 읽은 앞부분은 유지한다. 최종 판정 전에 전체 안전문을 읽게 한다.

03A 미완료자에게도 필요한 범위 조작의 짧은 안내를 제공한다. 신규 조건어 숙달 과제를 만들지 않는다. 기호 없이 재독할 기회를 주되 도움·뜻 조회를 막지 않는다.

완료 증거: 기존 일곱 위치의 의미 관계 대응표, 원문 전체 재독, 최종 판단의 과잉 일반화 거부, 03A 생략 경로, 결과 이야기·milestone 단일 발생.

### R5 — 종합 회귀와 마감

각 단위의 focused 검사를 마친 뒤 전체 콘텐츠·브라우저 회귀, 네 화면 크기, 하위 경로, 저장 호환을 확인한다. 통과한 입력에 변화가 없다면 같은 전체 검사를 불필요하게 반복하지 않는다.

다음 구현 세션에서 완결된 단위를 main에 반영하고 저장소의 기존 Pages 배포 절차를 따른다. 실제 배포 SHA·CI·cwt-build를 확인한다. 배포나 브라우저 확인이 불가능하면 원인과 미확인 항목을 명시하고 성공했다고 기록하지 않는다. iPhone 사용성은 사용자의 실기기 피드백 후에만 승인 완료로 표시한다.

## 5. 저장 호환 결정 규칙

현재 serializer·normalizer·백업 경로를 조사한 후 작업별 revision을 정한다. 기존 숫자를 추측해 올리지 않는다.

| 상태 | 처리 원칙 |
|---|---|
| 옛 저장에 새 필드가 없다. | 유효한 초기 상태를 만든다. 다른 지역 진행은 그대로 둔다. |
| 이미 완료한 방·묶음이다. | 완료·이야기·아이템을 유지하고 재플레이로 새 기믹을 연다. |
| 진행 중이고 명확하게 대응된다. | 같은 구절·태스크·선택을 새 표현으로 옮긴다. |
| 진행 중이며 대응이 불가능하다. | 해당 작업의 안전한 시작점으로만 이동한다. 이동 범위·이유를 구현 기록과 필요한 사용자 안내에 남긴다. |
| 잘못된 부분 상태다. | 해당 작업만 정규화하고 전체 저장을 초기화하지 않는다. |
| 재플레이다. | 정식 완료·이야기 획득 상태를 덮어쓰지 않는다. |

태스크 진행·구절 선택·관계·미확정 상태·표시 순서 등 실제 재개에 필요한 값을 식별한다. 원본 텍스트 전체 복제나 오답 횟수·반복 횟수의 숙련 지표는 추가하지 않는다. 저장·백업·복원 왕복과 단계별 새로고침을 검증한다.

## 6. 검사와 사용자 검수

기본 명령은 다음과 같다. 실제 지역 테스트·smoke 경로는 최신 저장소에서 확인한다.

```bash
node tools/verify-content.cjs
node tools/verify-content.cjs --browser
node tools/vocabulary-lifecycle-audit.cjs
```

새 smoke를 추가하면 기존 CI가 실행하는지 확인한다. 필수 검사가 이미 포함돼 통과했다면 별도 중복 실행은 필요 없다. 코드·콘텐츠 변경에 맞는 의미 있는 판정·상태 테스트를 작성한다.

공통 acceptance:

- 기호만 눌러서는 완료할 수 없고 원문 대상·범위·관계가 상태에 남는다.
- 정답을 기억한 플레이에서도 해당 의미 행동이 생략되지 않는다.
- 원문을 읽는 대신 한국어 정답만 고를 수 있도록 완역을 미리 노출하지 않는다.
- 선택은 미리보기이며 확정·판정과 구분한다. 잘못된 배치는 남고 되돌릴 수 있다.
- 사례의 결과가 좋거나 나쁘다는 이유만으로 관계를 고를 수 없다.
- 03A 미완료와 완료 상태에서 본선 흐름이 동일하다.
- 기존 완료·아이템·이야기·저장·복귀 위치가 보존된다.
- 375×812, 375×667, 375×640, 360×640에서 가로 넘침·버튼 잘림이 없고 터치 영역은 44px 이상이다.
- `/chinese-word-tactics/`에서 스크립트·스타일·자원이 정상 로드된다.

사용자에게는 다음을 확인한다.

1. 답을 기억해도 어느 구절을 연결하는지 다시 보게 되는가?
2. 기호는 읽는 의미를 보여 주는가, 별도의 암기 과제가 되는가?
3. 한국어 표현을 다시 해석해야 누를 수 있는 곳이 있는가?
4. 조작이 읽는 흐름을 돕는가, 같은 답을 반복 확인하게 하는가?
5. 기호를 줄인 새 사례에서도 같은 관계를 읽을 수 있는가?

새 사례는 문장·허용 대안을 검토한 소수 사례로 둔다. 이미 본 적용 사례를 '처음 보는 문장 검증'이라고 보고하지 않는다. 게임 세계의 실제 사건을 무작위로 바꾸지 않는다.

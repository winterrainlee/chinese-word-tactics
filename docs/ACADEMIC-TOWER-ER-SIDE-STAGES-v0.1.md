# 학술탑 而 곁가지 — 단계별 기믹 설계안 v0.1

작성일: 2026-10-06 (Asia/Taipei)
상태: **스토리라인 확정 / 단계별 기믹·저장 설계안 작성 / 런타임 미구현**
이야기 기준: [여백에 남은 길 — 확정 스토리라인](ACADEMIC-TOWER-ER-SIDE-STORY-v0.1.md).
공통 기준: [콘텐츠 구조](GAME-CONTENT-FRAMEWORK-v0.1.md), [개발 표준](REGION-STAGE-DEVELOPMENT-STANDARD-v0.1.md), [디자인 원칙 v0.3](DESIGN-PRINCIPLES-v0.3.md), [학술탑 UI](ACADEMIC-TOWER-UI-GUIDE-v0.1.md).
구현 비교 기준: `3431b5b1e29ebff08cd59d5bc5e4bbcd4d0a6dc4`의 `src/academic-tower-content.js`, `src/save-data.js`와 기존 학술탑 설계다.

사용자는 이야기를 승인하고 기믹 구상과 문서화를 요청했다. 이 문서는 새 기믹에 대한 별도의 사용자 승인, 구현 완료, 자동검사 통과, 배포 또는 iPhone 승인을 주장하지 않는다. 마지막 절의 G2 확인 항목을 닫기 전에는 구현 사양의 최종 확정으로 표시하지 않는다.

## 1. 설계 결정

**04A 한 연구 안에 일곱 개의 짧은 내부 스테이지를 둔다.** 여기서 내부 스테이지는 독립적으로 멈추고 이어 읽는 작업 단위다. 전역 `STAGES`에 일곱 판을 추가한다는 뜻이 아니다. 전역에는 선택 연구 하나만 추가하고 내부는 안정적인 `phaseId`와 `taskId`로 관리하는 안이다.

이야기의 진행은 `공통 글자 발견 → 서로 다른 보고 → 보고의 범위 → 판단의 근거 → 다음 조사 → 여백의 질문 → 교차 색인`이다. 조사 부록을 끝까지 읽고 연결하는 일이 플레이의 골격이며, 여덟 단어에 각각 전용 미니게임을 배정하지 않는다.

사용자가 수업에서 배운 `進而`는 참고 표에만 넣지 않는다. 별도 내부 단계 E05의 중심 표현이며, E07에서 다시 실제 판단에 사용한다. 기믹이 익숙해지는 것은 결함이 아니다. 단어를 다시 보고 관계를 생각할 이유가 남는지가 중요하다.

표의 신규 ID는 문서에서 예약한 값이다. 현재 코드에 등록돼 있거나 충돌 검사를 통과했다고 표시하지 않는다. 구현 직전 최신 저장소에서 중복을 검사한다.

연구실 옆방에는 기존 원칙대로 제목과 완료 체크만 표시한다. `+`, 여덟 표현 나열, 큰 번호, 의무 진행률을 덧붙이지 않는다. 전체 여정에는 `04A · 선택 연구` 참조를 두고, 내부 E01~E07을 별도 전역 완료 수에 포함하지 않는다.

04 첫 완료의 기존 05 도입을 가로채지 않는다. 사용자가 연구실에서 04A를 선택하면 도입이 열린다. 연구 중 나가기는 실제 출발 화면과 읽던 상태를 보존한다. 첫 결과 이야기는 탑 문을 나서는 장면이므로 실제 첫 완료의 후속 화면은 학술탑 위치가 보이는 월드맵으로 둔다. 이것은 기존 각 본선 방의 허브 복귀를 바꾸는 규칙이 아니라 04A 결과 장면의 국소적 예외다. 여정에서 결과 이야기를 재열람한 경우에는 원래 여정으로 복귀한다.

## 3. 일곱 내부 스테이지와 이야기 대응

E번호는 설계·검수용 참조다. 작업대에서 필요한 경우 `04A · 05`처럼 작게 참조할 수 있지만, 연구실의 작은 옆방 제목에는 노출하지 않는다.

| 단계·phaseId | 표시 제목 | 중심 표현 | 핵심 조작 | 확정 이야기 |
|---|---|---|---|---|
| E01 `er-01-character` | 이번에는 다른 쪽 글자 / 另一邊的字 | 而를 관찰하며 여덟 표현을 접한다. | 공통 글자를 짚고 발췌를 원본 위치에 연결한다. | 장면 1을 경험한다. |
| E02 `er-02-reports` | 수차는 돌아갔는데 / 水車轉了以後 | 而且·然而·反而를 쓴다. | 보고의 사실은 남기고 추가·전환·예상 이탈의 관계를 만든다. | 장면 2를 경험한다. |
| E03 `er-03-scope` | 기록은 어디까지인가 / 記錄寫到哪裡 | 而已·不是……而是……를 쓴다. | 해석 범위를 좁히고 조사 대상의 잘못된 추정을 고친다. | 장면 3을 경험한다. |
| E04 `er-04-basis` | 판단은 어디에서 왔나 / 判斷從哪裡來 | 因而·從而를 쓴다. | 근거와 판단, 방법과 목표를 잇고 사실·계획을 구분한다. | 장면 4 앞부분을 경험한다. |
| E05 `er-05-further` | 거기서 한 걸음 더 / 再往前問一步 | 進而를 중심으로 從而와 비교한다. | 첫 조사 작업을 다음 질문에 연결하되 결과는 미확인으로 남긴다. | 장면 4 뒷부분을 경험한다. |
| E06 `er-06-margin` | 지도 여백의 질문 / 留在圖邊的問題 | 而已·然而를 다시 쓴다. | 표식 비교의 범위를 제한하고 보고에서 빠진 질문을 되찾는다. | 장면 5를 경험한다. |
| E07 `er-07-index` | 옮기지 않고 이어 두기 / 把記錄連起來 | 而是·而已·進而 등을 종합한다. | 전달 메모를 고친 뒤 원본을 보존한 채 교차 색인을 만든다. | 장면 6을 경험하고 장면 7로 이어진다. |

기본 첫 읽기는 이 순서를 따른다. 그 순서는 사건이 드러나는 순서이지 한 번에 끝내야 하는 연속 시험이 아니다. 단계 안의 짧은 작업 뒤에도 저장하고 나갈 수 있다. `다음 기록`은 명시적으로 눌러야 열리며 다음 단계로 자동 밀어 넣지 않는다.

읽은 기록과 완료한 내부 단계는 바로 다시 펼칠 수 있다. 들어오자마자 궁금한 표현만 보려는 경우를 위해 연구 안의 작은 `표현 찾아보기` 진입을 허용한다. 이는 여덟 표현의 뜻과 비서사적 자작 예문을 보는 무료 참고 기능이다. 아직 안 읽은 약도·여백·결말은 노출하지 않고, 현재 단계나 완료 상태를 이동시키지 않는다. 완료하지 않은 후반 스토리 작업을 미리 수행하는 우회로로 만들지 않는다.

## 4. 언어 설계 — 닮은 글자를 배타적 공식으로 바꾸지 않는다

| 표현·주음 | 이번 기록에서 읽을 초점 | 의미를 다룰 때의 경계 |
|---|---|---|
| 而且 · ㄦˊ ㄑㄧㄝˇ | 앞 정보에 다른 정보가 더해진다. | 첨가뿐 아니라 점층도 가능하다. ‘而且에는 진전이 없다’고 가르치지 않는다. [L1] |
| 然而 · ㄖㄢˊ ㄦˊ | 앞 사실을 남기면서 뒤 상황으로 판단을 조정한다. | 앞 문장 전체를 거짓으로 지우는 말이 아니다. [L2] |
| 反而 · ㄈㄢˇ ㄦˊ | 기대했던 효과와 실제의 반대 방향을 함께 읽는다. | 항상 나쁜 결과라는 뜻으로 고정하지 않는다. 이번 본선의 예상/실제 구분을 재사용한다. |
| 而是 · ㄦˊ ㄕˋ | `不是 A，而是 B` 안에서 잘못 짚은 대상을 바로잡는다. | 이번에는 이 구문 전체로 가르친다. 독립 단어의 뜻을 모든 문장에 기계적으로 적용하지 않는다. |
| 因而 · ㄧㄣ ㄦˊ | 앞 사정이 뒤 판단·결과의 근거가 된다. | 從而와 의미가 겹칠 수 있다. [L3] |
| 從而 · ㄘㄨㄥˊ ㄦˊ | 앞의 원인·방법을 받아 결과나 목적을 잇는다. | ‘방법에는 從而만, 원인에는 因而만’이라는 구분은 금지한다. [L4] |
| 進而 · ㄐㄧㄣˋ ㄦˊ | 앞 작업을 발판으로 더 나아가는 조사 단계에 주목한다. | 단순 시간 순서, 반드시 좋은 결과, 因而·從而와 모든 문장에서 배타적인 관계로 만들지 않는다. [L6][L7] |
| 而已 · ㄦˊ ㄧˇ | 이 기록이 말하는 범위를 ‘그뿐’으로 한정한다. | 문장 끝의 한정 표현이다. 모든 而 표현을 두 절 사이의 접속사로 취급하면 안 된다. [L5] |

이번 묶음에서 새로 중심에 놓는 표현은 여섯 개이고, 然而·反而는 본선 재사용이다. 이것은 게임 전체에서 여섯 표현이 전부 처음 등장한다는 선언이 아니다. 실제 편집층·목표어 중복은 구현 전 어휘 생애주기 자료와 대조한다.

여덟 표현을 모두 담되 내부 학습 단위의 새 중심 표현은 E02 하나, E03 둘, E04 둘, E05 하나로 나눈다. E01의 목록 노출이나 이야기 속 재등장을 능동 재사용으로 계산하지 않는다. 전역 하나의 연구에 여덟 표현을 등록하는 것은 오래 머무르는 선택 연구이자 중간 저장 가능한 분할 단위라는 명시적 예외다.

### 판정 원칙

1. 정답은 `표현 이름 == 관계 아이콘`만으로 판정하지 않는다. 어떤 원본의 어떤 두 내용과 어떤 범위를 연결했는지 검사한다.
2. 읽기 과제에서는 원문의 표현이 보여도 된다. 그때 요구하는 것은 같은 글자를 빈칸에 복사하는 것이 아니라 해석의 수정이다.
3. 표현 복원·작성 과제에서는 미리 정답 단어를 강조하거나 정답 문장을 완성한 채 보여 주지 않는다. 정답 공개 시점은 읽기 과제와 구별한다.
4. 원문 표현을 다른 것으로 바꿔 보는 비교는 원본을 변조하지 않는 가상 사본에서 한다. 원본의 뜻을 보존하는 다른 표현은 통과 또는 초점 차이 안내로 처리한다.
5. 因而·從而를 한 번씩 써야 한다는 소모식 배치, ‘이 단어는 이미 썼으니 남은 답’ 같은 퍼즐을 만들지 않는다.
6. 자연스러운 대안에 점수를 깎지 않는다. 문법적으로 가능하지만 조사 초점이 다른 경우에는 무엇을 강조하게 되는지 설명한다. 판정이 애매한 문장은 객관식 정오 문제 대신 비교 자료로만 사용한다.
7. 계획, 질문, 미확인 사실은 관계선을 그렸다고 완료된 사실이 되지 않는다. ‘자료가 없다’와 ‘그 일은 일어나지 않았다’를 구별한다.

## 5. 공통 작업대와 입력 계약

원본은 출처가 붙은 읽기 전용 종이 면이다. 그 아래에 `나의 해석`, 필요한 경우 `전달할 메모`를 별도의 큰 작업 영역으로 둔다. 영역 제목 22px 가운데 정렬, 본문 19px 등 기존 학술탑 위계를 출발점으로 삼는다. 문장마다 큰 카드·테두리·갈색 세로 막대를 다시 만들지 않는다.

조작은 기본적으로 `구절 또는 문장 선택 → 연결할 내용/관계/수정안 탭 → 미리보기 → 확인`이다. 정밀 드래그, 선을 손으로 그리기, 작은 글자 사이에 커서를 놓기를 필수로 만들지 않는다. 연결은 선택한 두 텍스트 사이에 나타나며 무엇이 근거이고 무엇이 뒤의 판단인지 읽을 수 있어야 한다.

선택과 정오 판정을 분리한다. 선택 직후의 선·괄호·메모 변화는 미리보기다. 확인 전 초록 체크를 주지 않는다. 틀린 선택은 지우지 않고 근처에 문장 근거를 짧게 남긴다. 사용자에게 틀린 작업 하나를 고칠 기회를 주며 전체를 처음부터 다시 하게 하지 않는다.

피드백은 기본적으로 중국어 한 문장과 무료 한국어 뜻 조회로 구성한다. 정답 요약과 필요할 때의 비교 설명 이상으로 카드·설명을 중첩하지 않는다. 새 기록에서는 이전 성공 문구를 지운다. 현재 목표 표현만 가까이 보여 주고 여덟 표현의 큰 메뉴를 상시 펼치지 않는다.

확인 버튼과 뜻 조회를 포함한 모든 입력 영역은 44×44 CSS px 이상이다. 줄 단위 선택은 글자를 확대하거나 자간을 늘리지 않고 실제 입력 영역을 확보한다. 360×640·375×640·375×667·375×812에서 원본, 긴 선택 상태, 오류, 완료, 재개를 확인한다. 전체를 한 화면에 우겨 넣는 대신 의미 묶음 단위로 세로 읽기를 허용한다.

## 6. 기록 묶음과 출처

아래 `recordId`는 이야기 안의 창작 자료를 가리킨다. 실제 교재·국어사전의 출처 ID와 섞지 않는다. 원본 전체에서 발췌한 문장은 다시 원본 위치로 돌아갈 수 있다.

| recordId | 내용과 상태 |
|---|---|
| `er-restoration-note` | 수량·수차·공방의 회복을 적은 옛 보고다. |
| `er-field-note` | 수로 회복 뒤에도 수레가 우회했고, 한 수레꾼은 기대와 달리 시간이 더 걸렸다는 옛 보고다. 원인 확정은 없다. |
| `er-scope-note` | 수리 보고의 범위와 다음에 조사할 대상을 적은 검토 메모다. |
| `er-adjustment-note` | 수량 안정에 따라 추가 조절을 잠시 멈추기로 했다는 판단이다. |
| `er-investigation-plan` | 기록·지도 대조와 현장 조사 범위 축소, 우회 원인 조사의 계획이다. 수행·성공 보고가 아니다. |
| `er-map-copy` | 길표지에서 옮겼다는 작은 도안이 딸린 약도다. 표식 원본 자체가 아니다. |
| `er-margin-question` | 누가 무엇을 싣고 길을 지났는지 묻는 여백 메모다. 답이나 필자 신원은 없다. |

날짜·필자·수레 적재물·통행 제한 원인을 문제 제작 편의를 위해 지어 넣지 않는다. 문장에 필요한 문맥은 이 승인된 범위 안에서 보완하며, 별도 가상 비교 예문은 가상임을 표시한다.

## 7. E01 — 이번에는 다른 쪽 글자

### 상황과 목표

소년은 然而와 反而를 다시 보며 공통 글자를 발견하고, 문장만 떼어 읽지 않도록 출처를 남긴다. 한자의 어원이나 공통 글자만으로 뜻을 계산하는 규칙을 맞히는 단계가 아니다.

### 초기 상태와 조작

원본 영역에 이전의 두 표현을 중립적으로 놓는다. 모든 글자를 같은 기본 스타일로 보여 주고 而만 미리 강조하지 않는다. 사용자가 두 표현에서 같은 글자를 각각 탭하면 선택 미리보기가 생긴다. 확인 뒤에 확정 이야기 장면 1의 발견 대사가 나온다.

그 뒤 연구원이 부록을 건네며, 여덟 표현의 작은 색인을 보여 준다. 사용자는 대표 발췌 한 개의 `원본 위치`를 열어 출처를 연결한다. 전체 문장을 여덟 번 열어야 통과하는 확인 노동은 넣지 않는다.

### 의미 → 조작 → 변화

공통 글자를 찾는 관찰은 두 텍스트의 같은 위치를 짚는 행동으로 나타난다. 출처를 연결하면 발췌 아래에 원본 이름이 남는다. 연구의 질문은 `같은 而라도 무엇을 어떻게 말하는가`로 열린다.

- 정상 해법은 두 而를 짚고 발췌와 부록의 위치를 연결하는 것이다.
- 다른 글자를 짚었으면 선택만 남기고 다시 고를 수 있게 한다. `然` 자체가 의미 없는 관찰이라고 꾸짖지 않는다.
- 완료는 글자 발견과 대표 출처 연결이다. 목록에 여덟 표현이 보였다는 이유로 숙련도나 능동 재사용을 기록하지 않는다.
- 성공 피드백 예시는 `同一個字，還要放回句子裡看。`다.
- 다음은 E02이며, 여기서 저장하고 나갈 수 있다.

## 8. E02 — 수차는 돌아갔는데

### 상황과 원본

서로 다른 옛 보고가 수리의 결과와 아직 남은 문제를 다룬다. 원본을 지우지 않고 관계와 전달 메모를 만든다.

자작 원문 후보는 다음과 같다.

- `水量穩定了，而且水車重新轉動了。`는 회복 두 가지를 보탠다.
- `水道修好了。然而，貨車仍得繞路。`는 수리 사실과 우회 사실을 함께 남긴다.
- `車夫原以為走這條路會更快，結果反而多花了時間。`는 예상했던 시간 단축과 실제 시간 증가를 대비한다.

공방 작업 재개는 관련 보고의 배경으로 남긴다. 세 문장을 한 화면의 세 카드로 늘어놓지 않고 한 기록씩 읽는다.

### 작업과 상태 변화

`er-02-add`에서는 두 회복 사실을 선택해 같은 보고에 보탠다. 한쪽을 취소하거나 둘 사이에 기록이 말하지 않은 인과를 필수로 넣지 않는다.

`er-02-turn`에서는 `수리가 끝났으니 수레도 모두 통행할 수 있다`는 초안의 과도한 부분을 탭한다. 수리 사실은 그대로 두고 우회 보고를 연결하면 전달 메모의 통행 판단만 바뀐다.

`er-02-counter`에서는 `예상: 더 빠름`과 `실제: 시간이 더 걸림`을 각각 골라 잇는다. 예상은 역사에서 지워지는 것이 아니라 실현되지 않은 예상으로 남는다. 실제 결과만 확정 사실 쪽에 놓인다.

### 판정·오답·복구

두 보고가 맞지 않는다고 수리 사실을 삭제하면, 피드백은 `水道修好了，並不等於貨車都能通行。`처럼 판단의 과도한 범위에 주목하게 한다. 反而 작업에서 예상과 실제를 뒤바꾸면 원문의 시간 표현을 다시 볼 수 있게 한다.

관계 이름이 아니라 보존한 사실, 수정한 주장, 예상/실제의 구분을 검사한다. 같은 뜻의 중국어 메모 대안은 허용한다. 세 작업을 완료하면 장면 2의 마지막 대사를 보고 E03으로 갈 수 있다. 각 작업 뒤에도 독립 체크포인트를 남긴다.

재사용 후보는 본선의 주장 수정과 예상/실제 선택이다. 새로 필요한 것은 보고 사이의 첨가 연결이며, 이 기능을 다른 곳에 쓸 계획만으로 범용 그래프 엔진을 만들지 않는다.

## 9. E03 — 기록은 어디까지인가

### 상황과 원본

원본은 `這只是水道的修復記錄而已。`와 도로 조사 기록이 아직 없다는 설명, `下一次要查的不是水車，而是關外的道路。`다. E02에서 생긴 궁금증을 기록의 범위와 다음 조사 대상으로 나눠 읽는다.

### 작업과 상태 변화

`er-03-limit`의 작업 영역에는 `수로의 수리 상태`, `도로 전체의 통행 가능 여부`, `후속 조사의 완료 여부`라는 주장의 범위가 있다. 사용자는 첫 항목을 이 기록이 다루는 범위에 두고 나머지는 이 기록만으로 확인할 수 없는 쪽에 둔다. 而已에 대응하는 괄호가 선택한 보고 범위를 감싸되, 도로를 실제 폐쇄하는 결과는 만들지 않는다.

`er-03-correct`에서는 `다음 조사 대상은 수차다`라는 초안의 대상 부분을 탭하고 관문 바깥길로 바꾼다. 미리보기는 `不是〔水車〕，而是〔關外的道路〕`처럼 교정되는 짝을 드러낸다. 원본의 수차 수리 사실과 기존 결과는 그대로 남는다.

### 판정·오답·복구

정상 해법은 수리 기록의 범위를 제한하고 다음 조사 대상만 바꾸는 것이다. 도로 조사 자료가 없다는 이유로 `길은 통행 불가`를 확정하면 통과하지 않는다. `沒有道路調查記錄，不等於道路一定不能走。`라는 근거를 제공한다.

而是와 反而는 모두 대비를 드러낼 수 있지만 이 기록에서 부정하는 것은 기존 예상 결과가 아니라 다음 조사 대상을 잘못 짚은 주장이다. 이 비교는 정답 뒤 짧은 설명으로 붙인다. 모든 부정문에 而是만 가능하다는 규칙을 만들지 않는다.

두 작업의 순서 안에서 되돌릴 수 있으며, 이미 확인한 범위 판정을 지우지 않고 조사 대상만 수정할 수 있다. 완료 뒤 묶음의 제목을 다시 보는 짧은 대사와 E04가 이어진다.

재사용 후보는 본선 02의 잘못된 문장 부분 선택·직접 수정이다. 범위 괄호는 원본/작업 영역의 큰 경계와 경쟁하지 않는 국소 표현으로 추가한다.

## 10. E04 — 판단은 어디에서 왔나

### 상황과 원본

판단을 내리는 근거와, 다음 조사에 사용할 방법을 분리해 읽는다.

원문 후보 R1은 `水量已經穩定，工匠因而決定暫停進一步的調整。`다. R2는 조사 계획에 적힌 `先比對各處的記錄與舊地圖，從而縮小現場調查的範圍。`다.

R1은 옛 판단 보고다. R2는 계획 속 방법과 목표다. 표현만 보고 실제 성취 여부를 판단하지 않도록 문서 종류를 원본에 명시한다.

### 작업과 상태 변화

`er-04-cause`에서는 추가 조절을 멈추기로 했다는 판단을 먼저 고른 뒤, 그 판단을 뒷받침하는 수량 안정 구절을 연결한다. `수레가 돌아왔다`처럼 다른 기록의 사실을 원인으로 잘못 잇는지 검사한다.

`er-04-method`에서는 기록·지도 대조를 현장 조사 범위 축소에 잇는다. 원인 조사를 이미 마쳤다는 주장까지 한 번에 연결하지 않는다. 두 내용은 계획 영역에 남는다.

`er-04-compare`는 정오 시험이 아닌 표현 비교다. 원문의 가상 사본에서 因而와 從而를 바꿔 읽고, 의미가 겹칠 수 있음을 확인한다. 어느 단어를 쓰든 연결된 근거·내용과 문서의 계획 상태는 자동으로 변하지 않는다. 둘 다 자연스러운 문맥이라면 둘 다 허용한다.

### 판정·오답·복구

완료를 가르는 것은 `근거를 올바른 판단에 연결했는가`, `계획을 실제 결과로 바꾸지 않았는가`다. 비교 작업은 다른 표현 하나를 실제로 읽어 보고 닫으면 되며, 특정 우열을 고르게 하지 않는다.

대표 오답은 지도를 비교할 계획을 세웠다는 문장에서 `현장 조사 완료`를 만들어 내는 것이다. `這裡寫的是調查方法，還不是調查結果。`라고 안내한다. 근거선을 다른 구절로 다시 연결하면 수정되며 원본은 유지된다.

새로 필요한 것은 출처를 가진 근거 연결과 계획 상태 보존이다. 두 원문을 같은 곡선 색깔로 분류하는 퍼즐로 대체하지 않는다. 완료 뒤 E05에서 그 계획이 어느 질문까지 이어지는지 읽는다.

## 11. E05 — 거기서 한 걸음 더

### 상황과 원본

중심 원문은 승인된 이야기의 `先核對水道與道路的位置，進而查明貨車繞行的原因。`다. 원본 제목은 `후속 조사 계획`으로 명확히 보인다.

사용자는 계획자가 무엇을 먼저 하려 했고 그 작업에서 어디까지 더 나아가려 했는지를 재구성한다. 우회 원인을 실제로 밝혀내는 단계가 아니다.

### 작업과 상태 변화

`er-05-steps`에서는 문장의 두 행동 구절을 선택한다. 수로·도로 위치 대조를 첫 작업으로 놓고, 수레의 우회 원인 조사를 다음 작업으로 잇는다. 연결 뒤 다음 질문 영역이 펼쳐지지만 원인 칸은 비어 있다. 선은 조사 계획의 관계를 표현하고 완료 체크를 붙이지 않는다.

`er-05-focus`에서는 E04의 `從而縮小現場調查的範圍`와 이번 `進而查明貨車繞行的原因`를 함께 볼 수 있다. 전자는 방법으로 얻으려는 범위 축소에, 후자는 그 작업에서 한 단계 더 나아가는 조사에 주목한다. 고정된 한 문장에 從而/進而를 넣고 무조건 하나만 맞히게 하지는 않는다.

`er-05-status`에서는 전달 메모의 `원인을 밝혀냈다`를 `원인을 알아보려 했다`로 고친다. 다음 종이를 확인해도 결과가 이 묶음에는 없음을 확인하고 그 상태를 미확인으로 남긴다.

### 판정·오답·복구

정상 해법은 대조 작업과 후속 조사의 관계를 만들고 둘을 계획으로 표시하며, 우회 원인은 아직 모른다고 남기는 것이다. 메모 표현을 `계획했다`, `알아보려 했다` 중 어느 것으로 쓰든 같은 상태를 보존하면 허용한다.

대표 오답은 `進而`를 골랐다는 이유로 숨겨진 원인이나 다리 파손을 자동 발견하는 것이다. 피드백은 `進而指出下一步，不表示這一步已經完成。`로 한다. 이 문장은 이 계획 문맥에 대한 안내이지 進而가 완료 사건에 쓰일 수 없다는 일반 규칙이 아니다.

단순히 ‘다음에 일어난 일’이라는 이유만으로 연결한 경우에는 첫 작업이 다음 조사를 어떻게 준비하는지 원문 구절을 다시 짚게 한다. 계획의 순서를 고친 뒤에도 원인 미확인 상태는 남는다.

완료하면 장면 4의 ‘이 묶음에서는 모른다’ 대사를 보며 E06으로 이어진다. 이 시점은 자연스러운 중단 지점이다. 후속 장면을 열기 전에 나가도 다시 같은 계획 위치로 돌아온다.

## 12. E06 — 지도 여백의 질문

### 상황과 자료

약도 사본의 작은 표식, 기존 비교 자료, 여백의 `길을 지났다고 한 사람은 무엇을 싣고 있었나`라는 질문을 함께 읽는다. 표식을 픽셀 단위로 맞히거나 실제 도로의 퍼즐 해답을 찾는 단계가 아니다.

### 작업과 상태 변화

`er-06-similarity`에서는 표식 부분을 탭해 확대하거나 동일 정보를 담은 글 설명을 본다. 작은 그림에서 차이를 억지로 찾을 필요는 없다. 작업 메모의 `동일한 표식이다`를 `일부가 닮았을 뿐이며 원본 확인이 필요하다`로 고친다. 자작 중국어 메모 후보는 `圖上的記號只是有些相似而已；是否相同，還需要查看路標。`다.

`er-06-question`에서는 `지나갔다고 말한 사람`과 `되돌아온 수레꾼`의 보고를 함께 남긴다. 여백 질문에서 아직 답이 없는 `載了什麼`를 선택해 ‘다음에 물을 내용’으로 연결한다. 적재물 이름이나 수량을 임의로 채우지 않는다.

전달 메모에는 `有人說曾經走過這條路。然而，車夫還是繞了路。` 같은 대비를 만들 수 있다. 이 대비 자체가 둘 중 누군가 거짓말했다는 판정이 되지 않게 한다.

### 판정·오답·복구

정상 해법은 표식의 닮음과 동일성 미확인을 구분하고 여백의 질문을 질문으로 남기는 것이다. 질문의 존재만으로 적재량이 우회 원인이라고 확정하거나 필자를 연구원으로 정하면 통과하지 않는다. `問題留下了，答案還沒有。`처럼 짧게 피드백한다.

날짜·날씨·이동 수단도 더 물을 만하다는 선택을 제공한다면 틀린 생각이라고 처리하지 않는다. ‘추가로 물을 수 있음’과 ‘이 여백에 실제 쓰인 질문’을 구분한다. 핵심 작업은 이 여백의 관찰을 정확히 옮기는 것이므로 그 부분을 별도로 확인한다.

표식의 동일성은 플레이어가 밝혀내는 정답으로 제공하지 않는다. 확대·설명 조회는 무상이며 그림을 열었다는 이유만으로 연구 완료를 주지 않는다. 완료 뒤에도 표식은 빛나지 않는다. E07에서 이 불확실성을 지킨 채 자료를 정리한다.

## 13. E07 — 옮기지 않고 이어 두기

### 상황과 초기 초안

새 단어 없이 지금까지의 해석을 짧은 전달 메모와 색인으로 바꾼다. 여덟 표현을 한 번씩 사용해야 하는 최종 시험이 아니다. 원본의 여덟 표현은 찾아볼 수 있지만 현재 판단에 맞는 것만 사용한다.

초안에는 세 가지 과도한 서술이 있다.

1. 이 묶음은 관문 바깥길 조사를 마친 보고라는 서술이 있다.
2. 약도의 표식이 원본과 완전히 같다는 서술이 있다.
3. 수레가 우회한 원인을 이미 알아냈다는 서술이 있다.

### 작업과 상태 변화

`er-07-summary`에서는 각 과도한 구절을 탭해 원문에 맞게 수정한다. 대표 수정 문장은 다음과 같다.

- `這不是調查結果，而是後續調查計畫。`
- `圖上的記號只是有些相似而已，還需要確認原件。`
- `計畫先核對位置，進而查明貨車繞行的原因。是否實際進行過調查，仍不清楚。`

이 문장들은 모범 표현이지 단 하나의 문자열 정답이 아니다. 같은 사실·계획·불확실성을 보존하는 대안은 허용한다. 進而를 然後 등으로 바꿔 보는 경우에도 자연스러움과 의미 초점을 검토해야 하며, 사전에 허용 문장으로 검증하지 않은 항목을 자동 생성해 출제하지 않는다.

`er-07-reference`에서는 부록의 원본 위치를 선택하고 바깥길 조사 색인의 참조 대상으로 연결한다. 원본은 수로 기록의 원래 자리에 그대로 남고, 두 색인에서 같은 원본을 가리킬 수 있게 된다. 이미 있던 참조를 지우거나 사본을 서로 다른 원본으로 복제하지 않는다.

마지막으로 원래 띠에 `관문 바깥길의 후속 조사 계획 포함`이라는 짧은 설명을 더한다. 이때 이야기 장면 6의 소년 제안과 연구원의 응답이 작업과 이어진다.

### 완료와 결과

세 전달 메모가 원문 상태를 보존하고, 원본 위치를 바꾸지 않은 교차 참조가 만들어지면 E07을 완료한다. 수정할 순서는 자유다. 이미 올바른 부분을 다시 맞히게 하지 않는다.

완료 시 04A의 전역 완료만 남기고 결과 이야기를 읽을 수 있게 한다. 결과 이야기의 장면 7에서 일반 메모지 또는 실제 보유 관찰 카드에 확인한 사실과 남은 질문을 구분해 적는다. 소년은 문지기에게 인사하고 나간다. 기존 관찰 카드를 새로 지급하거나 여관에 자동으로 새 수집품을 배치하지 않는다.

결과 이야기 미열람 상태에서 나갔다면 다음 진입은 `결과 읽기`를 안내한다. E07을 다시 풀게 하지 않는다. 후속 본편 진입, 새 지역 개방, 표식 발광, 조사 원인 확정은 완료 보상이 아니다.

## 14. 저장·중단·재개 — 새로 필요한 국소 확장

기존 첫 연구 묶음 문서는 중간 카드 배치·오답·힌트를 영구 저장하지 않는다고 정했다. 현재 `src/save-data.js`는 고정된 다섯 저장 키를 내보내고 검증한다. 따라서 ‘중간 저장이 이미 있다’고 가정해서는 안 된다. **04A의 틈날 때 이어 읽기에는 새 체크포인트 지원이 필요하다.**

### 저장 위치 설계

새 localStorage 키를 만들지 않고 기존 journey 저장 객체에 선택 필드 `sideResearchProgress`를 추가하는 안이다. 이 필드가 없는 옛 저장은 빈 객체로 해석한다. 기존 외부 백업 형식의 `storage` 키 집합은 유지한다.

```text
journey.sideResearchProgress["academic-tower-turn-04a-er-family"] = {
  revision: 1,
  contentVersion: "er-side-v0.1",
  currentPhaseId: "er-05-further",
  currentTaskId: "er-05-status",
  completedPhaseIds: [...],
  completedTaskIds: [...],
  drafts: { taskId: { 허용된 선택 ID와 연결 관계만 저장 } },
  seenInterludeIds: [...],
  bookmark: { sourceId, anchorId },
  narrativeVariants: { 실제로 보여 준 변형 ID만 저장 }
}
```

이는 설계 스키마이며 현재 구현된 필드가 아니다. 정확한 JSON 타입·허용 ID 목록·상한은 G2에서 확정한다. 임의 HTML, 원본 전체 복제, 성공 문구의 DOM을 저장하지 않는다.

- 의미 있는 선택·수정·확인과 내부 대사 완료 뒤에 체크포인트를 갱신한다. 오답 횟수나 도움 열람 횟수는 숙련도에 쓰지 않는다.
- 작업 통과와 뒤따르는 대사 열람을 분리한다. 통과 직후 종료하면 재개 시 아직 안 읽은 전환부터 보여 주고 이미 푼 문제는 반복하지 않는다.
- 저장 실패 시 ‘이어 할 수 있다’고 거짓 표시하지 않는다. 현재 세션은 유지하고 실패 이유와 재시도 가능한 행동을 알려 준다.
- 관련 없는 본선·지역을 플레이해도 04A의 체크포인트를 덮어쓰지 않는다. 단일 전술 스냅샷에만 의존하지 않는다.
- 다른 표현을 잠깐 찾아보거나 단어장으로 나가도 진행 단계는 이동하지 않는다. 재개 뒤 선택·원본 앵커·포커스를 복원한다.
- 예전 대사의 변형은 재생 당시 상태를 보존한다. 새 장면은 그때의 실제 03A 완료·05 결과·소품 상태를 읽는다.

### 백업과 초기화

journey의 로더·정규화기·저장기에서 새 필드를 함께 보존해야 한다. JSON 백업이 원시 객체를 담는다는 사실만으로 전체 복원 지원을 완료했다고 보지 않는다. `validJourney`의 현재 조기 반환 경로를 포함해 선택 필드의 구조·revision·ID를 검증하도록 확장해야 한다.

옛 저장에는 새 필드가 없어도 정상 복원한다. 새 필드가 잘못된 백업은 실제 저장을 바꾸기 전에 오류와 이유를 보여 준다. 콘텐츠 버전이나 ID가 바뀌는 경우의 국소 마이그레이션을 마련하고, 호환되지 않는 체크포인트 때문에 본선 진행 전체를 초기화하지 않는다. 이미 완료한 연구의 완료 의미를 콘텐츠 추가 때문에 소급 취소하지 않는다.

진행 초기화와 백업 미리보기에도 새 필드의 처리를 포함한다. 오답·힌트·서술형 자유 메모를 점수 데이터로 축적하지 않는다.

### 재플레이와 복귀

완료 전 첫 연구의 `이어서 읽기`는 저장된 체크포인트를 쓴다. 완료한 내부 작업을 다시 펼치는 행위는 기존 진행을 지우지 않는다.

완료 후 `다시 연구`는 별도 세션 상태에서 시작한다. 본편 `completedStages`, 기존 milestone, 첫 완료의 세계 결과와 저장된 첫 연구 결과를 덮어쓰지 않는다. 연습을 중단하고 돌아와도 정식 완료는 유지된다. 중간 연습의 영구 저장은 이번 범위에 추가하지 않는다.

A05 복귀 계약을 재사용해 연구실·여정·단어장의 실제 출발점과 펼침·검색·스크롤·선택을 보존한다. 첫 결과 이야기 뒤 월드맵으로 나가는 장면과, 기록 재열람 뒤 실제 출발점으로 돌아가는 동작을 구별한다.

## 15. 콘텐츠·단어장·여정 연결

본선 05와 03A의 ID, 본선 집계, 04·05 선수 조건을 변경하지 않는다. 전역 배열 뒤에 신규 연구를 추가하고 `stage-reference`와 학술탑 표시 메타데이터에는 같은 `04A`를 연결한다.

목표어는 여덟 표현을 포함하되, 단어장에는 실제로 표현을 본 시점과 사용한 작업을 구분해 기록하는 방안을 사양화한다. 04A 진입만으로 안 읽은 모든 예문·이야기를 발견 처리하지 않는다. 전체 `words[]`를 한 번에 발견시키는 기존 경로가 있다면 이 연구의 순차 공개와 충돌하는지 먼저 검사한다.

공식 TBCL·교재 원자료는 변경하지 않는다. 사용자의 `이번 수업에서 進而를 배웠다`는 말은 개인 학습 필요의 출처이며 교재 판·쪽수·급수를 검증한 자료가 아니다. 표현의 주음·뜻·비교 설명·게임 예문은 원자료와 구분된 편집층에서 관리한다. `而是`의 표제는 이번 구문 `不是……而是……`를 함께 제시한다.

진행 화면을 업무 대시보드로 만들지 않는다. 상시 총 문제 수, 하루 목표, 출석, 학습 점수는 없다. 내부 제목과 읽던 위치, 완료된 작은 체크 정도로 충분하다. 이 연구의 성공은 완주율보다 사용자가 궁금한 말을 다시 생각할 수 있다는 데 있다.

첫 검증 대상으로는 E04·E05의 겹치는 표현 판정과 계획/결과 구분, 체크포인트를 우선한다. 이것들이 작동하지 않는데 전체 이야기를 얹어 완성처럼 보이게 하지 않는다. 시험용 강제 진입은 자연 진입의 검수와 구분한다. 미구현 후반 단계를 자동 완료시키거나 04A를 완성된 연구로 공개하지 않는다.

## 18. G2에서 남은 확인과 비목표

스토리라인은 확정됐지만 다음은 기믹 v0.1에서 후속 확인할 항목이다.

- [ ] 자작 원문·선택지·허용 대안을 번체 중국어 문맥에서 윤문한다. 특히 因而·從而·進而의 차이를 배타적 정답으로 만드는 사례를 제거한다.
- [ ] phase/task별 완전한 데이터 목록과 허용 해석 집합을 확정한다. 이 문서의 예문을 곧바로 유일 정답 문자열로 사용하지 않는다.
- [ ] 최신 학술탑 런타임의 재사용 가능한 함수·UI와 추가해야 하는 부분을 대조한다. 설계상의 연결 기믹을 이미 존재하는 기능으로 간주하지 않는다.
- [ ] `sideResearchProgress`의 타입·revision·ID 검증·serializer 보존·국소 마이그레이션을 확정하고 백업 왕복 예를 만든다.
- [ ] 모든 표현의 실제 원자료·편집층 등록 여부, `words[]`와 발견 시점·능동 재사용 처리의 차이를 점검한다.
- [ ] 03A·05 결과 상태 변형과 마지막 복귀 장면의 story/route 연결을 확정한다.

새 격자 전술, 범용 그래프 편집기, 전체 학술탑 저장 구조 재작성, 교재 전체의 而 수록어 수집, 본선 변경, 새 지역 구현, 관찰 카드 재지급은 이번 설계 범위가 아니다. 필요한 국소 저장 확장을 이유로 전체 게임의 진행 규칙을 바꾸지 않는다.

## 19. 언어 근거와 인용 범위

확인일은 2026-10-06이다. 아래 자료는 표현의 기본 기능과 예문 용례를 확인하는 근거다. 게임 속 수로·수레·약도·연구원 이야기는 창작이며 이 자료에서 인용한 실제 사건이 아니다. 본 문서의 비교 문구와 조작 설계는 사전 정의 자체가 아니라 게임 편집 판단이다.

- [L1] 교육부 《國語辭典簡編本》 [而且](https://dict.concised.moe.edu.tw/dictView.jsp?ID=39872&la=0&powerMode=0). 평렬과 점층을 함께 설명한다.
- [L2] 교육부 《重編國語辭典修訂本》 [然而](https://dict.revised.moe.edu.tw/dictView.jsp?ID=135523). 앞뒤 상황을 함께 두는 전환 기능을 확인했다.
- [L3] 교육부 《國語辭典簡編本》 [因而](https://dict.concised.moe.edu.tw/dictView.jsp?ID=41947&la=0&powerMode=0). 앞 내용을 받은 결과 관계를 확인했다.
- [L4] 교육부 《重編國語辭典修訂本》 [從而](https://dict.revised.moe.edu.tw/dictView.jsp?ID=142956&la=0&powerMode=0). 원인·방법과 결과·목적을 포괄하며 因而와의 의미 중첩을 확인했다.
- [L5] 교육부 《國語辭典簡編本》 [而已](https://dict.concised.moe.edu.tw/dictView.jsp?ID=39873&la=0&powerMode=0). 한정 용법을 확인했다.

- [L7] 교육부 《國語辭典簡編本》 [臨摹](https://dict.concised.moe.edu.tw/dictView.jsp?ID=14881&la=1&powerMode=0)의 예문에서 進而의 다음 단계 용례를 교차 확인했다. 별도의 進而 표제 정의를 확인했다고 주장하지 않는다.

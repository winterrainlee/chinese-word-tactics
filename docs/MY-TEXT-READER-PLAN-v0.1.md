## 1. 목표와 역할

사용자가 외부 중국어 글을 붙여 넣고, 등록된 표지어를 켜고 끄며 원문을 읽는 개인 학습 도구를 만든다.
게임에서 접한 연결 표현을 실제 글에서도 눈으로 찾아보는 것이 목적이다.
AI 없이 브라우저 안의 명시적 문자열 규칙으로 표시한다. 분석 API·서버·새 프레임워크가 필요하지 않다.

이 기능은 단어 전술게임의 보조 도구다. 스테이지·연구·의뢰가 아니며, 읽은 사실을 게임 진행이나 숙련의 증거로 취급하지 않는다.
외부 글은 차 주제로 제한하지 않는다. 당대중문 복습 Sites의 콘텐츠와 저장을 가져오거나 연결하지 않는다.

표지어 강조와 의미 경계 판정은 구별한다. v0.1은 등록 표현의 출현만 표시한다.

## 4. 화면과 사용 흐름

### 입력 화면

- 제목은 선택 입력으로 두며 제안 상한은 Unicode 코드 포인트 100자다.
- 본문은 필수 입력이며 제안 상한은 Unicode 코드 포인트 5,000자다. 처음 제안한 2,000자보다 일반 기사 붙여넣기에 여유를 주되 모바일 검사로 상한을 검증한다.
- ‘읽기’ 버튼을 누르면 같은 도구의 읽기 화면으로 바뀐다.
- 공백뿐인 입력은 읽기 버튼을 비활성화하고 이유를 짧게 알린다.
- 초과 입력은 조용히 잘라내지 않는다. 현재 글자 수와 제한을 보여주고 읽기·영구 저장을 보류한다.
- 새 글을 붙이기 위해 별도 클립보드 권한을 요구하지 않는다. 기본 텍스트 영역의 붙여넣기를 사용한다.

### 읽기 화면

상단에는 뒤로 가기, 제목, ‘글 수정’을 둔다. 본문 바로 위에 **표지어 표시** 토글을 둔다.
새 글의 첫 읽기는 표시가 꺼진 상태다. 같은 글의 수정·화면 왕복에서는 선택 상태를 유지한다.
미지정 제목은 ‘내 글 읽기’로 표시한다.

본문은 큰 번체 글자, 충분한 줄높이, 문서 스크롤로 보여준다.
표지어는 한 가지 옅은 배경과 적당한 굵기로만 표시한다. 유형별 색상·범례·말풍선은 넣지 않는다.
표시는 클릭 가능한 작은 단어 버튼으로 만들지 않는다. 실제 조작 버튼은 44px 이상의 터치 영역을 확보한다.

안내 문구:
> 등록된 표지어를 표시해. 문장 구조를 자동 분석하지는 않아.

원문 문자열·문장부호·줄바꿈을 유지하며, 화면 폭에 따른 자연스러운 줄바꿈만 허용한다.
토글 시 전체 화면이나 입력 폼을 다시 만들지 않고 본문의 표시만 갱신한다. 스크롤·포커스·글 선택의 영향을 확인한다.
검출 결과가 없으면 ‘등록된 표지어를 찾지 못했어.’라고만 안내한다. 문법 요소가 없다는 뜻으로 표현하지 않는다.

### 복귀와 중단

진입 전에 원래 화면의 복귀 문맥을 캡처한다. 뒤로 가기는 그 화면의 위치와 진행 중 선택을 복원한다.
읽기 화면에서 메뉴를 다시 열었다 닫아도 입력 글과 토글 상태를 잃지 않는다.
도구를 열었다는 이유로 `JourneyProgress.lastLocation`, 활성 스테이지 세션, 이야기 대사 위치를 덮어쓰지 않는다.
현재 복귀 함수의 화면 매핑에 없는 경로(예: `fieldView`)도 검사한다. 누락된 지원을 도구 기능에 필요한 최소 범위로 보완한다.
새로고침 뒤에는 기존 게임의 시작 정책을 유지하고, 도구를 다시 열었을 때 마지막 유효 글을 복구한다.

## 5. 표지어 목록과 매칭 규칙

### 자료 출처

기존 `data/tbcl-discourse-candidates-2025-04.json`은 어휘 91항목·문법점 130항목의 원자료 추출층이다.
`data/academic-tower-discourse-candidates-v0.1.json`은 기능군·선수 관계를 담은 편집층이다.
221항목은 고유 문자열 221개라는 뜻이 아니며, 그대로 정규식이나 검색 사전에 넣지 않는다.

공식 표제·발음·등급은 수정하지 않는다. 원자료에서 추적 가능한 source ID와 표기 변형을 가진 별도 표시용 편집 목록을 만든다.
큰 원자료는 모바일 실행 시 직접 읽지 않고, 검토한 소형 목록만 실행용으로 제공한다.
기초 표지어가 원자료 추출 범위에 없으면 기존 편집층 근거를 따로 남긴다. 공식 출처가 없는 항목에 공식 ID나 등급을 만들어 붙이지 않는다.

목록의 항목 제안:
- 안정된 `id`, 실제 문자열 `forms`, 사용 여부 `enabled`.
- 출처 참조 `sourceRefs`, 채택·제외 이유 `note`.
- 표현 안의 부분 문자열 오탐을 막을 필요가 있을 때만 명시적인 제외 사례.
- 목록 전체의 `schemaVersion`, `lexiconVersion`.

### 후보와 제외

초기 검토 후보는 然而·因此·所以·但是·而且·並且·雖然·即使·如果·只要·除非·否則·與其·不如·例如·總而言之 등이다.
이는 확정 실행 목록이 아니다. 구현 시 출처·변형·포함 관계·오탐 예문을 확인해 목록을 확정한다.

而·以·於·就·才·是·的 등 다의적인 한 글자는 기본 목록에서 제외한다.
不過·結果·只是 등 여러 글자여도 용법이 갈리는 표현은 별도 검토한다. 모든 두 글자 이상 표현이 안전하다고 가정하지 않는다.
번체를 기본으로 하며 승인된 표기 변형만 명시적으로 등록한다. 간체를 자동 변환하거나 원문 전체를 정규화하지 않는다.

### 일치 처리

1. 원문을 왼쪽에서 오른쪽으로 탐색한다.
2. 같은 시작 위치에 여러 표현이 맞으면 가장 긴 표현을 우선한다.
3. 이미 채택한 구간과 겹치는 하위 표현은 중복 표시하지 않는다.
4. 반복 출현은 각각 표시한다. 짝표현은 개별 출현만 표시하고 짝 성립이나 적용 범위를 단정하지 않는다.
5. 등록된 더 긴 표현 또는 명시적 제외 사례 내부의 부분 일치도 확인한다. 예를 들어 ‘要不然’과 ‘不然’, ‘然而’와 ‘而’를 중첩 처리하지 않는다.
6. 출력은 `start/end/markerId` 구간 목록으로 만들고 원문 문자열과 분리한다.

문자열 매칭만으로 중국어 단어 경계를 완벽하게 알 수는 없다. 오탐이 잦은 표현은 확장보다 기본 목록에서 제외하는 쪽을 우선한다.
글자 수 제한은 코드 포인트로 계산하되, 화면 구간 위치는 JavaScript 문자열의 UTF-16 인덱스로 통일한다. 이모지·희귀 한자 앞뒤에서 잘리는지 검사한다.

## 6. 저장과 입력 안전

전용 임시 보관 키 제안은 `chinese-word-tactics-reader-draft-v1`이다.
내용은 `schemaVersion/title/text/showMarkers/updatedAt` 정도로 제한한다. 강조 구간은 파생 값이므로 원문과 목록으로 다시 계산한다.

마지막 유효 글 한 편만 지연 저장한다. 화면을 떠날 때 유효한 변경을 저장하며, 상한 초과 입력은 기존 유효 글을 덮어쓰지 않는다.
저장소 접근 불가·용량 초과·잘못된 JSON이면 앱 전체를 중단하지 않는다. 메모리에서 읽기는 계속 제공하고 임시 저장 실패를 알린다.
저장된 데이터를 읽을 때도 타입·버전·길이를 검증한다.

안내 문구:
> 마지막 글은 이 브라우저에 임시 보관돼. 게임 진행 백업에는 포함되지 않아.

게임 진행 백업·복원·진행 초기화는 이 키를 건드리지 않는다. ‘임시 글 지우기’로 별도 삭제하며 확인·취소를 제공한다.
브라우저 사이트 데이터 삭제 시에는 임시 글도 사라진다. 파일 백업이나 장기 보관 기능으로 소개하지 않는다.

입력은 전부 일반 텍스트로 취급한다. `textContent`와 텍스트 노드로 출력하고, 강조 요소만 코드가 생성한다.
사용자 입력을 HTML·정규식·스크립트로 실행하지 않는다. 입력 글을 API, 로그 수집, URL 쿼리, 저장소 커밋에 보내지 않는다.
새 네트워크 요청 없이 처리하며, 기존 정적 자원 로딩과는 구별한다.

## 8. 검수와 완료 조건

### 내용·매칭 검사

- 짧은 표현과 긴 표현의 겹침, 반복 출현, 문단 끝, 줄바꿈, 빈 입력을 검사한다.
- 한 글자 기본 제외와 검토된 오탐 제외 사례를 검사한다.
- 이모지·희귀 한자·HTML처럼 생긴 문자열·정규식 특수문자를 검사한다.
- 토글 전후 본문 `textContent`가 입력값과 동일한지 확인한다.
- 표지어가 없는 글을 문법이 없는 글로 안내하지 않는지 확인한다.

### 상태·저장 검사

- 새 저장의 첫 화면에서도 도구를 열 수 있어야 한다.
- 본편·재플레이·이야기·학술탑·여정·단어장·2장 조사 화면에서 진입 후 원래 위치로 복귀해야 한다.
- 진입·읽기·수정·재개 과정에서 게임 진행, 단어 발견, 완료 수, 해금 상태가 바뀌지 않아야 한다.
- 마지막 글 복구, 토글 유지, 초과 입력, 저장 실패, 잘못된 저장, 별도 삭제를 확인한다.
- 기존 백업 내보내기·복원·초기화의 키와 형식을 유지한다.
- 기존 스테이지와 단어 카드의 기본 회귀검사를 실행한다.

### 모바일·배포 검사

375×812(iPhone 13 mini 기준), 375×667, 360×640에서 가로 넘침·44px 조작 영역·safe-area·키보드를 확인한다.
긴 본문은 하나의 문서 스크롤로 읽고, 입력 시 iOS 자동 확대를 피하도록 입력 글자 크기를 확보한다.
토글의 접근 가능한 이름과 상태, 뒤로 가기의 포커스 복귀를 검사한다.
GitHub Pages 하위 경로 자원 로딩을 확인한다.
자동검사·Pages 배포·실제 iPhone Safari 사용자 검수를 각각 별도로 기록한다.

완료는 기획 문서 커밋이 아니라 실제 기능 구현과 위 검수 결과로 판단한다.
이번 문서 작성 시점에는 실행 검사·배포·실기기 확인을 수행한 것으로 표시하지 않는다.

## 9. 작업 순서와 후속 범위

1. 표지어 소형 목록을 선정하고 출처·제외·겹침 사례를 검토한다.
2. 순수 매칭 함수와 원문 보존 검사를 작성한다.
3. 독립 입력·읽기 화면, 임시 보관과 토글을 연결한다.
4. 여행 메뉴와 원래 화면 복귀를 연결하고 기존 진행 불변을 검증한다.
5. 모바일·정적 경로 검수 뒤 본편에 반영한다.
6. 이후 필요하면 여관 책상 바로가기, 여러 글 보관, 별도 내보내기를 각각 검토한다.

AI 분석·문법 설명·자동 경계 표시·게임 학습 기록 통합은 이 기획의 구현에 포함하지 않는다.

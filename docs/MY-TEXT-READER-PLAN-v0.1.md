상태: 사용자와 합의한 방향을 정리한 기획안. 실행 기능은 미구현이다.
대상: `winterrainlee/chinese-word-tactics`.
초기 조사 기준: `main@8177231bedc0b49a0c2dabbd42f73eec7e13a1c8`.
2026-11-13 후속 보완: 사용자가 승인한 정방향 읽기 목표와 화면 참고 이미지를 반영한다. 정도·상태 보어 `得`는 문맥 매칭 검토 후보로 남긴다. [CNA 기사 10개 분석 시험 자료](READER-CNA-ANALYSIS-REFERENCE-2026-11-13.md)를 연결해 실제 글 기반 평가를 설계했다. 실행 코드·공식 자료·저장 형식은 아직 변경하지 않는다.

## 1. 목표와 역할

사용자가 외부 중국어 글을 붙여 넣고, 등록된 표지어를 켜고 끄며 원문을 읽는 개인 학습 도구를 만든다.
**목표는 문장을 자동으로 의미 단위로 나누는 것이 아니라, 앞 문장으로 되돌아가지 않고 처음부터 끝까지 정방향으로 읽는 습관을 돕는 것**이다. 사용자는 글을 읽거나 해당 글을 들으면서 표지어를 만나면 앞서 이해한 정보를 유지할지, 해석의 방향을 바꿀지, 뒤의 결론을 기다릴지 즉시 예상한다. 이 도구 자체는 음원 재생·청취 속도 제어를 제공하지 않는다.
게임에서 접한 단어의 의미 행동을 실제 글에서 다시 알아보는 것이 목적이며, 모든 중국어 문법 요소를 강조하는 도구로 확대하지 않는다.
AI 없이 브라우저 안의 검토된 문자열 규칙으로 표시한다. 분석 API·서버·새 프레임워크가 필요하지 않다.

### 정방향 읽기 행동 — 내부 설계 기준

| 독자가 표지어를 만났을 때 하는 행동 | 대표 후보(미확정) | 예측 |
|---|---|---|
| 기존 정보를 유지하거나 더한다 | 而且·另外·仍然 | 앞에서 만든 정보나 상태를 지우지 않고 다음 내용을 받는다. |
| 해석 방향을 바꾸거나 기대를 수정한다 | 但是·然而·卻·反而 | 앞의 예상과 다른 방향이 나올 것을 준비한다. |
| 결론을 잠시 보류한다 | 雖然·即使·如果·除非 | 조건·장애를 기억하고 뒤 내용을 기다린다. |
| 앞 내용에서 결과를 받는다 | 所以·因此·因而 | 앞의 근거를 가지고 결과를 읽는다. |
| 예시·재진술·정리를 받아들인다 | 例如·換句話說·總之 | 앞 정보를 새 주장으로 착각하지 않고 풀어 읽는다. |
| 순서·국소 구조를 예상한다 | 先…再…, 只有…才…, 정도·상태 보어 得(검토) | 앞의 행동·조건을 잠시 보유하고 이어질 정보의 역할을 기다린다. |

이 표는 **편집·검수용**이지 사용자에게 보여줄 분류표가 아니다. 하나의 표현은 문맥에 따라 다른 역할을 할 수 있다. 독자의 읽기 행동을 돕지 않는 분류는 UI에 늘리지 않는다.

이 기능은 단어 전술게임의 보조 도구다. 스테이지·연구·의뢰가 아니며, 읽은 사실을 게임 진행이나 숙련의 증거로 취급하지 않는다.
외부 글은 차 주제로 제한하지 않는다. 당대중문 복습 Sites의 콘텐츠와 저장을 가져오거나 연결하지 않는다.

표지어 강조와 의미 경계 판정은 구별한다. v0.1은 등록 표현의 **출현과 읽기 방향을 가늠할 단서**만 표시한다.
자동 문장 분할, 구절 사이 여백 삽입, 수식 범위 확정, 짝표현 연결선, 문장별 해설은 제공하지 않는다. UI의 강조만으로 문법 해석이 확정되었다고 표현하지 않는다.

## 4. 화면과 사용 흐름

### 입력 화면

- 제목은 선택 입력으로 두며 제안 상한은 Unicode 코드 포인트 100자다.
- 본문은 필수 입력이며 제안 상한은 Unicode 코드 포인트 5,000자다. 처음 제안한 2,000자보다 일반 기사 붙여넣기에 여유를 주되 모바일 검사로 상한을 검증한다.
- ‘읽기’ 버튼을 누르면 같은 도구의 읽기 화면으로 바뀐다.
- 공백뿐인 입력은 읽기 버튼을 비활성화하고 이유를 짧게 알린다.
- 초과 입력은 조용히 잘라내지 않는다. 현재 글자 수와 제한을 보여주고 읽기·영구 저장을 보류한다.
- 새 글을 붙이기 위해 별도 클립보드 권한을 요구하지 않는다. 기본 텍스트 영역의 붙여넣기를 사용한다.

### 읽기 화면

상단에는 뒤로 가기, 제목, ‘글 수정’을 둔다. 본문 바로 위에 **표지어 표시** 토글을 둔다.
새 글의 첫 읽기는 표시가 꺼진 상태다. 같은 글의 수정·화면 왕복에서는 선택 상태를 유지한다.
미지정 제목은 ‘내 글 읽기’로 표시한다.

사용자가 제공한 모바일 화면 참고를 따른다. **흰 바탕, 짙은 남색 계열의 큰 번체 본문, 넉넉한 줄·문단 간격, 장식 없는 문서 스크롤**을 기본으로 한다. 최초 시안은 본문 20~22px와 넉넉한 줄높이로 시작하되 실제 iPhone Safari에서 조정한다.
표지어는 **한 가지 아주 옅은 연녹색 배경만**으로 강조한다. 글자색 변화·굵은 테두리·색상별 유형 구분·범례·말풍선·강조별 해설을 넣지 않는다. 굵기 변경 때문에 줄바꿈이 흔들리지 않게 한다.
강조는 비대화형 표시다. 표지어를 눌러도 설명창이나 별도 반응이 나타나지 않는다. 실제 조작 버튼은 44px 이상의 터치 영역을 확보한다.
원문에 이미 문단 번호가 있으면 그대로 보존하고, 자동 번호 생성은 v0.1에서 하지 않는다.

도움말은 첫 사용 또는 입력 화면에만 짧게 노출하고 읽기 본문 위에 반복하지 않는다.
> 표지어를 표시하면, 뒤를 읽을 방향을 가늠하는 말이 강조돼.

원문 문자열·문장부호·줄바꿈을 유지하며, 화면 폭에 따른 자연스러운 줄바꿈만 허용한다.
토글 시 전체 화면이나 입력 폼을 다시 만들지 않고 본문의 표시만 갱신한다. 스크롤·포커스·글 선택의 영향을 확인한다.
검출 결과가 없으면 ‘등록된 표지어를 찾지 못했어.’라고만 안내한다. 문법 요소가 없다는 뜻으로 표현하지 않는다.

### 복귀와 중단

진입 전에 원래 화면의 복귀 문맥을 캡처한다. 뒤로 가기는 그 화면의 위치와 진행 중 선택을 복원한다.
읽기 화면에서 메뉴를 다시 열었다 닫아도 입력 글과 토글 상태를 잃지 않는다.
도구를 열었다는 이유로 `JourneyProgress.lastLocation`, 활성 스테이지 세션, 이야기 대사 위치를 덮어쓰지 않는다.
현재 복귀 함수의 화면 매핑에 없는 경로(예: `fieldView`)도 검사한다. 누락된 지원을 도구 기능에 필요한 최소 범위로 보완한다.
새로고침 뒤에는 기존 게임의 시작 정책을 유지하고, 도구를 다시 열었을 때 마지막 유효 글을 복구한다.

## 5. 표지어 목록과 매칭 규칙

### 자료 출처

기존 `data/tbcl-discourse-candidates-2025-04.json`은 어휘 91항목·문법점 130항목의 원자료 추출층이다.
`data/academic-tower-discourse-candidates-v0.1.json`은 기능군·선수 관계를 담은 편집층이다.
221항목은 고유 문자열 221개라는 뜻이 아니며, 그대로 정규식이나 검색 사전에 넣지 않는다.

공식 표제·발음·등급은 수정하지 않는다. 원자료에서 추적 가능한 source ID와 표기 변형을 가진 별도 표시용 편집 목록을 만든다.
큰 원자료는 모바일 실행 시 직접 읽지 않고, 검토한 소형 목록만 실행용으로 제공한다.
기초 표지어가 원자료 추출 범위에 없으면 기존 편집층 근거를 따로 남긴다. 공식 출처가 없는 항목에 공식 ID나 등급을 만들어 붙이지 않는다.

목록의 항목 제안:
- 안정된 `id`, 실제 문자열 `forms`, 사용 여부 `enabled`.
- 출처 참조 `sourceRefs`, 채택·제외 이유 `note`.
- 읽기 행동을 편집할 때만 쓰는 내부 메타데이터 `readingAction`(예: 유지·전환·보류·귀결·정리·국소 설명), 필요시 `matchMode`.
- 표현 안의 부분 문자열 오탐을 막을 필요가 있을 때만 명시적인 제외 사례.
- 목록 전체의 `schemaVersion`, `lexiconVersion`.

`readingAction`은 **사용자 화면·색·표지명·팝업에 연결하지 않는다**. 항목 선정·실제 문장 검수·향후 학술탑과의 의미 행동 대조에만 사용한다. 모든 표현을 단일 분류에 강제로 넣지 않아도 된다.

### 후보와 제외

초기 검토 후보는 然而·卻·反而·因此·所以·因而·但是·而且·並且·仍然·另外·雖然·即使·如果·只要·除非·否則·既然·例如·換句話說·總之·總而言之 등이다.
이는 확정 실행 목록이 아니다. 구현 시 출처·변형·포함 관계·오탐 예문을 확인해 목록을 확정한다. 실제 긴 글에서 읽기 방향을 예측하는 데 도움이 되는지가 추가 선정 기준이다. 2026-11-13 CNA 10개 기사에서 관찰할 **至於·其中·接著·隨後·另一方面·針對·對於·儘管·由於·為了·因應·受惠於·首先** 등은 우선 검토할 보강 후보이며 자동 채택하지 않는다. 한 글자 **若·則·但·仍·並·也·後·再·就·才·得** 등은 별도의 문맥 검증 없이는 기본 강조 목록에 추가하지 않는다.
사용자 참고 화면에는 為了·先把·再·只有·才·這樣一來·而是·就·可以 등도 보인다. 이들은 중요한 **정방향 읽기 후보**지만, 한 글자 전체 검출·문법 역할 자동 확정을 승인한 것으로 해석하지 않는다. 先…再…, 只有…才…, 不是…而是… 같은 쌍·구문을 먼저 검토한다.

而·以·於·就·才·是·的·得 등 다의적인 한 글자는 **무조건적 문자열 강조**에서 제외한다. 단, 문맥을 제한한 구조 표지 후보 자체를 영구히 제외한다는 뜻은 아니다.
不過·結果·只是 등 여러 글자여도 용법이 갈리는 표현은 별도 검토한다. 모든 두 글자 이상 표현이 안전하다고 가정하지 않는다.
번체를 기본으로 하며 승인된 표기 변형만 명시적으로 등록한다. 간체를 자동 변환하거나 원문 전체를 정규화하지 않는다.

### 정도·상태 보어 `得` — 별도 검토, 기본 목록은 보류

`得`는 담화 전체의 전환어는 아니지만, **이미 읽은 동작·상태 뒤에 어떻게 되었는지에 관한 설명이 이어진다**는 국소적인 정방향 읽기 신호가 될 수 있다. 따라서 원칙적으로 배제하지 않고 작은 문맥 검출 실험 후보로 둔다.

| 사례 | 읽는 사람에게 주는 단서 | 단순 `得` 강조 여부 |
|---|---|---|
| 他說得很清楚。 | ‘說’ 뒤에서 말하는 방식·정도를 설명한다. | 후보 |
| 茶泡得太濃了。 | ‘泡’ 뒤에서 우린 결과·정도를 설명한다. | 후보 |
| 他忙得沒時間休息。 | ‘忙’ 뒤에서 상태가 미친 정도·결과를 보충한다. | 후보 |
| 這句話我看得懂。 | 가능보어: ‘이해할 수 있다’는 가능 여부로, 정도보어와 다르다. | 별도 취급 |
| 我覺得很清楚。 | `覺得`는 여기서 ‘생각하다/느끼다’의 동사이다. | 제외 |
| 我得先走。 | `得`는 ‘~해야 한다(děi)’의 뜻이다. | 제외 |
| 我得到了答案。／不得不去。 | `得到`·`不得不`의 일부이지 정도보어가 아니다. | 제외 |

우선 결론: **v0.1 기본 표지어 목록에 독립된 한 글자 `得`를 넣지 않는다.** 무조건 표시하면 읽기 흐름을 돕기보다 오탐이 많아질 수 있다. 반면 `동사/형용사 + 得 + 보충 설명`을 높은 정확도로 검출할 수 있다면, 같은 연녹색으로 **得 글자만** 조용히 강조하는 후속 시험은 가치가 있다.
`得很` 같은 오른쪽 문맥만으로 판정하면 `覺得很好`에도 걸리므로, 왼쪽 동사·형용사와 오른쪽 보충 표현을 함께 제한해 검증해야 한다. 고정된 어휘·구문 목록으로 입증 가능한 패턴부터 시험하며, 중국어 전체 문장을 분석하거나 정도·상태·가능보어를 자동 분류한다고 주장하지 않는다.
시험 항목에는 **정확히 잡는 사례와 잡으면 안 되는 사례를 모두** 포함한다. 실제 본문에서 오탐이 거슬리거나 읽기 효용이 낮으면 기본 표시로 승격하지 않고 남겨 둔다. 추가하더라도 화면에서 다른 색이나 문법 라벨을 제공하지 않는다.

### 일치 처리

1. 원문을 왼쪽에서 오른쪽으로 탐색한다.
2. 같은 시작 위치에 여러 표현이 맞으면 가장 긴 표현을 우선한다.
3. 이미 채택한 구간과 겹치는 하위 표현은 중복 표시하지 않는다.
4. 반복 출현은 각각 표시한다. 짝표현은 개별 출현만 표시하고 짝 성립이나 적용 범위를 단정하지 않는다.
5. 등록된 더 긴 표현 또는 명시적 제외 사례 내부의 부분 일치도 확인한다. 예를 들어 ‘要不然’과 ‘不然’, ‘然而’와 ‘而’를 중첩 처리하지 않는다.
6. 출력은 `start/end/markerId` 구간 목록으로 만들고 원문 문자열과 분리한다.

문자열 매칭만으로 중국어 단어 경계나 문법 용법을 완벽하게 알 수는 없다. 오탐이 잦은 표현은 확장보다 기본 목록에서 제외하는 쪽을 우선한다. 정도보어 `得`처럼 문맥이 필요한 후보는 단순 문자열 목록과 섞지 말고, 향후 독립적인 검사 가능 규칙으로만 다룬다.
글자 수 제한은 코드 포인트로 계산하되, 화면 구간 위치는 JavaScript 문자열의 UTF-16 인덱스로 통일한다. 이모지·희귀 한자 앞뒤에서 잘리는지 검사한다.

## 6. 저장과 입력 안전

전용 임시 보관 키 제안은 `chinese-word-tactics-reader-draft-v1`이다.
내용은 `schemaVersion/title/text/showMarkers/updatedAt` 정도로 제한한다. 강조 구간은 파생 값이므로 원문과 목록으로 다시 계산한다.

마지막 유효 글 한 편만 지연 저장한다. **유효한 입력 변경을 짧은 지연 뒤 자동 저장하고 화면을 떠날 때 한 번 더 저장**한다. 상한 초과 입력은 기존 유효 글을 덮어쓰지 않는다. 탭 비활성화·강제 종료에서도 마지막 유효 입력의 소실을 줄인다.
저장소 접근 불가·용량 초과·잘못된 JSON이면 앱 전체를 중단하지 않는다. 메모리에서 읽기는 계속 제공하고 임시 저장 실패를 알린다.
저장된 데이터를 읽을 때도 타입·버전·길이를 검증한다.

안내 문구:
> 마지막 글은 이 브라우저에 임시 보관돼. 게임 진행 백업에는 포함되지 않아.

게임 진행 백업·복원·진행 초기화는 이 키를 건드리지 않는다. ‘임시 글 지우기’로 별도 삭제하며 확인·취소를 제공한다.
브라우저 사이트 데이터 삭제 시에는 임시 글도 사라진다. 파일 백업이나 장기 보관 기능으로 소개하지 않는다.

입력은 전부 일반 텍스트로 취급한다. `textContent`와 텍스트 노드로 출력하고, 강조 요소만 코드가 생성한다.
사용자 입력을 HTML·정규식·스크립트로 실행하지 않는다. 입력 글을 API, 로그 수집, URL 쿼리, 저장소 커밋에 보내지 않는다.
새 네트워크 요청 없이 처리하며, 기존 정적 자원 로딩과는 구별한다.

## 7. 구현 파일 제안

아래 파일과 API는 아직 존재하는 구현이 아니라 제안이다.

| 파일 | 책임 |
|---|---|
| `index.html` | `readerView` 화면 셸과 상대 경로 자원 연결을 추가한다. |
| `src/reader-content.js` | 검토한 소형 실행용 표지어 목록을 제공한다. |
| `src/reader-matcher.js` | DOM과 저장소에 의존하지 않는 순수 매칭 함수를 제공한다. |
| `src/reader-runtime.js` | 입력·읽기·토글·임시 보관·복귀를 관리한다. |
| `src/reader.css` | 읽기 화면에 한정된 스타일을 제공한다. |
| `src/flow-runtime.js` | 메뉴 항목과 화면 복귀 연결을 담당한다. |
| `data/reader-markers-v0.1.json` | 출처와 채택 근거를 가진 편집 목록을 관리한다. |

목록은 JSON을 원본으로 삼고 검증·생성 절차를 통해 실행용 JS를 만든다. 두 목록을 손으로 따로 유지하지 않는다.
상대 경로로 GitHub Pages의 `/chinese-word-tactics/`에서 동작하도록 한다.
읽기 모듈이 실패해도 기존 게임을 시작·재개할 수 있어야 한다.
책상 연결을 위해 방의 그림이나 사건 레이어를 바꾸지 않는다. v0.1에서는 해당 코드 변경이 필요하지 않다.

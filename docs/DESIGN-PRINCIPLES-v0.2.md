# 번체 중국어 단어 전술게임 — 디자인 원칙 v0.2

> 기준 버전: v0.6 + 단어장 v0.1
> 개정일: 2026-09-20
> 이전 문서: `DESIGN-PRINCIPLES-v0.1.md`
> 적용 대상: 월드맵, 전술 스테이지, 단어장, 여정, 이야기, 상태 피드백, 이후 지역·의뢰·참고 화면
> 목적: 기능이 늘어나도 화면이 흔한 학습 앱이나 생성형 UI 템플릿처럼 흐르지 않도록 시각적 판단 기준을 고정한다.
> 이번 개정: 전술 스테이지의 모바일 시선 흐름, 판 고정, 단어 뜻 진입, 설명형 텍스트 예산, 행동-단어 피드백, 짧은 Safari 화면의 세로 예산 원칙을 추가한다.

---

## 1. 한 줄 방향

**조용한 여행 세계 위에서, 단어와 변화만 또렷하게 살아나는 작은 전술게임.**

UI는 설명하려고 앞에 나서기보다 플레이어가 세계와 단어를 읽을 수 있게 자리를 비켜준다.

- UI는 조용하게.
- 공간은 하나의 장소처럼.
- 단어는 특별하게.
- 참고 화면은 사람이 정리한 노트처럼.

---

## 2. v0.1에서 이어받는 핵심

v0.1의 다음 원칙은 그대로 유지한다.

- UI 자체보다 핵심 경험을 주역으로 둔다.
- 선·테두리·그림자를 남발하지 않는다.
- 여백과 면 차이로 관계를 만든다.
- 단어는 일반 버튼처럼 보이지 않게 한다.
- 카드와 테두리는 정보의 존재를 증명하기 위해 쓰지 않는다.
- 44px 최소 터치 영역과 iPhone 13 mini 세로 화면을 기준으로 검수한다.
- 색은 장식보다 상태 전달에 우선 사용한다.
- 단어 뜻 확인에는 페널티가 없다.
- 점수·연속 학습·가짜 숙련도 같은 학습 앱 장식을 기본 화면에 넣지 않는다.

v0.2는 이 원칙을 바꾸는 문서가 아니라, **실제 구현에서 어떻게 어긋나는지를 더 구체적으로 정의하는 개정판**이다.

---

## 3. 가장 중요한 새 원칙: 컨테이너 인플레이션을 막는다

정보를 정돈하는 가장 쉬운 방법은 모든 것을 둥근 상자에 넣는 것이다.
하지만 이 방법을 반복하면 화면은 빠르게 다음 형태가 된다.

`카드 안 카드 → 버튼 안 버튼 → 둥근 테두리의 반복`

이 구조는 기능적으로 안전하지만, 화면이 흔한 대시보드·학습 앱·생성형 UI 템플릿처럼 보이게 만든다.

### 기본 규칙

**둥근 사각형은 기본 컨테이너가 아니다.**

새 요소를 만들 때 먼저 다음 순서로 분리할 수 있는지 확인한다.

1. 여백
2. 정렬
3. 글자 크기와 굵기
4. 얇은 구분선
5. 아주 약한 면 차이
6. 그래도 독립된 덩어리가 필요할 때만 카드

테두리와 배경은 마지막 수단이다.

### 금지에 가까운 패턴

- 목록의 모든 행을 독립 둥근 카드로 만드는 것
- 섹션마다 같은 흰 카드와 같은 radius를 반복하는 것
- 누를 수 있다는 이유만으로 모든 요소를 솟아 보이게 만드는 것
- 상위 탐색, 하위 탐색, 콘텐츠를 전부 같은 카드 문법으로 처리하는 것
- 작은 관련 단어까지 전부 pill/chip으로 만드는 것

## 4. 시각적 크기는 정보 구조와 비례해야 한다

화면의 실제 정보 구조와 시각적 무게가 어긋나면 불균형하게 느껴진다.

예를 들어:

`장 → 지역 → 비교 묶음 → 단어`

이라는 구조에서 장 선택은 작고 약한 폼 컨트롤인데 지역은 거대한 카드라면, 사용자는 지역이 장보다 더 상위 개념처럼 느끼게 된다.

### 원칙

- 상위 구조는 제목·위치·전환 방식으로 존재감을 가진다.
- 하위 구조는 상위보다 과도하게 큰 컨테이너를 반복하지 않는다.
- 콘텐츠의 양이 적다면 컴포넌트 높이도 작아져야 한다.
- 의미가 같은 깊이의 항목은 같은 시각적 크기를 유지한다.
- 화면 높이를 채우기 위해 항목을 불필요하게 키우지 않는다.

**컴포넌트 크기는 클릭 가능 여부가 아니라 정보의 역할과 밀도로 정한다.**

---

## 5. 화면 유형에 따라 다른 문법을 쓴다

모든 화면을 같은 카드 시스템으로 만들지 않는다.

### 5.1 세계·전술 화면

메타포: **장소**

- 길, 지형, 오브젝트가 하나의 공간처럼 보여야 한다.
- 개별 칸이나 장소가 버튼 카드처럼 보이지 않는다.
- 상태 변화는 세계 위에 얹힌다.

### 5.2 선택·설정 화면

메타포: **조작 도구**

- 폼 컨트롤이나 명확한 버튼 문법을 써도 된다.
- 단, 화면 전체가 설정 화면처럼 보이지 않게 사용 범위를 제한한다.

### 5.3 단어장·여정·기록 화면

메타포: **여행 노트 / 색인 / 기록장**

- 카드 대시보드보다 문서와 색인에 가깝게 만든다.
- 텍스트의 위계, 들여쓰기, 여백, 얇은 선으로 구조를 표현한다.
- 항목 하나하나가 독립 상품처럼 보이지 않게 한다.

참고 화면에서 가장 먼저 떠올려야 할 질문은

> 어떤 카드 스타일을 쓸까?

가 아니라

> **사람이 이 내용을 노트에 정리했다면 어떻게 나눴을까?**

이다.

### 5.4 전술 스테이지 진행 화면

메타포: **고정된 판과 바뀌는 상황**

전술 화면의 시선은 언제나 위에서 아래로만 흐르지 않는다.
이동판, 불과 풀무, 장터의 장소처럼 행동 가능한 세계가 먼저 눈에 들어올 수 있다.
따라서 모든 스테이지에 같은 읽기 순서를 강요하지 않고, 다음 상태 문법을 일관되게 유지한다.

- 어디를 누를 수 있는가
- 지금 무엇이 선택되었는가
- 현재 위치는 어디인가
- 방금 무엇이 바뀌었는가

기본 정보 구조는 다음을 권장한다.

`짧은 목표·사전 진입 → 위치가 고정된 판 → 선택 대상·가능 행동·직전 결과 → 소지 상태·되돌리기`

이 순서는 큰 카드 네 개를 세로로 쌓으라는 뜻이 아니다.
판은 세계로 남기고, 선택 대상과 결과만 정해진 상황 영역에서 교체한다.

#### 짧은 Safari 높이를 기준으로 먼저 맞춘다

iPhone 13 mini의 기기 해상도 `375×812 CSS px`를 그대로 플레이 가능 높이로 간주하지 않는다.
브라우저 UI가 펼쳐진 상태까지 고려해 전술 스테이지는 다음 두 수치를 기본 계약으로 삼는다.

- **최소 설계·검수 viewport:** `375×640 CSS px`
- **무스크롤 핵심 UI의 최대 세로 예산:** `620px`

핵심 UI에는 헤더, 목표와 사전 진입, 판, 상황·수량 요약, 핵심 행동, 되돌리기, 영역 사이 간격이 모두 포함된다.
실제 적용 예산은 `620px`과 `visualViewport.height`에서 상·하단 safe-area 및 바깥 패딩을 뺀 값 중 더 작은 쪽이다.
`620px`은 고정 높이를 강제하는 값이 아니라, 짧은 화면에서 기본 플레이 흐름이 차지할 수 있는 상한이다.
최종 판정은 문서 높이와 마지막 핵심 조작의 하단이 실제 `visualViewport.height` 안에 들어오는지로 한다.

- 진입 화면이 아니라 **정보가 가장 많이 나타나는 선택·행동 상태**를 기준으로 맞춘다.
- 진입, 선택, 행동 불가, 행동 직후, 완료 상태를 모두 같은 viewport에서 검사한다.
- `375×812`에서 남는 높이는 여백과 안정적인 판 배치에 사용하고, 상시 설명을 추가하는 근거로 삼지 않는다.
- 사전이나 사용자가 명시적으로 연 상세 시트는 내부 스크롤을 허용한다.
- 페이지 전체 스크롤은 큰 글자나 더 작은 실가용 높이의 접근성 안전망으로만 남기고, 기본 행동 경로로 사용하지 않는다.
- Safari UI로 이미 줄어든 `visualViewport.height`에서 브라우저 도구막대 높이를 다시 차감하지 않는다. 활성 safe-area와 실제 적용 패딩만 별도로 확인한다.

세로 예산을 초과하면 다음 순서로 줄인다.

1. 판단에 필요 없는 설명 문장을 제거한다.
2. 선택 확인, 제목, 상태처럼 같은 내용을 반복하는 영역을 통합한다.
3. 번역·세부 규칙·복수 행동 목록을 필요할 때 여는 상세로 접는다.
4. 카드 안팎 여백과 구역 간 간격을 줄인다.
5. 그래도 부족할 때만 판과 장식의 크기를 줄인다.

`44×44px` 터치 영역, safe-area, 중국어 핵심어, 현재 위치·선택·행동 가능 표식, 다음 행동에 필요한 수량과 조건은 세로 예산을 맞추기 위해 축소하거나 제거하지 않는다.

`651~700px` 높이는 별도 compact 구간으로 다룬다.
현재의 더 짧은 화면용 규칙을 그대로 확대해 터치 영역까지 줄이지 말고, 간격·패딩·반복 설명·장식 높이만 먼저 조정한다.
좁은 폭 회귀는 `360×640`에서도 별도로 확인한다.

#### 판은 상태가 바뀌어도 움직이지 않는다

- 진입, 대상 선택, 조사, 행동, 완료 사이에 판의 위치와 크기를 가능한 한 유지한다.
- 상세 정보가 늘어났다는 이유로 판을 위아래로 밀지 않는다.
- 긴 상세는 압축하거나 필요할 때 펼친다.
- 현재 위치, 선택한 대상, 지금 행동 가능한 대상은 서로 다른 표식으로 구분한다.
- 스테이지마다 조작 방식이 달라도 `선택 / 행동 가능 / 변화 완료`의 상태 표시는 같은 문법을 쓴다.

플레이어가 장소를 다시 찾기 위해 공간 기억을 재구성해야 한다면 상황 영역의 설계가 잘못된 것이다.

#### 단어 뜻 진입은 사전 표식으로 나타낸다

단어 뜻 확인은 실행 명령이나 정답 선택이 아니라 **참고 사전을 여는 행동**이다.

- 기본 진입 표식은 `📖`, `📚` 같은 사전 이모지 또는 사전 형태의 SVG 아이콘을 사용한다.
- 아이콘은 단어 가까이에 두되 중국어 단어 자체를 가리거나 대신하지 않는다.
- 일반 행동 버튼과 같은 채움색·테두리·선택 상태를 쓰지 않는다.
- 시각적 아이콘이 작아도 실제 터치 영역은 최소 `44×44px`로 확보한다.
- `aria-label="단어 뜻 보기"`처럼 접근 가능한 이름을 제공한다.
- 모바일에서 hover 설명에 의존하지 않는다.
- 사용자 검수에서 사전 기능으로 이해되지 않을 때만 짧은 `뜻` 보조 라벨을 추가한다.

이모지는 빠른 시안과 친숙한 표식에 적합하다.
화면마다 크기와 무게를 정확히 맞춰야 하거나 운영체제별 이모지 차이가 문제가 되면 프로젝트의 사전 SVG 아이콘을 사용한다.

#### 설명형 텍스트에는 노출 예산이 있다

설명형 텍스트는 공간이 남아서 넣는 기본 요소가 아니다.
**그 문장이 없으면 플레이어가 현재 판단이나 다음 행동을 합리적으로 결정할 수 없을 때만 항상 노출한다.**

항상 노출할 수 있는 경우:

- 판에서 직접 표현할 수 없는 규칙이나 제약
- 조사한 뒤 새로 밝혀진 정보
- 아이콘·수량·배치만으로 구분되지 않는 행동 조건
- 잘못 이해하면 진행 상태를 신뢰하기 어려운 예외

기본적으로 숨기거나 제거하는 경우:

- 목표 문장을 다시 풀어쓴 설명
- 판에 이미 보이는 상태를 한국어로 반복한 문장
- 바로 옆 조작만 보아도 알 수 있는 사용법
- 방금 누른 버튼 이름만 반복하는 상태 문구
- 사전에서 필요할 때 확인할 수 있는 상시 번역

우선순위는 다음과 같다.

1. 판의 배치·아이콘·수량·상태 변화
2. 대상 가까이 붙는 짧은 중국어 결과
3. 사전 아이콘을 통해 필요할 때 여는 뜻과 풀이
4. 그래도 판단이 불가능할 때만 설명형 문장

문장을 지웠을 때 첫 유효 행동과 현재 상태 해석이 그대로라면 그 문장은 기본 화면에서 제거한다.

#### 보충 정보만 가로 카드로 넘긴다

짧은 화면에서 판 아래 설명이 세로로 잘릴 때는 작은 영역 안에 세로 스크롤을 만들지 않는다.
먼저 선택 확인, 상태 제목, 대상 제목처럼 같은 사실을 반복하는 영역을 하나의 **판단 트레이**로 합친다.

판단 트레이에는 다음 정보를 고정한다.

- 현재 소지량과 운반 한도
- 선택한 대상
- 다음 판단에 필요한 수량·가격·교환식
- 현재 핵심 행동 또는 행동 불가 이유

한국어 풀이, 부가 사실, 이미 확인한 비교 정보처럼 없어도 바로 다음 행동을 결정할 수 있는 내용만 가로 카드에 둔다.
핵심 행동과 부족 이유를 두 번째 카드 뒤에 숨기지 않는다.

- 카드는 한 번에 한 장을 읽되 다음 카드가 `16~24px` 보이게 해 좌우 이동 가능성을 드러낸다.
- `scroll-snap`을 사용하고 카드마다 하나의 짧은 정보 단위만 담는다.
- 긴 문단을 가로 페이지처럼 나누지 않는다. 장문은 명시적으로 여는 상세 시트에 둔다.
- 가로 카드가 있어도 판단 트레이 자체에는 세로 overflow가 없어야 한다.
- 선택 확인 메시지가 트레이 제목과 같다면 별도 상태 줄을 제거한다.
- 실제 행동 결과, 실패, 완료 피드백은 선택 확인과 구분해 다시 강조한다.

판을 줄여 공간을 회수할 때도 칸의 실제 터치 영역은 `44×44px` 아래로 줄이지 않는다.

#### 행동과 단어를 같은 순간에 연결한다

그림, 색, 수량, `− / +` 같은 비언어 단서는 제거하지 않는다.
이들은 의미를 추론하게 하는 좋은 학습 발판이다.
대신 비언어 단서만으로 행동한 뒤 중국어를 만나지 않고 끝나는 흐름을 피한다.

- `− 減少`, `＋ 增加`처럼 조작과 목표어를 가까이 둔다.
- 행동 직후 변화가 일어난 대상 가까이에 `火力減少了`처럼 결과를 보여준다.
- 지속 상태와 직전 행동 결과를 한 문장에 섞지 않는다.
- 단어를 눌러야만 행동할 수 있게 강제하지 않는다.
- 같은 단어를 다른 사물·방향·수량 상황에서도 판단하게 하여 위치 암기와 의미 이해를 구분한다.

학습 흐름은 다음 고리를 목표로 한다.

`상황 발견 → 뜻 회상·조회 → 가설 → 행동 → 대상의 변화 → 단어로 결과 확인 → 다음 상황에 전이`

#### 완료는 진행 상세를 의미 복기로 바꾼다

- 마지막 행동 뒤에도 판을 남겨 결과의 공간적 맥락을 보존한다.
- 완료 신호는 한 번만 분명하게 표시한다.
- 진행 중이던 긴 대상 상세는 성공에 사용한 단어와 변화의 짧은 복기로 교체한다.
- 완료 문구와 미충족처럼 보이는 수량·배지·행동 버튼을 동시에 남기지 않는다.
- 완료 복기는 새로운 설명을 추가하는 곳이 아니라 방금 경험한 의미 관계를 정리하는 곳이다.

## 6. 카드 사용 예산

카드는 존재 이유가 명확할 때만 쓴다.

### 카드가 자연스러운 경우

- 화면 위에 떠 있는 바텀시트·모달
- 긴 설명과 행동이 함께 묶인 독립 정보층
- 서로 다른 상태를 가진 선택지가 실제로 독립 개체일 때
- 설정처럼 경계가 명확해야 하는 조작 덩어리

### 카드가 기본값이 아닌 경우

- 지역 목록
- 단어 목록
- 비교 묶음 목록
- 문서형 상세 화면의 각 섹션
- 관련 단어 링크
- 단순한 통계 숫자
- 제목 한 줄과 설명 한 줄뿐인 항목

한 화면에서 카드가 반복되기 시작하면 먼저 카드 수를 줄이는 방향을 검토한다.

---

## 7. 모서리와 테두리

둥근 모서리는 친근함을 만드는 장식이 아니라 **층의 성격을 구분하는 신호**로 쓴다.

### 권장

- 모달 / 바텀시트: 비교적 큰 radius
- 주요 입력: 중간 radius
- 정말 독립된 버튼: 필요한 만큼만
- 세계와 기록 본문: radius 없이도 성립해야 함

### 피할 것

- 페이지의 모든 블록이 12~18px radius를 공유하는 것
- 얇은 회색 테두리 + 흰 배경 + 둥근 모서리를 기본 컴포넌트 문법으로 삼는 것
- 각 계층이 동일한 둥근 사각형으로 중첩되는 것

**같은 모서리 모양이 화면 전체를 지배하면 정보의 성격 차이가 사라진다.**

## 8. 여백과 선을 적극적으로 사용한다

카드를 제거한다고 구조가 약해져서는 안 된다.

카드가 하던 일을 다음 요소가 나눠 맡는다.

- 큰 단계 변화: 큰 세로 여백
- 같은 목록 항목: 일정한 리듬
- 항목 경계: 1px 이하의 약한 구분선
- 현재 선택: 글자 무게·작은 표식·면 차이
- 중요 정보: 타이포그래피 크기
- 보조 정보: 낮은 대비와 들여쓰기

구분선도 모든 곳에 넣지 않는다.
이미 여백으로 충분히 나뉘면 선을 생략한다.

## 9. 타이포그래피가 컨테이너 역할을 한다

상자 없이도 구조가 보이려면 글자 역할이 명확해야 한다.

최소 역할:

- 페이지/장 제목
- 지역/섹션 제목
- 중국어 핵심어
- 한국어 핵심 뜻
- 본문 설명
- 메타 정보
- 발견 수·상태 같은 작은 숫자

중국어 단어는 단어장에서도 시각적 주인공이다.
한국어 설명이 중국어보다 더 큰 카드 제목처럼 앞에 나오지 않는다.

**굵기와 크기는 장식이 아니라 구조를 대신한다.**

## 10. 단어장 전용 적용 원칙

단어장의 기본 구조는 그대로 유지한다.

`장 → 지역 → 비교 묶음 → 단어`

다만 시각 문법은 카드 목록이 아니라 색인과 노트에 가깝게 한다.

### 10.1 장 선택

현재 장은 폼의 한 필드라기보다 **현재 펼쳐 둔 여행 구간의 제목**이다.

권장 형태:

`1장 · 물길마을  ⌄`

- 별도 `여행 구간` 라벨을 반드시 두지 않는다.
- 전체 폭의 두꺼운 둥근 입력 필드가 아니어도 된다.
- 장이 여러 개가 되었을 때 전환 가능하다는 단서만 충분히 준다.

### 10.2 지역 목록

지역은 큰 카드가 아니라 **색인 행**에 가깝다.

예:

```text
길목  關口                              4 / 14
경로 · 위치 · 이동
────────────────────────────────
장인골  工坊谷                          3 / 14
변화 · 조건 · 상태
```

- 한 지역을 56~64px 안팎의 밀도로 표현할 수 있으면 더 키우지 않는다.
- 지역명과 중국어명은 같은 한 줄에서 관계가 보이게 한다.
- 발견 수는 보조 정보로 오른쪽에 둔다.
- 지역 간 구분은 여백 또는 얇은 선을 우선한다.

### 10.3 비교 묶음 목록

비교 묶음도 작은 독립 카드의 반복으로 만들지 않는다.

권장 구조:

```text
같은 거래, 두 관점
買 ⇄ 賣
같은 거래를 구매자와 판매자 쪽에서 본다.
```

다음 묶음과는 여백이나 얇은 구분선으로 나눈다.

### 10.4 비교 상세

두 단어를 비교하는 화면에서 단어마다 큰 카드 하나씩 주면 관계가 끊겨 보인다.

따라서 **같은 비교 평면 위에 단어를 놓는다.**

예:

```text
買  ⇄  賣

買  ㄇㄞˇ
사다, 구입하다
我們買了……

────────────

賣  ㄇㄞˋ
팔다
菜販賣出……

어떻게 다를까?
……
```

관계를 먼저 보고, 각각의 용례가 그 아래에서 이어져야 한다.

### 10.5 개별 단어 상세

개별 단어 상세는 **문서**처럼 읽혀야 한다.

`일반 용례 / 게임에서 / 이것도 참고하자 / 여정에서 만난 곳`

각 항목을 모두 둥근 카드로 감싸지 않는다.

권장:

- 섹션 제목 + 본문
- 필요할 때만 위쪽 얇은 선
- `게임에서`처럼 특별한 맥락만 옅은 면이나 왼쪽 선으로 강조 가능
- 관련 단어는 작은 텍스트 링크 또는 단순 버튼

### 10.6 관련 단어

`이것도 참고하자`는 부가 탐색이다.

관련 단어가 작은 카드/칩 군집으로 본문보다 더 강하게 보이면 안 된다.

`賣 · 價格 · 價值`

처럼 텍스트 중심으로 보여도 충분하다.

## 11. 조작 가능성과 버튼 모양을 분리한다

누를 수 있는 요소가 반드시 전통적인 버튼처럼 보여야 하는 것은 아니다.

다음 요소로 상호작용 가능성을 전달할 수 있다.

- 행 전체의 충분한 44px 터치 영역
- 눌렀을 때의 배경 변화
- 끝의 작은 화살표 또는 전환 표식
- 일관된 위치와 패턴
- 포커스 표시

따라서 접근성을 위해 터치 영역을 확보하되, 시각적으로는 평평한 색인 행을 유지할 수 있다.

## 12. AI slop 방지 체크

새 화면이나 컴포넌트를 검토할 때 다음 징후가 보이면 다시 줄인다.

- 흰 둥근 카드가 세 개 이상 연속되는가?
- 모든 정보 단위에 테두리가 있는가?
- 모든 클릭 요소가 같은 버튼 모양인가?
- 같은 radius가 페이지 전체에 반복되는가?
- 정보가 적은데 카드가 지나치게 높은가?
- 상위 선택기는 작고 하위 항목은 과도하게 큰가?
- 배경, 카드, 내부 카드가 여러 겹으로 중첩되는가?
- 카드 제거 후 여백과 타이포그래피만으로도 이해 가능한가?
- 화면을 캡처했을 때 제품 고유의 세계보다 일반 SaaS/학습 앱처럼 보이는가?
- 단어 뜻 확인이 일반 행동 버튼이나 정답 선택지처럼 보이는가?
- 사전 아이콘으로 충분한데 `뜻 보기` 같은 설명 버튼이 반복되는가?
- 판에 이미 보이는 내용을 설명형 문장이 다시 말하는가?
- 선택·조사·행동 결과가 나타날 때 판의 위치가 움직이는가?
- 행동 결과가 변화한 대상보다 먼 상태 상자에만 나타나는가?
- `375×640`에서 핵심 조작까지 무스크롤로 보이지 않는가?
- `375×812`에서만 남는 공간을 이유로 설명을 더 붙였는가?

마지막 질문에 `그렇다`면 기능적으로 문제가 없어도 디자인은 다시 본다.

## 14. 현재 단어장 리디자인 우선순위

코드 변경 전에 다음 순서로 시안을 비교한다.

### 1차 — 구조 평탄화

- 장 드롭다운을 장 전환기/제목처럼 축소
- 지역 카드를 색인 행으로 전환
- 발견 수를 보조 메타 정보로 약화

### 2차 — 카드 제거

- 비교 묶음 카드 제거
- 비교 상세의 단어별 독립 카드 제거
- 개별 상세의 섹션 카드 제거

### 3차 — 리듬 재구성

- 여백 단계 정의
- 얇은 구분선 규칙 정의
- 제목/중국어/뜻/메타 글자 역할 정리

### 4차 — 실기기 검수

- iPhone 13 mini Safari
- 한 손 탐색
- 지역 → 비교 → 단어 → 뒤로가기 왕복
- 긴 비교 묶음 개행
- VoiceOver/포커스

## 15. 유지할 것

이번 개정은 기능 구조를 뒤엎는 것이 아니다.

유지한다.

- `장 → 지역 → 비교 묶음 → 단어` 정보 구조
- 지역 중심 탐색
- 비교/용례 우선
- 발견 전 단어 숨김
- 중국어 우선
- 한국어 핵심 뜻의 참고 기능
- 플레이 중 빠른 단어 시트
- 사전 이모지 또는 SVG 아이콘을 통한 페널티 없는 뜻 확인
- 행동 가능한 세계와 위치가 고정된 판
- 비언어 단서와 중국어 결과의 결합
- `375×640` 최소 검수 viewport와 `620px` 무스크롤 세로 예산
- 단어장의 독립 페이지 역할
- 검색
- 44px 터치 기준
- 따뜻한 종이 계열 배경과 절제된 색

바꾸는 것은 **정보를 감싸는 방식**이다.

## 16. 핵심 문장

**카드를 쌓아 위계를 만들지 않는다. 여백, 선, 타이포그래피로 위계를 만든다.**

단어장은 대시보드가 아니다.

> **여행하며 만난 말을 사람이 차분히 정리해 둔 색인과 노트처럼 보인다.**

그리고 게임 전체에서 UI는 제품의 개성을 대신 만들지 않는다.

> **세계와 단어가 이미 개성이다. UI는 그것을 가리지 않는다.**

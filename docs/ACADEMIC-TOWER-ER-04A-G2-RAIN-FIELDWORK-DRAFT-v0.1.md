## 0. 이번 설계의 핵심 한 문장

소년은 큰비 뒤 상류의 흔적·관리 수문·공방 수로를 관찰하고 예상보다 약한 흐름을 확인한다. B~C 구간의 물소리를 따라 되짚어 **원래 도면에 없는 인공 측벽 통로 D를 발견**한다. 무엇이 확인됐고 무엇이 미확인인지 구별해 적은 뒤, **다음에 조사할 질문 하나를 정하는 것**으로 04A를 마친다.

학습 목표는 여덟 표현을 정확히 한 번씩 소모하는 일이 아니다. 첨가(而且), 전환(然而), 예상 역전(反而), 정정(不是……而是……), 범위 제한(而已), 근거에 따른 조치(因而), 방법과 얻은 결과(從而), 앞 결과를 발판으로 다음 단계 결정(進而)을 **각기 다른 실제 행동**에 결합한다. 因而와 從而의 의미 중첩을 부당하게 배타적 정답으로 만들지 않는다.

## 2. 관측 사실·자료·가설의 단일 기준

정확한 수위 수치·유속·날짜를 지어내어 정답 조건으로 삼지 않는다. 서로 다른 위치·시점의 눈금을 같은 물리량인 것처럼 직접 빼거나 누수량을 계산하지 않는다.

| 장소·자료 | 플레이어가 확인할 수 있는 사실 | 확정하지 않는 것 |
|---|---|---|
| A 상류 관측 자리 | 비 뒤 남은 **새 높은 수위 흔적**, 그 높이의 석틈에 걸린 잎·풀, 지금은 그보다 내려간 수위 | C의 현재 유량, 하류 침수, 원래 수문의 고장 |
| B 취수·분수문 | 수문 담당자가 비 뒤 유입을 조절한 기록이 있음. 현재 공방용 인공 수로로 **물이 들어가고 있음** | 어느 만큼의 물이 C까지 갔는지, B가 유일한 설명인지 |
| C 공방 수로 | 현재 물이 흐르지만 **소년이 큰비 뒤 예상한 만큼 세지 않음** | C가 평소보다 낮음, 수량이 사라진 정확한 규모, D가 단일 원인 |
| D B~C 사이 인공 수로 측벽 | 안전한 점검길에서 다른 방향의 물소리. 탐색하면 하류를 바라본 왼쪽 석벽의 작은 네모 입구, **수로 안에서 수풀 아래로 나가는 물**, 다듬은 돌과 반복된 도구 흔적 | 입구가 원래 비로 깨진 자연 균열이라는 단정 |
| 연구원이 가진 원래 설계도 | 해당 위치에 D가 그려져 있지 않음 | 이후 변경·보수 도면도 없었다는 단정 |
| 아직 확인하지 못한 사실 | D의 행선지, 정확한 영향량, 누가·언제·왜 만들었는지, 관리 허가 여부 | 어느 한 가설을 정답으로 확정하지 않음 |

**C에서 B~C를 되짚는 이유:** 연구원은 B에서 관리 기록을 읽었지만, 그 기록만으로 중간 구간의 실제 흐름 전체를 확인했다고 볼 수 없다. 소년의 예상과 C 관측의 차이를 계기로 안전한 점검길에서 확인을 이어 간다. 이는 합리적인 현장 확인이지 "B~C 사이의 누수가 이미 입증됐다"는 판단이 아니다.

**D의 反而를 성립시키는 예상:** 물소리를 듣고 소년은 수풀 쪽에서 남은 빗물이 공방 수로로 **유입**되는 것일지도 모른다고 추측한다. 플레이어가 직접 입구와 물의 움직임을 관찰한 뒤에야 실제 **유출**을 확정한다. 이 예상은 장면 속 소년의 가설이므로 플레이어에게 일부러 틀린 답을 고르라고 강요하지 않는다.

## 3. 전개·중간 이야기·화면 분담

**공통 이야기 화면:** S0 학술탑 밖 우연한 만남 → T1 → T2 → I1 점검길을 되짚으며 소년이 다른 물소리를 알아차림 → T3 → I2 발견 직후 연구원이 원래 도면을 꺼냄 → T4 → T5 → 결과 이야기 S1.

- S0: 소년은 별 목적 없이 지나가고, 연구원은 큰비 뒤 점검에 필요한 도구를 들고 이미 외출 준비를 마친 상태. 03B를 완료한 경우 익숙한 인사 한두 줄만 다르게 한다. 03B 미완료일 때 도시락이나 공동 지도 해설은 전제하지 않는다. 05 결과 미열람일 때 관찰 카드·소년 기록 칸도 전제하지 않는다.
- I1: C를 관찰한 뒤 연구원이 B~C의 점검길을 더 확인하자고 제안. 소년은 수풀 쪽에서 별도의 물소리를 듣는다. **D라는 마커·입구·유출 방향을 먼저 보여 주지 않는다.**
- I2: T3에서 실제 입구와 유출 방향을 확인한 뒤, 연구원이 기존 도면을 펴서 비교 준비를 한다. 도구 흔적·제작자·합법성은 T4에서 살핀다.
- S1: 정확히 발견한 것과 아직 모르는 것을 대조한다. 연구원이 관리자에게 현장 사실을 알리고, 소년은 다음 질문 하나를 정했다는 작은 성과를 남긴다.
- 인물의 관계는 정답 뒤 작업대 대사를 반복하여 설명하지 않는다. 대화는 StoryRuntime 공통 인물 화면, 판단은 학술탑 작업대에서 진행한다.

## 4. T1 — A 《남은 흔적》

**학습 표현:** 而且. **행동 문장:** 소년은 상류에서 큰물이 지나간 흔적을 하나 확인한 다음, 이를 뒷받침하는 **다른 현장 증거를 추가**해 관찰 메모를 보강한다.

- **읽는 원자료(작업용 번체 초안):** 「石壁上留著新近的高水痕。」 / 「高處的石縫裡還卡著被水沖上來的草葉。」 / 「現在的水位已經低於那道水痕。」 실제 관찰 카드에서는 과거 흔적과 현재 수위를 서로 다른 시간으로 표시한다.
- **조작:** 현재 보이는 높은 물 자국을 탭해 관찰 메모에 넣는다. 이어서 현장 도식의 후보 중 **높은 석틈에 걸린 풀잎**을 추가 증거로 선택한다. 수문 고장이라는 추측, 단순한 현재 눈금 등은 ‘높은 수위의 추가 증거’로 선택하지 않는다. 선택 미리보기 뒤 확인한다.
- **확정 뒤 중국어 문장 후보:** 「石壁上有新留下的高水痕，而且高處的石縫裡還卡著被水沖上來的草葉。」
- **trigger → predicate → delta → win:** 높은 물 자국 관찰 → 추가로 서로 다른 관련 증거 선택 → 소년의 현장 메모에 두 관찰이 나란히 남음 → 둘의 관측 출처·시점이 유지되면 통과.
- **허용 경로:** 고수위 흔적·풀잎 중 먼저 살필 순서는 자유다. 이미 기록된 증거를 다시 탭해도 완료를 초기화하지 않는다.
- **대표 오답·복구:** 「비가 많이 왔으니 수문이 고장 났다」는 확인되지 않은 추론이라고 설명하고, 추가 관측 후보만 바꾼다. 현재 수위와 지난 높은 물 자국을 같은 시점의 값으로 합치면 두 시점을 분리해 준다.
- **작성 주체·피드백:** ‘소년의 상류 관찰 메모’. 피드백은 "흔적 두 가지를 더했어. 그런데 오늘의 물높이는 그때와 다르지." 정도로 짧게.
- **저장:** 선택한 증거 ID, 확인 여부, 원문·뜻 조회의 펼침 위치는 가벼운 국소 상태로 구분한다.

## 5. T2 — B·C 《예상과 다른 물》

**학습 표현:** 然而(본선 02 능동 재사용). **행동 문장:** 연구원의 수문 기록과 소년의 공방 수로 관측을 **둘 다 보존**하면서, 소년의 지나치게 빠른 해석을 수정하고 다음 점검 대상을 정한다.

- **읽는 원자료:** B 「管理人員在雨後調整了進水口，現在仍有水流入工坊水道。」 / C 「工坊水道下段的水流，比少年原先想的弱。」 / 소년의 예상 「前幾天下了那麼大的雨，工坊水道的水流應該也會很急吧？」
- **조작 1:** 현재 B·C의 관측을 나란히 놓고, 두 기록의 관계를 고른다. ‘B에 물이 들어가고 있어도 C는 예상보다 약하다’는 두 사실 보존이 핵심이다.
- **조작 2:** 소년의 메모 초안 「所以一定是水門壞了。」의 **단정**을 선택해 수정한다. 새 메모는 ‘중간 구간을 다시 확인하자’이며, 관리 수문을 직접 여닫거나 손실량을 계산하지 않는다.
- **확정 뒤 중국어 문장 후보:** 「進水口仍有水流入工坊水道。然而，下段的水流沒有少年預想的那麼急。」 / 「單靠水門的紀錄，還不能確定中間每一段的情況。」
- **trigger → predicate → delta → win:** B·C 자료 확인 → 사실 둘 모두 유지, 성급한 고장 단정 제거, B~C 구간 재확인 선택 → 연구원 점검 메모가 ‘추가 확인’으로 수정됨 → 두 조건을 만족하면 통과.
- **대표 오답·복구:** B·C 기록 중 하나를 삭제, C의 흐름이 평소보다 낮아졌다고 덧붙임, D의 누출을 이미 원인으로 확정하는 선택은 근거 범위를 안내한다. 기존 관찰은 지우지 않고 판단 초안만 다시 고른다.
- **작성 주체:** ‘연구원의 현장 대조 메모를 소년이 함께 검토’. B 수문 관리자의 기록과 소년의 관측을 동일한 사람의 목격담으로 합치지 않는다.
- **저장:** B·C 확인, 수정 대상, 후속 점검 확정. 통과하면 I1을 열되 미열람 이야기는 건너뛰지 않는다.

## 6. T3 — B~C의 D 《물소리의 방향》

**학습 표현:** 反而(본선 04 능동 재사용). **행동 문장:** 소년의 유입 예상과 실제 물의 **반대 방향 유출**을 관찰로 구별하며, 이전 도면에 아직 없는 새로운 입구를 발견한다.

- **시작에서 아는 것:** I1에서 들은 수풀 쪽 물소리, 점검길에서 안전하게 볼 수 있는 수로·둑·수풀, 소년의 잠정 가설 「會不會是草叢裡的雨水流進水道？」. **D의 위치와 유출 방향은 보이지 않는다.**
- **조작 1 — 조사 위치:** 한 화면의 단순한 수로 도식에서 ‘수풀 쪽에 물소리가 나는 구간’을 탭한다. 다른 안전한 관측 구간을 조사해도 ‘여기는 일반적인 수로 소리’ 같은 정보가 남으며, 오답 벌점·무한 수색을 요구하지 않는다. 손가락으로 작은 틈을 정확히 누르는 픽셀 탐색은 금지한다.
- **조작 2 — 흐름 관찰:** 좁은 입구가 드러난 뒤, 눈으로 확인되는 물결/떠내려가는 잎의 이동을 보고 **수로 안 → 측벽 입구 → 수풀 아래** 방향을 고른다. 실제 물소리 오디오의 청취는 필수가 아니다. 내레이션과 시각 흔적으로 동등한 정보를 준다.
- **확정 뒤 중국어 문장 후보:** 「我以為草叢裡的雨水會流進水道，沒想到水反而從水道流向草叢。」
- **trigger → predicate → delta → win:** 소리 단서 확인 → 안전한 조사 구간 탭 → 입구 발견(아직 흐름 방향 미확정) → 유출 방향의 관측 선택 → 현장 메모에 ‘추측: 유입 / 실제: 유출’ 표시 → D 발견 및 흐름 확정 시 통과.
- **대표 오답·복구:** ‘수풀에서 수로로 들어온다’를 그대로 선택하면 "물결이 어느 쪽으로 움직이는지 다시 보자"라는 단서를 표시한다. "물소리만 들었으니 아직 방향을 모르겠다"는 입구 관측 전에는 합리적인 유보이며 부당하게 오답 처리하지 않는다. 관측 뒤 다시 방향을 선택할 수 있다.
- **정보 공개 경계:** D는 해당 구간 관찰 전 새 지도 핀이나 정답 화살표로 나오지 않는다. 위치 탐색 성공만으로 인공 공사·절도·종착지를 보여 주지 않는다.
- **UI:** 44px 이상 탭 영역을 가진 **고정된 간단 도식+관찰 선택**. 화살표는 정답 시연이 아니라 플레이어의 선택 미리보기로 표시한다. 확대/드래그/정밀 소리 감지는 요구하지 않는다.
- **저장:** 발견된 구간 ID, 입구 발견 여부, 방향 선택·확인, 소년 예상/실제 구분. 통과하면 I2를 연다.

## 7. T4 — D와 설계도 《도면에 없는 길》

**학습 표현:** 不是……而是…… / 而已. **행동 문장:** 물길의 형태를 보고 **자연 균열이라는 추측을 인공 통로라는 근거 있는 판단으로 고치되**, 원래 도면에 없다는 사실을 절도 단정으로 넓히지 않는다.

- **읽는 자료:** D의 네모난 입구·일정하게 다듬은 돌면·반복된 도구 자국(관찰 가능), 원래 설계도(그 위치에 D 미표시), T3에서 확인한 유출 방향. 이후 수정 도면의 유무는 미확인이다.
- **조작 1 — 근거에 의한 정정:** 소년의 「비 때문에 돌벽이 자연히 깨진 걸까요?」 가설에서 확인되지 않은 부분을 짚고 **인위적으로 낸 통로의 근거**를 선택한다. 결과 문장 후보 「這不是自然裂開的縫，而是有人鑿出的通道。」. 단, ‘사람 손이 간 통로’가 ‘불법 취수’와 같지 않음을 남긴다.
- **조작 2 — 판단 범위 한정:** 연구원이 적을 보고 초안의 「原圖沒有畫，所以一定有人偷水。」에서 과도한 결론을 고친다. 한정 문장 후보 「我們目前只知道這張原圖沒有畫出這個孔而已；後來有沒有修改紀錄，還得查。」. D의 실제 유출·인공 흔적은 별도의 **확인한 사실** 칸에 유지한다.
- **trigger → predicate → delta → win:** 도구 흔적 확인, 원본 도면 대조 → 대상(자연 균열/인공 통로) 수정 + ‘원래 도면에 없음’과 ‘변경 기록 유무 불명’을 분리 → 근거 있는 도면 대조 메모 생성 → 두 의미 판단이 완료되면 통과.
- **허용 경로:** 도면 대조와 도구 흔적 관찰의 순서는 자유. 같은 사실을 다른 자연스러운 문장으로 표현하는 것이 가능하면 표현 문자열 대신 근거·판단 ID로 판정한다.
- **대표 오답·복구:** ‘옛 도면에 없으니 불법’ 또는 ‘지금 물이 나가니 반드시 누가 훔친다’는 미확정 범위를 안내하고, 확정된 사실은 지우지 않는다. 인공 흔적과 자연 균열의 근거를 반대로 연결했으면 해당 단서만 다시 비교한다.
- **작성 주체:** ‘연구원의 도면 대조 메모’. 소년이 발견한 소리와 연구원이 확인한 원래 도면을 출처별로 구분한다.
- **저장:** 인공 흔적 선택, 도면 대조, 한정된 진술 ID·확인 여부. 원본 도면을 고치지 않고 별도 관측 주석만 남긴다.

## 8. T5 — 현장 조사 마무리 《다음 질문》

**중심 표현:** 因而 / 從而 / 進而. **행동 문장:** 소년과 연구원은 관측 기록을 근거로 ‘방법으로 확인한 결과’, ‘근거에 따라 필요한 조치’, ‘다음 질문’을 각각 적고 실제 결과와 **미실행 계획**을 구별한다.

이 작업은 같은 세 칸에 서로 다른 접속어를 한 번씩 소모하는 빈칸 게임이 아니다. 한 장의 조사 기록을 **서로 역할이 다른 세 작업면**에서 완성한다.

### 8.1 조사 방법과 확인한 결과 — 從而

- **원자료:** D 현장 관측과 연구원의 **원래 설계도**.
- **조작:** ‘현장 입구 위치 확인 + 원래 도면 대조’라는 **실제로 한 방법**을 선택하고, 그 방법으로 확인한 결과를 연결한다.
- **중국어 문장 후보:** 「我們對照現場與原圖，從而確認這裡有一條原圖沒有標出的通道。」
- **통과:** 원래 도면에 D가 없고 실제 현장에는 출수 통로가 있다는 범위만 확인. ‘이후 변경 기록도 없다’, ‘불법임이 밝혀졌다’는 허용하지 않는다.
- **판정 원칙:** 從而를 ‘방법에만 쓰고 因而는 방법에 절대 못 쓴다’는 식으로 출제하지 않는다. 확인된 결과와 아직 모르는 결과의 구분을 검사한다.

### 8.2 발견을 근거로 취할 조치 — 因而

- **원자료:** 인공 통로 D의 현재 유출, 원래 도면 미표시, 시설의 담당자는 별도로 존재함.
- **조작:** 근거를 선택한 뒤 해야 할 조치를 정한다. **시설 관리자에게 현재 관측 사실을 알리고 변경·관리 기록을 확인해 달라고 요청**하는 선택이 정당하다.
- **중국어 문장 후보:** 「現場發現了原圖沒有標示的出水口，因而需要通知管理人員核對。」
- **오답:** 구멍을 직접 막기, 소년을 통로 안에 들여보내기, 절도범을 이미 확정했다고 보고하기. 안전과 근거의 문제를 짧게 설명하고 조치만 다시 고르게 한다.

### 8.3 기록을 마친 뒤 다음 질문 선택 — 進而

- **선행 조건:** D의 위치·관측 시점·실제 유출 방향·도면 차이를 **기록으로 정리**함.
- **실제 조작:** 다음 둘 중 하나를 고른다. 둘 다 유효한 進而의 후속 질문이며 숨은 정답 차이가 없다.
  - inquiry-records: **이후 변경/보수 기록을 찾아 누가 어떤 용도로 만들었는지 확인할 계획**.
  - inquiry-outlet: **관리자의 안전 확인과 허가를 거쳐 하류 출구를 관측할 계획**.
- **중국어 문장 후보 A:** 「先記下孔口的位置和水流方向，進而安排查閱後來的修繕紀錄。」
- **중국어 문장 후보 B:** 「先記下孔口的位置和水流方向，進而規劃在確認安全後觀察下游出口。」
- **판정:** 두 선택 모두 통과. 선택은 **계획**이지 이미 기록을 찾았거나 출구를 확인했다는 보고가 아니다.
- **최종 상태:** 확인·가설·미확인/다음 질문의 세 범위를 구분한 **두 사람의 조사 기록**을 만든다. 선택한 계획은 최초 완료 기록에 남긴다. 04A만의 작은 성과로 닫고 새로운 필수 지역/후속 의뢰를 개방하지 않는다.

### T5 종합 오답·복구

「找到出口了」, 「已經查到誰挖的」처럼 **미래 계획을 완료된 조사 성과로 바꾸는 진술**은 아직 수행하지 않았다는 점을 알려 준다. 세 조작의 선후 관계는 논리적 의존성만 지킨다. 어느 정보를 잘못 연결했더라도 이미 올바르게 적은 다른 범주는 지우지 않고 국소 수정할 수 있다.

## 9. 어휘·관찰·정답 공개 계약

| 표현 | 실제 의미 행동 | 첫 의도적 소개/재사용 |
|---|---|---|
| 而且 | 관련 있지만 별개인 관측 증거를 **추가** | T1에서 능동 적용 |
| 然而 | B의 사실을 유지하면서 C의 예상 밖 상태를 함께 기록 | T2 본선 재사용 |
| 反而 | **소년의 유입 예상 ↔ 실제 유출**을 관찰 뒤 대조 | T3 본선 04 재사용 |
| 而是 | 자연 균열이라는 추측을 인공 통로로 **근거 있게 정정** | T4 |
| 而已 | 도면에서 확인된 범위를 **그뿐**으로 한정 | T4 |
| 因而 | 새 현장 발견을 근거로 **관리자 통보 필요** 판단 | T5 |
| 從而 | 실제 현장 관측과 도면 대조가 낳은 **확인 결과** 연결 | T5 |
| 進而 | 확보한 기록을 발판으로 **새 조사 질문** 정하기 | T5, 결말에서 재언급 |

표현 풀이·주음·사전 예문은 언제나 무료로 조회할 수 있다. 그러나 원문이 나오기도 전에 아직 안 본 사실이나 D의 방향을 정답 해설로 미리 노출하지 않는다. 연구 시작만으로 여덟 표현을 단어장의 ‘발견’으로 처리하는 기존 visitStage 일괄 등록과 충돌하므로, 04A는 실제 단계 진입/표현 노출에 맞춘 발견 처리의 국소 확장이 필요하다. 기존 WORDS와 공식 TBCL 원자료는 변경하지 않고 여섯 신규 표현은 편집층·lifecycle에 등록한다.

**언어 검토 상태:** 위 번체 문장은 **학습·판정 설계를 위한 1차 창작 초안**이다. 실제 화면에 실을 최종 중국어 대사·주음/문장 연결·허용 대안을 별도 윤문하고, 문장이 자연스럽다는 판단을 자동 테스트로 대체하지 않는다. 교육부 사전: [而且](https://dict.revised.moe.edu.tw/dictView.jsp?ID=148316), [然而](https://dict.revised.moe.edu.tw/dictView.jsp?ID=135523), [反而](https://dict.revised.moe.edu.tw/dictView.jsp?ID=35200), [從而](https://dict.revised.moe.edu.tw/dictView.jsp?ID=142956); 그 밖의 언어 검토 근거는 [이전 E단계 문서 §19](ACADEMIC-TOWER-ER-SIDE-STAGES-v0.1.md)를 따른다.

## 10. 화면·조작 계약

- 학술탑의 기존 공간 언어(짙은 타공판, 얇은 금속 레일, 밝은 작업면)를 유지한다. **원본/관찰 자료 → 작성 주체가 표시된 작업면**이 최상위 시각 경계다. 원본 한 문장마다 큰 카드를 만들지 않는다.
- T1은 관찰 증거를 추가하는 방식, T2는 추론의 범위를 고치는 방식, T3은 지역과 물의 이동 방향을 직접 찾는 방식, T4는 도면 근거와 한정 범위를 수정하는 방식, T5는 한 장의 최종 기록을 완성하는 방식이다. 다섯 단계가 모두 같은 삼지선다 문장 맞히기가 되면 G2 의도에 실패한 것이다.
- T3 도식은 세계지도·물리 시뮬레이션이 아닌 **한 구간의 정적 개념 그림**이다. 방문 가능 안전 관측 구역은 44×44 CSS px 이상, 작은 구멍을 정확히 누를 필요 없음. 실제 물소리는 필수 기능이 아니며 텍스트와 시각 단서로 동등하게 조사 가능. 단어/관찰 의미에 무관한 픽셀 숨기기 게임 금지.
- 선택한 순간은 **미리보기**이고, 의미를 판정하는 확정 입력 뒤에만 성공 표시를 준다. 틀린 선택은 근거와 함께 남기고 그 선택 부분만 고친다. 원본과 이미 확인된 관측 사실은 지우지 않는다.
- 단어·주음·원문 뜻 조회는 무료. 원래 원본/번체 기록/소년 예상/연구원의 초안/두 사람의 최종 기록의 작성 주체를 혼동하지 않는다. 사용자에게 항상 ‘나의 해설’이라고 표기하지 않는다.
- 기본 작은 화면 점검: 360×640, 375×640, 375×667, 375×812. 최초 진입, 가장 긴 자료·오답, D 발견 전후, 마지막 선택, 중간 재개, 결과 열람을 모두 검사한다. 44px 터치, safe area, 내부 스크롤·포커스를 보존하고 정답 화살표가 화면을 가로막지 않도록 한다.
- 모든 단계의 정답이 버튼의 고정 위치나 이전 디버깅 암기로만 결정되지 않도록, **누르는 행동을 곧 관찰·근거 연결과 일치**시킨다. 학습 의미를 지우는 무작위 오답 섞기를 필수로 삼지 않는다.

## 11. 중단·재개·완료·백업 — G2 설계 제안

**현재 코드 대비:** 학술탑 meaning-links의 taskIndex·선택·판정 및 03B 중간 장면은 저장할 수 있지만, 전술 저장은 기본적으로 마지막 스테이지 **한 슬롯**이고 학술탑 허브의 미완료 연구 재진입은 playStage로 초기화될 수 있다. 04A는 다른 지역/연구를 거친 뒤에도 독립 재개되어야 하므로, 03B의 장면 구현을 통째로 복제하는 대신 **연구별 저장 경계**를 설계해야 한다.

새 localStorage 키를 늘리는 대신 기존 journey 객체의 선택 필드로 아래 구조를 **제안**한다. 확정 코드 스키마는 G2 검토 종료 뒤 결정한다.

~~~text
journey.sideResearchProgress["academic-tower-turn-04a-er-family"] = {
  revision: 1,
  contentVersion: "er-rain-g2-v0.1",
  currentTaskId: "er-rain-03-side-flow",
  phase: "work | scene | result-pending | complete",
  completedTaskIds: ["er-rain-01-upstream", "er-rain-02-contrast"],
  observedIds: ["a-watermark", "a-grass", "b-gate-log", "c-workshop-flow"],
  draftsByTaskId: { ...허용된 ID/선택 상태만... },
  seenInterludeIds: ["academic-tower-er-scene-retrace"],
  scene: { id: null, beat: 0 },
  lastSourceId: null,
  introVariantId: "met-before | ordinary"
}
journey.stageOutcomes["academic-tower-turn-04a-er-family"] = {
  nextInquiryId: "inquiry-records | inquiry-outlet"
}
~~~

- **중간 저장:** 관측·선택·확인·장면 beat마다 기록. 단계 완료와 다음 장면 열람은 별개로 보존. 종료 후 다시 들어오면 완료한 판을 되풀이하지 않고 가장 최근 의미 있는 작업/안 읽은 장면으로 돌아온다.
- **첫 완료:** 전역 completedStages에는 04A 전역 ID 하나만 추가. 첫 플레이의 inquiry 선택은 기존 stageOutcomes 형태처럼 스칼라 ID로 보존하고, 이후 replay의 선택으로 덮지 않는다. 결과 이야기 미열람이면 ‘결과 읽기’로 재개한다.
- **재플레이:** 별도 연습 스냅샷 사용. 완료했던 다섯 작업과 첫 결과, 본선 상태, 03B 기록, 관찰 카드·아이템을 바꾸지 않는다.
- **이전 저장:** optional sideResearchProgress가 없는 기존 JSON은 정상 복원한다. 새로운 필드의 revision·task ID·phase·배열·길이를 검사하고, 잘못된 백업은 **기존 데이터를 변경하기 전에** 오류를 반환한다. journey 정규화기가 새 필드를 버리지 않도록 하고, save-data.validJourney가 lastLocation=null/world일 때 일찍 return 하더라도 새 필드 검증을 건너뛰지 않게 한다.
- **버전 변경:** 저장한 답안과 단계 ID가 달라질 때 04A만 국소 마이그레이션한다. 완료 기록을 새 내용 추가 때문에 소급 취소하지 않는다. 저장 실패는 계속할 수 있는 현재 세션과 실제 재개 가능 여부를 분명히 구별한다.
- **다른 화면 왕복:** 월드맵/여정/단어장/설정/본선 05를 다녀와 04A 옆방에 다시 들어가도 진행이 유지된다. 미완료인 04A를 ‘다시 연구’로 초기화하지 않는다. 읽던 원문·열린 뜻·포커스는 가능한 범위에서 복원한다.

## 12. G3를 위한 최소 책임·위험 순서 (아직 구현하지 않음)

1. **의미 판정 먼저:** T3의 미공개 단서→D 발견→반대 방향 판정, T4의 근거 있는 정정·한정. 가장 새로운 경험과 오답 처리를 작은 순수 판정으로 검토한다.
2. **흐름 연결:** T1 A → T2 B/C → I1 → T3 → I2 → T4 → T5 → 결과를 하나의 선택 연구로 연결한다. 내부 T들을 STAGES에 넣지 않는다.
3. **저장 계약:** 연구별 progress 정규화·허브 resume·story beat·백업/복원·최초 결과 보존을 검증한다.
4. **표현·읽기:** 새 WORDS 편집층/주음/뜻, 단계별 발견, 문장과 스토리 주음 검사.
5. **회귀와 실제 사용자 검수:** 모바일 작업대/학술탑 본선·03A/03B·05·설정의 기존 행동을 보존한 후 Pages 및 iPhone Safari. G3/G4/G5/G6 각각 별도 상태로 기록한다.

## 14. G2 최종 검토에서만 닫을 사항

- [ ] T1~T5의 번체 원문·한국어 해설·주음·허용 대안을 교정한다. 특히 因而/從而의 중첩, T3 反而, T4 不是……而是…… 및 而已의 자연스러움을 확인한다.
- [ ] T3 도식에서 사용자가 실제로 보는 위치·소리·물결 단서를 **정답 노출 없이** 화면 순서로 그린다. 좌우는 ‘하류를 바라본 왼쪽 벽’이며 화면 좌표와 혼동하지 않는다.
- [ ] 04A 전용 선택 상태 스키마와 save-data/JourneyProgress의 상호작용을 실제 함수 단위로 확정한다. 기존 코드가 이미 지원한다고 표시하지 않는다.
- [ ] T5의 두 유효한 차후 조사 계획과 결과 이야기에서의 표시 문구를 확정한다.
- [ ] 모든 문항의 근거 ID·허용 상태·오답 피드백·완료 판정 목록을 G3 구현자가 추가 발명 없이 구현할 수준으로 정리한다.

**현재 결론:** 사용자 다섯 결정이 반영된 일관된 **G2 상세 검토 초안**은 마련할 수 있다. 그러나 위 윤문·T3 실제 화면·정확한 저장 계약을 닫기 전에는 **G2 통과/구현 준비 완료**로 상태를 올리지 않는다. 여기까지는 **문서 작업만**이며 실행 코드·월드맵·저장 데이터·검증·배포를 변경하지 않는다.

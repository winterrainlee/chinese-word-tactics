# 용사 위험 표정 반응 구현 계획 v0.1

> 작성일: 2026-09-10
> 기준 런타임: v0.5 + 첫 아이콘 SVG 웹 적용본
> 목표 기기: iPhone 13 mini Safari 세로 화면
> 상태: **기획 확정 / 표정 자산·코드 구현 전**

## 1. 한 줄 목표

**위험한 행동을 시도했을 때 용사가 잠깐 `으악!` 표정으로 바뀌어, 실패를 벌이 아니라 살아 있는 반응으로 느끼게 한다.**

이 기능은 귀여운 장식이지만 동시에 위험 행동의 즉각적인 피드백이다. 기존 상태 메시지와 판정은 그대로 유지하고, 표정만 보조 신호로 더한다.

## 2. v0.1에서 먼저 하는 범위

첫 버전은 표정 상태를 두 개만 쓴다.

- `normal`: 현재 기본 용사 표정이다.
- `panic`: 위험 행동을 시도했을 때 약 450ms 동안 보이는 `으악!` 표정이다.

`alert`, `happy`, `relief` 같은 추가 표정은 이번 범위에 넣지 않는다.

### panic이 발생하는 경우

1. 용사를 선택한 뒤 **가시 칸으로 이동을 시도**한다.
2. 이동 또는 기다리기 행동이 **현재/다음 늑대 위험 범위 판정 때문에 거부**된다.

### panic이 발생하지 않는 경우

- 단순히 가시나 늑대 옆에 서 있는 것
- 위험한 칸을 아직 누르지 않은 상태
- 수풀·벽처럼 원래 통과할 수 없는 지형을 누른 경우
- 닫힌 문을 누른 경우
- 한 번에 한 칸보다 먼 위치를 누른 경우
- 살펴보기 모드에서 위험 정보를 확인한 경우
- 일반적인 되돌리기·재시작·화면 이동

닫힌 문이나 벽은 `무섭다`가 아니라 `갈 수 없다`는 정보이므로 공포 표정과 섞지 않는다.

## 3. 왜 미리 긴장 표정을 보여주지 않는가

현재 게임의 핵심은 플레이어가 단어와 판을 보고 직접 해법을 찾는 것이다.

용사가 위험에 가까워지는 것만으로 자동으로 긴장하면, 아직 플레이어가 확인하지 않은 위험을 캐릭터가 먼저 알려주는 힌트가 될 수 있다. 따라서 v0.1은 **위험 행동을 실제로 시도한 뒤에만 반응**한다.

후속 버전에서 `alert`를 추가한다면 자동 감지가 아니라 다음처럼 플레이어가 이미 정보를 확인한 맥락을 우선한다.

- 살펴보기로 늑대 위험 범위를 확인한 뒤
- 위험 경고가 이미 화면에 명시된 뒤
- 특정 장면 연출에서만

## 4. 현재 코드에서 연결할 지점

현재 `src/app.js`의 `attemptMove()`는 위험 행동을 상태 변경 전에 거부한다.

### 가시

`ch === 'X'`이면 위험 메시지를 표시하고 즉시 반환한다.

이 판정은 `history.push(...)`, 용사 위치 변경, `state.turn++`보다 먼저 실행된다.

### 늑대

현재 늑대 위치와 다음 늑대 위치를 확인해 위험 범위에 들어가면 메시지를 표시하고 즉시 반환한다.

이 역시 `history.push(...)`, 용사 위치 변경, 턴 증가보다 먼저 실행된다.

따라서 이 두 거부 지점에서 표정 반응을 호출해도 게임 상태를 수정할 필요가 없다.

## 5. 게임 상태와 분리하는 원칙

표정은 **표현 상태**이지 게임 상태가 아니다.

다음에 저장하지 않는다.

- `state`
- `history`
- localStorage
- 완료 기록
- 학습 기록

표정 때문에 다음 값이 바뀌어서는 안 된다.

- 용사 위치
- 늑대 phase
- turn
- 승리 조건
- 되돌리기 스택

위험 행동이 거부된 뒤 기존과 똑같이 그 자리에 머물고, 기존 메시지를 그대로 보여준다.

## 6. 자산 계획

새 자산 1개를 추가한다.

```text
icons/world/world-hero-panic.svg
```

기본 `world-hero.svg`와 같은 좌표계·몸 크기·망토색·외곽 실루엣을 유지한다.

바꿀 부분은 작은 화면에서도 읽히는 얼굴 요소에 제한한다.

- 눈을 크게 뜬다.
- 입을 작은 열린 모양으로 만든다.
- 눈썹을 올리거나 안쪽으로 모아 놀란 인상을 준다.
- 필요하면 어깨를 아주 조금 올리되, 기본 용사와 다른 캐릭터처럼 보일 정도로 자세를 바꾸지 않는다.

말풍선 `!`, 글자 `으악`, 큰 땀방울 같은 별도 기호는 v0.1에서 넣지 않는다. 먼저 표정 자체가 32~48px에서 읽히는지 확인한다.

## 7. 런타임 구현 구조

현재 아이콘 적용은 `src/icons-runtime.css`와 `src/icons-runtime.js`에 분리되어 있다. 표정 반응도 이 구조를 유지한다.

### `src/app.js`

위험 행동을 거부하는 두 지점에서 표현 훅만 호출한다.

```js
window.flashHeroReaction?.('panic');
```

호출 실패나 아이콘 스크립트 미로딩이 게임 판정에 영향을 주지 않도록 optional chaining을 사용한다.

### `src/icons-runtime.js`

`flashHeroReaction(kind)`가 표현 상태를 관리한다.

권장 동작:

1. 현재 반응 종료 시각을 `performance.now() + 450`으로 갱신한다.
2. 현재 `.hero`에 `data-mood="panic"`을 붙인다.
3. 450ms 뒤 아직 더 최근 반응이 없으면 `data-mood`를 제거한다.
4. 반응 중 `render()`로 용사 DOM이 새로 만들어져도 `sync()`가 남은 반응 시간을 보고 새 `.hero`에 상태를 다시 붙인다.
5. 위험을 여러 번 연속 누르면 타이머를 겹쳐 쌓지 않고 마지막 시도 기준으로 450ms를 다시 센다.

### `src/icons-runtime.css`

기본 용사 자산은 그대로 두고 상태만 덮어쓴다.

```css
.hero[data-mood="panic"] {
  background-image: url("../icons/world/world-hero-panic.svg");
}
```

v0.1에서는 흔들기·점프 같은 이동 애니메이션을 추가하지 않는다. 표정 교체만으로 먼저 효과를 확인한다.

## 8. 피드백 우선순위

위험 행동 하나에 다음 세 층이 동시에 작동한다.

1. **판정:** 행동을 거부한다.
2. **문구:** 기존 위험 메시지를 보여준다.
3. **캐릭터:** 용사가 잠깐 `panic` 표정을 짓는다.

표정만 보고 위험의 정확한 이유를 알아야 하는 구조로 만들지 않는다. 색각·시력·작은 화면 문제로 표정 변화를 놓쳐도 기존 게임 정보는 모두 남아야 한다.

## 9. 동작 줄이기와 접근성

v0.1은 정적인 SVG 교체이므로 `prefers-reduced-motion`에서도 같은 표정을 보여줄 수 있다.

후속으로 흔들기나 튀기기 같은 움직임을 추가한다면 `prefers-reduced-motion: reduce`에서는 해당 움직임을 제거하고 표정 교체만 남긴다.

표정 자산은 장식적인 보조 피드백이므로 별도 음성 이름을 추가하지 않는다. 기존 상태 메시지와 칸의 접근성 설명을 유지한다.

## 10. 검수 시나리오

### Stage 4 — 가시

- [ ] 용사를 선택하고 인접 가시 칸을 누르면 `panic` 표정이 즉시 보인다.
- [ ] 약 450ms 뒤 기본 표정으로 돌아온다.
- [ ] 용사는 이동하지 않는다.
- [ ] turn과 history가 증가하지 않는다.
- [ ] 기존 `這裡有危險。` 메시지가 그대로 나온다.

### Stage 2 / Stage 5 — 늑대

- [ ] 늑대의 현재 위험 범위로 들어가려 하면 `panic`이 나온다.
- [ ] 늑대의 다음 위치 때문에 위험해지는 행동도 기존 판정대로 거부되고 `panic`이 나온다.
- [ ] `1턴 기다리기`가 다음 늑대 위치 때문에 거부되는 경우에도 `panic`이 나온다.
- [ ] 용사 위치, 늑대 phase, turn, history가 바뀌지 않는다.

### 비위험 거부

- [ ] 벽·수풀을 눌러도 `panic`이 나오지 않는다.
- [ ] 닫힌 문을 눌러도 `panic`이 나오지 않는다.
- [ ] 먼 칸을 눌러도 `panic`이 나오지 않는다.

### 연속 입력

- [ ] 위험 칸을 연속해서 누르면 표정 타이머가 마지막 입력 기준으로 자연스럽게 연장된다.
- [ ] 오래된 타이머가 새 반응을 중간에 끊지 않는다.

### 화면·기기

- [ ] 32~48px 실제 게임 크기에서 기본/으악 표정 차이가 읽힌다.
- [ ] 용사가 출구·유적 위에 있을 때도 배경 지형을 가리지 않는다.
- [ ] iPhone 13 mini Safari에서 SVG가 정상 표시된다.
- [ ] 기존 튜토리얼 6판의 이동·기다리기·살펴보기·되돌리기·완료 흐름이 그대로 동작한다.

## 11. 완료 조건

v0.1은 다음을 모두 만족하면 완료다.

1. `world-hero-panic.svg`가 기본 용사와 동일 캐릭터로 읽힌다.
2. 가시·늑대 위험 행동 거부에서만 표정이 발동한다.
3. 표정 지속 시간은 약 450ms이며 반복 입력에서도 안정적이다.
4. 게임 상태·저장·턴·되돌리기에 변화가 없다.
5. 기존 위험 메시지가 그대로 유지된다.
6. GitHub Pages 배포가 통과한다.
7. iPhone 13 mini Safari 실기기에서 표정과 기존 플레이 흐름을 확인한다.

## 12. 후속 확장 후보

v0.1이 자연스럽게 느껴질 때만 확장한다.

- `alert`: 플레이어가 이미 위험 정보를 확인한 뒤의 긴장 표정
- `surprise`: 석비가 처음 반응했을 때 놀라는 표정
- `relief`: 늑대 위험을 벗어났을 때 짧은 안도 표정
- `happy`: 스테이지 완료 순간의 작은 웃음

표정이 많아져서 학습 단어와 판보다 캐릭터가 더 시선을 끌기 시작하면 추가하지 않는다.

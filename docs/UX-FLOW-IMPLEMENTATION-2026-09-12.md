작성일: 2026-09-12  
상태: **구현·자동검사·모바일 Chromium 검수 완료 / iPhone 13 mini Safari 최종 실기기 검수 전**  
기준 문서:

- `DESIGN-PRINCIPLES-v0.1.md`

- `UX-AUTOMATED-REVIEW-BASELINE-2026-09-12.md`

이번 변경은 전술판 자체의 기믹이나 승리 조건을 바꾸지 않고, **플레이 현장 주변의 정보 위계와 스테이지 사이 이동 흐름**을 정리했다.

핵심 원칙은 다음과 같다.

> **목표는 이번 판의 의도, 판은 현재 상태, 상태 메시지는 직전 행동의 의미를 맡는다. 성공 뒤에는 판을 자동으로 덮지 않고 플레이어가 직접 다음 이야기로 넘어간다.**

## 1. 상시 목표 영역

기존 `goalbox`는 큰 카드·18px 굵은 글씨·보조 규칙 문장까지 항상 차지했다. 플레이 시작 전에는 유용했지만, 행동을 시작한 뒤에도 판과 상태 메시지보다 강하게 보였다.

현재는 `src/ux-play.css`와 `src/ux-play-runtime.js`에서 다음처럼 정리한다.

- 목표 영역 최소 높이: `52px`
- 목표 글자: `16px`
- 카드 그림자 제거
- `ruleline`은 상시 숨김
- 우측 `뜻` 버튼: `44×44px`
- `뜻`을 누르면 원래 `stage.goal`과 `stage.rule`을 시트에서 다시 확인
- 상세 확인은 턴·판 상태·선택 결과를 바꾸지 않음

원본 목표와 규칙 데이터는 삭제하지 않았다. 상시 화면에서만 압축하고, 필요하면 전체 문장을 다시 읽을 수 있다.

### M8 짧은 상시 목표

장터 M8은 기존 목표가 특히 길어 별도의 짧은 상시 문구를 둔다.

```text
開市以前，補齊各處需要的東西。
```

전체 목표와 규칙은 `뜻`에서 그대로 확인할 수 있다.

## 2. 상태 메시지와 플레이 현장의 관계

상태 메시지는 `14px`의 가벼운 반투명 영역에서 다음처럼 조정했다.

- 기본 글자: `15px`
- 최소 높이: `48px`
- `info / good / bad`에 배경과 테두리를 함께 사용
- `role="status"`, `aria-live="polite"`

의도는 메시지를 목표보다 더 크게 만드는 것이 아니라, **행동 직후 판 아래에서 바로 읽히는 피드백**으로 만드는 것이다.

자동 브라우저 검수에서는 G1의 행동 전후 상태 문구가 실제로 바뀌고, 판과 메시지가 같은 화면 흐름 안에 남는지 확인한다.

## 3. 장터 대상 패널 재배치

기존 장터는 다음 순서였다.

```text
격자
대상 상황 패널
공통 상태 메시지
단어
조작
```

따라서 플레이어가 판에서 행동한 뒤 결과 문구를 보려면 대상 정보 패널을 지나야 했다.

현재는 `ux-play-runtime.js`가 장터 렌더 뒤 `.market-panel`을 공통 `#contextPanel`로 옮겨 다음 순서가 된다.

```text
격자
상태 메시지
대상 상황 패널
단어
조작
```

역할은 다음처럼 분리된다.

- 격자: 현재 장소·인물·수량 상태
- 상태 메시지: 방금 행동의 결과
- 대상 상황 패널: 현재 살펴보는 대상의 상세 정보와 가능한 행동

대상을 선택하지 않은 첫 화면에서는 상황 패널을 소지품 중심의 약 `42px` 요약으로 줄인다.

### 선택 후 상세 패널 압축

M8에서 `늦게 온 짐`처럼 자원이 여러 종류 있는 대상은 정보가 많다. 초기 재배치만 했을 때 이 패널은 약 `365.8px`까지 커져 문서가 `137px` 스크롤됐다.

그래서 각 자원 행을 다음처럼 두 열로 다시 정렬했다.

```text
[분류]  [중국어 품목 ×수량]
        [한국어 설명]
```

정보를 삭제하지 않고 같은 항목을 한 행 안에 묶었다.

최종 자동 측정:

| M8 선택 대상 | 상세 패널 높이 | 812px 초과 |
|---|---:|---:|
| 빵집 | 약 `215.8px` | `0px` |
| 밧줄 좌판 | 약 `165.8px` | `0px` |
| 장터 천막 | 약 `215.8px` | `0px` |
| 채소 좌판 | 약 `207.8px` | `0px` |
| **늦게 온 짐** | 약 `265.8px` | **`38px`** |
| 여관 | 약 `215.8px` | `0px` |
| 등잔기름 좌판 | 약 `215.8px` | `0px` |

`늦게 온 짐`만 내용량 때문에 작은 세로 스크롤이 남는다. 첫 화면이나 일반 대상에는 스크롤이 없고, 가로 넘침·44px 미만 터치 대상도 없다.

이 `38px`는 자동검사에서 허용하되 **iPhone 13 mini Safari에서 실제 손가락 조작 시 불편하지 않은지 최종 확인한다.** 한 화면 고정을 위해 글자나 격자를 더 줄이지는 않았다.

## 5. 완료 경험

기존 구조는 승리 뒤 완료 시트를 자동으로 띄웠다.

- 기본 전술: 약 `120ms`
- 장터·장인골 일부: 약 `420ms`

따라서 최종 판 변화와 성공 메시지를 읽기도 전에 모달이 판을 덮을 수 있었다.

현재는 기존 타이머가 실행되더라도 `GameFlow.showStageComplete`를 UX 층에서 바꾸어 **모달을 열지 않는다.**

완료 뒤 화면은 다음처럼 유지된다.

```text
완료된 최종 판
성공 상태 메시지
✓ 스테이지 완료     [후일담 보기 / 다음 판 시작 / ...]
핵심 단어
```

완료 뒤에는 일반 조작 버튼을 숨기고 최종 판을 읽기 전용으로 남긴다. 플레이어가 진행 버튼을 눌러야 다음 콘텐츠가 열린다.

재플레이 완료도 같은 인라인 구조를 사용하되, 본편 위치는 바꾸지 않고 호출한 `월드맵 / 여정`으로 돌아간다.

## 6. 완료 직후 새로고침

`chinese-word-tactics-pending-completion-v1`을 추가했다.

목적은 새로운 진행 데이터를 늘리는 것이 아니라 **완료했지만 아직 플레이어가 다음 장면을 선택하지 않은 순간**을 보존하는 것이다.

동작:

1. 첫 본편 스테이지 완료
2. 최종 판과 완료 바 표시
3. 아직 `다음`을 누르지 않은 상태에서 새로고침
4. 저장된 최종 판으로 복귀
5. 완료 바와 성공 피드백 복원
6. 플레이어가 `다음 판 시작 / 후일담 보기`를 누르면 pending 기록 삭제

브라우저 자동검사에서는 실제로 `stage-0`을 격자 클릭으로 완료하고, 새로고침한 뒤 다시 `stage-0` 완료 화면으로 돌아온 다음 `stage-1`으로 직접 넘어가는 경로를 확인한다.

여정 전체 초기화 시 이 pending 키도 함께 삭제한다.

## 7. 같은 구역의 연속 진행

이전 데이터에는 길목·장인골·장터의 중간 후일담에도 `returnToWorldAfter: true`가 여러 번 들어 있었다.

따라서 같은 구역에서 다음 일이 바로 있어도 다음처럼 움직일 수 있었다.

```text
후일담
→ 월드맵
→ 같은 구역 다시 선택
→ 다음 도입
```

`src/continuous-region-flow.js`에서 실제 모든 journey 확장 파일이 로드된 뒤 각 구역을 정규화한다.

원칙:

- 같은 구역의 중간 story: `returnToWorldAfter = false`
- 그 구역의 마지막 story만: `returnToWorldAfter = true`

현재 자동검사에서 다음 세 구역 모두 이 조건을 확인한다.

- `gate-town`
- `workshop-town`
- `market-town`

그래서 기본 본편은 한 구역을 선택하면 그 구역의 사건을 계속 이어갈 수 있고, 구역 최종 후일담에서만 월드맵으로 돌아간다.

재독·재플레이 메뉴 구조는 그대로 유지한다.

## 8. 이야기 연결부 반복 감사

`tools/story-handoff-audit.cjs`를 추가했다.

실제 여정에서 인접하는 다음 세 종류를 자동 수집한다.

- `완료 피드백 → 후일담`
- `후일담/이야기 → 다음 이야기`
- `도입 이야기 → 스테이지 목표·초기 안내`

M5·M6 선택 후일담과 G7 경로별 후일담도 별도 variant로 검사한다.

중국어와 한국어를 각각 문자 bigram Dice 유사도로 비교하며, 자동 실패 기준으로 쓰지 않는다. 반복이 학습·인물 반응에 필요할 수 있기 때문이다.

최종 CI 기준:

- 인접 연결부 `71개` 검사
- `0.34` 이상 REVIEW 후보 `9개`

주요 후보:

- `gate-stage-6 → gate-after-leading`
- `gate-stage-7 → gate-after-convoy` 및 경로별 변형
- `gate-stage-5 → gate-after-narrow-gate`
- `gate-stage-2 → gate-after-bell`
- `workshop-w4-setup → workshop-stage-4`
- `workshop-before-core → workshop-stage-7`

이는 오류 목록이 아니라 **최종 시나리오 윤문 때 우선 읽어볼 목록**이다. 특히 현재 인라인 완료 UI는 예전 `stage.story`를 별도 완료 시트로 표시하지 않으므로, 높은 유사도 자체가 실제 사용자 중복을 뜻하지는 않는다.

## 10. 남은 실기기 확인

자동검사로 닫지 않는 항목은 다음과 같다.

1. iPhone 13 mini Safari에서 52px 목표줄이 실제로 읽기 편한지 확인한다.
2. 행동 직후 15px 상태 메시지가 손가락 시선 이동 안에서 충분히 눈에 들어오는지 확인한다.
3. M8 `늦게 온 짐` 선택 시 남는 약 38px 세로 스크롤이 불편하지 않은지 확인한다.
4. 완료 순간 마지막 판 변화가 충분히 보이고, 새 인라인 진행 버튼을 실수로 연속 탭하지 않는지 확인한다.
5. 완료 직후 Safari 새로고침·앱 전환 뒤에도 최종 판과 완료 상태가 자연스럽게 복원되는지 확인한다.
6. 길목·장인골·장터를 연속해서 플레이할 때 중간 월드맵 왕복이 사라진 것이 실제 게임 리듬에 더 자연스러운지 확인한다.
7. REVIEW 후보 9개의 이야기 연결을 최종 전체 윤문에서 사람이 읽고, 의도 없는 반복만 줄인다.

이 실기기 검수에서 큰 문제가 없다면 이번 UX 묶음은 `✅`로 닫을 수 있다.

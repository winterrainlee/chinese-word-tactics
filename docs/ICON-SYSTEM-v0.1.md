# 아이콘 시스템 v0.1

> 작성일: 2026-09-10
> 기준: v0.5 월드맵의 현재 코드와 [디자인 원칙 v0.1](DESIGN-PRINCIPLES-v0.1.md)
> 적용 범위: 전술판 오브젝트, 조작 아이콘, 상태 표식, 월드맵 지역 표식이다.
> 현재 상태: 코드 대조와 목록화를 마쳤다. 추천 형태·세부 수치는 첫 시안용 제안이며, SVG 제작·런타임 교체·실기기 검수는 아직 하지 않았다.

## 1. 한 줄 방향

**조작은 조용하게, 사물은 또렷하게, 상태는 구분되게 표현한다.**

아이콘은 단어를 대신하지 않는다. 단어를 이해한 플레이어가 판을 읽고 자기 해법을 찾도록 돕는다.

[디자인 원칙의 아이콘·일러스트 원칙](DESIGN-PRINCIPLES-v0.1.md#15-아이콘과-일러스트-원칙)을 구체화하는 하위 문서다. 최종 그림체나 색상 값을 확정한 문서는 아니다. 기존 문서 §20의 후반 아트 작업 중 목록화와 첫 시안 준비만 앞당긴다. 전체 화면 개편이나 게임 규칙 변경을 함께 시행하지 않는다.

## 2. 확인한 코드와 자료의 경계

이 문서의 ‘현재 표현’은 다음 파일을 직접 대조한 결과다. ‘추천 형태’와 ‘제안’은 이번 디자인 작업에서 새로 정리한 내용이다. 실제 화면을 렌더하거나 iPhone에서 검수한 결과로 해석하지 않는다.

| 출처 | 확인한 내용 |
|---|---|
| [`index.html`](../index.html) | 메뉴·재시작·뒤로가기 기호, 텍스트 조작 버튼, 장식용 나침반 표식이 있다. |
| [`src/app.js`](../src/app.js) | `render()`의 용사·늑대·이동 화살표, `showComplete()`의 완료 표식, `showMenu()`의 지도 이모지, `renderWorld()`의 지역 상태와 방문 표시를 확인했다. |
| [`src/styles.css`](../src/styles.css) | 석비·문·유적·가시의 CSS 도형과 글자, 이동·조사·활성·완료 상태 스타일이 있다. |
| [`src/view.css`](../src/view.css) | 지역 상태를 CSS `::after` 문구로 다시 표시한다. 교체 시 JavaScript의 표식만 바꾸면 이모지·문구가 남을 수 있다. |
| [`src/content.js`](../src/content.js) | 실제 목표어와 주음, 지역 이름, 권장 경로와 잠금 조건을 확인했다. |
| [디자인 원칙 v0.1](DESIGN-PRINCIPLES-v0.1.md) | 세계와 UI 분리, 색 역할, 단어 우선, 최소 터치 영역, 실기기 검수 원칙을 따른다. |

아이콘을 바꾸면서 원래의 목표어·주음·예문·판정 규칙을 수정하지 않는다. `WORDS`의 `p` 필드는 현재 주음 문자열이며, CSS 이름이 `.pinyin`이라는 이유로 병음 데이터로 바꾸지 않는다.

## 3. 세 가지 계열

| 계열 | 역할과 표현 방향 | 피할 표현 |
|---|---|---|
| UI | 메뉴·이동·조작을 안내한다. 일정한 굵기의 단순한 선과 작은 면으로 표현한다. | 큰 색 배경, 개별 아이콘의 과도한 장식, 같은 역할에서 섞이는 선 굵기를 피한다. |
| 세계 | 용사·늑대·지형·장소를 나타낸다. 작은 크기에서 실루엣이 다른 면 중심 그림을 쓴다. | 모든 물체를 둥근 버튼이나 앱 아이콘 상자에 넣지 않는다. |
| 상태 | 선택·이동 가능·위험·완료 등을 알린다. 기존 사물 위에 작은 기호·범위·패턴으로 겹친다. | 사물을 덮는 큰 배지나 색만 다른 상태를 피한다. |

‘스타일을 통일한다’는 것은 세 계열을 똑같이 그린다는 뜻이 아니다. 계열 안에서는 도형과 굵기를 통일하고, 계열 사이에서는 색·크기·시각적 무게를 맞춘다.

중국어 지명·목표 문장·핵심 단어는 텍스트로 유지한다. `碑 / 門 / 開 / 遺`처럼 사물 그림을 대신하던 임시 문자는 그림으로 교체할 수 있지만, 학습할 한자와 필요한 라벨까지 제거하지 않는다.

## 4. 필수 목록: 전술판의 사물

P0는 첫 비교 시안에 포함할 기본형이고, P1은 후속 묶음이다. 아래 ID는 제작 시 사용할 이름의 제안이며 현재 존재하는 파일명이 아니다.

| 우선 | 제안 ID | 대상 / 현재 표현 | 전달해야 할 의미 | 추천 형태와 주의점 |
|---|---|---|---|---|
| P0 | `world-hero` | 용사는 `🧑‍🎒`로 표시한다. | 내가 조작하는 인물이다. | 작은 머리와 망토 몸통으로 된 사람 토큰을 쓴다. 칼·갑옷·직업 장비를 추가하지 않는다. |
| P0 | `world-wolf` | 늑대는 `🐺`로 표시한다. | 위험의 원인이며 순찰할 수 있는 동물이다. | 두 귀와 긴 주둥이가 구분되는 늑대 머리 실루엣을 쓴다. 바라보는 방향이 공격 방향이라는 오해를 주지 않는다. |
| P0 | `world-exit` | 출구는 바닥색과 `出口` 글자로 표시한다. | 도착해야 하는 목적지다. | 도착 깃발과 작은 바닥 표식을 쓴다. 일반 문과 구분하고 `出口` 라벨을 유지한다. 단순히 도착했다고 모든 조건이 완료된 것처럼 표시하지 않는다. |
| P0 | `world-stele` | 석비는 직사각형 도형과 `碑` 글자로 표시한다. | 접근하면 반응하는, 올라갈 수 없는 물체다. | 세로로 긴 돌과 적은 각인 선을 쓴다. 반응 전후에도 같은 돌로 보이며 활성 상태는 별도 표식으로 얹는다. |
| P0 | `world-gate` | 문은 `門 / 開`와 바닥색으로 상태를 바꾼다. | 닫히면 막히고 열리면 통행할 수 있다. | 두 기둥과 문짝을 기본형으로 쓴다. 닫힘은 가로막힌 문짝, 열림은 비어 있는 중앙으로 구분한다. 색만 바꾸지 않는다. |
| P0 | `world-ruin` | 유적은 `遺` 글자가 놓인 연속 타일이다. | 한쪽 입구에서 들어가 다른 입구로 나오는 통로다. | 부서진 낮은 기둥과 이어진 바닥 흔적을 쓴다. 각 칸을 독립 건물처럼 그리지 않고 연결된 영역을 보여준다. |
| P0 | `world-thorns` | 가시는 회전한 `✦` 기호로 표시한다. | 들어가는 행동이 확정되지 않는 위험한 바닥이다. | 뾰족한 가시 3개와 낮은 바닥선을 쓴다. 반짝임·보상·마법 효과처럼 보이지 않게 한다. |
| P1 | `world-bush` | 수풀은 CSS로 겹친 둥근 면이다. | 통과할 수 없는 지형이다. | 이어진 수풀 덩어리로 정리한다. 상태 표식의 강한 녹색을 장식색으로 재사용하지 않는다. |

`world-gate`의 열림·닫힘은 한 계열의 상태 변형이다. `world-stele` 활성화와 유적 통과 흔적도 기본 사물과 상태 표현을 나누어 관리한다.

## 6. 필수 목록: 상태 표식

범위 표현은 모든 칸에 같은 작은 그림을 찍기보다 면·외곽선·패턴으로 처리한다. 상태 중복을 지우거나 서로 덮어쓰지 않는다.

| 우선 | 제안 ID / 상태 | 현재 표현 | 추천 형태와 의미 |
|---|---|---|---|
| P0 | `status-move` / 한 칸 이동 가능 | `↑ ↓ ← →`와 녹색 안쪽 테두리다. | 한 방향 화살표 기본형을 회전해 사용한다. 선택한 용사가 이번 행동에 이동할 수 있는 인접 칸만 표시한다. 정답 경로를 잇는 선은 그리지 않는다. |
| P1 | `status-selected` / 선택 중 | `selected` 상태가 이동 표시를 제어하며 용사 전용 선택 표식은 없다. | 용사 바닥에 짧은 모서리 표시를 둔다. 사각형 전체를 채우거나 용사를 가리지 않는다. |

| P1 | `status-locked` / 진입 조건 미충족 | `🔒 잠김`, 낮은 불투명도, 비활성 버튼을 쓴다. | 닫힌 자물쇠와 `잠김`을 쓴다. 잠금 이유는 별도 문구나 설명 경로에서 확인 가능해야 한다. 그 경로는 아이콘 교체만으로 구현됐다고 보지 않는다. |
| P1 | `status-disabled` / 해당 조작 사용 불가 | 되돌릴 기록이 없을 때 버튼이 비활성화된다. | 글자와 기호를 중성색으로 낮춘다. 자물쇠를 쓰지 않는다. 조작 불가와 지역 잠금은 다른 상태다. |

판정 정보는 `acceptedMove()`·`wolfPos()`·`nextPhase()` 등 실제 런타임 상태에서 가져온다. 문서용 거리 계산이나 이미지 색만 보고 새로운 판정을 만들지 않는다. 현재 구현에서는 현재와 다음 늑대 위치가 이동 가능 판정에 모두 관여한다. 이동 표식이 있다고 이후 모든 턴까지 안전하다는 뜻은 아니다.

## 7. 월드맵 지역 표식: 후속 묶음

현재 지역별 고유 그림은 없다. 지역 이름·부제·상태와 연결선으로 표현한다. 아래는 모두 새 그림의 후보이며, 지역 이름은 반드시 텍스트로 남긴다.

| 제안 ID | 장소 | 추천 실루엣 | 혼동을 줄이는 기준 |
|---|---|---|---|
| `region-origin` | 出發 | 낮은 집 지붕과 바깥으로 이어진 길을 쓴다. | 출발 장소를 나타내며 판의 도착 깃발과 다르게 만든다. |
| `region-gate-town` | 關口鎮 | 두 탑 사이의 관문을 쓴다. | 전술판의 단일 문보다 장소 규모가 느껴지되 세부 벽돌은 생략한다. |
| `region-workshop-town` | 工坊村 | 작은 지붕과 높은 굴뚝을 쓴다. | 설정에 쓰는 톱니바퀴 아이콘처럼 만들지 않는다. |
| `region-market-town` | 市集鎮 | 넓은 천막 지붕과 낮은 판매대를 쓴다. | 선 몇 개의 천막 주름만 남겨 작은 크기에서 읽히게 한다. |
| `region-border-village` | 邊境村 | 낮은 울타리와 높은 경계 기둥을 쓴다. | 강한 위험색으로 지역 전체를 칠하지 않는다. |
| `region-council-town` | 議會鎮 | 넓고 낮은 지붕 아래 회당 기둥을 쓴다. | 세로로 긴 연구 탑과 가로 실루엣을 구분한다. |
| `region-research-city` | 研究城 | 세로로 긴 탑과 관측 고리 하나를 쓴다. | 관측 고리는 장소의 그림이며 목표 반응용 반짝임을 장식으로 쓰지 않는다. |

방문·권장·잠김은 지역 건물 그림에 새겨 넣지 않고 별도 상태 층으로 얹는다. 지역 지점의 작은 그림과 실제 누를 수 있는 영역은 분리하며, 누르는 영역은 최소 44×44 CSS px로 확보한다.

장식용 `⌖`는 UI 정리에 따라 제거할 수 있다. 튜토리얼 완료의 `🌄`는 이야기 삽화 후보이지 필수 조작 아이콘이 아니다. 현재 기호가 있다는 이유만으로 모든 장식을 새 자산으로 제작하지 않는다.

## 8. 공통 제작 규칙: 첫 시안용 제안

### 형태와 크기

| 항목 | 제안 기준 |
|---|---|
| UI 기본 좌표 | `viewBox="0 0 24 24"`를 사용한다. 기본 표시 크기는 20 CSS px, 선 굵기는 2 좌표 단위로 시작하며 끝과 연결부를 약하게 둥글린다. |
| 전술 사물 | `32×32` 좌표계에서 면 중심으로 그린다. 칸 너비의 약 60~70%를 후보로 삼고, 가장 작은 칸에서 먼저 검토한다. 이는 색 면의 점유율이 아니라 그림의 외곽 크기다. |
| 지역 표식 | 우선 24 CSS px로 비교한다. 세부가 사라지면 그림을 단순화한 뒤 크기 조정을 검토한다. |
| 작은 상태 배지 | 12~16 CSS px를 후보로 둔다. 이동 화살표와 위험 범위는 이 크기 제한에 묶지 않는다. |
| 터치 영역 | 조작 버튼과 누를 수 있는 지역 지점은 최소 44×44 CSS px다. 아이콘 그림 자체를 44px로 키우라는 뜻은 아니다. |
| 라벨 | 주요 행동에는 문구를 유지한다. 긴 중국어·한국어를 그림이나 작은 고정 폭 안에 억지로 넣지 않는다. |

이 값은 이 프로젝트의 시안 시작점이며 외부 표준의 준수 인증이나 실기기 통과 수치가 아니다.

### 색과 의미

[디자인 원칙의 색 역할](DESIGN-PRINCIPLES-v0.1.md#7-색의-의미를-고정한다)을 따른다. 최종 hex 값은 아직 확정하지 않는다.

- 기본 먹색·돌색은 일반 UI와 사물을 나타낸다.
- 녹색 강조는 실행 가능·선택 가능 상태를 나타낸다. 안전·완료·활성 전부를 녹색 하나로 묶지 않는다.
- 적갈색은 위험과 손실 관련 정보에 쓴다.
- 금색은 목표와 단어 반응에 쓴다. 석비 활성화는 이 역할에 속한다.
- 청색은 정보 확인과 조사 상태에 쓴다.
- 낮은 채도의 중성색은 비활성에 쓰되 글자와 잠금 이유가 읽히지 않을 만큼 흐리게 하지 않는다.

모든 중요한 상태에는 색 이외의 형태·문구·패턴을 함께 사용한다. 흑백으로 봐도 출구/문, 열린 문/닫힌 문, 방문/완료, 현재/다음 위험을 구분할 수 있어야 한다.

### 배치와 겹침

아래에서 위로 `바닥 → 범위 표시 → 사물·인물 → 작은 상태 표식` 순서를 시작점으로 삼는다. 선택·키보드 포커스 경계는 별도로 구분한다. 이 순서로 위험이 가려지면 범위 경계나 모서리 표시를 추가해 정보를 보존한다.

용사가 출구나 유적 위에 있을 때도 바닥의 목적지·영역 정체를 읽을 수 있어야 한다. 큰 도장·광채·배지로 인물, 입구, 위험 경계를 덮지 않는다. 이동 가능과 목표 상태처럼 동시에 성립하는 정보는 함께 남긴다.

### 의미와 접근성

아이콘이 붙은 버튼은 기존 클릭 범위와 접근성 이름을 유지한다. 문구 옆 장식 SVG는 보조기술이 같은 정보를 반복해서 읽지 않게 한다. 아이콘만 있는 버튼에는 동작을 설명하는 이름을 붙인다. `살펴보기`의 상태와 복귀 동작도 문구·접근성 상태에서 확인 가능해야 한다.

닫기 아이콘을 바꾸면서 시트의 포커스 이동·닫기·원래 버튼으로 복귀하는 동작을 별도 검수한다. 현재 구현이 이 접근성 항목을 모두 충족한다고 가정하지 않는다.

`接近` 전용 자석, `避開` 전용 우회 화살표처럼 단어마다 정답을 대신하는 고정 그림을 만들지 않는다. 동시에 학습을 어렵게 만들겠다는 이유로 위험·이동 가능·장치 규칙 같은 필요한 정보를 숨기지도 않는다.

## 9. 제작·구현 방식

SVG를 우선 후보로 삼는다. 저장소 안에 두고 프레임워크·아이콘폰트·CDN 의존성을 새로 만들지 않는 방향이다.

향후 자산 배치 제안은 다음과 같다. 이번 문서 변경에서 폴더나 그림 파일을 만들었다는 뜻은 아니다.

```text
icons/
  ui/
  world/
    regions/
  status/
```

일반 UI SVG는 `currentColor`로 색을 받는 방향으로 작성한다. 사물 기본형과 상태 표현을 분리하고, 실제 학습 단어·지명·버튼 이름은 HTML 텍스트로 둔다. 같은 기본형을 상태마다 무관한 그림으로 복제하지 않는다. SVG 안의 임의 스크립트·외부 리소스·중복 ID는 허용하지 않는다.

개별 SVG를 런타임에서 사용하는 방식과 심벌 스프라이트로 묶는 방식 중 어느 것을 택할지는 실제 교체 단계에서 정한다. 외부 자산을 채택하게 되면 출처와 라이선스를 먼저 기록한다. 이 문서는 외부 아이콘 세트나 폰트를 채택하지 않았다.

CSS `content`로 들어간 `碑 / 門 / 開 / 遺 / ✦`와 `src/view.css`의 지역 상태를 함께 점검한다. 새 그림과 옛 기호가 동시에 보이지 않도록 하고, 의미 있는 상태 문구는 DOM에서 한 번만 관리하는 방향으로 정리한다.

`legacy/tutorial-v03.html`, 스테이지 데이터, 진행 저장 키와 승리 판정은 아이콘 교체 때문에 변경하지 않는다.

## 10. 첫 제작 묶음과 순서

첫 비교 시안은 아래 **기본형 15종**으로 제한한다.

- 세계 7종은 용사·늑대·출구·석비·문·유적·가시다.
- UI 7종은 메뉴·뒤로·다시 시작·되돌리기·1턴 기다리기·살펴보기·닫기다.
- 상태 1종은 인접 칸 이동 화살표다.

15종은 파일 개수가 아니라 기본형의 개수다. 문 열림/닫힘, 화살표 4방향 등 상태·방향 변형은 별도로 비교한다. 석비 활성 상태와 유적 통과 흔적도 함께 확인하되 새로운 기본형 수에 섞지 않는다.

진행 순서는 다음과 같다.

1. 먼저 15종과 필요한 변형을 같은 판에 배치한 비교 시안을 만든다. 형태 후보는 제안 상태로 남긴다.
2. 용사/늑대, 출구/문, 재시작/되돌리기를 색 없이 비교하고 실제 표시 크기에서 고른다.
3. 현재 UI의 위치와 게임 규칙을 유지한 채 첫 묶음만 교체한다. 아이콘 변경과 레이아웃 전면 개편을 한 번에 섞지 않는다.
4. 튜토리얼과 단어 시트를 회귀 검수한다. 이후 상태 표식·위험 예고와 월드맵 지역 그림을 후속 묶음으로 진행한다.

위험 범위 오버레이, 다음 위치 예고, 잠긴 지역의 설명 경로는 별도 구현·검수 항목이다. 아이콘 파일을 만들었다고 이 기능들을 완료로 기록하지 않는다.

## 11. 검수 기준

현재는 아래 항목을 실행하지 않았다. SVG 제작과 화면 적용 후 각각 확인한다.

- [ ] 실제 크기와 흑백에서도 용사/늑대, 출구/문, 열린 문/닫힌 문이 구분된다.
- [ ] 재시작/되돌리기/화면 돌아가기를 서로 다른 동작으로 이해할 수 있다.
- [ ] `1턴 기다리기`가 실시간 대기나 일시정지로 보이지 않는다.
- [ ] 단어·주음·중국어 라벨이 아이콘으로 대체되거나 가려지지 않는다.
- [ ] 용사가 출구·유적을 점유해도 지형과 상태를 읽을 수 있다.
- [ ] 이동 표시는 기존 엔진 판정과 일치하고 정답 경로를 제시하지 않는다.
- [ ] 지역의 정보 확인/방문과 지역 의뢰 완료를 혼동하지 않는다.
- [ ] 권장 지역에 들어갈 수 있으며 잠금 지역에는 조건이 설명된다. 후속 기능이 필요한 항목은 미구현으로 남긴다.
- [ ] 모든 대상 버튼의 터치 영역, 이름, 포커스 표시와 시트 열기/닫기를 확인한다.
- [ ] 동작 줄이기 환경에서 활성·완료 의미가 정적 형태로 남는다.
- [ ] GitHub Pages의 `/chinese-word-tactics/` 하위 경로에서 자산을 읽는다.
- [ ] 실제 iPhone 13 mini Safari 세로 화면에서 전체 판, 긴 목표 문장, 단어 5개가 있는 마지막 튜토리얼을 확인한다.

코드 대조, 시안 검토, 런타임 구현, 실기기 통과를 서로 다른 상태로 기록한다. 이번 작업은 **아이콘 목록과 시안 제작 규칙의 문서화**까지다.

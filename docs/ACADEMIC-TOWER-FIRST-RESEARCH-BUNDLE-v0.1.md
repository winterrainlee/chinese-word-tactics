# 학술탑 첫 연구 묶음 `방향이 바뀌는 문장` v0.1

> 상태: `🟨` 구현 가능한 사양 확정 / 런타임 미구현
> 작성일: 2026-09-25
> 적용 범위: 학술탑 첫 입장, 독해 작업대 공통 조작, 첫 연구 묶음 5개 방

## 1. 결정

학술탑의 첫 연구 묶음은 `卻 → 然而`의 **대조·중심 이동**과 `果然／竟然`의 **예상 확인·이탈**을 따로 익힌 뒤 `反而`의 **방향 반전**에서 합친다.

```text
01 卻
├─> 02 然而 ─────────┐
└─> 03 果然／竟然 ───┴─> 04 反而 ─> 05 종합
```

이 순서를 택한 이유는 다음과 같다.

- `然而`와 `反而`를 한국어의 비슷한 역접 표현으로 한꺼번에 외우지 않는다.
- `然而`는 앞 내용과 뒤 내용을 **대조하면서 중심을 뒤로 옮기는 표지**, `反而`는 예상한 결과와 실제 결과의 **방향 자체를 뒤집는 표지**로 서로 다른 조작에 대응시킨다.
- `果然／竟然`을 먼저 비교해 “예상과 다름”을 표현할 수 있어야, `反而`가 단순한 놀라움보다 한 단계 더 나아간 반전임을 판 위에서 확인할 수 있다.
- 첫 묶음의 새 목표 표현은 다섯 개지만 한 방에는 0~2개만 도입한다. 마지막 방은 새 표현 없이 앞의 다섯 표현을 능동 재사용한다.

이 묶음을 끝내도 학술탑 전체가 완료되거나 격파되지 않는다. 방 완료와 첫 연구 묶음 milestone만 남고, 이후 연구 묶음은 같은 탑에 계속 추가한다.

## 3. 후보 우선순위와 첫 묶음 선택

221개 원자료 기록은 다음 세 단계로 관리한다. 단어표 표제와 문법점이 같은 교육 단위를 가리켜도 원자료 추적을 위해 각각 센다.

| 우선순위 | 기록 수 | 사용 원칙 |

우선순위는 구조 활용도, 선수 관계 중심성, 유사 표현과의 대조 필요, 전술 조작 가능성, 사용 문체의 폭을 함께 본 편집 판단이다. TBCL 급수가 높다는 이유만으로 앞세우거나 미루지 않는다.

## 4. G1 — 공통 상황·어휘·기믹

상황 한 문장:

> 플레이어는 오래된 물길·장치 기록을 들어오는 순서대로 읽고, 의미 덩어리를 나누고, 예상 방향과 실제 방향을 연결하여 기록이 요구하는 안전한 해석을 만든다.

### 4.1 기존 단어 능동 재사용

새 접속 표현을 익히는 동안 내용어는 1.0에서 직접 조작한 단어를 우선한다.

- 길목: `距離 / 範圍`
- 장인골: `增加 / 減少 / 調整 / 損壞 / 修復 / 恢復`
- 북쪽 숲: `情況 / 安全 / 危險`
- 기초 접속 표현: `因為 / 所以 / 如果 / 但是 / 可是 / 不過 / 雖然`

`水量 / 水車 / 裝置 / 齒輪`은 이미 장인골 이야기와 판에서 본 문맥어다. 접속 표현이 아닌 낯선 내용어를 한꺼번에 추가하지 않는다.

### 4.2 독해 작업대 공통 조작

모든 방은 같은 작업대 문법을 공유하되 각 방의 핵심 판단은 다르게 한다.

1. 문장이나 기록이 덩어리 단위로 순차 공개된다. 시간 제한과 열람 횟수 제한은 없다.
2. 플레이어는 경계 후보를 눌러 의미 덩어리를 나눈다.
3. 표지어를 중심으로 `앞 정보`, `뒤 중심`, `예상`, `실제` 레일에 덩어리를 놓거나 연결선을 바꾼다.
4. 관계가 성립하면 작업대의 화살표·중심 표식이 갱신된다.
5. 마지막에는 번역문을 고르는 대신 기록으로부터 안전한 해석이나 상태 판단을 완성한다.

문자 하나의 정확한 절단 위치를 시험하지 않는다. 다음 두 조건을 만족하는 경계 후보는 모두 허용한다.

- 핵심 표지 앞뒤의 의미 역할이 보존된다.
- 수식어를 어느 덩어리에 포함해도 원인·대조·예상·반전 관계가 바뀌지 않는다.

오답은 정답을 바로 말하지 않고 현재 배치가 만든 읽기를 보여 준다. 플레이어는 카드나 연결선을 다시 옮길 수 있고, `되돌리기`는 직전 확정 전 상태로 돌아간다. 단어 카드 열람에는 페널티가 없다.

### 4.3 화면 정보 위계

375×640의 620px 세로 예산에서는 다음 순서를 고정한다.

1. 방 제목·한 줄 목표
2. 순차 공개되는 원문 기록
3. 현재 조작 하나가 놓인 작업대
4. 관계 상태와 짧은 피드백
5. `되돌리기`, `단어 보기`, `확정` 행동

긴 설명은 기본 화면에 상시 노출하지 않고 단어 카드와 `기록 다시 보기`에 둔다. 조작 버튼과 경계 표식은 최소 44×44px 터치 영역을 가진다. 중국어 원문은 가로 스크롤 없이 줄바꿈한다.

## 5. G2 — 방별 구현 수준 사양

### 5.1 01 `뒤에 남는 중심 / 重點卻在後面`

| 항목 | 사양 |
|---|---|
| 스테이지 ID | `academic-tower-turn-01-que` |
| 상황 한 문장 | 짧아 보이는 수로의 장점과 비 오는 날의 위험을 나눠 읽고, `卻` 뒤에 실제 판단의 중심을 둔다. |
| 학습 단어 | `卻` |
| 기존 단어 능동 재사용 | `但是 / 可是 / 不過`, `危險` |
| 원문 | `這條水道比較短，雨天卻更危險。` |
| 맵 | 위쪽 원문 띠, 가운데 `앞 정보 → 뒤 중심` 두 칸, 아래 중심 표식 하나 |
| 초기 상태 | 원문 전체 공개, 경계 미확정, 중심 표식은 어느 쪽에도 없음 |
| 직접 탭 정보 | `卻` 단어 카드, `但是／可是／不過`와 공유하는 대조 기능, 문장 속 위치 차이 |
| 상황형 행동 | 쉼표 또는 `卻` 앞 경계 탭 → 두 덩어리 확인 → 중심 표식을 뒤 덩어리에 놓기 |
| 재사용/신규 기믹 | 기존 선택·되돌리기 계약 재사용. `의미 경계`와 `중심 표식`은 첫 공통 작업대 slice에서 신규 구현 |

행동 계약:

- trigger: 경계를 확정하고 중심 표식을 한 덩어리에 놓는다.
- predicate: `雨天卻更危險`이 뒤 덩어리이며 중심 표식이 뒤에 있다.
- state delta: `splitConfirmed=true`, `focus='later'`.
- feedback: 앞에 두면 “짧다는 정보만 남기면 비 오는 날의 판단이 사라진다.”를 보여 주고, 뒤에 두면 앞 정보가 흐려지고 뒤 덩어리가 강조된다.
- win: 올바른 두 덩어리와 뒤 중심을 모두 만든다.

대표 정상 해법은 쉼표에서 나눈 뒤 뒤 중심을 표시하는 것이다. `卻` 바로 앞을 경계로 잡는 분석도 같은 두 의미 역할을 만들면 허용한다. 앞 덩어리를 중심으로 확정하면 실패 상태를 저장하지 않고, 화면이 실제로 “짧으니 선택”이라는 잘못된 읽기를 잠깐 보여 준다. 중심 표식을 다시 옮기면 복구된다.

완료 시 첫 플레이만 스테이지 완료를 저장하고 02와 03을 함께 연다. 재플레이는 저장을 바꾸지 않는다.

자동검사 acceptance:

- 허용 경계 두 종류가 같은 관계 상태로 정규화된다.
- 뒤 중심 없이 완료되지 않는다.
- 오답 뒤 이동과 되돌리기로 완료할 수 있다.
- 완료 뒤 02·03이 모두 열리고 04는 잠긴다.

iPhone 관찰 질문: 두 덩어리와 중심 표식이 한 화면에서 함께 보이는가, `卻` 카드와 경계 표식의 터치 대상이 겹치지 않는가?

### 5.2 02 `기록 사이의 전환 / 然而，記錄還沒結束`

| 항목 | 사양 |
|---|---|
| 스테이지 ID | `academic-tower-turn-02-raner` |
| 선수 방 | `academic-tower-turn-01-que` |
| 상황 한 문장 | 수로 수리의 긍정 기록 뒤에 이어지는 제한을 연결해, 최종 상태가 아직 정상은 아님을 판단한다. |
| 학습 단어 | `然而` |
| 기존 단어 능동 재사용 | `卻 / 修復 / 增加 / 恢復 / 裝置` |
| 원문 | `修復舊水道可以增加水量。然而，這個裝置還沒有恢復正常。` |
| 맵 | 서로 떨어진 기록 카드 두 장, 가운데 연결 슬롯, 아래 `최종 판단` 자리 |
| 초기 상태 | 첫 기록만 펼쳐져 있고 임시 판단은 `수리 효과 있음`. 다음 기록 열람은 언제든 가능 |
| 직접 탭 정보 | `然而` 카드, 문장 안의 `卻`과 문장·기록 사이 `然而`의 범위 비교 |
| 상황형 행동 | 두 번째 기록 펼치기 → `然而` 연결선 놓기 → 최종 판단을 뒤 기록에 맞춰 갱신 |
| 재사용/신규 기믹 | 01의 중심 이동 재사용. 떨어진 기록 카드 사이 연결은 같은 판정의 두 번째 사용처로 일반화 |

trigger는 연결선을 놓고 최종 판단을 확정하는 것이다. predicate는 두 기록이 대조 연결되고 `아직 정상 아님`이 최종 판단이어야 한다. state delta는 `relation='contrast'`, `focus='later-record'`, `conclusion='not-restored'`다. 앞 기록만으로 `정상 회복`을 확정하면 두 번째 기록이 펼쳐진 채 남아 정보가 추가됐음을 보여 준다. 연결선과 판단을 다시 바꾸면 복구된다.

`然而`를 `卻`보다 더 강한 같은 단어로 설명하지 않는다. 01에서는 한 문장 안의 뒤 절에 중심을 옮겼고, 02에서는 완결된 앞 기록을 인정하면서 다음 기록이 전체 판단을 제한한다는 **범위 차이**를 조작하게 한다.

완료 시 첫 플레이만 방 완료를 저장하고 허브로 돌아간다. 03을 먼저 끝냈다면 04가 열린다.

자동검사 acceptance:

- 두 번째 기록을 읽기 전에는 완료할 수 없다.
- 대조 연결만 하고 최종 판단을 갱신하지 않으면 완료되지 않는다.
- 02와 03 완료 순서가 어느 쪽이든 04 해금 결과가 같다.

iPhone 관찰 질문: 두 기록 카드가 세로로 떨어져도 연결 방향이 명확한가, 긴 두 번째 문장이 가로 스크롤 없이 읽히는가?

### 5.3 03 `예상과 실제 / 果然，還是竟然？`

| 항목 | 사양 |
|---|---|
| 스테이지 ID | `academic-tower-turn-03-expectation` |
| 선수 방 | `academic-tower-turn-01-que` |
| 상황 한 문장 | 원인 기록만 보고 임시 예상을 만든 뒤, 실제 결과가 예상과 일치하는지 이탈하는지 두 사례로 구분한다. |
| 학습 단어 | `果然 / 竟然` |
| 기존 단어 능동 재사용 | `因為 / 所以 / 增加 / 修復 / 恢復` |
| 사례 A | `水量增加後，水車果然轉得更快。` |
| 사례 B | `修復齒輪後，水車竟然還是沒有轉動。` |
| 맵 | 위쪽 `근거 → 임시 예상`, 아래쪽 `예상대로 / 예상 밖` 두 레일 |
| 초기 상태 | 각 사례의 앞 덩어리만 공개. 플레이어가 임시 예상 방향을 먼저 놓음 |
| 직접 탭 정보 | 두 표지의 카드와 “좋은/나쁜 결과”가 아니라 “예상과의 일치 여부”라는 설명 |
| 상황형 행동 | 예상 화살표 놓기 → 결과 공개 → 결과 카드를 한 레일에 배치 |
| 재사용/신규 기믹 | 순차 공개와 중심 이동 재사용. 공개 전 예상 상태와 두 결과 레일 신규 구현 |

각 사례는 `예상 먼저 만들기 → 결과 공개 → 관계 분류`를 거친다. A는 `果然 / expected`, B는 `竟然 / unexpected`여야 한다. 결과의 긍정·부정만 보고 분류할 수 없도록, 후속 콘텐츠에서는 나쁜 예상이 그대로 맞거나 좋은 뜻밖의 결과가 나오는 사례도 같은 판정으로 추가할 수 있다.

대표 오답은 `果然=좋은 결과`, `竟然=나쁜 결과`로 분류하는 것이다. 오답이면 작업대가 플레이어가 방금 세운 임시 예상과 실제 결과를 나란히 남겨 불일치 지점을 보여 준다. 레일을 바꾸면 즉시 복구된다. 두 사례를 모두 맞춰야 완료된다.

완료 시 첫 플레이만 방 완료를 저장한다. 02까지 끝났다면 04가 열린다.

자동검사 acceptance:

- 결과 공개 전에 임시 예상이 없으면 다음 단계로 갈 수 없다.
- A와 B를 각각 올바른 레일에 놓아야 완료된다.
- 잘못된 레일 배치 뒤 예상 기록은 사라지지 않고 재배치할 수 있다.
- 02·03의 완료 순서를 바꿔도 04 해금은 동일하다.

iPhone 관찰 질문: 두 레일의 이름과 현재 사례가 함께 보이는가, 사례 전환 뒤 이전 사례의 완료 표식이 과도한 세로 공간을 차지하지 않는가?

### 5.4 04 `반대로 나온 결과 / 結果反而相反`

| 항목 | 사양 |
|---|---|
| 스테이지 ID | `academic-tower-turn-04-faner` |
| 선수 방 | `academic-tower-turn-02-raner`, `academic-tower-turn-03-expectation` |
| 상황 한 문장 | 물을 늘리면 더 빨라질 것이라는 예상을 만든 뒤, 실제로 멈춘 결과를 반대 방향 화살표로 갱신한다. |
| 학습 단어 | `反而` |
| 기존 단어 능동 재사용 | `卻 / 然而 / 果然 / 竟然 / 增加 / 水量 / 水車` |
| 원문 | `水量增加以後，水車沒有轉得更快，反而停了下來。` |
| 맵 | 가운데 기준 상태, 오른쪽 예상 방향, 왼쪽 실제 반대 방향을 가진 세 칸 작업대 |
| 초기 상태 | `水量增加`와 `더 빨라짐` 예상만 공개. 실제 결과는 접혀 있음 |
| 직접 탭 정보 | `竟然`의 예상 이탈과 `反而`의 반대 방향 비교 |
| 상황형 행동 | 예상 화살표 만들기 → 실제 결과 공개 → 기존 화살표를 반대편으로 뒤집고 두 결과를 대조 연결 |
| 재사용/신규 기믹 | 03의 예상 상태 재사용. 양극 방향축과 화살표 반전은 신규 구현 |

trigger는 실제 결과 공개 뒤 화살표를 뒤집는 것이다. predicate는 예상 상태가 `faster`, 실제 상태가 `stopped`, 관계가 `reversal`이어야 한다. state delta는 원래 예상선을 점선으로 남기고 실제선을 반대 방향 실선으로 바꾼다. win은 원래 예상과 반대 실제를 모두 보존한 문장 지도를 만드는 것이다.

`竟然` 레일에만 놓으면 “예상과 다르다는 건 찾았지만, 어느 방향으로 뒤집혔는지는 아직 표시하지 않았다.”는 피드백을 준다. 단순 대조선만 놓으면 “두 사실이 다르다는 것과 예상 결과가 반대로 나온 것은 다르다.”를 보여 준다. 화살표를 뒤집으면 복구된다.

완료 시 첫 플레이만 방 완료를 저장하고 05를 연다.

자동검사 acceptance:

- 예상 화살표 없이 실제 결과를 확정할 수 없다.
- `unexpected`만으로는 완료되지 않고 `reversal` 방향축이 필요하다.
- 원래 예상선과 실제 반전선이 완료 상태에 함께 남는다.
- 02 또는 03 하나만 끝낸 저장에서는 04가 잠긴다.

iPhone 관찰 질문: 좌우 방향축이 360px 폭에서도 눌리지 않는가, 색 없이도 점선·실선·화살표 방향으로 예상과 실제를 구분할 수 있는가?

### 5.5 05 `겹쳐진 방향 / 讀懂轉折與反轉`

| 항목 | 사양 |
|---|---|
| 스테이지 ID | `academic-tower-turn-05-synthesis` |
| 선수 방 | `academic-tower-turn-04-faner` |
| 상황 한 문장 | 여러 시기의 수로 기록을 순서대로 읽으며 예상 확인, 이탈, 대조, 반전을 하나의 안전 판단으로 종합한다. |
| 신규 학습 단어 | 없음 |
| 능동 재사용 | `卻 / 然而 / 果然 / 竟然 / 反而` 전부 |
| 기록 1 | `第一次增加水量後，水車果然轉得更快。` |
| 기록 2 | `第二次增加水量後，水車卻沒有轉得更快，竟然停了下來。` |
| 기록 3 | `修復舊裝置通常能讓水車恢復。然而，這次增加水量沒有幫助，反而使另一個齒輪損壞。` |
| 최종 안전문 | `雖然增加水量可以讓水流更快，然而如果水量超過安全範圍，剛修復的裝置反而可能損壞。` |
| 맵 | 세 기록 카드, 각 카드의 문장 지도, 아래 `안전한 범위 안에서만 증가` 결론 슬롯 |
| 초기 상태 | 기록 1만 공개. 새 목표어 카드는 없고 앞 방의 다섯 카드가 열려 있음 |
| 상황형 행동 | 각 기록 분할·관계 표시 → 기록 사이 방향 변화 연결 → 최종 안전문 지도 완성 |
| 재사용/신규 기믹 | 01~04의 경계, 중심, 예상 레일, 반전 화살표만 조합. 새 공통 기믹 없음 |

대표 정상 해법:

1. 기록 1을 예상 확인으로 놓는다.
2. 기록 2에서 `卻` 뒤로 중심을 옮기고 `竟然`을 예상 밖 결과로 둔다.
3. 기록 3의 두 문장을 `然而`로 연결한 뒤 예상 결과를 `反而`가 반대로 바꾼다고 표시한다.
4. 최종 안전문을 `양보 / 대조+조건 / 반전 결과` 세 덩어리로 나눈다.
5. “물을 무조건 늘린다”가 아니라 “안전 범위 안에서만 늘린다”는 상태 판단을 완성한다.

수식어 경계를 다르게 나누더라도 세 관계와 최종 판단이 같으면 허용한다. 기록 2의 `卻`와 `竟然` 중 하나만 표시하면 부분 관계는 남지만 완료되지 않는다. 최종 안전문에서 `雖然`이나 `如果`는 신규 목표어가 아니므로 별도 암기 문제로 만들지 않고 이미 아는 관계 슬롯으로 제공한다.

오답으로 `물을 늘리면 항상 빨라진다`를 확정하면 기록 2·3의 멈춤과 손상 상태가 그대로 남고, 서로 충돌하는 근거 수가 표시된다. 어느 기록도 소모되지 않으며 관계선과 최종 판단을 다시 바꿀 수 있다.

첫 플레이에서는 방 완료 뒤 `academic-tower-turn-result`로 이어지고, 그 이야기를 마치면 `academic-tower-turn-foundation`을 기록한 뒤 허브로 돌아간다. 재플레이는 결과 이야기를 자동 재생하거나 milestone을 바꾸지 않고 바로 허브로 돌아간다.

자동검사 acceptance:

- 다섯 표현을 모두 한 번 이상 능동 관계에 사용해야 한다.
- 최종 안전문은 새 목표어 0개로 판정된다.
- 허용 절단안이 달라도 정규화한 관계 그래프가 같으면 완료된다.
- 05 첫 플레이 뒤 결과 이야기에서만 묶음 milestone이 생긴다.
- 05 재플레이와 오답 횟수는 기존 완료·milestone을 바꾸지 않는다.

iPhone 관찰 질문: 한 번에 기록 카드 하나만 중심에 두어 620px 예산을 지키는가, 이전 기록 요약을 접고 펼칠 수 있는가, 최종 안전문 세 줄 이상에서도 조작 대상이 밀리지 않는가?

## 6. 이야기 흐름

전체 사건·인물·한중 대사 초안은 `ACADEMIC-TOWER-OPENING-STORY-v0.1.md`를 따른다.

`academic-tower-arrival`에서는 학술탑을 처음 찾은 소년이 누구를 만나야 할지 설명하지 못해 문지기에게 제지된다. 지나가던 수로 기록 연구원이 공방 수리패와 옛 조절기 이야기를 알아보고, 보관실 전체가 아니라 자기 연구실 방문에 한해 책임지고 들인다. 수리패만으로 출입할 수 있는 구조가 아니며, 실제로 문 안에 들어간 뒤 `academic-tower-entered`를 기록한다.

`academic-tower-turn-intro`에서는 담당 연구원이 소년에게 문법 시험을 내지 않는다. W7 명판의 표식을 자기 연구 분야인 옛 수로 색인에서 찾지만, 함께 묶인 기록이 서로 모순돼 보이기 때문에 실제로 안전한 판단을 다시 만들어야 한다.

허브는 층 번호 대신 연구 묶음과 선수 선을 보여 준다. 아직 잠긴 방도 이름과 선수 선은 보이되 목표 표현은 `???`로 숨기지 않는다. 학술탑의 목적은 발견형 월드 탐색이 아니라 읽을 구조를 스스로 조작하는 데 있기 때문이다.

중간 이야기 세 개는 선수 그래프를 서사 흐름으로 연결한다. 01 뒤 02·03을 병렬로 열고, 둘을 모두 마치면 04를, 04 뒤에는 05를 제시한다. 중간 이야기는 milestone을 만들지 않으며 재플레이에서 자동 재발생하지 않는다.

`academic-tower-turn-result`에서는 플레이어가 만든 최종 문장 지도를 오래된 기록 옆에 보관한다. 길목과 명판에서 본 표식이 기록의 순서와 관계를 맞춘 순간 희미하게 반응하고, 연구원도 처음으로 그 빛을 함께 본다. 둘은 원인을 단정하지 않고 관찰 조건만 적는다. 연구원은 “탑을 끝냈다”고 말하지 않고 소년에게 다음 기록을 놓을 탁자 칸 하나를 남긴다.

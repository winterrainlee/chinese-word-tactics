## 1. 결정

학술탑의 첫 연구 묶음은 `卻 → 然而`의 **대조·중심 이동**과 `果然／竟然`의 **예상 확인·이탈**을 따로 익힌 뒤, 예상했던 결과가 생기지 않고 다른 결과가 대신 생기는 `反而`의 **결과 교체**에서 합친다.

```text
01 卻
├─> 02 然而 ─────────┐
└─> 03 果然／竟然 ───┼─> 04 反而 ─> 05 종합
                      │
                      └─> 03A 같은 然 〔선택 연구〕
```

03A는 02·03을 모두 끝낸 뒤 열리는 곁방이다. 플레이어가 `然而 / 果然 / 竟然`에 반복되는 `然`을 스스로 발견했다는 상황에서 출발하며, 완료하지 않아도 04와 05를 진행할 수 있다. 첫 연구 묶음의 완료 milestone에도 포함하지 않는다.

이 순서를 택한 이유는 다음과 같다.

- `然而`와 `反而`를 한국어의 비슷한 역접 표현으로 한꺼번에 외우지 않는다.
- `然而`는 앞 내용과 뒤 내용을 **대조하면서 중심을 뒤로 옮기는 표지**, `反而`는 기대했던 A가 생기지 않고 실제 B가 **그 자리를 대신하는 관계**로 서로 다른 조작에 대응시킨다.
- `竟然`은 실제 B를 뜻밖이라고 평가하고, `反而`는 생기지 않은 A와 대신 생긴 B를 잇는다. 한 결과에 두 관점이 함께 성립할 수 있으므로 둘을 배타적인 정답으로 만들지 않는다.
- 첫 묶음의 본선 새 목표 표현은 다섯 개지만 한 방에는 0~2개만 도입한다. 마지막 방은 새 표현 없이 앞의 다섯 표현을 능동 재사용한다.
- 03A는 본선 기능 사슬을 확장하는 방이 아니라, 이미 만난 표현의 글자 구조에서 플레이어가 스스로 규칙 후보를 발견하는 **형태 관찰형 선택 연구**다. 신규 중심 표현은 `既然 / 不然` 두 개만 두고 `雖然 / 然後 / 然而 / 果然 / 竟然`은 선수·재사용 표현으로 쓴다.
- 03A의 결론은 `然이 들어가면 모두 같은 뜻`이 아니다. `然`에 `그렇다 / 그렇게 / 그러한 상태`라는 공통 흔적이 보일 수 있으나, 실제 문장 기능은 결합한 글자와 위치, 전체 문맥에서 판단해야 한다는 데 둔다.

이 묶음을 끝내도 학술탑 전체가 완료되거나 격파되지 않는다. 방 완료와 첫 연구 묶음 milestone만 남고, 이후 연구 묶음은 같은 탑에 계속 추가한다.

## 3. 후보 우선순위와 첫 묶음 선택

221개 원자료 기록은 다음 세 단계로 관리한다. 단어표 표제와 문법점이 같은 교육 단위를 가리켜도 원자료 추적을 위해 각각 센다.

| 우선순위 | 기록 수 | 사용 원칙 |
|---|---:|---|
| `core` | 110 | 문장 분할·방향 갱신의 뼈대. 여러 묶음에서 반복 사용 |
| `secondary` | 65 | 핵심의 말투·문체·관점 확장 또는 다음 묶음 후보 |
| `later` | 46 | 맥락이 좁거나 비슷한 핵심 표현 뒤에 다룰 장기 후보 |

우선순위는 구조 활용도, 선수 관계 중심성, 유사 표현과의 대조 필요, 전술 조작 가능성, 사용 문체의 폭을 함께 본 편집 판단이다. TBCL 급수가 높다는 이유만으로 앞세우거나 미루지 않는다.

목록은 `data/academic-tower-discourse-candidates-v0.1.json`의 `priorityPolicy`가 기준이다. `coreSourceRefs`와 `laterSourceRefs`에 없는 후보는 `secondary`로 계산한다. 세 집합은 221개를 중복·누락 없이 덮어야 한다.

첫 묶음 목표 표현과 원자료 참조는 모두 `core`다.

| 방 | 신규 목표 표현 | 원자료 참조 | 핵심 구분 |
|---|---|---|---|
| 01 | `卻` | `w4-que`, `g262` | 뒤 절로 중심 이동 |
| 02 | `然而` | `w5-raner`, `g490` | 문장·기록 사이의 문어적 전환 |
| 03 | `果然 / 竟然` | `w4s-guoran`, `g345`, `w4s-jingran`, `g346` | 예상 확인 / 예상 이탈 |
| 04 | `反而` | `w5-faner`, `g492` | 예상 A가 생기지 않고 실제 B가 대신 생김 |
| 05 | 없음 | 없음 | 다섯 표현 종합 |

본선과 별도로 다음 선택 연구를 둔다.

| 방 | 신규 중심 표현 | 재사용 표현 | 역할 |
|---|---|---|---|
| 03A | `既然 / 不然` | `雖然 / 然後 / 然而 / 果然 / 竟然` | 반복되는 `然`을 형태 단서로 관찰하되, 같은 글자가 같은 문장 기능을 보장하지 않음을 확인 |

03A는 `core` 다섯 표현의 기능 사슬을 바꾸지 않는다. `既然`은 이후 원인·귀결 학습으로 이어지는 선행 관찰이고, 우선순위가 낮은 `不然`은 이 방에서 `그렇지 않으면`이라는 투명한 조합을 비교하기 위한 제한적 도입으로만 사용한다. `居然 / 忽然 / 依然 / 固然`처럼 현대어에서 글자별 계산만으로 쓰임을 예측하기 어려운 표현은 이 방의 목표 목록에서 제외한다.

## 4. G1 — 공통 상황·어휘·기믹

상황 한 문장:

> 플레이어는 오래된 물길·장치 기록을 들어오는 순서대로 읽고, 의미 덩어리를 나누고, 예상 방향과 실제 방향을 연결하여 기록이 요구하는 안전한 해석을 만든다.

### 4.1 기존 단어 능동 재사용

새 접속 표현을 익히는 동안 내용어는 1.0에서 직접 조작한 단어를 우선한다.

- 길목: `距離 / 範圍`
- 장인골: `增加 / 減少 / 調整 / 損壞 / 修復 / 恢復`
- 북쪽 숲: `情況 / 安全 / 危險`
- 기초 접속 표현: `因為 / 所以 / 如果 / 但是 / 可是 / 不過 / 雖然`

`水量 / 水車 / 裝置 / 齒輪`은 이미 장인골 이야기와 판에서 본 문맥어다. 접속 표현이 아닌 낯선 내용어를 한꺼번에 추가하지 않는다.

### 4.2 독해 작업대 공통 조작

첫 두 방의 단일 학습 모델은 다음과 같다.

> 문장이나 기록을 사실 단위로 나누어 읽고, `卻 / 然而`가 드러내는 대조를 근거로 앞 사실은 보존하면서 그 사실에서 성급하게 끌어낸 판단을 고친다.

작업대는 연구원이 남긴 원문과 소년의 검토 메모를 비교하는 형식이다.

1. 짧은 문장이나 기록 두 장을 처음부터 전부 읽고 검토 초안과 비교한다. 문장 분할은 독해 보조이며 절단 위치를 채점하지 않는다.
2. 연습에서는 `기록이 직접 말한 사실`, `두 사실을 올바르게 합친 판단`, `근거를 넘은 주장`을 구별해 고칠 주장을 고른다.
3. 두 사실을 모두 남기는 메모로 수정한다.
4. 반대 방향의 새 사례에서는 통합 메모 한 번으로 같은 판단을 전이한다.

각 선택은 미선택 상태에서 시작한다. 선택지는 입장마다 위치가 달라지지만 같은 플레이·새로고침 안에서는 순서를 보존한다. 연습의 `주장 찾기`, `메모 수정`, 새 사례의 정답 위치가 서로 달라 항상 같은 자리를 누르는 전략으로 완료할 수 없다.

`卻 / 然而` 자체를 빈칸에 넣거나 번역을 고르는 문제로 만들지 않는다. 표지어는 원문에서 강조하고, 성공 화면에서 뒤 근거와 수정된 추론의 연결을 보여 준다. 오답은 원문 사실을 지우지 않고 무엇을 과도하게 확대하거나 취소했는지 한국어로 즉시 설명한다. 단어 카드 열람에는 페널티가 없다.

### 4.3 화면 정보 위계

375×640의 620px 세로 예산에서는 다음 순서를 고정한다.

1. 방 제목·한 줄 목표
2. 현재 판단 질문
3. 처음부터 전부 보이는 원문 기록과 검토 초안
4. 현재 단계의 세로 선택지 4개
5. 한국어 피드백과 `되돌리기`, `단어 보기`, `확정` 행동

이전 단계의 선택지는 다음 단계에서 제거하고 수정 대상만 짧게 남긴다. 긴 설명은 단어 카드에 두되, 현재 오답의 이유는 접지 않고 바로 보여 준다. 모든 조작 버튼은 최소 44×44px이고 중국어 원문은 가로 스크롤 없이 줄바꿈한다.

4개 보기는 찍기 확률만 낮추기 위한 수량 규칙으로 쓰지 않는다. 네 보기가 `앞 사실`, `뒤 사실`, `두 사실을 올바르게 합친 판단`, `근거를 넘은 판단`처럼 서로 다른 독해 상태를 진단할 수 있을 때만 사용한다. 수정 단계의 네 번째 오답도 기존 오답의 말바꾸기가 아니라 `근거 없는 금지·예측·후속 결정`을 따로 드러낸다.

연습의 원문 사실은 `수로가 더 짧다`, `비 오는 날에는 더 위험하다`다. 검토 메모의 `짧으니 비 오는 날 이용하기 좋다`가 수정 대상이다. 정답 메모는 `짧다는 장점은 있다. 우천 시 위험도 이용 판단에 반영한다`다. 원문은 사용 금지까지 말하지 않으므로 금지 명령을 정답으로 만들지 않는다.

새 기록은 `這個裝置很舊，卻還能正常運作。`다. 불리한 특성 뒤에 가능한 작동이 이어지는 반대 방향 사례로 바꾸어, 언제나 부정적인 뒤 결론을 고르는 전략을 막는다. `장치는 오래되었다. 그래도 지금은 정상 작동한다`처럼 두 사실을 함께 남겨야 한다.

완료 시 첫 플레이만 스테이지 완료를 저장하고 현재 구현된 02를 연다. 03은 구현 전까지 `준비 중`으로 표시한다. 재플레이는 본편 저장을 바꾸지 않는다.

자동검사 acceptance:

- 사실 자체를 수정 대상으로 고르면 완료되지 않고 즉시 이유를 보여 준다.
- 올바른 주장을 찾아도 두 사실 중 하나를 지우는 수정안으로는 연습을 마칠 수 없다.

- 연습과 새 기록의 정답 슬롯이 서로 달라 같은 위치 반복으로 완료할 수 없다.

### 5.3A 선택 연구 03A `같은 然 / 怎麼又有「然」？`

| 항목 | 사양 |
|---|---|
| 스테이지 ID | `academic-tower-turn-03a-ran-family` |
| 성격 | 첫 연구 묶음 옆의 선택 연구. 본선 완료와 04 해금에 필요하지 않음 |
| 공개 조건 | 02 `然而`와 03 `果然／竟然` 첫 완료 |
| 도입 이야기 | `academic-tower-ran-intro` |
| 결과 이야기 | `academic-tower-ran-result` |
| 상황 한 문장 | 소년이 방금 읽은 기록들에서 `然`이 반복되는 것을 발견하고, 남은 색인 문장 조각을 직접 배열해 공통 흔적과 서로 다른 문장 기능을 비교한다. |
| 신규 중심 표현 | `既然 / 不然` |
| 기존 표현 능동 재사용 | `雖然 / 然後 / 然而 / 果然 / 竟然` |
| 핵심 발견 | `然`에는 ‘그렇다·그렇게·그러한 상태’라는 공통 흔적을 잡아볼 수 있지만, 표현 전체의 기능은 앞뒤 글자와 위치, 문맥이 결정한다. |
| 금지 결론 | ‘`然`이 들어간 표현은 같은 종류다’, ‘글자 뜻만 더하면 모든 현대어 용법을 계산할 수 있다’ |
| 본선 연결 | 03A 완료 여부와 무관하게 04 진입 가능. 완료했다면 04 도입에서 “이번에는 `然`이 없네요” → “그러니 글자 하나가 아니라 관계를 봐”라는 짧은 변형 대사를 허용 |

#### 학습 흐름

1. 첫 화면에는 앞서 실제로 읽은 `然而 / 果然 / 竟然` 세 카드를 놓는다. 소년의 질문 `……怎麼又有「然」？`에서 시작한다.
2. `雖然 / 然後`처럼 이미 알고 있다고 보는 기초 표현과 `既然 / 不然` 두 새 문장 조각을 더 꺼낸다.
3. 1차 조작에서는 글자 위치만 관찰한다. `雖→然 / 既→然 / 不→然 / 果→然 / 竟→然`과 `然→而 / 然→後`를 배열한다. 이 단계는 정답 암기가 아니라 공통 글자를 눈으로 묶는 발견 단계다.
4. 각 카드에서 결합 글자의 기본 감각을 짧게 연다. 예: `既=이미 + 然=그러하다 → 이미 그러한 이상`, `不=아니다 + 然=그러하다 → 그렇지 않다면`. 이 설명은 기억 보조이며 엄밀한 어원 공식으로 제시하지 않는다.
5. 2차 조작에서는 문장 관계로 다시 분류한다. 순서(`然後`), 양보(`雖然`), 이미 성립한 전제(`既然`), 그렇지 않을 경우의 분기(`不然`), 문장·기록의 전환(`然而`), 예상 일치(`果然`), 예상 이탈(`竟然`)을 서로 다른 자리로 옮긴다.
6. 같은 `然`이 있어도 서로 교환할 수 없음을 문장 적용으로 확인한다. 글자 모양 묶음과 실제 기능 묶음이 다르다는 점이 성공 조건이다.
7. 결과에서는 소년이 “`然`에는 같은 흔적이 보이지만 앞뒤에 무엇이 붙는지에 따라 문장 방향이 달라진다”고 적고, 연구원은 이를 정답 선언이 아닌 **현재까지의 쓸 만한 가설**로 받아들인다.

#### 표현별 이 방의 역할

| 표현 | 이 방에서 읽는 글자 감각 | 실제 관계 |
|---|---|---|
| `雖然` | `雖` 비록 + `然` 그러하다 | 앞 사실을 인정하고 뒤 결론을 남기는 양보 |
| `既然` | `既` 이미 + `然` 그러하다 | 이미 성립한 상황을 뒤 판단의 전제로 둠 |
| `不然` | `不` 아니다 + `然` 그러하다 | 그렇지 않을 경우의 대안·귀결 |
| `然而` | `然` 그렇다 + `而` 이어 전환 | 앞을 인정하면서 뒤 기록으로 판단을 제한 |
| `然後` | `然` 그렇게 + `後` 뒤 | 앞 단계를 닫고 다음 순서로 이동 |
| `果然` | `果` 과연·실제로 + `然` 그러하다 | 실제 결과가 예상과 일치 |
| `竟然` | `竟` 뜻밖의 귀결 감각 + `然` 그러하다 | 실제 결과가 예상에서 이탈 |

이 표의 글자 풀이를 곧바로 현대어 의미를 산출하는 공식으로 쓰지 않는다. 특히 후속 연구에서 `居然 / 忽然 / 依然 / 固然` 등을 만날 때는 분해 가능성이 더 흐려진다는 사실을 다시 확인할 수 있다.

#### 자동검사 acceptance

- 02·03을 완료하면 03A가 열리지만, 03A 미완료 상태에서도 기존 합류 이야기와 04를 진행할 수 있다.
- 04·05 또는 첫 묶음 milestone을 먼저 완료한 저장에서도 03A가 사라지지 않는다.
- 03A 완료가 `academic-tower-turn-foundation`을 요구하거나 다시 발생시키지 않는다.
- 1차 배열만으로 완료되지 않고, 문장 관계 분류까지 맞혀야 한다.

### 5.4 04 `예상 대신 생긴 결과 / 沒有更快，反而停下來`

| 항목 | 사양 |
|---|---|
| 스테이지 ID | `academic-tower-turn-04-faner` |
| 선수 | `academic-tower-turn-02-raner`, `academic-tower-turn-03-expectation`과 합류 이야기 `academic-tower-turn-before-faner` |
| 상황 한 문장 | 예상됐지만 생기지 않은 결과 A와 실제로 대신 생긴 결과 B를 골라 `沒有 A，反而 B` 문장 지도로 연결한다. |
| 학습 단어 | `反而` |
| 기존 단어 능동 재사용 | `卻 / 然而 / 果然 / 竟然 / 增加 / 水量 / 水車` |
| 원자료 경계 | TBCL `w5-faner`, `g492 (不但)不/沒……反而……`; `反而`를 정확한 반대축에만 제한하지 않음 |
| 맵 | 한 번에 기록 하나, 결과 카드 네 장, `未發生`·`實際發生` 두 슬롯, 관계 연결 슬롯 |
| 초기 상태 | 중국어 예상 기록과 실제 기록만 공개. 한국어 완역, 정답 색, 기본 선택 없음 |
| 직접 탭 정보 | 단어 카드에서 `竟然`은 뜻밖의 B, `反而`는 일어나지 않은 A와 대신 생긴 B를 잇는다는 차이를 확인 |
| 상황형 행동 | 예상 결과 A 선택 → 실제 결과 B 선택 → 두 결과를 `反而` 관계로 연결 → 완성 문장 검토 |
| 재사용/신규 기믹 | 03의 예상·실제 카드와 관계 상태 재사용. 두 결과 슬롯을 연결하는 `replacement-link`만 학술탑 런타임에 추가 |

`竟然`과 `反而`는 양자택일이 아니다. 같은 B가 뜻밖이라는 평가는 `竟然`, 예상 A가 생기지 않고 B가 그 자리를 대신한다는 문장 관계는 `反而`가 맡는다. 따라서 `竟然`을 고른 플레이어에게 “틀린 단어”라고 하지 않고 “뜻밖이라는 표시는 맞지만 A 대신 B가 생긴 관계는 아직 연결하지 않았다”고 피드백한다.

사례는 두 개만 두고 결과의 좋고 나쁨을 교차한다.

| 사례 | 모드 | 예상 기록 | 실제 기록 | 완성 지도 |
|---|---|---|---|---|
| 1 | 안내·부정 결과 | `水量增加了。預計：水車會轉得更快。` | `水車停了下來。` | `水量增加以後，水車沒有轉得更快，反而停了下來。` |
| 2 | 적용·긍정 결과 | `水量減少了。預計：水車會停下來。` | `水車恢復了正常。` | `水量減少以後，水車沒有停下來，反而恢復了正常。` |

안내 사례의 결과 카드는 `轉得更快 / 停了下來 / 水量增加 / 裝置完全損壞`, 적용 사례는 `停下來 / 恢復正常 / 水量減少 / 所有水道都修復`다. 원인 카드와 기록보다 넓은 결론을 각각 하나씩 섞어 오답 원인을 구분한다.

안내 사례는 `沒有 [A]，反而 [B]` 틀을 먼저 보여 주고 결과 카드 네 장에서 A와 B를 고르게 한다. 적용 사례는 중립적인 `預想未發生 / 實際發生` 슬롯만 보여 준 뒤, 두 결과를 놓고 `卻 / 然而 / 竟然 / 反而` 가운데 관계 연결을 고르게 한다. 네 연결 표현은 문법적으로 겹칠 수 있으므로 판정 질문을 “B가 놀라운가?”가 아니라 “A가 생기지 않고 B가 대신 생겼다는 관계를 어느 표현이 남기는가?”로 고정한다.

오답은 카드를 없애지 않는다.

- 원인 카드 `水量增加 / 水量減少`를 A에 놓으면 예상 결과와 원인을 구분하라고 한다.
- 기록에 없는 `裝置完全損壞 / 所有水道都修復`를 B에 놓으면 실제 기록보다 넓힌 판단임을 표시한다.
- `竟然`은 예상 밖 표지를 인정하되 결과 교체 연결은 미완료로 남긴다.
- `卻 / 然而`는 대조·중심 이동은 만들지만 A 대신 B가 생겼다는 슬롯 관계가 남지 않았다고 알려 준다.

상태 전이는 `place-results → choose-link → review → next/complete`다. 오답 뒤 선택한 카드와 두 원문은 유지하며, 되돌리기는 직전 카드 배치 또는 연결 선택만 취소한다. 완료 시 첫 플레이만 방 완료를 저장하고 `academic-tower-turn-before-synthesis`로 이어진다. 재플레이는 바로 허브로 돌아간다.

저장 계약은 `academicTower.kind='replacement-link'`, `schemaVersion=1`로 두고 `caseIndex`, `phase`, 두 결과 슬롯, `linkId`, `completedCaseIds`, `lastCheck`만 전술 저장에 둔다. 새 전역 저장 키는 만들지 않는다. 이번 방은 `反而`의 모든 용법을 다루거나 학술탑 밖 공통 엔진을 만드는 것이 비목표다.

자동검사 acceptance:

- 두 사례 모두 A와 B를 맞게 놓고 `replacement` 관계를 연결해야 한다.
- 첫 입력 전 예상·실제 카드에 한국어 완역이나 정답 강조가 없다.
- `竟然` 선택은 예상 밖 관계를 보존하지만 `replacement` 완료로 처리하지 않는다.
- 부정 결과와 긍정 결과를 모두 해결해야 하며 `反而=나쁜 결과` 요령으로 통과할 수 없다.
- 오답 뒤 원문·카드·선택을 유지한 채 복구할 수 있다.
- 02 또는 03 하나만 끝낸 저장에서는 04가 잠긴다.
- 첫 플레이 완료와 재플레이가 story·milestone을 섞지 않는다.

iPhone 관찰 질문: 360×640에서 두 원문과 네 결과 카드가 세로 흐름으로 읽히는가, 한국어 완역 없이도 단어 카드를 열고 돌아와 선택을 계속할 수 있는가, 선택·오답·검토 상태에서 핵심 버튼이 잘리지 않는가?

### 5.5 05 `접속어 복원 / 把褪色的連接詞補回去`

| 항목 | 사양 |
|---|---|
| 스테이지 ID | `academic-tower-turn-05-synthesis` |
| 선수 | `academic-tower-turn-04-faner`와 전환 이야기 `academic-tower-turn-before-synthesis` |
| 상황 한 문장 | 접속어가 빠진 세 시기의 수로 기록을 읽고, A1 기본 연결과 구별해 다섯 목표 표현을 복원한 뒤 긴 안전문을 완성한다. |
| 신규 학습 단어 | 없음 |
| 능동 재사용 | `卻 / 然而 / 果然 / 竟然 / 反而` 전부 |
| 맵 | 한 번에 기록 하나와 현재 빈칸 하나만 중심에 둔다. 완료한 기록은 접힌 원문으로 남고 마지막에 3행 안전문을 연다. |
| 초기 상태 | 빈칸 앞뒤의 중국어 문장 전체를 즉시 표시. 한국어 완역, 관계 이름, 정답 색, 기본 선택 없음 |
| 상황형 행동 | 앞뒤 문장 읽기 → 접속어 네 개 중 하나 선택 → 관계 확정 → 세 기록 뒤 안전문 두 빈칸 해결 |
| 재사용/신규 기믹 | 01~04와 반대로 결과 문장을 먼저 주고 접속어를 복원하는 `connector-cloze` 전용 판정 |

세 기록에 다섯 표현을 한 번씩 배치하고, 마지막 안전문에서 `然而 / 反而`를 한 번 더 확인한다.

| 빈칸 | 문장 | 정답 | 보기 4개 |
|---|---|---|---|
| R1 | `研究員先前預計：「增加水量後，水車會轉得更快。」第一次增加水量後，水車 ___ 轉得更快。` | `果然` | `果然 / 竟然 / 然後 / 所以` |
| R2-a | `第二次增加水量後，水車 ___ 沒有轉得更快。` | `卻` | `卻 / 然後 / 所以 / 而且` |
| R2-b | `記錄旁寫著：「沒想到會完全停下來。」水車 ___ 完全停了下來。` | `竟然` | `竟然 / 果然 / 然後 / 所以` |
| R3-a | `修復舊裝置通常能讓水車恢復。___，這次增加水量沒有幫助。` | `然而` | `然而 / 然後 / 所以 / 而且` |
| R3-b | `這次增加水量沒有幫助，___ 使另一個齒輪損壞。` | `反而` | `反而 / 然後 / 所以 / 而且` |
| S-a | `雖然增加水量可以讓水流更快，___如果水量超過安全範圍，` | `然而` | `然而 / 然後 / 所以 / 而且` |
| S-b | `剛修復的裝置___可能損壞。` | `反而` | `反而 / 果然 / 然後 / 所以` |

`然後`와 `所以`는 후보 데이터의 TBCL `1*` 기본 연결이다. `而且`은 첨가 관계지만 TBCL 3이므로 A1이라고 부르지 않는다. 모든 빈칸에 같은 전환 표현 다섯 개를 한꺼번에 넣으면 `卻 / 然而`, `竟然 / 反而`가 문맥에 따라 함께 성립할 수 있으므로, 각 보기 묶음은 문법적으로 겹치지 않는 범위로 제한한다. 보기 위치는 진입마다 회전하고 전술 저장에 고정한다.

앞 방에서는 관계를 만들어 문장을 확인했지만, 05에서는 문장 전체를 먼저 읽고 관계를 복원한다. 문장 속 앞뒤 사실 자체가 단서이며 UI는 별도 힌트를 주지 않는다. 오답 뒤에도 문장과 선택을 남기고, 선택한 `然後 / 所以 / 而且`가 각각 순서·원인 결과·첨가를 나타내 현재 문장의 대조나 예상 관계를 보존하지 못한다는 점만 설명한다. 정답 표현은 피드백에서 직접 말하지 않는다.

상태 전이는 `choose-connector → review → next-blank/complete`다. 같은 기록의 두 빈칸은 순서대로 열어 뒤 빈칸이 앞 정답을 노출하지 않게 한다. 기록 하나를 끝내면 완성한 중국어 원문만 접힌 요약으로 남긴다. 안전문 완료 전에는 한국어 결론을 보여 주지 않고, 완료 검토에서만 “안전한 범위 안에서만 늘린다”는 요약을 공개한다.

저장 계약은 `academicTower.kind='connector-cloze'`, `schemaVersion=1`로 두고 `blankIndex`, `selectedConnectorId`, `completedBlankIds`, 빈칸별 `optionOrders`, `lastCheck`를 전술 저장에 둔다. 새 전역 키는 결과 이야기에서 기록하는 `academic-tower-turn-foundation` 하나뿐이다. 새 목표어, 점수·시간제한, 한 화면에 모든 기록 펼치기, 탑 전체 완료 상태는 비목표다.

첫 플레이에서는 방 완료 뒤 `academic-tower-turn-result`로 이어지고, 그 이야기를 마치면 `academic-tower-turn-foundation`을 기록한 뒤 허브로 돌아간다. 재플레이는 결과 이야기를 자동 재생하거나 milestone을 바꾸지 않고 바로 허브로 돌아간다.

자동검사 acceptance:

- 다섯 목표 표현을 각각 맞혀야 하며 안전문의 `然而 / 反而`까지 해결해야 한다.
- `然後 / 所以`가 모든 관련 보기에서 실제 오답으로 존재한다.
- 보기 정답 위치가 회전하고 저장·새로고침 뒤 유지된다.
- 최종 안전문은 새 목표어 0개로 판정된다.
- 첫 입력 전 원문에 한국어 완역·관계 이름·정답 색·기본 선택이 없다.
- 오답 뒤 원문과 선택이 남고 같은 빈칸에서 복구·되돌리기할 수 있다.
- 모든 빈칸을 해결하기 전에는 완료되지 않는다.
- 05 첫 플레이 뒤 결과 이야기에서만 묶음 milestone이 생긴다.
- 05 재플레이와 오답 횟수는 기존 완료·milestone을 바꾸지 않는다.

iPhone 관찰 질문: 한 번에 기록 하나와 빈칸 하나만 중심에 두어 620px 예산을 지키는가, 4개 보기가 44px을 지키는가, 긴 안전문이 세 행으로 자연스럽게 줄바꿈되는가, 첫 입력 전에 화면이 답을 강조하지 않는가?

## 6. 이야기 흐름

전체 사건·인물·한중 대사 초안은 `ACADEMIC-TOWER-OPENING-STORY-v0.1.md`를 따른다.

`academic-tower-arrival`에서는 학술탑을 처음 찾은 소년이 누구를 만나야 할지 설명하지 못해 문지기에게 제지된다. 지나가던 수로 기록 연구원이 공방 수리패와 옛 조절기 이야기를 알아보고, 보관실 전체가 아니라 자기 연구실 방문에 한해 책임지고 들인다. 수리패만으로 출입할 수 있는 구조가 아니며, 실제로 문 안에 들어간 뒤 `academic-tower-entered`를 기록한다.

`academic-tower-turn-intro`에서는 담당 연구원이 소년에게 문법 시험을 내지 않는다. W7 명판의 표식을 자기 연구 분야인 옛 수로 색인에서 찾지만, 함께 묶인 기록이 서로 모순돼 보이기 때문에 실제로 안전한 판단을 다시 만들어야 한다.

허브는 층 번호 대신 연구 묶음과 선수 선을 보여 준다. 아직 잠긴 방도 이름과 선수 선은 보이되 목표 표현은 `???`로 숨기지 않는다. 학술탑의 목적은 발견형 월드 탐색이 아니라 읽을 구조를 스스로 조작하는 데 있기 때문이다.

중간 이야기 세 개는 선수 그래프를 서사 흐름으로 연결한다. 01 뒤 02·03을 병렬로 열고, 둘을 모두 마치면 04를, 04 뒤에는 05를 제시한다. 중간 이야기는 milestone을 만들지 않으며 재플레이에서 자동 재발생하지 않는다.

`academic-tower-turn-result`에서는 플레이어가 접속어를 복원한 사본과 최종 안전문을 오래된 기록 옆에 보관한다. 길목과 명판에서 본 표식이 기록의 순서와 관계를 맞춘 순간 희미하게 반응하고, 연구원도 처음으로 그 빛을 함께 본다. 둘은 원인을 단정하지 않고 관찰 조건만 적는다. 연구원은 “탑을 끝냈다”고 말하지 않고 소년에게 다음 기록을 놓을 탁자 칸 하나를 남긴다.

## 7. 구현 slice 순서

한 번에 다섯 방을 구현하지 않는다.

1. **Slice A — 01·02**: 경계, 뒤 중심, 떨어진 기록 연결, 첫 입장·허브·재플레이 저장을 검증한다. 완료.
2. **Slice B1 — 03**: 예상 확인·이탈 레일과 02·03 병렬 진입을 검증한다. 완료.
3. **Slice B2 — 합류 이야기·04**: 생기지 않은 A와 대신 생긴 B의 결과 교체 연결을 검증한다. 다음 구현 단위.
4. **Slice C — 전환 이야기·05·결과**: 접속어 선택으로의 역방향 전이, 긴 문장 모바일 배치, 묶음 milestone을 검증한다.

2026-09-26 현재 Slice A·B1의 첫 방문·허브·01~03·재플레이·재진입을 구현했다. 실제 파일 경계와 자동검사 증거는 `ACADEMIC-TOWER-SLICE-A-IMPLEMENTATION-v0.1.md`에 기록한다. 04·05와 묶음 milestone은 아직 구현하지 않았으므로 묶음 전체 상태는 `🟨`로 유지한다.

Slice A에서 만든 공통 작업대는 02가 두 번째 실제 사용처이므로 그때 필요한 범위까지만 일반화한다. 03의 예상 레일과 04의 결과 교체 연결도 이후 다른 연구 묶음이 생기기 전에는 학술탑 런타임 안에 둔다.

## 8. 전체 acceptance와 비목표

Node 계약:

- 5개 방 ID, 원자료 참조, 목표 표현 수 0~2, 선수 그래프에 누락·순환이 없다.
- 첫 묶음 목표 원자료는 모두 `core`이고, 221개 우선순위는 중복·누락이 없다.
- 01 뒤 02·03 병렬, 두 방 뒤 04, 04 뒤 05가 정확히 열린다.
- 첫 플레이 완료와 재플레이가 저장을 섞지 않는다.
- 방 05만으로 탑 전체 완료 상태를 만들지 않는다.

브라우저 계약:

- 375×812, 375×667, 375×640, 360×640에서 가로 overflow가 없다.
- 진입, 가장 긴 기록, 오답, 되돌리기, 완료 상태에서 44px 터치 영역을 지킨다.
- 단어 카드 열기·닫기, 기록 다시 보기, 관계 재배치, 첫 플레이·재플레이를 실제 클릭으로 확인한다.
- `/chinese-word-tactics/` 하위 경로에서 자원과 연구 묶음 데이터가 로드된다.

이번 묶음에서 만들지 않을 것:

- 학술탑 전체 완료·격파·별점·시간 제한
- 221개 후보 전체의 방 배정
- 접속 표현 번역 짝맞추기만으로 끝나는 객관식
- 음성 듣기 횟수 제한이나 오답 페널티
- 모든 문장에 유일한 문자 단위 절단 위치 강제
- 회의소·끝마을 콘텐츠 동시 구현

## 1. 한 줄 방향

> **여관은 소년에게 생긴 첫 ‘내 자리’이자, 세계를 돌아다니며 생활어를 발견하고 모으는 생활 거점이다.**

여관은 메인 전술 지역이 아니다.

1.0 본편이 `需求 / 範圍 / 符合 / 分配`처럼 의미 관계를 깊게 체험하는 곳이라면, 여관과 자유 의뢰는 `床 / 枕頭 / 蘋果 / 紅色 / 毛巾`처럼 실제 생활에서 자주 만나는 단어를 넓게 발견하는 층을 담당한다.

여관 안에서는 단어를 퀴즈로 먼저 제시하지 않는다.

> **사물이 먼저 있고, 행동이 일어나고, 그 뒤 중국어 이름이 따라온다.**

## 2. 여관 진입 UX

### 2.1 지도 아이콘을 누르면 바로 전체 화면으로 이동하지 않는다

물길마을 지도에서 `客棧` 아이콘을 누르면 먼저 기존 월드맵 문법과 같은 **작은 장소 시트**를 연다.

시트의 목적은 기능 선택이 아니라 장소 확인이다.

예:

```text
여관
客棧

방 열쇠가 생긴 돌아올 곳

여관 주인이 맡긴 방이 있다.
마을 일을 마치면 언제든 돌아올 수 있다.

[닫기]        [들어가기]
```

M4 뒤 아직 `market-core` 전이라면 문구는 다음처럼 더 가볍다.

```text
오늘부터 돌아올 수 있는 곳

여관 주인이 빈방 하나를 남겨 두었다.

[닫기]        [들어가기]
```

### 2.2 시트 안에 기능 메뉴를 넣지 않는다

입구 시트에 다음 버튼들을 한꺼번에 두지 않는다.

- 내 방
- 식당
- 게시판
- 쉬기
- 단어장
- 설정

이렇게 하면 여관이 장소가 아니라 대시보드가 된다.

입구 시트의 행동은 기본적으로 두 개뿐이다.

- `닫기`
- `들어가기`

### 2.3 `들어가기` 뒤에는 여관 전용 전체 화면을 사용한다

여관은 장기적으로 다음 기능을 가진다.

- 방 안 사물 탐색
- 생활 루틴
- 생활어 발견
- 게시판
- 여행 흔적
- 공용공간
- 이후 주방·식당·빨래 공간 확장

따라서 큰 모달 안에 계속 기능을 중첩하지 않는다.

> **팝업/시트는 장소 확인에 사용하고, 실제 생활은 전용 화면에서 한다.**

## 3. 첫 진입은 ‘내 방’으로 한다

여관에 처음 들어갈 때는 1층 공용공간보다 **소년의 방**을 먼저 보여준다.

이유는 M8 뒤 받은 방 열쇠의 서사적 의미 때문이다.

```text
방 열쇠를 받음
  ↓
여관으로 돌아옴
  ↓
방까지 안내받음
  ↓
처음으로 ‘내 방’ 전체 화면을 봄
```

플레이어가 먼저 느껴야 하는 보상은 새로운 메뉴가 아니라 다음 감각이다.

> **“이제 이 마을에 내 물건을 놓고 돌아올 자리가 생겼다.”**

첫 방 화면에서는 침대, 창문, 짐, 옷, 책상처럼 개인 생활과 직접 연결되는 사물을 자유롭게 눌러볼 수 있다.

## 4. 공간 구조

여관의 기본 공간 관계는 다음처럼 잡는다.

```text
여관
│
├─ 내 방            ← 첫 진입 / 홈
│   ├ 침대
│   ├ 창문
│   ├ 짐
│   ├ 옷
│   └ 책상
│
├─ 1층 공용공간     ← 방의 문을 통해 이동
│   ├ 여관 주인
│   ├ 식탁
│   ├ 게시판
│   └ 공용 물건
│
└─ 이후 확장
    ├ 식당 / 주방
    └ 뒤뜰 / 세면·빨래 공간
```

### 공간 이동 원칙

공간 전환을 버튼 메뉴 목록으로 만들기보다 **실제 장소의 출입 행동**으로 보여준다.

예:

- 방 안의 문을 누른다 → 1층으로 나간다.
- 1층의 계단/방 방향을 누른다 → 내 방으로 돌아간다.
- 1층 뒤쪽 문을 누른다 → 뒤뜰 또는 세면 공간으로 간다.
- 게시판 자체를 누른다 → 의뢰를 살펴본다.

따라서 플레이어는 `방 / 식당 / 게시판 / 빨래터` 메뉴를 고르는 것이 아니라 여관 안을 작은 공간처럼 오간다.

## 5. 공간별 학습 역할

### 5.1 내 방 — 개인 생활어

내 방은 **반복 노출이 강한 생활어**를 담당한다.

후보:

- 침구: `床 / 枕頭 / 被子`
- 방: `房間 / 窗戶 / 門 / 桌子 / 椅子`
- 개인 물건: `衣服 / 鞋子 / 行李 / 鑰匙`
- 행동: `睡覺 / 起床 / 穿 / 脫 / 整理 / 收拾 / 打開 / 關上`

여행을 계속하는 동안 반복해서 같은 방으로 돌아오므로, 이 단어들은 별도 반복 퀴즈 없이도 자연스럽게 다시 만날 수 있다.

### 5.2 1층 공용공간 — 사람과 공동 생활어

1층은 혼자 쓰는 물건보다 **사람과 함께 쓰는 장소·물건**을 담당한다.

후보:

- `桌子 / 椅子 / 杯子 / 碗 / 盤子`
- 식사 관련 기본어
- 여관 주인과 다른 여행자
- 편지·메모·게시판

게시판은 별도 메뉴가 아니라 1층 공간 안에 실제로 존재하는 사물로 둔다.

### 5.3 식당/주방 — 음식·과일·맛

향후 확장 시 다음 의미군을 자연스럽게 수용한다.

- 과일: `蘋果 / 香蕉 / 橘子 / 鳳梨`
- 채소·식재료
- 식기
- 맛: `甜 / 酸 / 苦 / 鹹 / 辣`
- 조리·먹기 행동

모든 음식어를 목표 퍼즐어로 만들 필요는 없다.

### 5.4 뒤뜰 / 세면·빨래 공간 — 씻기·옷·상태

로우 판타지 세계이므로 현대식 세탁기 공간이 아니라, 물통·대야·비누·빨랫줄·햇볕 같은 생활 공간으로 구성한다.

후보:

- `毛巾 / 肥皂 / 水盆`
- `洗手 / 洗臉 / 洗衣服`
- `擦 / 晾`
- `濕 / 乾`

이곳은 `젖다 → 널다 → 마르다`처럼 사물 상태 변화와 생활 행동을 함께 보여주기 좋다.

## 6. 여관과 의뢰의 어휘 역할

여관/의뢰는 본편과 다른 어휘 선정 규칙을 가진다.

### 본편 핵심어 — `target`

예:

- `需求`
- `範圍`
- `符合`
- `分配`

특징:

- 뜻을 이해해야 판을 풀 수 있다.
- 하나의 개념을 깊게 경험한다.
- 1.0→2.0에서 재사용 생애주기를 관리한다.

### 생활 수집어 — `collection`

예:

- `蘋果`
- `毛巾`
- `床`
- `紅色`

특징:

- 사물·생활·채집 속에서 자연스럽게 발견한다.
- 처음부터 능동 산출이나 퍼즐 해법을 요구하지 않는다.
- TBCL이 낮은 기본어도 적극적으로 포함한다.
- 의미 분야별 묶음으로 단어장에 축적한다.

### 재등장어 — `carryover`

예:

- 이미 1.0에서 배운 `位置 / 剩下 / 選擇 / 障礙`

특징:

- 여관·의뢰 문장이나 상황에서 자연스럽게 다시 사용한다.
- 다시 새 단어처럼 가르치지 않는다.
- 2.0에서 복잡한 문장의 익숙한 내용어가 되기 위한 다리 역할을 한다.

한 단어의 역할은 영구 고정일 필요가 없다.

예:

```text
需求
1.0 장터: target
후속 생활/스토리: carryover
2.0 회의소: 익숙한 내용어
```

반면 `蘋果`는 오랫동안 `collection`으로만 존재해도 괜찮다.

## 7. 생활어는 ‘의미 묶음’으로 모은다

생활어의 기본 학습 단위는 스테이지가 아니라 **의미 분야**다.

예:

```text
침구
床 / 枕頭 / 被子

과일
蘋果 / 香蕉 / 橘子 / 鳳梨

색
紅 / 黃 / 綠 / 藍 / 白 / 黑

씻기
毛巾 / 肥皂 / 洗手 / 洗臉
```

단어장은 생활어를 단순 발견 순서로만 나열하지 않는다.

### 장소와 의미 묶음을 동시에 기억한다

`蘋果`를 주방에서 발견했더라도 단어장에서는 다음 두 관점으로 찾을 수 있어야 한다.

- 발견 장소: `客棧`
- 의미 묶음: `과일`

### 횡단 묶음도 허용한다

특히 색깔처럼 장소 하나에 귀속되지 않는 어휘는 여러 공간을 가로질러 모을 수 있다.

예:

- 장터의 붉은 천 → `紅`
- 여관의 흰 수건 → `白`
- 과일의 노란 껍질 → `黃`
- 숲의 푸른/초록 식물 → `綠`

플레이어가 세계를 돌아다니다 보니 어느새 `색` 묶음이 채워지는 방식이 자연스럽다.

## 8. 단어 발견 방식

생활어는 화면에 미리 라벨을 붙여 놓기보다 사물을 먼저 보여준다.

예:

```text
[침대 그림]
   ↓ 터치
床
ㄔㄨㄤˊ
침대
```

행동이 가능한 사물이라면 이어서 행동 표현을 발견할 수 있다.

```text
床
  ↓
睡覺
```

```text
窗戶
  ↓
打開 / 關上
```

```text
衣服
  ↓
穿 / 脫 / 換
```

단, 모든 사물에 행동을 억지로 붙이지 않는다.

### 발견에 페널티를 두지 않는다

- 여러 번 눌러도 된다.
- 뜻을 바로 열어봐도 된다.
- 발견 순서 점수를 매기지 않는다.
- ‘몇 개 못 찾았음’으로 하루를 실패 처리하지 않는다.

여관은 탐색 공간이지 숨은그림찾기 시험이 아니다.

---

## 9. 생활 루틴

자유 탐색으로 발견한 단어는 실제 생활 상황에서 다시 등장한다.

### 밤 예시

```text
關窗
整理行李
關燈
睡覺
```

### 아침 예시

```text
起床
洗臉
換衣服
整理行李
出門
```

정해진 순서를 암기하게 하는 것이 목적은 아니다.

의미상 순서가 필요한 행동만 조건을 두고, 나머지는 다양한 순서를 허용한다.

예를 들어 `起床` 전에 `出門`할 수 없게 하는 정도는 자연스럽지만, `洗臉`과 `整理行李`의 순서를 강제할 필요는 없다.

생활 루틴은 생존 게이지나 일일 숙제로 만들지 않는다.

## 10. 첫 방문과 이후 방문을 구분한다

### 첫 방문

첫 방문의 주목적은 **열쇠 보상의 감정적 완성**이다.

- 여관 주인이 방을 알려준다.
- 내 방을 처음 본다.
- 3~5개의 대표 사물을 자유롭게 눌러본다.
- 방 문을 통해 1층으로 나갈 수 있다는 것을 알게 된다.

모든 기능을 첫 방문에 설명하지 않는다.

### 이후 방문

이후에는 방이 기본 복귀 지점이 된다.

필요에 따라:

- 생활 루틴
- 새 물건
- 여행 흔적
- 1층 게시판
- 새 NPC
- 새 생활 공간

이 조용히 추가될 수 있다.

---

## 11. 게시판과의 관계

의뢰 게시판은 세 구역 핵심 완료 뒤 1층 공용공간에 생긴다.

```text
내 방
  ↓ 문
1층 공용공간
  ↓ 게시판 터치
의뢰 보기
```

게시판이 열리기 전에도 1층 공간은 존재할 수 있다.

게시판 해금 순간에는 새로운 페이지 메뉴가 생기기보다 **벽에 실제 종이와 판이 추가되는 시각 변화**를 우선한다.

첫 의뢰는 기존 설계대로 여관 주인의 숲 채집 부탁을 기본 후보로 둔다.

이 의뢰는 자유 의뢰 루프와 함께 **첫 야외 생활어 수집 묶음**을 소개할 수 있다.

후보:

- `蘑菇`
- `草`
- `樹`
- `石頭`
- `籃子`

이 단어들은 메인 스테이지 목표어처럼 모두 깊게 판정할 필요가 없다.

## 12. MVP 범위

v1.0 여관 MVP는 공간을 한꺼번에 크게 만들지 않는다.

### 필수

1. 월드맵 여관 아이콘 → 장소 시트
2. `닫기 / 들어가기`
3. 여관 전용 전체 화면
4. 첫 진입은 내 방
5. 방 안 대표 사물 3~5개 상호작용
6. 사물에서 생활어 발견
7. 방 문 → 1층 공용공간 이동
8. 1층의 여관 주인·식탁·게시판 자리 표현
9. 게시판은 조건 전에는 비어 있거나 아직 사용하지 않는 상태
10. 지도 또는 방으로 자연스럽게 돌아가기

### 가능하면 포함

- 밤 또는 아침 루틴 1개
- 첫 생활어 의미 묶음 기록
- 여행에서 얻은 방 열쇠의 시각적 존재

### 1.0에서 보류 가능

- 별도 주방 화면
- 별도 빨래터 화면
- 여러 여행자 NPC의 상시 방문
- 영구 경제 시스템
- 식사·수면 수치
- 방 꾸미기 시스템
- 생활어 퀴즈 모드

## 13. 모바일 UX 기준

기준 기기는 iPhone 13 mini Safari 세로 화면이다.

### 방 화면

- 사물 자체가 충분히 크게 보인다.
- 터치 대상은 최소 44px 이상 확보한다.
- 모든 사물을 버튼 카드로 감싸지 않는다.
- 조사 가능한 사물에 상시 강한 테두리를 두지 않는다.
- 필요하면 첫 방문에만 아주 약한 힌트를 준다.
- 단어 정보는 사물 위를 크게 가리지 않는다.

### 공간 이동

- 문·계단 등 이동 가능한 장소의 의미가 장식과 구분된다.
- 뒤로가기 동작과 세계 안 이동을 혼동하지 않는다.
- 브라우저 뒤로가기를 눌러도 이상한 중간 상태가 남지 않도록 화면 상태를 관리한다.

### 1층

- 게시판이 UI 메뉴 버튼처럼 떠 있지 않고 실제 공간의 사물처럼 보인다.
- 게시판의 새 의뢰 표시는 상시 빨간 배지 대신 종이 한 장 추가 같은 조용한 변화로 표현한다.

## 14. 디자인 원칙

### 해야 하는 것

- 여관을 실제 장소처럼 느끼게 한다.
- 방을 소년의 홈으로 사용한다.
- 사물에서 단어를 발견하게 한다.
- 생활어는 쉬운 단어도 적극적으로 사용한다.
- 생활어는 의미 분야로 묶는다.
- 본편에서 배운 단어를 생활 문장에 자연스럽게 재사용한다.
- 공용공간을 새 생활 콘텐츠의 확장 슬롯으로 사용한다.

### 피할 것

- 여관을 기능 메뉴 대시보드로 만들기
- 방 안 모든 사물을 카드·버튼으로 보이게 만들기
- 생활어를 전부 퍼즐 목표어로 승격하기
- A1/A2라는 이유로 기본 생활어를 빼기
- 매 방문마다 같은 루틴을 강제로 수행하게 하기
- 수면·식사·청결 게이지를 핵심 진행 조건으로 만들기
- 발견 단어 수를 숙련도처럼 표시하기
- 게시판을 출석/일일퀘스트 UI로 만들기

## 15. 이후 상세 설계 순서

다음 설계는 아래 순서로 진행한다.

1. **내 방 첫 화면의 시각 구조**
   - 카메라 시점
   - 보이는 사물
   - 문 위치
   - 첫 상호작용

2. **방의 첫 생활어 묶음 확정**
   - 무엇을 `collection`으로 둘지
   - 무엇을 행동어로 연결할지

3. **1층 공용공간 구조**
   - 여관 주인
   - 식탁
   - 게시판
   - 방으로 돌아가는 동선

4. **첫 생활 루틴**
   - 밤 / 아침 중 어느 쪽을 먼저 만들지

5. **첫 게시판 의뢰**
   - 숲 채집
   - 첫 야외 생활어 묶음

6. 이후 필요할 때 주방·식당·뒤뜰/빨래 공간을 확장한다.

## 16. 현재 승인 기준

v0.2에서 다음을 기준선으로 확정한다.

- 지도 여관 아이콘은 **장소 확인 시트**를 연다.
- 시트에는 기능 메뉴를 나열하지 않고 `닫기 / 들어가기`만 둔다.
- `들어가기` 뒤에는 **여관 전용 전체 화면**으로 전환한다.
- 첫 진입은 **소년의 방**이다.
- 방은 여관의 홈이고, 공용공간은 생활 콘텐츠의 확장 세계다.
- 방과 1층은 메뉴 버튼이 아니라 **문과 공간 이동**으로 연결한다.
- 여관/의뢰의 주된 새 어휘는 본편과 다른 **생활 수집어(`collection`)**다.
- 생활어는 장소뿐 아니라 `과일 / 색 / 침구 / 씻기` 같은 **의미 묶음**으로도 축적한다.
- 기존 본편 단어는 여관/의뢰에서 `carryover`로 자연스럽게 재등장시킨다.
- v1.0 MVP는 **내 방 + 1층 공용공간**까지만 필수로 하고, 주방·빨래터는 이후 확장한다.

> **방에서 생활을 배우고, 공용공간에서 사람과 부탁을 만나고, 의뢰를 따라 다시 세계로 나간다.**

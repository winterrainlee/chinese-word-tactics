### 영 스크린 레이아웃 보정 원칙

- 3갈래 월드 트리 구조는 유지한다.
- 세 칸짜리 노드 안에서는 아이콘과 제목을 가로로 놓지 않는다.
- 지역 노드는 **상태 → 아이콘 → 한글 이름 → 한자 → 짧은 설명** 순으로 읽힌다.
- 지역 이름은 카드 폭에 맞추려고 의미를 축약하지 않고 전체 한글 이름을 유지한다.
- 390px 이하에서는 아이콘·글자·간격을 한 단계 줄이고, 360px 이하에서 한 번 더 줄인다.
- 카드 밖으로 콘텐츠가 삐져나가지 않게 노드 내부 폭을 100%로 고정한다.
- 2026-09-10 iPhone Safari 재검수에서 카드 경계, 연결선, 이름, 아이콘 정렬을 확인했다.

## 지역별 기획 깊이

### 관문 마을（關口鎮）— 길을 읽는 마을

상태: **기획 완료 / 구현 시작 전**

첫 묶음의 축:

1. `進入 / 退出`
2. `距離 / 範圍`
3. `路線 / 經由`
4. `位置 / 周圍 / 障礙` — 일반 어휘형 포함
5. `移動 / 前進 / 後退`
6. `跟隨 / 帶領`
7. 관문 핵심 시험

다음 판 `進入 / 退出`의 핵심 판정:

- 밖 → 영역 안: `進入`
- 영역 안 → 밖: `退出`
- `通過`과 달리 **같은 입구로 되돌아 나와도 `退出`은 성립**
- 정답 이동 순서를 강제하지 않고 목표 상태만 판정

### 공방 마을（工坊村）— 상태를 바꾸는 마을

상태: **1차 흐름 기획 완료 / 구현 전**

주요 축:

- `改變 / 保持`
- `增加 / 減少 / 調整`
- `集中 / 分配`
- `條件 / 允許 / 禁止`
- `維持 / 出現`
- `破壞 / 消失 / 恢復`
- 공방 핵심 시험 → `研究城` 해금

아직 장치 UI, 수치 규칙, 실제 맵은 만들지 않았다.

### 시장 마을（市集鎮）— 자원을 고르는 마을

상태: **1차 흐름 기획 완료 / 구현 전**

주요 축:

- `需求 / 足夠 / 缺少`
- `資源 / 數量 / 剩下`
- `交換 / 取得 / 獲得`
- `價值 / 效果 / 費用`
- `價格` 중심 일반 어휘형 의뢰
- `分配 / 公平`
- `付出 / 負擔`
- 시장 핵심 시험

영구 경제나 반복 파밍은 만들지 않는다. 자원은 판 안의 퍼즐 상태로만 사용한다.

### 변경 마을（邊境村）

상태: **방향 기획만 완료**

- 입장은 처음부터 가능
- 관문 마을을 선행 추천하지만 잠그지 않음
- 위험 범위·손실·경로 퍼즐 중심
- 구체 스테이지 순서와 맵은 아직 없음

### 의회 마을（議會鎮）

상태: **방향 기획만 완료**

- 입장은 처음부터 가능
- 시장 마을을 선행 추천하지만 잠그지 않음
- `接受 / 拒絕 / 支持 / 反對 / 公平` 등 관계·판단 어휘 중심
- 전술 격자 + 대화/정보 확인 혼합 예정
- 구체 스테이지 순서와 UI는 아직 없음

### 연구 도시（研究城）

상태: **역할과 해금 조건만 기획**

- 공방 마을 핵심 시험 완료 후 해금
- 초기 단계의 첫 큰 이정표
- 이전까지의 단어를 비교·조건 판단·추론 도구로 확장
- 실제 스테이지는 아직 설계하지 않음

## 업데이트 규칙

기능이나 기획을 바꿀 때 다음 세 칸을 따로 갱신한다.

1. **기획** — 규칙과 성공 조건이 문서로 결정됐는가?
2. **구현** — 코드와 데이터가 실제로 연결됐는가?
3. **검수** — 목표 기기에서 주요 흐름을 직접 확인했는가?

`구현 완료`와 `검수 완료`를 같은 의미로 쓰지 않는다.

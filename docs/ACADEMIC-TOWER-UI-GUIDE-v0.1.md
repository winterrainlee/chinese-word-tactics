# 학술탑 UI 설계 기준

2026-10-05. 실제 플레이 피드백으로 확정한 작업대 원칙과 연구실·여정 설계를 통합한다. 앞으로의 학술탑 UI 변경은 이 문서를 기준으로 삼는다. 개별 구현 이력은 [MVP](ACADEMIC-TOWER-UI-MVP-v0.1.md), [확장 계획](ACADEMIC-TOWER-UI-EXPANSION-v0.1.md), 콘텐츠 구성은 [첫 연구 묶음](ACADEMIC-TOWER-FIRST-RESEARCH-BUNDLE-v0.1.md)을 참고한다.

## 장소와 화면의 역할

학술탑은 원본을 읽고 해석·판단·복원을 직접 조작하는 장소다. 이동 격자를 사용하는 지역의 화면 규칙을 그대로 적용하지 않는다. 단어의 의미 차이가 사용자의 선택과 결과로 드러나야 한다.

| 화면 | 사용자가 하는 일 | 중심 정보 |
|---|---|---|
| 연구실 | 지금 할 연구를 고른다. | 연구 묶음, 가능한 행동, 완료한 성과를 보여준다. |
| 작업대 | 기록을 읽고 해석하거나 복원한다. | 원본과 조작 영역을 구분하고 선택 결과를 보여준다. |
| 전체 여정 | 이야기와 연구의 흐름을 돌아본다. | 같은 묶음 이름으로 이야기와 연구를 함께 보여준다. |

## 작업대의 정보 위계

- 원본 기록과 나의 해석을 명시적으로 구분한다. 직접 빈칸을 복원하는 경우에는 ‘원본에 직접 복원’, 마지막 판단은 ‘전달할 판단’으로 표시한다.
- 섹션 제목은 가운데 정렬한 22px 굵은 글씨로 표시한다. 본문은 19px, 행동 목표는 18px, 수정안 고르기는 17px로 구분한다. 갈색 세로 막대는 사용하지 않는다.
- 행동 목표는 작업 영역의 고정 제목이다. 다음 기록 안내를 일시적인 파란 상자에 넣지 않는다. ‘예상과 실제를 잇는 말’ 같은 중복 제목은 제거한다.
- 05에서는 원본의 맥락과 복원할 문장을 구분하고, 작업 문장을 중복해서 보여주지 않는다. 미선택 공란은 문자 밑줄 하나만 사용한다.
- 뜻 조회와 이전 복원 기록은 펼침 영역에 둔다. 뜻 조회는 무료이며 필요할 때 접근할 수 있어야 한다.

### 1차 경계는 문장 사이가 아니라 작업 영역 사이에 둔다

학술탑 작업대에서 사용자가 가장 먼저 알아야 하는 것은 개별 문장의 구획이 아니라 **어디까지가 가져온 기록이고 어디부터가 내가 손대는 영역인지**다.

- 원본 기록, 나의 해석, 원본에 직접 복원, 전달할 판단을 최상위 작업 영역으로 본다. 이 영역 제목은 문장·기록 번호·행동 목표보다 먼저 눈에 들어와야 한다.
- 원본은 하나의 종이 면처럼 묶는다. 원본 안에 예상/실제 또는 기록 1/2가 여러 개 있어도 각 문장에 전체 폭 구분선을 반복하지 않는다. 작은 소제목과 여백으로만 나눈다.
- 나의 해석과 복원은 원본과 다른 작업면으로 보이게 한다. 색 차이는 낮은 채도의 면 차이로 제한하며, 정답/오답 상태색과 경쟁하지 않는다.
- 선택지·빈칸·확정 버튼처럼 실제 조작물에는 테두리를 사용할 수 있다. 다만 조작물의 테두리가 원본/작업 영역의 외곽보다 더 큰 구조처럼 보이면 안 된다.
- 원본과 작업 영역 사이는 넉넉한 여백과 한 번의 큰 면 전환으로 끊는다. 문장 사이의 선을 늘려 이 경계를 대신하지 않는다.
- 직접 복원 단계에서도 원래 주어진 맥락과 사용자가 채우는 문장을 분리해 보여준다. ‘원본에 직접 복원’이라는 이름은 사용자가 원문을 편집하는 단계임을 명시한다.

### 학술탑의 공간 언어

학술탑 연구실과 작업대에는 도서관 열람석에서 가져온 **짙은 무광 타공판 → 얇은 금속 레일 → 밝은 작업면**의 구조를 추상화해 사용한다. 장인골에서 올라온 수로·수차·장치 기록을 분석하는 장소라는 설정과 맞도록, 고풍스러운 서재보다 조용한 연구실·작업대에 가깝게 유지한다.

배경은 분위기를 만들되 정보 위계보다 앞서지 않는다. 특히 작은 화면에서는 장식물을 추가하기보다 타공판, 금속 경계, 종이 면의 재질 차이만 남긴다. 초록 스탠드 같은 상징물은 넓은 화면의 선택적 장식으로만 검토한다.

## 선택과 피드백

- 선택만으로 정답을 판정하지 않는다. 선택 내용을 문장에 미리 보여주고 사용자가 검토·확정한다.
- 선택 상태는 선택된 버튼·칸 자체가 이미 보여 주는 내용을 별도 문장으로 다시 읽어주지 않는다. 예: `然이 앞에 있다. 예상과 실제의 일치` 같은 재서술은 기본 화면에서 생략한다.
- 정답 뒤에는 같은 뜻의 성공 라벨·요약 카드·설명 문장을 겹쳐 쓰지 않는다. **정답 요약 1개 + 필요한 설명 1개**까지만 남긴다.
- 한 문제의 성공 피드백은 다음 문제로 넘어가지 않는다. 새 원본이나 새 문장이 열리면 이전의 `✓ 기록과 맞아` 같은 판정 문구를 지운 상태로 시작한다.
- 정답 뒤 설명에서 이전 스테이지의 유사 표현과 비교가 학습 판단에 도움이 되면, **현재 표현의 역할 1문장 + 이전 표현과의 공통점·차이 1문장**으로 붙인다. 비교를 위한 비교는 하지 않으며 새 카드나 긴 해설을 추가하지 않는다.

- 정답과 오답은 색뿐 아니라 기호와 문구로 함께 표시한다. 잘못된 선택은 지우지 않는다.
- 검토 뒤에는 틀린 조작에 포커스를 둔다. 여러 곳이 틀리면 첫 번째로 이동한다. 정답이면 결과 안내에 포커스를 둔다.
- 같은 기록 안에서 다음 작업으로 넘어가면 해당 작업을 보여준다. 새로운 원본으로 넘어가면 원본 시작을 보여준다.
- 필요한 선택지는 다음 단계가 열릴 때 자동으로 펼친다. 특히 04의 두 결과 검토 뒤에는 관계 표현 선택이 바로 보여야 한다.
- 04-01은 생기지 않은 예상과 실제 결과를 함께 선택한다. 이후 관계 표현 선택은 별도 단계로 드러낸다.
- 02는 실제 보고 문장의 고칠 부분을 직접 고른다. 03의 원본에는 골라야 할 果然/竟然을 미리 넣지 않는다.
- 되돌리기, 재진입, 첫 플레이와 재플레이의 저장 분리를 유지한다.

## 연구실

‘학술탑 / 學術塔 · 연구실’ 아래에 연구 묶음 ‘방향이 바뀌는 문장’을 표시한다. 진행 중에는 연구 수와 안내를, 결과 이야기를 마친 뒤에는 ‘연구 완료 · 첫 관찰 메모를 보관했어.’를 표시한다. ‘탑 전체 완료 조건 없음’이라는 운영 규칙은 노출하지 않는다. 다섯 연구를 끝냈어도 결과 이야기를 보지 않았다면 이를 확인하도록 안내한다.

| 구분 | 포함 연구 | 안내 |
|---|---|---|
| 첫 기록 | 01 수로 이용 검토 | 첫 연구를 시작한다. |
| 두 갈래 연구 | 02 장치 복구 검토, 03 예상과 실제 | 어느 쪽부터 해도 된다. |
| ↳ 곁가지 연구 | 색인 옆의 메모 | 02·03에서 파생된 선택 연구다. 기본 연구 완료에는 필요하지 않는다. |
| 기록 종합 | 04 예상 대신 생긴 결과, 05 접속어 복원 | 두 갈래 연구를 마친 뒤 이어간다. |

### 선택 연구는 ‘옆방’으로 배치한다

학술탑의 선택 연구는 별도의 최하단 목록으로 모으지 않는다. **어떤 본선 연구에서 질문이 갈라져 나왔는지**가 위치만으로 읽히도록, 직접 선행 연구가 속한 묶음 바로 아래에 작은 옆방으로 붙인다.

- 선택 연구 데이터는 `sideGroup`으로 어느 본선 묶음의 옆방인지 명시한다. 현재 연구실 그룹 ID는 `first / branch / synthesis`를 사용한다.
- 같은 본선 묶음에서 여러 선택 연구가 파생되면 같은 `sideGroup`을 사용해 하나의 옆방 묶음 안에 함께 놓는다.
- 선수 조건(`requires`)은 잠금 규칙을 담당하고, `sideGroup`은 화면에서 어디에 붙을지를 담당한다. 둘을 서로 대신하지 않는다.
- 옆방은 본선 층보다 폭을 좁게 하고 한쪽으로 붙여, ‘다음 층’이 아니라 현재 층에서 갈라진 공간으로 보이게 한다.
- 옆방 제목은 `곁가지 연구`로 통일하고, 개별 선택 연구의 내부 번호(예: 03A)는 화면에서 노출하지 않는다.
- 본선 진행선은 옆방을 지나더라도 끊기지 않는다. 선택 연구를 하지 않아도 다음 본선 묶음의 잠금·완료 규칙은 변하지 않는다.
- `sideGroup`이 없는 선택 연구는 예외적으로 별도 곁가지 묶음으로 둔다. 이 경우에는 왜 부모 묶음을 지정할 수 없는지 설계 문서에 남긴다.

현재 `색인 옆의 메모(03A)`는 02와 03을 모두 선행 조건으로 가지므로 `두 갈래 연구`의 옆방에 둔다. 이는 03 하나의 하위 스테이지가 아니라 **02·03을 함께 본 뒤 생긴 관찰**이라는 관계를 시각적으로 보존한다.

본선 연구 카드는 한국어 제목, 목표 표현, 상태를 중심으로 구성하고 중국어 부제는 목록에서 생략한다. 완료 카드에는 ‘✓ 연구 완료’를 표시하며 누르면 다시 연구한다. **곁가지 연구의 옆방 카드는 더 가볍게 취급해 `+`, 표현명, 상태 문구를 노출하지 않고 스테이지 이름만 한 줄로 표시한다.** 완료·잠금 상태는 카드의 색과 비활성 상태로만 드러내며, 접근성 라벨에는 상태를 남긴다. 선택 연구의 내부 ID와 03A 번호는 유지하되 화면에는 노출하지 않는다.

상단의 중복 路 버튼은 제거한다. 하단에는 ‘월드맵으로’와 ‘이야기와 연구 기록’을 둔다. 연구실 진입 시 내부 목록은 처음부터 보여준다.

## 전체 여정

‘학술탑 · 계속되는 연구’ 아래에 ‘방향이 바뀌는 문장’과 ‘색인 옆의 메모 · 선택 연구’를 둔다. 같은 지역명 ‘학술탑’을 두 번 반복하지 않는다. 각 묶음은 연구 수와 이야기 수를 따로 표시한다. 잠금·공개 조건은 기존 콘텐츠 정의를 따른다.

연구실에서 기록 버튼을 누르면 전체 여정의 학술탑 묶음을 펼치고 ‘전체’ 필터로 이동한다. 다른 지역의 연습 이동은 기존 스테이지 필터를 유지한다. 기본 연구의 목록에는 ‘두 갈래 연구’와 순서 자유 안내, ‘기록 종합’ 구분을 표시한다. 이 구분은 추천 흐름을 설명하며 새로운 잠금 조건을 만들지 않는다.

## 신규 학술탑 스테이지의 고정 계약

앞으로 학술탑에 추가되는 모든 연구·스테이지는 이 문서의 공간 언어와 작업 영역 위계를 기본값으로 사용한다. 새 콘텐츠라는 이유로 별도의 카드형 작업대나 다른 시각 문법을 만들지 않는다.

필수 계약은 다음과 같다.

- 화면의 1차 구조는 반드시 **원본 영역 → 사용자 작업 영역**으로 읽혀야 한다.
- 사용자 작업 영역의 이름은 기본적으로 `나의 해석`, `원본에 직접 복원`, `전달할 판단`, `원본에서 관찰` 계열 중 실제 행동에 맞는 것을 쓴다.
- 새로운 작업 유형이 필요하면 먼저 기존 네 계열 중 하나로 설명 가능한지 검토한다. 정말 다른 인지 행동일 때만 새 영역 이름을 추가하고 이 문서에 먼저 정의한다.
- 여러 문장·기록·예상/실제가 있어도 원본은 한 장의 자료처럼 묶는다. 문장마다 독립 카드나 전체 폭 구분선을 반복하지 않는다.
- 선택지·빈칸·판정처럼 상호작용이 필요한 요소만 내부 컨트롤 외형을 가진다.
- 타공판·금속 레일·밝은 작업면의 연구실 공간 언어는 학술탑 공통 배경으로 유지한다. 개별 스테이지 장식이 이 공간 구조를 덮지 않는다.
- 선택 연구를 추가할 때는 관련 본선 묶음의 `sideGroup`을 지정하고 기존 옆방 패턴을 재사용한다. 선택 연구만 모은 별도 최하단 구역을 기본값으로 만들지 않는다.
- 가능한 한 `academicOriginal`, `data-academic-zone="work"`, `data-academic-work-kind` 등 기존 작업대 구조와 스타일을 재사용한다. 스테이지별 일회성 CSS로 같은 위계를 다시 만들지 않는다.
- 예외가 필요하면 구현 전에 이유와 대체 위계를 이 문서 또는 해당 연구 묶음 설계 문서에 남긴다.

신규 스테이지 자동검사에는 최소한 원본 영역과 작업 영역이 각각 존재하는지, 작업 유형이 올바르게 표시되는지, 기존 모바일 작업대 높이·스크롤·44px 터치 계약을 깨지 않는지 포함한다.

## 검증 기준

이번 반영에서는 빠른 콘텐츠 게이트, 전체 여정 브라우저 검사 17개, 학술탑 01–05 완주·재플레이·재진입, 모바일 네 크기 검사를 통과했다. 연구실에서 전체 필터로 여정을 열고 이야기와 두 연구 묶음을 확인하는 검사를 추가했다. 실기기 확인은 아직 남아 있다.

기존 저장으로 미진입·분기 진행 중·기본 완료·선택 연구 완료 상태를 확인한다. 연구실에서 여정으로 이동할 때 이야기와 연구가 함께 보이는지, 선택 연구의 공개 조건과 재플레이 저장이 유지되는지 확인한다. 모바일 세로 화면의 넘침, 내부 스크롤 초기화, 44px 터치 영역을 검사한다. 실기기 승인은 자동 검사와 구분한다.

# 상태 메시지 언어 UX 규칙 v0.1

작성일: 2026-09-12  
상태: 1.0 적용

## 목적

전술 화면의 상태 메시지는 공략을 자동으로 번역해 주는 창이 아니라, 플레이어가 **중국어를 먼저 읽고 판의 변화와 연결하는 학습 피드백**이어야 한다.

동시에 조작법이나 오류까지 중국어 독해 문제로 만들면 게임 사용성이 무너진다. 따라서 메시지의 역할에 따라 언어 표시 방식을 나눈다.

## 기본 원칙

### 1. 세계 상태·행동 결과·학습 단어의 성립

중국어를 먼저 보여준다. 한국어는 같은 메시지의 `뜻` 버튼을 눌러야 나타난다.

예:

```text
還沒接近石碑。                     [뜻]
```

뜻을 열면:

```text
還沒接近石碑。                     [접기]
아직 비석에 접근하지 않았어.
```

새 상태 메시지가 생기면 한국어 뜻은 다시 접힌 상태로 시작한다.

적용 대상 예:

- `接近`, `通過`, `進入`, `退出` 등 핵심 단어가 실제 판에서 성립하거나 성립하지 않은 상태
- 장치·수량·장소처럼 판의 현재 상태를 확인한 결과
- 문이 열림, 장애물이 치워짐, 물이나 바람이 변함 같은 세계 변화
- NPC/환경 반응 중 플레이 의미를 해석하는 문장

한국어는 번역까지만 제공한다. 다음 행동 순서나 정답을 추가로 설명하지 않는다.

### 2. 조작·제약·입력 모드

한국어를 즉시 보여준다. `뜻` 버튼을 만들지 않는다.

적용 대상 예:

- 먼저 캐릭터를 누르라는 안내
- 한 번에 한 칸만 이동할 수 있다는 조작 규칙
- 수레와 캐릭터의 충돌 때문에 입력이 불가능한 경우
- 살펴보기/이동 모드 전환
- 되돌리기 완료
- 수레가 자동으로 따라오는 등 스테이지 조작법

이 정보는 중국어 실력을 시험하는 대상이 아니라 사용자가 게임을 정상적으로 조작하기 위한 인터페이스다.

### 3. 시스템·저장 오류

항상 한국어를 즉시 보여준다.

예:

```text
진행 상태를 저장하지 못했어. 이 탭에서는 계속 플레이할 수 있어.
```

저장, 브라우저, 데이터 복구 같은 시스템 문제는 학습층과 분리한다.

## 구현

`src/ux-play-runtime.js`가 공통 표시 정책을 맡는다.

- 이미 중국어+한국어로 작성된 학습 메시지는 중국어와 한국어를 분리한다.
- 중국어는 항상 보이고 한국어는 `뜻` 뒤에 숨긴다.
- 일부 기존 런타임의 한국어 전용 세계 상태 문구는 `normalizeLearningFeedback()`에서 중국어 우선 메시지로 승격한다.
- 개별 기믹 런타임은 조작 정책을 직접 구현하고, 공통 UX 층은 표시 정책을 담당한다.

현재 공통 승격 대상은 다음과 같다.

- 비석에 아직 `接近`하지 않은 상태
- 장터에서 특정 장소의 상태를 확인한 결과
- 문이 열려 수레가 `通過`할 수 있는 세계 상태

## 자동 감사

`tools/status-language-audit.cjs`가 모든 `src/*.js`의 리터럴 `setStatus()` 메시지를 검사한다.

분류:

- `bilingual-learning`: 중국어+한국어 학습 피드백
- `chinese-only`: 중국어 단독 피드백
- `korean-only:OPERATIONAL`: 즉시 읽어야 하는 조작·시스템 안내
- `korean-only:UX-NORMALIZED`: 공통 UX 층에서 중국어 우선으로 승격되는 기존 문구
- `korean-only:REVIEW`: 아직 어느 층에도 명시적으로 분류되지 않은 문구

`REVIEW`가 하나라도 생기면 CI를 실패시킨다. 새 상태 메시지를 추가할 때는 의도적으로 학습층 또는 조작/시스템층 중 하나를 선택해야 한다.

## 1.0 판단 기준

메시지를 작성할 때 다음 질문 하나로 먼저 나눈다.

> 이 문장을 이해하지 못하면 **중국어 학습 기회**를 놓치는가, 아니면 **게임 조작 자체**가 막히는가?

전자라면 중국어 우선 + `뜻`, 후자라면 한국어 즉시 표시를 사용한다.

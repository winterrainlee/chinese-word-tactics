## 0. 설계의 출발점

**세계는 화면보다 오래 살아남아야 한다.**

- **고정 세계:** 지형·위치·건물·교량·도로·물길 및 이들 사이의 관계.
- **시점에 따른 실제 상태:** 큰비의 전후, 통행 제한, 관리 점검 등. 과거 장면을 다시 읽는 것과 현재 월드맵의 상태는 별개다.
- **소년의 지식:** 직접 확인한 곳, 들은 이야기, 기록으로 검증된 사실, 아직 모르는 사항.
- **화면:** 현재 수채화 삽화 지도, 추후 격자 지도·경로 지도·사건 지도. 어느 화면도 세계 데이터 자체를 소유하지 않는다.

기본 의존 방향:

~~~text
세계 데이터 (spaces / terrain / features / networks / places)
                 +
진행 상태에서 파생한 사건 상태  +  소년이 확인한 지식
                 |
          공통 조회·구성 계층
                 |
     ┌───────────┼───────────┐
  현재 삽화     격자·조사     경로·물류
  월드맵         지도          지도
~~~

스테이지별 기존 격자는 이 데이터와 **다른 해상도의 국소 전술 공간**이다. G1~G7의 칸 좌표가 월드 격자 칸에 일대일 대응할 필요는 없다. 특정 스테이지가 어떤 세계 시설/경로를 묘사하는지만 안정된 ID로 연결할 수 있다.

## 2. 공간을 세 규모로 분리한다

| 규모 | 무엇을 관리하나 | 1차 적용 |
|---|---|---|
| **세계 연결망(world graph)** | 서로 다른 정착지·외부로 향하는 노선. 아직 그려지지 않은 공간도 연결 가능 | 물길마을 ↔ 끝마을 ↔ 이후 대도시 방향. 정확한 노선과 거리는 보류 |
| **지역 공간(local space)** | 실제 지형 격자, 강·길·다리의 형상과 연결, 주요 장소 범위 | 물길마을 삽화가 묘사한 생활권. 외부의 끝마을 자체를 삽화 안에 억지로 넣지 않음 |
| **현장·스테이지(local scene)** | 수문 B~C 사이, 다리 점검 지점, G7 수레 이동 등 세밀한 현장 | 기존 전술판·04A 관측 구조를 유지. 상위 공간의 featureId를 선택적으로 참조 |

처음부터 국가 전체의 단일 초대형 격자를 만들지 않는다. 각 지역 공간은 별도 좌표계/격자를 사용하고, 이웃 공간과의 이동은 연결망이 담당한다.

## 3. 좌표계와 격자 — 화면 좌표를 복제하지 않는다

- **세계 좌표:** 지역 공간마다 독립된 연속적인 2D 좌표 공간을 둔다. 그림 픽셀이나 CSS %를 권위 있는 지리 좌표로 사용하지 않는다. 초기 좌표의 단위는 **편집용 임의 단위**이며 실제 미터·거리·고도·방향을 뜻하지 않는다.
- **격자:** 연속 좌표 공간을 일정한 행·열로 샘플링한 **넓은 지형의 관리·조회층**이다. 격자 해상도를 바꿔도 장소/길/수로의 고유 ID는 바뀌지 않아야 한다.
- **화면 변환:** 각 삽화·격자·경로 화면마다 세계 좌표 → 화면 좌표를 계산하는 별도 변환 정의를 둔다. 현행 삽화의 좌표는 처음에는 기존 x/y를 그대로 유지하고 기준점 보정은 수동으로 검토한다.
- **방향과 거리:** 그림의 위·아래와 실제 북·남, 격자 칸 수와 실제 여행 거리, 그림의 강선과 정확한 수문학적 흐름을 동일시하지 않는다.

**첫 격자 시험 후보: 32열 × 57행(1,824칸).** 20×36은 빠르지만 다리·강변이 거칠 수 있고, 40×71은 작업량이 늘어난다. 세 가지를 실제 삽화 위에 겹쳐 본 뒤 해상도를 확정한다. 32×57은 데이터 표준이나 세계관 사실이 아닌 비교를 위한 시안이다. 파일 저장 형태는 사람이 관리하기 쉬운 원본 편집 형식과, 필요한 경우 생성하는 압축된 실행용 배열을 구분한다.

한 칸에는 모든 것을 단일 문자로 압축하지 않는다. 최소한 다음이 독립적으로 겹칠 수 있어야 한다.

- **기본 지형(terrain):** 물, 평지, 숲, 경사지 등. 아직 정확히 구별하기 어려운 곳은 unknown 허용.
- **지형 속성(attributes):** 높이대·범람 가능성·연약 지반 등은 확인된 경우에만. 삽화만으로 정확한 높이·수위를 만들지 않는다.
- **시설 및 구역(features):** 건물·교량·수문·수차·길목·장터 등은 고유 ID와 점/선/면의 형상을 가진다.
- **사건 결과(event state):** 침수 흔적, 잔해, 통행 제한은 기본 지형을 수정하지 않고 해당 시설·구간에 덧씌운다.

## 4. 도로·물길은 격자와 별도 연결망으로 기록한다

도로와 하천은 그림 위의 선이면서 **이어지는 관계**다. 단순히 이웃 격자 칸이 모두 연결된 것으로 판정하지 않는다.

- **도로망:** node(갈림길·초소·교량·출입구), edge(그 사이의 통행 구간), edge가 허용하는 이동 방식(보행·경량 손수레·무거운 수레). 실제 제한은 사건 상태로 덮어쓴다.
- **물길망:** node(합류부·분기·수문·관측점), edge(자연 하천·인공 수로). 물의 방향·관측 시점·자료 출처를 보존하며 미확인 연결은 미확인으로 둔다.
- **교량:** 도로망의 통행 관계와 물길의 횡단 관계를 참조하는 별도 시설이다. 물길 위를 지나간다고 두 망이 서로 연결되지는 않는다.
- **관측과 가설:** 정확한 경로가 불명확하면 연결을 억지로 이어 닫지 않는다. 연결 상태 unknown, 위치 후보, 근거 자료 링크를 허용한다.

끝마을에서 외부 교역 지역으로 향하는 일부 구간의 무거운 수레 양방향 임시 제한은 **2장 이야기에서 채택한 조건**이다. 어느 격자 칸을 통과하는지, 정확한 위험 위치·허용 적재량·운송량은 아직 설계하지 않았다. 지역 공간의 바깥이면 세계 연결망의 구간 속성으로 나타낸다.

04A의 D는 또 다른 사례다. **B와 C 사이 인공수로 측벽에 있고 물 일부가 바깥 수풀 아래로 흐른다**는 사실은 실제 연구에서 확인됐다. 그러나 그 다음 목적지는 알 수 없으므로 목적지가 정해진 새 하천 edge를 만들면 안 된다. 03B의 옛 지도는 자료, C+D(임시 보수 통로+잊힌 옛 물길)는 후속 이야기 후보이지 현재 물길의 확정 지리 데이터가 아니다.

## 5. 실제 세계·사건·지식을 별도로 관리한다

### 5.1 정적 사실(배포물의 세계 데이터)

각 지형·장소·망 구성 요소에 안정 ID와 최소 출처/상태를 부여한다.

- 확정 설정: WORLD-v0.6의 마을 구조와 실제 구현에서 확인되는 사실.
- 삽화 참고: 그림에 강·다리·건물처럼 **보이는 형상**. 그림만 보고 고도, 물의 방향, 실제 이용 도로, 취수관계를 확정하지 않는다.
- 설계 후보: 앞으로 승인받아야 할 지형·시설·위치.
- 미확인: 알려지지 않은 연결·종착지. 빈 값 또는 unknown을 허용해 허구의 연결을 채우지 않는다.

### 5.2 사건 오버레이(현재 세계 상태)

기준 지형은 유지하고, 큰비를 겪은 뒤에는 별도 변화 목록을 적용한다.

~~~json
{
  "id": "chapter2-after-rain",
  "when": { "event": "rain-passed" },
  "changes": [
    {
      "featureId": "corridor:border-outside-limited",
      "property": "heavyCartPassage",
      "value": "temporarily-restricted"
    }
  ]
}
~~~

**예시 구조이며 featureId는 신규 예약 ID가 아니다.** 실제 지형 확정 전에는 정확한 위치를 요구하지 않는다. rain-passed는 임의 저장 플래그를 추가하지 않고 기존 JourneyProgress.hasRainPassed의 판정으로 해석한다. 비가 내린 뒤 수로 전체가 침수 중이라고 표시하거나 1장 해결을 미완료로 돌리지 않는다.

서로 다른 시점의 장면도 구분한다. 1장 스테이지의 재플레이는 **당시 장면의 상태**를 써야지, 현재 월드맵이 큰비 이후라고 1장 전술판까지 수정하지 않는다.

### 5.3 소년의 지식·표시 가능 여부

세계에 존재하는 시설과 지도에 나타나는 표식은 다르다. 출처가 있는 실제 **관찰/연구 기록**을 확인한 뒤 플레이어에게 보일 수 있다. 단지 같은 장에 도달했다는 사실을 특정 발견의 근거로 삼지 않는다.

예: D 샛구멍은 04A 이전에도 세계에는 존재하지만, 발견하기 전 월드맵에 정답 아이콘으로 표시되지 않는다. 04A 진행 중 발견 상태와 실제 완료 상태도 구분할 수 있어야 한다. 처음에는 기존 story/stage/sideResearchProgress를 읽어 표시를 파생하고, 저장 필드를 늘리는 것은 새 사용 사례가 생긴 뒤 별도 설계한다.

현장 관측, 자료 기록, 소문의 구별도 보존한다. 세계 데이터가 미확정 가설을 실제 물길로 표현해서는 안 된다.

## 6. 제안하는 데이터 책임과 최소 개념 스키마

~~~text
WorldCatalog
  ├─ settlements / places         이름·지역 ID·소속
  ├─ spaces                        지역 공간의 좌표계와 범위
  │    ├─ terrainGrid             기본 지형·알려진 속성
  │    ├─ features                시설, 다리, 구역
  │    ├─ roadNetwork             node / edge / 이동 수단
  │    └─ waterNetwork            node / edge / 분기·합류
  ├─ connections                  지역 밖으로 이어지는 노선
  └─ presentationProfiles         삽화별 자산·투영·마커 앵커

WorldStatusResolver(progress, sceneContext)
  ├─ story 기반 사건 오버레이
  ├─ 시설·경로의 실제 적용 상태
  └─ 아직 확정하지 않은 상태는 unknown

WorldKnowledgeResolver(progress)
  └─ 관측·기록·발견에 따른 노출 가능 사실

WorldViewModel(worldStatus, knowledge, presentationProfile)
  ├─ 현재 그림지도
  ├─ 개발용 격자·요소 조사 화면
  └─ 미래 경로·사건 지도
~~~

필드는 제안된 **책임 분할**이지 확정된 파일 형식/JS API가 아니다. 저장/불러오기·격자 압축·편집기 선택은 G2에서 데이터 샘플을 만든 뒤 결정한다. 현행 WORLD.regions ID와 여정 ID는 바꾸지 않는다.

## 7. 물길마을에서 먼저 등록할 대상

| 대상 | 첫 자료 근거 | G1에서 할 일 |
|---|---|---|
| 여섯 현행 마커 | src/world-v06-content.js | 그림 앵커를 보존하고 지역 내 시설/구역인지 외부 방향 표식인지 구분 |
| 큰 자연 물줄기와 합류부 | WORLD-v0.6 + 그림 | 시각적 물 영역을 임시 격자로 추적하되 세 물줄기의 이름·정확한 합류 관계는 미정으로 표시 |
| 중앙의 다리·관문 접근로 | 그림 + WORLD-v0.6 | 다리 그림 위치와 실제 통행 edge를 별도 기록, 임의 붕괴를 부여하지 않음 |
| 장인골~학술탑 수계 | 04A 실제 관측 + 수계 초안 | 확인된 B/C/D 상대 관계부터 등록, 전체 수계를 자동 연결하지 않음 |
| 장터·회의소 생활권 | WORLD-v0.6 | 영역 후보/현행 POI를 분리, 범람·침수 범위 확정 금지 |
| 바깥 끝마을 방면 | G7 후일담 + 2장 스토리라인 | 방향/외부 연결을 우선 정의, 삽화 바깥 실제 정착지 좌표를 만들지 않음 |

**지형 좌표를 등록하는 작업은 세계관 설정을 확정하는 작업이기도 하다.** 그림에서 보이는 것과 서사에서 확정한 것을 자동으로 동일시하지 않는다. 불명확한 부분을 unknown으로 남기는 편이 임의로 만든 수로보다 낫다.

## 8. 이행·호환 원칙

1. G0(이번 문서): 역할·기준·비목표와 후보 해상도만 제안. 런타임·월드맵·저장 미변경.
2. G1: 현행 삽화 위 격자 20×36 / 32×57 / 40×71을 비교하는 **개발용 표시층**을 시험한다. 원본 지도와 여섯 POI의 위치·이야기 진행은 변하지 않는다.
3. G2: 수작업으로 확인한 강·다리·도로·시설의 작은 표본부터 공간 데이터로 기록한다. 표시된 칸/선 선택 시 ID·출처·확실성·연결 관계를 볼 수 있어야 한다.
4. G3: 같은 데이터에서 삽화형과 격자형 표시를 생성할 수 있는 조회 계층을 소규모로 구현한다. 기존 world-runtime의 화면을 일괄 교체하지 않는다.
5. G4 이후: 2장의 우천 상태 등 사건 오버레이를 시험하고, 선택 연구의 발견 표시를 검증한다. 세계 간 연결은 3장의 대도시가 실제로 필요할 때 확장한다.

초기에는 **코드/JSON으로 배포하는 정적 세계 자료 + 기존 진행 기록에서 계산하는 상태**면 충분하다. 매 칸의 현재 상태를 LocalStorage에 복제해서 보관하지 않는다. 새 저장 키·백업 포맷 버전·전역 물리 엔진은 우선 도입하지 않는다.

### 검증할 불변 조건

- 큰비 전/후, 1장 재플레이, 구형 저장 복원에서 기존 완료·학술탑 선수·G7 경로·04A 결과가 바뀌지 않는다.
- 격자선·개발 편집 모드 OFF면 현행 그림·아이콘·터치 동작이 그대로다.
- 장소와 도로·물길 ID는 격자 크기, 화면 너비, 그림 자산 교체로 바뀌지 않는다.
- 도로 연결·하천 분기·교량 횡단을 혼동하지 않는다. 미확인 연결은 오류나 무리한 연결 대신 명시적 미확인으로 표현한다.
- 우천 상태는 기존 큰비 판정과 일치하며, 시점이 다른 기록을 섞지 않는다.
- 04A 미진행/진행 중/완료한 상태에 따라 실제 확인한 정보만 표시한다. C+D의 역사 가설은 확인된 지형으로 승격되지 않는다.
- 현행 다섯 저장 영역의 내보내기·복원 형식과 이전 백업의 호환성을 유지한다.
- iPhone 세로 화면에서 격자 개발 표시층이 터치 대상·지역 정보·지도 조작을 가리지 않는다.

## 9. 다음 검토에서 결정할 항목

**바로 결정하고 시험할 것:** 격자 크기 후보 비교, 최소 지형 종류, 단일 공간의 범위, 각 지형·시설의 근거 표기 방식, 작은 연결망 예시, 지도 위 개발용 격자 표시/숨김.

**실제 그림과 이야기 근거를 본 뒤 결정할 것:** 다리와 도로의 정확한 연결, 물길의 굴곡과 합류, 높이대·범람 영역, 특정 시설의 우천 피해.

**아직 하지 않을 것:** 홍수·유량·침수의 자동 물리 시뮬레이션, 월드 전역 자동 길찾기, 이동 시간·식량 소모 시스템, 대도시의 정확한 위치, 새로운 지도 그림 제작, 필수 본편·04A의 해금 변경, 기존 스테이지 격자의 일괄 변환.

### G1 종료 시 원하는 결과물

현행 삽화 위에서 격자를 켜고 끌 수 있고, 손가락으로 칸 또는 선을 선택하면 **어느 지형·시설·연결인지, 무엇을 근거로 아는지, 무엇은 아직 모르는지** 확인할 수 있는 읽기 전용 시험판. 최초 범위는 **물길마을의 큰 물길과 다리, 여섯 지역 마커**이며, 실제 통행·우천 판정은 별도 승인 후 연결한다.

## 10. 2026-11-01 · G1 읽기 전용 시험판 (구현·배포 검증 별도)

별도 실험 경로 **/chinese-word-tactics/world-grid-test/** 에 현재 월드맵 삽화를 불러와 다음 항목을 비교하는 개발용 화면을 추가했다. 본편에 들어오지 않아도 열 수 있으며 기존 게임 화면·저장·월드맵 삽화를 변경하지 않는다.

- 세 격자 후보 **20×36 / 32×57 / 40×71**을 전환한다. 32×57은 초기 표시 기본값이지 지형 표준의 확정이 아니다.
- 물길·도로의 **육안 추적선 후보**와 다리 위치 후보를 지도 위에 겹쳐 보여준다. 추적선은 각 그림 위치를 참고한 **후보**이며 실제 수계 연결, 방향, 고도, 피해 범위를 뜻하지 않는다.
- 실제 게임에 사용되는 여섯 장소 마커는 **기존 화면 백분율 좌표**를 그대로 가져온다. 외부 끝마을 방향 표식을 지도 속 정착지의 실제 좌표로 해석하지 않는다.
- 칸을 선택하면 좌표와 가까운 후보 선/점을 보여준다. 후보가 없는 칸은 **미분류**로 표시하며 '평지'나 '안전'이라고 추정하지 않는다.
- 파일 분리: **data/world-spatial-illustration-trace-v0.1.json**(검토 데이터), **src/world-spatial-prototype.js**(DOM 없는 순수 조회 로직), **world-grid-test/**(화면).
- 정적 데이터와 진행 상태를 섞지 않았다. localStorage 및 기존 백업 형식에 새 값을 쓰지 않는다.
- 검증: **tests/world-grid-prototype.test.cjs**(격자·근접 후보·원래 마커 좌표·미확정 보존), **tests/smoke_world_grid.py**(실제 원본 WebP 로딩·모바일 3종·탭·격자 변경·켜기/끄기·저장 미사용). CI에 연결했다.

**범위 주의:** 이 첫 실험은 실제 지형 격자 데이터의 제작 전 단계인 **삽화 추적·해상도 비교**다. 데이터의 후보 선·점은 월드 실제 지형으로 승인되지 않았고, 임시 연결선이 실제 도로·물길 연결망을 대체하지 않는다. 이후 원본과 추적 후보를 사용자와 비교하여 필요한 선을 조정하고, 근거가 확인된 곳부터 월드 지역 공간으로 승격한다.

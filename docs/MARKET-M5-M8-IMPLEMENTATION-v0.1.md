## 1. 후반 학습 흐름

장터 후반은 다음 순서로 이어진다.

```text
M5 價值 / 選擇
가격과 용량을 함께 보고 두 유효한 선택 중 하나를 고른다.
↓
M6 放棄
운반 한도가 있을 때 하나를 먼저 고르고 다른 하나를 다음 차례로 미룬다.
↓
M7 分配 / 補充
여러 물건을 각 장소의 필요에 맞게 나누고 부족분을 채운다.
↓
M8 종합
需求 / 剩下 / 交換 / 買 / 分配를 새 규칙 없이 조합한다.
```

M5부터는 한 가지 정답을 고르는 판에서 벗어나기 시작한다. M5와 M6의 선택은 우열 점수 없이 모두 유효한 완료로 취급한다.

---

## 2. M5 `어느 것이 나을까`

핵심어: `價值 / 選擇`, 재사용 `價格`

### 상태

- 예산: 동전 8
- 옮길 짐: 3개
- 작은 바구니: 가격 3, 운반 한도 2
- 큰 나무상자: 가격 6, 운반 한도 3

두 도구를 모두 살펴본 뒤 하나를 선택한다.

### 두 유효한 해결

작은 바구니:

- 남은 돈 5
- 운반 한도 2
- 두 번에 나누어 운반

큰 나무상자:

- 남은 돈 2
- 운반 한도 3
- 한 번에 운반

시간·턴 보너스나 별점은 없다. 어느 쪽도 더 좋은 정답으로 표시하지 않는다.

후일담은 최초 선택을 반영한다.

- 바구니: 돈을 더 남기는 대신 한 번 더 오감
- 나무상자: 돈을 더 쓰는 대신 한 번에 끝냄

공통 결론은 다음과 같다.

> `價格`은 얼마를 내는지이고, `價值`는 지금 무엇을 필요로 하는지까지 함께 본다.

최초 선택 저장:

```text
market-stage-5
choice: basket | crate
```

---

## 3. M6 `짐칸은 하나뿐`

핵심어: `放棄`, 재사용 `選擇`

### 상태

- 운반 한도: 1
- 밀가루 1 → 빵집
- 등잔기름 1 → 등잔기름 좌판

플레이어는 이번 차례에 먼저 보낼 하나를 선택한다. 선택하지 않은 물건은 사라지지 않는다.

화면에서는 선택하지 않은 쪽을 다음처럼 표시한다.

```text
放棄 · 下一趟
이번에는 미루고 다음 차례
```

즉 M6의 `放棄`는 영구 폐기나 손실이 아니라 **이번 차례의 우선순위를 다른 물건에 내주는 것**이다.

최초 선택 저장:

```text
market-stage-6
chosenCargo: flour | oil
deferredCargo: oil | flour
```

후일담도 최초 선택을 반영한다. 재플레이에서 다른 선택을 해도 본편 최초 선택을 덮어쓰지 않는다.

---

## 4. M7 `제자리로 돌아갈 물건`

핵심어: `分配 / 補充`, 재사용 `需求 / 數量 / 剩下`

6×5 판을 사용한다.

필요 상태:

- 빵집: 밀가루 2 / 필요 3
- 여관: 채소 0 / 필요 1
- 등잔기름 좌판: 등잔기름 1 / 필요 2
- 창고: 천을 돌려받음

늦게 도착한 짐:

- 밀가루 1
- 채소 1
- 등잔기름 1
- 천 1

운반 한도는 2라서 최소 두 번에 나누어 움직이게 된다.

어느 순서로 분배해도 된다.

부족했던 장소가 필요한 수량에 도달하는 순간 `補充` 경험을 기록한다. 네 물건이 모두 알맞은 장소에 도착하면 `分配`가 완료된다.

잘못된 장소에 물건을 놓으려 하면 상태를 변경하지 않고 이유를 알려준다.

---

## 5. M8 `장날이 열리기 전에`

새 핵심어는 없다.

재사용 중심:

- `需求`
- `剩下`
- `交換 / 獲得`
- `買 / 價格`
- `選擇`
- `分配 / 補充`

### 시작 자원

늦게 온 짐:

- 밀가루 1
- 등잔기름 1
- 천 1

추가 조건:

- 천 1 ↔ 밧줄 1 교환 가능
- 채소 1 가격 3
- 시작 동전 5
- 운반 한도 2

### 최종 필요 상태

- 빵집: 밀가루 1
- 등잔기름 좌판: 등잔기름 1
- 장터 천막: 밧줄 1
- 여관: 채소 1

해결 순서는 저장하지 않는다. 오직 최종 세계 상태로 완료를 판정한다.

자동검사에서는 최소 세 가지 서로 다른 순서가 모두 완료되는 것을 확인한다.

M8 최초 완료:

```text
market-core
```

을 기록한다.

## 6. 공통 런타임 확장

`src/market-runtime.js` 하나를 계속 사용한다. M5~M8 전용 런타임 파일은 만들지 않았다.

새 공통 기능:

- `decisions`
- 선택에 따른 임시 운반 한도 변경
- 선택 비용 지불
- 선택 전 조건 확인
- 선택한 물건만 가져가기
- 다른 선택을 `deferred` 상태로 보존
- `all / any` 복합 판정
- 잘못된 목적지에 놓기 시도와 무변경 피드백
- 부족 상태를 채운 순간 `replenished` 기록
- 스테이지별 최초 선택 outcome 추출

M7·M8의 6열 판은 iPhone 세로 화면에서 44px 최소 터치 영역을 유지하도록 별도 셀 폭 규칙을 사용한다.

---

## 7. 저장 규칙

영구 저장:

- M5 최초 선택
- M6 최초 선택·보류 물건
- M8 `market-core`

영구 저장하지 않음:

- M5 판 내부 돈
- M5 도구의 임시 운반 한도
- M6~M8 인벤토리
- M7 분배 순서
- M8 해결 순서
- 되돌리기 이력

재플레이는 기존 본편 선택과 milestone을 덮어쓰지 않는다.

---

## 8. 검증

추가 자동검사:

- M5 두 도구 모두 완료 가능
- M5 두 도구를 확인하기 전 선택 차단
- M5 선택별 돈·운반 한도 변화
- M6 밀가루/등잔기름 어느 선택도 완료 가능
- M6 보류 물건이 삭제되지 않음
- M7 오배송 시 상태 무변경
- M7 네 물건 최종 분배
- M8 서로 다른 세 해결 순서 완료
- M5/M6 최초 선택 저장과 재플레이 비덮어쓰기
- M8 최초 완료에서만 `market-core`
- M5/M6 선택별 후일담
- M7/M8 6열 모바일 판 규칙
- M5~M8 여정 연결과 월드맵 복귀

실기기에서는 다음을 확인한다.

1. M5 선택지가 정답/오답처럼 보이지 않는가.
2. M5의 가격·용량 정보가 작은 화면에서 비교하기 쉬운가.
3. M6의 `放棄`가 삭제로 오해되지 않는가.
4. M7 6열 판의 44px 터치가 충분한가.
5. M7에서 잘못 놓았을 때 이유를 곧바로 이해할 수 있는가.
6. M8에서 원하는 순서로 푼다는 감각이 실제로 살아 있는가.
7. M8 뒤 장터가 하나의 생활 공간으로 마무리되는가.

## 1. 후반 학습 흐름

장터 후반은 다음 순서로 이어진다.

```text
M5 價值 / 選擇
가격과 용량을 함께 보고 두 유효한 선택 중 하나를 고른다.
↓
M6 放棄
운반 한도가 있을 때 하나를 먼저 고르고 다른 하나를 다음 차례로 미룬다.
↓
M7 分配 / 補充
서로 다른 부족량을 읽고 여러 물건을 필요한 수만큼 나눈다.
↓
M8 종합
需求 / 剩下 / 交換 / 買 / 分配를 새 규칙 없이 조합한다.
```

M5부터는 한 가지 정답을 고르는 판에서 벗어나기 시작한다. M5와 M6의 선택은 우열 점수 없이 모두 유효한 완료로 취급한다.

## 2. M5 `어느 것이 나을까`

핵심어: `價值 / 選擇`, 재사용 `價格`

### 상태

- 예산: 동전 8
- 옮길 짐: 3개
- 작은 바구니: 가격 3, 운반 한도 2
- 큰 나무상자: 가격 6, 운반 한도 3

두 도구를 모두 살펴본 뒤 하나를 선택한다.

### 두 유효한 해결

작은 바구니:

- 남은 돈 5
- 운반 한도 2
- 두 번에 나누어 운반

큰 나무상자:

- 남은 돈 2
- 운반 한도 3
- 한 번에 운반

시간·턴 보너스나 별점은 없다. 어느 쪽도 더 좋은 정답으로 표시하지 않는다.

후일담은 최초 선택을 반영한다.

- 바구니: 돈을 더 남기는 대신 한 번 더 오감
- 나무상자: 돈을 더 쓰는 대신 한 번에 끝냄

공통 결론은 다음과 같다.

> `價格`은 얼마를 내는지이고, `價值`는 지금 무엇을 필요로 하는지까지 함께 본다.

최초 선택 저장:

```text
market-stage-5
choice: basket | crate
```

## 3. M6 `짐칸은 하나뿐`

핵심어: `放棄`, 재사용 `選擇`

### 상태

- 운반 한도: 1
- 밀가루 1 → 빵집
- 등잔기름 1 → 등잔기름 좌판

플레이어는 이번 차례에 먼저 보낼 하나를 선택한다. 선택하지 않은 물건은 사라지지 않는다.

화면에서는 선택하지 않은 쪽을 다음처럼 표시한다.

```text
放棄 · 下一趟
이번에는 미루고 다음 차례
```

즉 M6의 `放棄`는 영구 폐기나 손실이 아니라 **이번 차례의 우선순위를 다른 물건에 내주는 것**이다.

최초 선택 저장:

```text
market-stage-6
chosenCargo: flour | oil
deferredCargo: oil | flour
```

후일담도 최초 선택을 반영한다. 재플레이에서 다른 선택을 해도 본편 최초 선택을 덮어쓰지 않는다.

---

## 4. M7 `제자리로 돌아갈 물건`

핵심어: `分配 / 補充`, 재사용 `需求 / 數量 / 剩下`

6×5 판을 사용한다.

필요 상태:

- 빵집: 밀가루 1 / 필요 3 → **부족 2**
- 여관: 채소 0 / 필요 1 → 부족 1
- 등잔기름 좌판: 등잔기름 1 / 필요 4 → **부족 3**
- 창고: 천 1을 돌려받음

늦게 도착한 짐:

- 밀가루 2
- 채소 1
- 등잔기름 3
- 천 1

운반 한도는 3이다. 총 7개를 옮기므로 최소 세 번은 짐을 나누게 된다. 한 번에 어느 조합을 들고 갈지는 플레이어가 정한다.

여기서 처음으로 부족량이 `1`로 통일되지 않는다. `1/3`, `1/4`처럼 현재 수량과 필요 수량을 비교하고, 같은 물건을 같은 장소에 두세 번 보충해야 한다.

부족했던 장소가 필요한 수량에 도달하는 순간 `補充` 경험을 기록한다. 모든 물건이 알맞은 장소에 도착하면 `分配`가 완료된다.

잘못된 장소에 물건을 놓으려 하면 상태를 변경하지 않고 이유를 알려준다.

## 5. M8 `장날이 열리기 전에`

새 핵심어는 없다.

재사용 중심:

- `需求`
- `剩下`
- `交換 / 獲得`
- `買 / 價格`
- `選擇`
- `分配 / 補充`

### 시작 자원

늦게 온 짐:

- 밀가루 2
- 등잔기름 1
- 천 1

추가 조건:

- 천 1 ↔ 밧줄 1 교환 가능
- 채소 1 가격 3
- 시작 동전 5
- 운반 한도 2

### 최종 필요 상태

- 빵집: 밀가루 **2**
- 등잔기름 좌판: 등잔기름 1
- 장터 천막: 밧줄 1
- 여관: 채소 1

M7에서 2·3개 보충을 본 뒤, M8은 종합판의 길이가 너무 늘지 않도록 빵집만 두 개가 필요하게 둔다. 따라서 플레이어는 반복 보충과 교환·구매를 한 판에서 함께 조합하지만, 단순 왕복이 과도하게 늘지는 않는다.

해결 순서는 저장하지 않는다. 오직 최종 세계 상태로 완료를 판정한다.

자동검사에서는 최소 세 가지 서로 다른 순서가 모두 완료되는 것을 확인한다.

M8 최초 완료:

```text
market-core
```

을 기록한다. 월드맵의 기존 `客棧 · 여관` 표식은 이 milestone을 읽어 `has-room-key` 상태가 되며, 처마 오른쪽에 작은 나무패와 황동 방 열쇠가 달리고 문 안쪽 빛이 미세하게 따뜻해진다. 이는 새 장소 해금이 아니라 소년에게 방 열쇠가 생겼다는 생활 흔적이다.

## 6. 판 위 수량 상태 표시

실기기 검수에서, 하단 상황 패널만으로는 이미 확인한 장소가 아직 부족한지 충분한지 판 위에서 다시 읽기 어렵다는 문제가 드러났다.

그래서 `src/market-state-visuals.js`와 `src/market-state-visuals.css`를 추가했다.

원칙:

1. **살펴보기 전에는 정답 정보를 노출하지 않는다.**
2. 한 번 살펴본 장소는 판 위에 수량 상태가 계속 남는다.
3. 필요가 있는 장소는 `현재/필요`로 표시한다.
   - 예: `1/3` → `2/3` → `3/3`
4. 부족 상태와 충분 상태는 테두리·바탕과 숫자를 함께 사용해 구분한다.
5. 짐 더미·판매 좌판처럼 공급원은 살펴본 뒤 현재 남은 총량을 `×N`으로 표시한다.
6. 물건을 가져가거나 놓아 실제 재고가 변한 장소는 짧게 반짝여 변화 지점을 보여준다.
7. 숫자 정보는 접근성 라벨에도 `현재 / 필요 / 부족 / 충분`으로 함께 들어간다.

따라서 플레이어는 `需求`을 직접 확인해야 하지만, 확인한 정보를 외워 두는 것이 퍼즐의 핵심이 되지는 않는다.

## 7. 공통 런타임 확장

`src/market-runtime.js` 하나를 계속 사용한다. M5~M8 전용 행동 엔진은 만들지 않았다.

새 공통 기능:

- `decisions`
- 선택에 따른 임시 운반 한도 변경
- 선택 비용 지불
- 선택 전 조건 확인
- 선택한 물건만 가져가기
- 다른 선택을 `deferred` 상태로 보존
- `all / any` 복합 판정
- 잘못된 목적지에 놓기 시도와 무변경 피드백
- 부족 상태를 채운 순간 `replenished` 기록
- 스테이지별 최초 선택 outcome 추출

수량 시각화는 행동 엔진과 분리한 작은 렌더 보강층으로 두었다. 따라서 이후 장터 판에도 같은 `stock / needs` 데이터만 있으면 자동으로 적용된다.

M7·M8의 6열 판은 iPhone 세로 화면에서 44px 최소 터치 영역을 유지하도록 별도 셀 폭 규칙을 사용한다.

## 8. 저장 규칙

영구 저장:

- M5 최초 선택
- M6 최초 선택·보류 물건
- M8 `market-core`

영구 저장하지 않음:

- M5 판 내부 돈
- M5 도구의 임시 운반 한도
- M6~M8 인벤토리
- M7 분배 순서
- M8 해결 순서
- 여관 방 열쇠 전용 boolean이나 새 save key
- 되돌리기 이력
- 판 위 수량 표시의 일시적 변화 애니메이션

재플레이는 기존 본편 선택과 milestone을 덮어쓰지 않는다.

M7·M8은 수량 구성이 바뀌었으므로 `revision`을 올려, 이전 판 내부 저장과 충돌하면 해당 스테이지의 임시 상태만 새 구성으로 초기화한다. 본편 완료 기록은 건드리지 않는다.

## 9. 검증

자동검사:

- M5 두 도구 모두 완료 가능
- M5 두 도구를 확인하기 전 선택 차단
- M5 선택별 돈·운반 한도 변화
- M6 밀가루/등잔기름 어느 선택도 완료 가능
- M6 보류 물건이 삭제되지 않음
- M7 오배송 시 상태 무변경
- M7 부족 2와 부족 3을 포함한 7개 물건 최종 분배
- M7 운반 한도 3에서 세 번의 운반으로 완료 가능
- M8 빵집에 밀가루 2개 보충
- M8 서로 다른 세 해결 순서 완료
- M5/M6 최초 선택 저장과 재플레이 비덮어쓰기
- M8 최초 완료에서만 `market-core`
- `inn-unlocked` 전 여관 미노출, M4 기본 여관, M8 `has-room-key` 상태 전환
- M8 여관의 접근성 이름·상세 시트 문구와 기존 클릭 동작
- 여관 SVG의 상대 경로·모바일 좌표·터치 영역 유지와 저장 포맷 비확장
- M5/M6 선택별 후일담
- M7/M8 6열 모바일 판 규칙
- 살펴본 장소의 `현재/필요`·공급량 표시 코드와 재고 변화 애니메이션 로드 순서
- M5~M8 여정 연결과 월드맵 복귀

실기기에서는 다음을 확인한다.

1. `1/3`, `1/4` 같은 배지가 6열 판에서도 아이콘·장소명을 가리지 않는가.
2. 부족/충분 상태가 색에만 의존하지 않고 수량으로도 분명한가.
3. 물건을 가져가거나 놓았을 때 바뀐 장소가 자연스럽게 눈에 들어오는가.
4. M7의 2개·3개 보충이 반복 작업보다 운반 계획으로 느껴지는가.
5. M5 선택지가 정답/오답처럼 보이지 않는가.
6. M6의 `放棄`가 삭제로 오해되지 않는가.
7. M8에서 원하는 순서로 푼다는 감각이 실제로 살아 있는가.
8. M8 뒤 장터가 하나의 생활 공간으로 마무리되는가.

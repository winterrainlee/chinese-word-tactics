## 3. 잠정 정답과 측정 방법

정답은 **Codex 한 검토자가 원문을 순서대로 읽고 직접 선정한 잠정 주석**이다. 별도 사람 검수·독립 평가자 합의·학습자 실험은 없었다. 문서와 후보를 먼저 읽었기 때문에 후보에 대한 완전한 맹검도 아니다. 다만 검출 결과를 생성하기 전에 문단별 유용 표현 192곳을 고정했고, 그 뒤 검출·오탐·위험 한 글자 검토를 수행했다. 위치 점검 중 잘못 지정한 `使` 1곳을 실제 귀결 위치로 수정한 뒤 측정했다. 사용자가 요청한 사람 기준 정답의 대용이며 사람 검증이 끝난 정답이라고 부르지 않는다.

긍정 기준은 그 지점에서 다음 내용의 역할을 예상할 실익이 있는가이다. 단순 문법적 성립이나 어휘의 중요도는 충분조건이 아니다. 인물 이름·보도 동사·일반 날짜를 전부 강조하지 않는다. 따라서 정답은 모든 문법 요소의 전수 목록이 아니라 이 편집 기준 아래 선택된 단서의 집합이다. 재독 가능성·잡음·효용·확신도는 문맥상의 예상이며 행동 측정치가 아니다.

- 위치는 문단 번호 1부터, 문단 내부 UTF-16 시작 0부터, 끝 제외다. 마커 양끝이 정확히 같아야 TP다. 부분 일치에는 점수를 주지 않는다. 짝표현은 양끝을 따로 세며 자동 의미 구간으로 세지 않는다.
- FP는 잘못된 문자열 구간과 문맥상 강조 실익이 낮은 구간을 포함한다. JSON의 `errorType`으로 두 종류를 구별한다. A1/A2의 FP 4곳 중 2곳은 명확한 단어 경계 오류, 2곳은 효용에 이견이 가능한 대상 표시다.
- FN은 긍정 정답 중 검출하지 못한 위치다. 정밀도=TP/(TP+FP), 재현율=TP/(TP+FN). 분모 0은 null/N/A다. TN 전체 개수나 정확도(accuracy)는 정의하지 않는다.
- 유보 3곳은 정답 분모와 FP에서 제외했다. `但`의 인용 중복 1곳, `其中` 뒤의 `包括` 2곳이다. A2는 유보 1곳을 검출한다. 이것까지 FP로 취급하면 A2 전체 정밀도는 96.8%에서 96.0%가 된다.
- 강조 비율은 공백·숫자·라틴자·문장부호를 포함한 본문 코드 포인트 중 강조된 글자 비율이다. 문단 구분자는 제외한다. 유보·오탐도 실제 표시 밀도에는 포함한다. A/B/전체 값은 문단 비율의 평균이 아닌 전체 글자 수로 가중한 micro 집계다.

## 5. 새 후보와 다의어 별도 실험

## 6. 得 및 위험한 한 글자

### 得

실제 자료의 17곳은 의무 1, 值得 1, 獲得 3, 取得 1, 不得 5, 법적 허용 4, 覺得 1, 驗得 1이다. 정도보어 긍정 0개이므로 **기사에서 得의 양성 재현율은 N/A**다. A2의 고정 동사/형용사 `說·跑·做·泡·忙` + 得 + `很·太·不錯·沒時間` 규칙은 17개 음성에서 오탐 0이었다.

직접 만든 검증 문장에서는 요청한 `說得很清楚·跑得很快·做得不錯`와 `泡得太濃·忙得沒時間`을 검출했다. `覺得很好·得到·不得·得易科罰金·得先走·看得懂` 등을 포함한 음성 10개는 검출하지 않았다. 가능보어 `看得懂`은 정도보어와 별도 취급한다. `說得過去`도 별도 가능/관용 용법으로 제외했다.

그러나 허용 어휘 밖의 `寫得很清楚`, `累得不能走路`는 놓쳤다. 양성 7개 중 5개 검출, 음성 10개 중 0개 오탐으로, 이 작은 작성 예문의 정밀도 100%·재현율 71.4%다. 좋은 일반 언어 분석기로 해석할 수 없다. 특히 B10 p3의 `覺得很` 때문에 ‘得 뒤에 很이 있으면 표시’하는 완화는 금지한다.

A2는 `繼…後`, `先…再`, `只有…才`, `不是…而是`, `不僅…更`, `不但…也`, `待…後`, `當…時`, `除…外`, `沒有…就沒有`, `以…為例`, `雖…仍`, `雖然…但`, `但…仍`, `若…就/則`를 시험했다. 문장부호와 길이 제한이 있어도 다음 반례가 남았다.

- `先進`에서 先을 잡아 뒤의 再와 잘못 연결한다.
- `當時`의 當을 뒤에 나온 時間의 時와 잘못 연결한다.
- `只有人才`의 人才 안에 든 才를 조건 귀결로 오인한다.
- `除…外觀外`에서 外觀 안의 外를 먼저 잡는다.

이 반례들은 문장부호 또는 최대 거리만으로 단어 경계·구문 성립을 증명할 수 없음을 보여준다. 일부 패턴에서의 무오탐은 실제 출현이 없어서일 수도 있다. 본문 TP와 자체 문장 검증 결과를 합쳐 하나의 성능 수치로 제시하지 않는다.

## 7. 채택·조건부·보류·제외 권고

**추가 채택 제안:** 至於·其中·此外·接著·隨後·另一方面·儘管·由於·為了·因應·受惠於·首先. 실제 근거가 있는 12개이며, 안전한 모든 중국어 용법을 입증한 것은 아니다. ‘채택’은 후속 구현 사전의 검토 목록에 넣자는 권고이고 이번에 활성화하지 않았다.

**함께 보강할 신규 제안:** 因為·甚至·也就是·隨著·除了·不論. 根據·依照·受惠는 근거/원인 배경 용법을 제한하는 조건부 후보로 둔다. 자료층 A/B 중복을 감안하면 근거가 각각 1~2개 수준이므로 다른 장르 검수가 필요하다.

**조건부 채택:** 針對·對於는 화제 설정 위치에 한정하고 내포된 단순 대상에서는 보수적으로 처리한다. 다만 B06처럼 문장 중간의 초점도 있으므로 문두만 허용하면 누락이 생긴다. 不過는 절 전환 용법부터, 열거 서수는 뒤 쉼표와 문단 구조를 확인하는 방식부터 검토한다. 但·若·則·仍과 짝표현은 별도 시험 목록에 남긴다.

**보류:** 정도보어 得, 독립 並·也·後·再·就·才, 무제한 不過·結果·只是·包括·同時, 方面·主要是·考量 등 문맥 의존 후보. 受惠를 무조건 문자열로 추가하는 것도 보류한다. 가능보어는 별도 목표를 정하기 전까지 섞지 않는다.

**표시 제외:** 覺得·得到·不得·의무/허용 得·得易科罰金, 原則·準則·人才·把握·並列의 내부 글자, 廢除非核의 除非, 立即使用의 即使, 第三方의 第三. 전체 표현이나 해당 문장을 삭제한다는 뜻이 아니라 잘못된 부분 강조를 막는다는 뜻이다.

기존 목록에서 실제 도움이 확인된 것은 卻·因此·而且·另外·雖然·如果·只要다. 나머지 기존 후보는 미출현 또는 잘못된 부분 출현이므로 ‘이번 기사에서 충분히 검증됐다’고 쓰지 않는다. 특히 除非·即使는 개념을 폐기할 대상이 아니라 **어휘 경계 예외를 추가 검증할 대상**이다.

TBCL 원자료에는 至於(w5-zhiyu/g467), 此外(w5-ciwai/g481), 由於(w4s-youyu/g363), 儘管(w5-jinguan/g435), 首先(w4-shouxian), 根據(w4s-genju/g352), 甚至(w4s-shenzhi/g365), 隨著(w5-suizhe/g410), 不論(w4-bulun/g260)이 연결된다. 為了는 g413의 구문 근거다. 接著는 학술탑 편집층 foundation-sequence, 因為는 foundation-cause-result, 除了는 foundation-exception, 也就是는 g386의 표기 변형 근거를 검토할 수 있다. 그 밖의 뉴스 문체 표현에는 공식 ID·등급을 만들어 붙이지 않는다. 두 기존 후보 JSON은 읽고 대조했으며 수정하지 않았다.

## 8. 다음 구현 규칙과 미결 사항

1. 정식 사전을 만들기 전에 이번의 두 단어 경계 오탐을 회귀 사례로 넣는다. `廢除非…`, `立即使…`를 넓게 전부 차단하면 다른 유효한 문맥을 놓칠 수 있으므로, 확인한 어휘 결합과 반례를 함께 검증한다.
2. 초기 구현은 A1 계열의 검토된 다글자 + 긴 표현 우선 + 검토된 제외 구간을 중심으로 한다. 확률적 효용 판단을 완전한 문법 판정처럼 표시하지 않는다. 단색의 옅은 연녹색 외 분류·해설·연결선은 추가하지 않는다.
3. A2 전체를 그대로 제품에 가져오지 않는다. 긍정·부정·거리·인용·중첩·어휘 내부 반례를 각 규칙별로 통과시켜야 한다. 이번의 알려진 실패를 숨기려고 정답을 바꾸지 않는다.
4. 표지어를 더 넣기 전에 다른 날짜·서사·설명문으로 별도 평가한다. 새 검토자에게 이번 정답을 재검수받고, 針對/對於와 반복 첨가 등의 이견을 조정한다.
5. 이후 사용자가 같은 난도의 새 글을 표시 켬/끔으로 읽는 시험에서 되돌아 읽기·이해·주관적 잡음을 확인한다. 이번 분석은 학습 효과를 입증하지 않는다.

## 9. 재현·검증

전문·문단·복원 가능한 발췌 묶음은 저장소에 저장하지 않았다. JSON에는 기사 메타데이터, 본문 문단별 해시/길이, 짧은 표지어·오프셋·판정·측정치와 직접 쓴 시험 문장만 있다. 실제 열람 본문은 작업용 비공개 임시 경로에서만 사용했다.

```sh
python tools/reader-cna-eval.py --self-test
python tools/reader-cna-eval.py --verify-recorded
python tools/reader-cna-eval.py --corpus /private/texts.json --output /private/measured.json
```

`--self-test`는 직접 쓴 45문장 중 의도한 정답과 일치한 33개와 알려진 실패 12개를 확인한다. **45개 모두 검출 성공이라는 뜻이 아니다.** 12개는 정도보어 누락 2, 짝표현 반례 4, 다의어 반례 4, 기준선 단어 경계 반례 2다. UTF-16 이모지 위치, 긴 표현 중첩, 빈 입력도 검사한다.

전문 재측정 입력은 `[{"id":"cna-20261113-01","layer":"A","paragraphs":["..."]}, ...]` 형식이다. 합법적으로 다시 열람한 본문을 §2와 동일하게 추출해 저장소 밖에 준비해야 한다. 스크립트는 문단 수·해시·표지어 구간을 확인하고 하나라도 달라지면 중단한다. 본문 변경 시 오프셋을 재사용하지 말고 재주석한다. 본문을 저장소에 넣지 않아 깨끗한 checkout만으로 온라인 본문 탐지까지 재현되지는 않는다. 자체 문장 검사와 저장된 집계 검증은 전문 없이 가능하다.

본문 20개 동일 스냅샷으로 전체 비교를 재실행했고 저장된 집계와 일치했다. 전문 없는 주석·집계 검사, Python 컴파일, 저장소의 `node tools/verify-content.cjs`도 통과했다. 이번 작업은 분석 전용이므로 UI·브라우저·실기기 검수는 수행하지 않는다. 커밋에 `[skip ci]`를 넣어 main push에 연결된 Pages 자동 배포를 실행하지 않도록 한다.

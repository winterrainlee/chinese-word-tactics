## 1. 행상인 재등장

튜토리얼을 마친 뒤 소년은 길가에서 늑대를 피하다 수레가 걸린 행상인을 돕는다. 행상인은 물길마을 장터에 물건을 넘기러 간다고 말하고, 소년과 함께 물길마을 안으로 들어온 뒤 장터로 사라진다.

이 관계를 장터에서 다시 사용한다.

### M1 도입

소년이 장터로 들어서면 멀리 익숙한 짐수레가 보인다.

> `那輛車……好像在哪裡看過。`  
> 저 수레…… 어디서 본 것 같은데.

이 단계에서는 행상인에게 바로 말을 걸지 않는다. 장터지기가 두 좌판의 밀가루 상황을 확인해 달라고 부탁하고 M1이 시작된다.

### M1 뒤

장터지기는 늦게 도착한 짐수레의 정리도 거의 끝났다고 말한다. 소년이 다시 수레를 보고 프롤로그에서 만났던 수레임을 알아차린다.

### M2 도입

행상인과 정식으로 다시 만난다.

> `咦？是你！你也到市集來了？`  
> 어? 너구나! 너도 장터에 왔네?

행상인은 길에서 조금 지체했지만 물건은 거의 모두 넘겼다고 말한다. 다만 수레에 몇 상자가 남아 있어, 원래 수량과 이미 보낸 수량이 아니라 **지금 실제로 `剩下`은 양**을 확인해야 한다.

M2의 `數量 / 剩下`은 이 행상인의 실제 수레를 정리하는 사건이 된다.

### M2 뒤 → M3

등잔기름 두 상자를 창고로 돌려보낸 뒤 행상인이 천 한 묶음을 따로 꺼낸다.

> `這個不用帶回去。前面的繩子攤正好需要布。`

행상인은 다음 배달에 밧줄 한 묶음이 필요하다. 밧줄 좌판은 마침 천을 필요로 하므로, 소년이 천 한 묶음을 받아 실제로 교환한다.

M3에서는:

- 시작 인벤토리: `布 ×1`
- 밧줄 좌판: `布 ×1 ↔ 繩子 ×1`
- 교환 결과: `布 -1`, `繩子 +1`
- 소년은 `獲得`한 밧줄을 행상인에게 가져다준다.

M3 뒤 행상인은 다음 짐을 배달하러 장터 안으로 이동한다. 장터의 주 안내자는 계속 장터지기이며, 행상인은 자기 일을 하다가 소년과 다시 만난 생활 인물로 남는다.

## 2. M1 구현

핵심어: `需求 / 足夠 / 不足`

두 좌판의 필요량을 먼저 확인해야 한다.

- 빵 좌판: 밀가루 2 / 필요 3 → `不足 1`
- 국수 좌판: 밀가루 2 / 필요 2 → `足夠`
- 배달수레: 밀가루 1
- 운반 한도: 1

완료 조건에는 두 좌판을 모두 살펴본 기록이 포함된다. 따라서 부족한 위치를 우연히 알고 바로 물건만 옮겨서는 완료되지 않는다.

이미 충분한 국수 좌판에 밀가루를 잘못 놓는 행동은 허용한다. 대신 다시 한 자루를 회수할 수 있어 진행 불능이 되지 않는다. 필요량 아래로 재고를 빼는 행동은 막는다.

---

## 3. M2 구현

핵심어: `數量 / 剩下`

행상인의 수레:

- 천: 원래 2, 이미 배달 2, 현재 남음 0
- 등잔기름: 원래 3, 이미 배달 1, 현재 남음 2

창고에는 등잔기름 두 상자를 돌려보내야 한다.

운반 한도는 2다.

핵심은 숫자 `2`를 찾는 문제가 아니라, **원래 수량 2와 현재 남은 수량 2가 서로 다른 물건에 붙어 있음**을 읽는 것이다.

---

## 4. M3 구현

핵심어: `交換 / 獲得`

교환은 하나의 원자적 행동으로 처리한다.

```text
布 -1
繩子 +1
```

동시에 밧줄 좌판에서는 천 재고가 1 늘고 밧줄 재고가 1 줄어든다. 되돌리기는 이 전체 상태 변화를 한 번에 복원한다.

`交換`은 얻는 방법이고 `獲得`은 그 결과라는 차이를 실제 자원 상태로 보여준다.

## 5. 공통 런타임

추가 파일:

- `src/market-content.js`
- `src/market-journey-content.js`
- `src/market-runtime.js`
- `src/market-runtime.css`

`MarketMechanic`은 DOM과 분리된 순수 자원 로직을 제공한다.

현재 지원 기능:

- 장소별 stock / need
- 플레이어 inventory
- 운반 한도
- 장소 살펴보기 기록
- 가져가기 / 놓기
- 필요량 아래로 재고를 빼지 못하게 하는 보호
- 교환
- 여러 predicate 조합

M4 이후 구매·가격·돈은 이 런타임에 필요한 만큼 확장한다.

## 6. 저장 호환

기존 전술 저장은 `stageIndex`를 포함하므로 새 장터 스테이지를 기존 G7보다 앞에 삽입하면 이전 저장의 인덱스가 밀릴 수 있다.

따라서 `index.html`에서 신규 `market-content.js`는 기존 `g7-content.js` 뒤에 로드한다. 결과적으로 기존 스테이지 인덱스는 유지되고 M1~M3만 뒤에 추가된다.

여정에서의 장터 순서는 별도의 `market-journey-content.js`가 담당하므로 실제 이야기 순서는 장터 M1 → M2 → M3으로 정상적으로 보인다.

5. M2의 `原來數量 / 已送出 / 剩下` 정보가 작은 화면에서도 한눈에 구분되는가.
6. M3 교환 뒤 상태 변화가 즉시 납득되는가.

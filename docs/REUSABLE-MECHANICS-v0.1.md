# 재사용 가능한 게임 규칙·기믹 도감 v0.1

작성일: 2026-09-10

이 문서는 튜토리얼 6판과 길목 G1까지 실제로 구현·검증한 규칙을, 이후 스테이지에서 다시 조합해 쓸 수 있도록 정리한다.

목적은 스테이지마다 전용 코드를 계속 늘리는 것이 아니라, **이미 검증한 작은 규칙을 조합해 새로운 단어 경험을 만드는 것**이다.

이 문서는 아이디어 목록이 아니다. 실제 구현 상태를 다음 세 단계로 구분한다.

- `✅ 재사용 가능`: 현재 구조에서 그대로 또는 데이터 변경만으로 다시 쓸 수 있다.
- `🟨 일반화 필요`: 동작 자체는 검증됐지만 특정 스테이지·타일 이름에 코드가 묶여 있다.
- `⬜ 예정`: 아직 구현하지 않은 다음 공통 기믹이다.

---

## 1. 공통 설계 모델

현재까지의 좋은 기믹은 대부분 다음 구조로 설명할 수 있다.

> **행동/사건 → 조건 판정 → 상태 변화 → 피드백**

그리고 스테이지 완료는 여러 상태 조건의 조합이다.

예를 들어 G1 `관문 안의 길표지`는 다음과 같다.

1. `D → I` 이동
2. 경계 바깥에서 안쪽으로 이동했는지 판정
3. `entered = true`
4. `已進入關口。` 피드백
5. 길표지 조사 후 `inspected = true`
6. 다시 `D → 바깥` 이동
7. `exited = true`
8. `entered && inspected && exited`이면 완료

즉 새 중국어 단어를 구현할 때 가장 먼저 정해야 하는 것은 전용 버튼이나 효과가 아니라, **그 단어가 판 위의 어떤 관계·상태 변화로 보일 것인가**다.

## 2. 전술 핵심 규칙

| 규칙/기믹 | 상태 | 현재 사례 | 재사용 방법 |
|---|---|---|---|
| 상하좌우 한 칸 이동 | ✅ | 모든 전술판 | 기본 이동 규칙으로 유지한다. |
| 이동 불가 지형 | ✅ | 수풀, 석비, 길표지 | 타일을 통과할 수 없게 하여 경로 선택을 만든다. |
| 목적지 도착 | ✅ | `到達`, 출구 | 특정 타일에 도달했는지를 완료 조건으로 쓴다. |
| 인접 거리 판정 | ✅ | `接近`, 길표지 조사 | 상하좌우 한 칸 관계를 조건으로 쓴다. |
| 위험 칸 진입 거부 | ✅ | `避開`의 가시 | 잘못된 행동을 확정하지 않고 정보만 준다. |
| 이동하는 위험 대상 | ✅ | 늑대 | 고정된 순환 경로와 위험 반경을 데이터로 지정한다. |
| 한 턴 기다리기 | ✅ | 튜토리얼 Stage 5 | 플레이어 위치는 유지하고 움직이는 대상의 상태만 진행한다. |
| 되돌리기 | ✅ | 모든 전술판 | 직전 행동 전 상태를 복원한다. |
| 여러 조건을 모두 만족해 완료 | 🟨 | `stone + at_exit`, `crossed + at_exit`, G1 3조건 | 현재 조건 이름이 코드에 등록돼 있다. 종류가 늘어나면 일반 predicate registry로 바꾼다. |

### 2.1 이동은 단어 효과가 아니다

`接近`을 눌러 순간이동하거나 `避開` 버튼을 눌러 위험을 제거하지 않는다.

플레이어가 평범한 이동을 이용해 직접

- 가까워지고,
- 멀어지고,
- 통과하고,
- 도착하고,
- 피하는

상태를 만든다.

이 원칙은 이후 단어에도 유지한다.

## 3. 거리와 위험

### 3.1 인접 판정 `dist === 1`

상태: `✅`

현재 상하좌우 한 칸 거리는 여러 곳에서 공통으로 사용한다.

- 석비에 `接近`
- 길표지 조사 가능 여부
- 늑대의 위험 범위

대각선은 한 칸으로 취급하지 않는다.

현재 거리 계산은 맨해튼 거리다.

이 규칙은 다음 G2 `距離 / 範圍`의 기반이 된다.

### 3.2 위험 범위

상태: `✅`

늑대는 `cycle + radius`로 움직임과 위험 범위를 가진다.

행동을 확정하기 전에 현재 위치와 다음 위치의 위험 범위를 함께 검사한다. 위험하면 해당 행동을 취소하고 위치·턴을 소비하지 않는다.

이 패턴은 늑대가 아닌 다른 대상에도 재사용 가능하다.

예:

- 감시병 시야
- 불꽃이 번지는 범위
- 종소리나 신호가 닿는 범위
- 움직이는 수레의 충돌 예상 영역

다만 코드와 데이터 명칭이 현재 `wolf`에 묶여 있으므로 두 번째 이동 위험 대상이 등장하면 일반화한다.

### 3.3 기다리기

상태: `🟨`

플레이어가 움직이지 않고 외부 대상의 상태만 한 단계 진행시킨다.

전술적으로는 이미 매우 유용하다. 다만 현재 UI 노출 조건이 `wolf` 존재 여부에 묶여 있다.

두 번째 시간 진행형 기믹이 등장하면 `hasTurnCycle` 같은 일반 조건으로 바꾼다.

## 4. 접근·통과·진입·퇴출

이 네 가지는 비슷해 보이지만 판정이 다르다. 이후 공간 단어 설계에서 중요한 기준이다.

### 4.1 접근 `接近`

상태: `🟨`

현재 구현:

- 특정 대상과 상하좌우 한 칸 거리가 되면 상태가 바뀐다.
- 튜토리얼에서는 석비가 반응하고 문이 열린다.

재사용 가능한 개념은 **proximity trigger**다.

현재 상태 이름과 대상이 `stone / K`에 묶여 있으므로 다른 인접 반응 대상이 하나 더 생기면 일반화한다.

후보 형태:

`proximityTriggers: [{ target:'...', distance:1, flag:'...' }]`

### 4.2 통과 `通過`

상태: `🟨`

현재 구현:

- 통로 한쪽 입구로 들어간다.
- 통로 영역을 지난다.
- 다른 쪽 입구로 빠져나와야 `crossed = true`가 된다.

중요한 의미는 단순히 어떤 타일을 밟는 것이 아니라 **A 쪽에서 들어가 B 쪽으로 나가는 경로 관계**다.

현재 구현 이름이 `ruin / portals / crossed`에 묶여 있다. 다리, 문, 골목 등 두 번째 통과 기믹이 생기면 `passage` 개념으로 일반화한다.

### 4.3 진입 `進入`

상태: `✅`

현재 G1에서는 경계 타일 `D`를 기준으로 바깥에서 안쪽 타일 `I`로 이동하면 성립한다.

핵심은 특정 위치가 아니라 **경계 밖 → 경계 안**의 상태 전이다.

같은 구조로 다음을 표현할 수 있다.

- 건물 안으로 들어가기
- 작업 구역에 진입하기
- 감시 범위에 들어가기
- 특정 지역 안으로 물체를 옮기기

### 4.4 퇴출 `退出`

상태: `✅`

안쪽에서 경계를 지나 바깥으로 나오면 성립한다.

`通過`와 달리 반대편 출구가 필요하지 않다. 들어왔던 문으로 다시 나와도 된다.

G1에서는 길표지 확인이라는 선행 조건을 붙여, 단순 왕복이 아니라 `進入 → 볼일 → 退出`의 생활 상황을 만들었다.

## 5. 살펴보기와 상호작용

### 5.1 자유 살펴보기 모드

상태: `✅`

`살펴보기`를 누르면 이동 대신 맵의 지형·대상을 눌러 정보를 볼 수 있다.

현재 사례:

- 늑대의 다음 행동과 위험 범위
- 유적 통로의 역할
- 석비
- 가시
- 길표지

이 기능은 공략을 주는 것이 아니라 **판의 규칙을 공개하는 정보 도구**로 사용한다.

### 5.2 인접한 유일 행동은 한 번에 실행

상태: `🟨`

G1 실기기 검수에서 나온 공통 UX 규칙이다.

플레이어 바로 옆에 명확한 상호작용 대상이 하나뿐이면,

`살펴보기` → `길표지 살펴보기`

처럼 버튼 이름을 상황에 맞게 바꾸고 한 번의 탭으로 실행한다.

대상도 조사 가능 상태로 표시한다.

반대로

- 인접 행동 대상이 없거나
- 여러 개라 선택이 필요하면

기존 `살펴보기 모드`를 사용한다.

현재 `interaction-runtime.js`의 `actionFor()`가 `L` 길표지만 알고 있다. 상자·장치·NPC 등 두 번째 맥락 행동이 추가되면 데이터 기반 action registry로 일반화한다.

권장 형태:

`상호작용 대상 → 조건 → 버튼 라벨 → 실행 동작`

예:

- 상자 + 인접 → `상자 열기`
- 장치 + 인접 → `수문 조절하기`
- NPC + 인접 → `길지기에게 말 걸기`

## 6. 실패와 피드백 규칙

### 6.1 실패 비용은 낮게

상태: `✅`

초기 스테이지에서 잘못 판단했다고 즉시 게임 오버시키지 않는다.

현재 사례:

- 유적을 통과하지 않고 출구에 도착 → `還沒通過遺跡。`
- 위험 칸을 밟으려 함 → 행동 취소 + 위험 메시지
- 늑대에게 너무 가까운 이동 시도 → 행동 취소 + 위험 메시지
- G1에서 표지를 안 보고 퇴출 → 퇴출 자체는 허용하지만 완료되지 않음 + `路標還沒看。`

잘못된 선택은 처벌보다 **다음 판단에 쓸 정보**를 남겨야 한다.

### 6.2 위험 행동은 가능하면 확정 전에 막는다

상태: `✅`

위험 칸·늑대 범위처럼 명확히 위험한 행동은 현재 위치를 망가뜨리지 않는다.

이 방식은 특히 모바일 학습게임에서 실수 탭과 전략 실패를 구별하는 데 유리하다.

### 6.3 상태 변화는 즉시 보인다

상태: `✅`

상태 변화에는 최소 하나의 피드백을 준다.

- 목표 단어 완료 표시
- 타일 상태 변화
- 짧은 중국어 + 한국어 상태 메시지
- 필요한 경우 캐릭터 표정 반응

같은 정보를 여러 UI에 과도하게 반복하지 않는다.

## 7. 목표 조건 조합

현재 `win` 배열은 여러 조건을 AND로 묶는다.

현재 조건:

- `at_exit`
- `stone`
- `crossed`
- `entered`
- `inspected`
- `exited`

예:

- Stage 1: `stone + at_exit`
- Stage 3: `crossed + at_exit`
- G1: `entered + inspected + exited`

이 구조 덕분에 하나의 단어를 버튼 효과로 만드는 대신 **여러 작은 상태를 조합한 과제**를 만들 수 있다.

상태: `🟨`

현재 `isWin()`과 목표 강조가 조건 이름을 직접 알고 있다. 조건 종류가 계속 늘어나기 전에 다음 구조로 일반화하는 것이 좋다.

- `predicate registry`: 조건 ID → 판정 함수
- 목표 문구와 predicate 연결
- 스테이지별 전용 boolean을 줄이고 공통 flag/state 사용

단, G2 하나를 만들기 위해 미리 거대한 규칙 엔진을 만들지는 않는다.

## 8. 이야기·여정에서 재사용 가능한 진행 규칙

전술 기믹뿐 아니라 콘텐츠 흐름에도 재사용 가능한 규칙이 생겼다.

| 규칙 | 상태 | 설명 |
|---|---|---|
| `story → stage → story` 직접 연결 | ✅ | 정상 진행에서는 메뉴를 거치지 않는다. |
| `requires` 기반 노드 해금 | ✅ | 저장된 결과에서 열린 노드를 계산한다. |
| 지역별 병렬 section | ✅ | 길목·장인골·장터는 서로 자동으로 이어지지 않는다. |
| 다시 보기/다시 플레이 분리 | ✅ | replay는 본편 진행과 체크포인트를 바꾸지 않는다. |
| 중단 후 이어하기 | ✅ | 마지막 story beat 또는 tactical node를 저장한다. |
| 여정 전체 초기화 | ✅ | 1.0 이전 반복 플레이테스트를 위한 개발 편의 기능이다. |
| milestone으로 역할 계산 | ✅ | `소년/용사`를 문자열로 저장하지 않고 완료 조건에서 계산한다. |

이 규칙은 새 지역을 추가할 때 그대로 반복한다.

## 9. 현재 코드에서 일반화가 필요한 부분

새 기능을 만들 때 아래 항목은 무조건 즉시 리팩터링하지 않는다. **두 번째 실제 사용처가 생길 때 일반화한다.**

### 우선순위 A — 두 번째 사용처가 생기면 바로 일반화

1. `interaction-runtime.js`의 `L` 길표지 전용 `actionFor()`
2. `stone / K`에 묶인 인접 반응
3. `ruin / crossed`에 묶인 통과 판정
4. `wolf`에 묶인 이동 대상·기다리기

### 우선순위 B — 조건 종류가 더 늘면 일반화

1. `isWin()`의 조건별 하드코딩
2. `renderGoal()`의 단어별 하드코딩
3. `state.stone / crossed / entered / inspected / exited` 같은 개별 플래그

목표는 추상화 자체가 아니다.

> **같은 의미의 규칙을 두 번 구현하려는 순간 공통 규칙으로 올린다.**

## 10. 다음으로 추가할 공통 기믹

### G2 `距離 / 範圍`

상태: `⬜ 예정`

G2에서 새로 만들어야 할 공통 규칙 후보는 다음과 같다.

- 두 대상 사이 거리 읽기
- `거리 <= n`, `거리 > n`, `거리 == n` 판정
- 특정 중심에서 일정 거리까지의 범위 계산
- 판 위에 범위를 보조 표시하되 정답 경로는 표시하지 않기
- 하나의 범위 안/밖에 여러 대상이 있는지 판정

이미 있는 맨해튼 거리 함수를 기반으로 만들 수 있다.

이 기믹은 이후에도 재사용 폭이 매우 크다.

예:

- 경비 시야
- 종소리
- 화살 사거리
- 폭발/회복 범위
- NPC와 유지해야 할 거리
- 짐수레 사이 간격

따라서 G2는 `종소리 전용 코드`보다 **distance / range라는 공통 관계**를 구현하는 것을 우선한다.

### 이후 예정

- `路線 / 經由`: 경로 기록과 필수 경유지
- `位置 / 周圍 / 障礙`: 위치·주변 관계와 조사 결과
- `移動 / 前進 / 後退`: 플레이어 외 대상 이동
- `跟隨 / 帶領`: 두 유닛 사이의 주체·종속 이동
- `改變 / 保持`: 상태값 변경과 유지
- `增加 / 減少 / 調整`: 수치 변화
- `集中 / 分配`: 제한 자원의 이동과 배분

아직 구현 전이므로 이 문서에서는 규칙을 확정하지 않는다.

---

## 11. 새 스테이지 설계 체크 양식

새 판을 만들 때 아래 항목을 먼저 채운다.

```text
학습 단어:
단어가 뜻하는 관계/변화:
플레이어가 직접 만드는 상태:

재사용할 기존 기믹:
새로 필요한 기믹:

행동/사건(trigger):
조건(predicate):
상태 변화(state delta):
피드백(feedback):
완료 조건(win):

잘못된 시도에서 얻는 정보:
실패 비용:
가능한 해결 경로 수:
```

특히 `새로 필요한 기믹`이 많다면 스테이지를 다시 단순화한다.

초반 지역에서는 기본적으로 **새 공통 기믹 1개 + 이미 배운 기믹 몇 개**의 조합을 우선한다.

---

## 12. 한 줄 원칙

**새 단어를 새 버튼으로 만들지 말고, 이미 있는 세계의 규칙을 새 관계로 조합한다.**

그리고 같은 관계가 두 번 등장하면 그때부터는 스테이지 전용 코드가 아니라 공통 기믹으로 취급한다.

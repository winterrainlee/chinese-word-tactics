# 추가 디자인 감사 — 경계 표현과 여정 스테이지 번호

작성일: 2026-10-05
대상 저장소: winterrainlee/chinese-word-tactics
기준 커밋: 076f16f5a5add053d6e729d0f6afa1dbba319fad (A01–A03 반영 이후)
상태: 확인 사실과 제안 규칙을 정리한 추가 감사다. 2026-10-05 완료 처리·우선순위 갱신에서 저장소 문서로 편입했다. **경계 표현(A09)과 여정 번호(A10)는 미구현이다.** 아래 테스트는 후속 구현 사양이며 완료 보고가 아니다.
현재 완료 현황과 실행 순서는 [전체 디자인 감사 §7](DESIGN-AUDIT-v0.1.md)을 단일 기준으로 삼는다. A01~A03은 구현·자동검사·배포와 사용자 종료 승인으로 완료 처리했으며, 별도 실기기 검증 결과를 뜻하지 않는다.

## 1. 감사 방법과 한계

GitHub 연결로 최신 main, 디자인 원칙, 구현과 Actions 실행을 확인했다. 해당 커밋의 Pages 아티팩트에서 소스 파일을 확보했고, 같은 커밋의 design-audit-snapshots 아티팩트를 열어 화면을 비교했다.

- 배포 실행: 37307615543. 소스 아티팩트: 11344064452.
- 디자인 수집 실행: 37307615719. 화면 아티팩트: 11344034207.
- manifest: 네 viewport에서 160개 캡처, 수집 실패 없음. 이 결과는 기존 CI 수집의 성공이지 이번 제안의 적합성 검사 결과가 아니다.
- 이번에 자세히 비교한 화면: 375×640의 이야기에서 연 메뉴, 설정, 새 의뢰 게시판, 전체 학술탑 여정, 단어장 홈, 학술탑 연구실. 전체 페이지 캡처와 실제 첫 viewport를 구분했다.

## 2. 핵심 결론

문제는 둥근 모서리 자체보다 **서로 다른 역할의 요소를 모두 같은 닫힌 상자로 표현하는 것**이다. 메뉴 항목, 설정의 구분, 문서 목록, 현재 페이지 표시, 실행 버튼이 같은 외형을 공유하면 정보의 역할이 약해진다.

단순히 border-radius를 0으로 만들거나 border만 지우는 것으로 해결하지 않는다. 배경색·그림자·간격이 여전히 각각의 상자를 만들면 같은 구조가 남는다. 감사 단위는 CSS border 선언이 아니라 **사용자에게 보이는 경계 전체**다.

A01–A03의 터치 영역과 행동 역할 개선은 보존한다. 경계 정리는 그 위에서 할 시각 구조 감사이며, 버튼을 다시 작게 만들거나 접근성 상태를 되돌리는 작업이 아니다.

## 3. 확인된 구현과 변경 제안

| 위치 | 확인한 구현 | 제안 |
|---|---|---|
| 여행 메뉴 | journey.css의 .flowMenu button이 매 행에 1px 외곽선·12px 모서리·독립 배경을 부여한다. | 보조 창 하나 안의 텍스트 행으로 바꾼다. 상시 외곽선과 행별 배경은 없애고 묶음 간격을 사용한다. 필요할 때만 묶음 경계에 가는 선을 둔다. |
| 설정 | .settingsSection은 18px 모서리·외곽선·그림자, .settingsAction과 .settingsToggle은 다시 14px 외곽선을 가진다. | 섹션은 제목과 여백, 항목은 정렬된 행으로 구분한다. 스위치 자체의 외곽과 위험 행동 확인·복원 미리보기의 의미 있는 구분은 보존한다. |
| 공통 하단 탐색 | .flowNav button이 각각 14px 모서리·외곽선·배경을 가진다. | 하나의 텍스트 탐색 영역으로 묶고 현재 페이지는 글자 굵기와 짧은 밑줄 등으로 표시한다. 위치 고정이나 지도 축소는 이 감사의 자동 결론이 아니다. |
| 의뢰 게시판 | .questBoardNote는 13px 외곽, 내부 .questBoardAction은 11px 외곽을 가진다. | 게시판의 개별 의뢰서라는 실물 비유를 살리는 안을 권한다. 얕은 종이 면과 작은 모서리만 남기고, 내부 의뢰 확인은 상자 없는 명확한 텍스트 행동으로 한다. 필요하다면 반대로 목록형으로 만들 수도 있지만 종이와 버튼 외곽을 같은 의미로 중첩하지 않는다. |
| 여정 본문 | .journeyNode는 이미 border:0, border-radius:0인 연속 기록 행이다. | 새 카드로 바꾸지 않는다. 번호만 조용하게 추가하고 시간선·진행·완료 표식을 유지한다. |
| 단어장 목록 | 텍스트·정렬·얇은 행 구분선이 구조를 만든다. | 테두리 없는 목록의 좋은 사례로 삼는다. 새 공통 카드 규칙을 덮어씌우지 않는다. |
| 학술탑 연구실 | 초기 .academicTowerRoom 선언은 15px이지만 최종 .academicTowerShell 스코프는 5px로 재정의된다. | 첫 CSS 선언만 보고 큰 둥근 카드라고 판정하지 않는다. 실제 연구 카드·방·레일의 구획은 보존하고, 동일 의미를 중복하는 경계만 따로 판단한다. |

메뉴의 화살표는 목적지가 있는 탐색에만 사용한다. 모든 명령과 닫기까지 같은 꺾쇠를 기계적으로 추가하지 않는다. 버튼의 동사와 위치 자체가 충분한 단서라면 아이콘도 필요하지 않다.

## 4. 경계 표현 규칙 — 제안

### B1. 기본값은 닫힌 테두리가 아니다

읽기나 탐색 목록은 여백 → 정렬 → 제목/본문 위계로 먼저 구성한다. 구분이 여전히 필요하면 한쪽 구분선이나 면 차이를 검토하고, 그다음 독립된 외곽을 검토한다. 모든 행을 상자로 감싸는 것을 출발점으로 삼지 않는다.

### B2. 테두리는 다음 기능 중 하나를 설명해야 한다

1. **실제 조작 범위**: 입력란, 채울 칸, 비교·선택할 대안의 경계다.
2. **독립된 물체나 면**: 개별 의뢰서, 연구 카드, 보조 창처럼 독립적으로 다루는 단위다. 이름만 카드로 붙였다는 이유는 충분하지 않다.
3. **관계와 구획**: 표의 열, 작업 영역, 판의 영향 범위처럼 읽어야 할 관계다. 닫힌 사각형보다 한쪽 선이 적합할 수 있다.
4. **현재 상태**: 선택·포커스·오류처럼 그 순간 알아야 하는 상태다.

'클릭할 수 있다', '공간이 비었다', '항목이 여러 개다', '보기 좋게 정돈한다'만으로는 닫힌 외곽선을 정당화하지 않는다. 반대로 조작 가능성이 사라지도록 필수 테두리를 제거하지도 않는다.

### B3. 경계 종류는 역할에 맞게 고른다

| 역할 | 기본 제안 | 피할 것 |
|---|---|---|
| 메뉴·설정 행·기록 | 상시 외곽선 없음. 눌림 배경과 포커스 표시는 유지한다. | 각 행의 둥근 배경·외곽선·그림자를 동시에 사용한다. |
| 묶음 구분·표 | 필요할 때 1px의 차분한 단선, 보통 한쪽만 사용한다. | 제목·여백·외곽선이 충분한 곳에 선을 또 반복한다. |
| 종이·기록·연구 카드 | 밝은 면과 작은 모서리. 외곽이 필요할 때만 얇은 실선이다. | 종이마다 두꺼운 테두리·큰 라운딩·그림자를 겹친다. |
| 입력·선택·빈칸 | 실제 조작 범위에만 분명한 실선을 사용한다. | 독립 조작물이 무엇인지 알 수 없게 모두 무테로 만든다. |
| 선택 상태 | 같은 크기를 유지하는 강조선이나 inset 표시를 사용한다. 선택 의미를 색만으로 전달하지 않는다. | 선택할 때 선 두께가 커져 문장이나 판이 밀린다. |
| 키보드 포커스 | 기존 3px outline 계약과 구별되는 위치를 보존한다. | 미관을 이유로 outline을 전역 제거한다. |
| 비어 있는 자리 | 사용자가 채울 곳임을 구별할 필요가 있을 때만 점선·파선을 검토한다. | 잠긴 항목·미구현 장소를 전부 점선 카드로 만든다. |
| 떠 있는 보조 창 | 바깥 면, 적절한 모서리, 배경 가림이나 그림자로 층을 구별한다. | 보조 창이 분리돼 있다는 이유만으로 모든 내부 요소도 상자화한다. |

표의 숫자는 후속 시안의 시작점이다. 대비 적합성을 자동 보장하지 않는다. 가는 장식 구분선과 조작을 식별하는 필수 선은 같은 옅은 색으로 일괄 처리하지 않는다.

### B4. 모서리는 단위의 성격에 따른다

전역 radius 토큰 교체가 아니라 아래 역할을 기준으로 시안을 비교한다.

- 목록·텍스트 탭에는 보이는 외곽 자체가 없다. 클릭 영역은 사각형이어도 된다.
- 종이·작업물에는 0–6px 정도의 작은 모서리를 시작점으로 삼는다. 학술탑의 실제 5px 사례를 보존한다.
- 독립 실행 버튼은 적당한 작은 라운딩을 허용한다. 이번 감사만으로 기존 버튼을 모두 같은 수치로 바꾸지 않는다.
- 떠 있는 큰 보조 창은 현재처럼 더 넓은 모서리를 허용한다. 큰 면과 내부 목록의 모서리를 같게 만들지 않는다.
- 원형과 캡슐형은 스위치, 지도 표식, 시간선의 점처럼 형태 자체가 역할을 갖는 곳에 쓴다. 숫자·단어·상태를 모두 캡슐 배지로 만들지 않는다.

### B5. 같은 의미를 두 번 감싸지 않는다

'보조 창 → 메뉴 항목 카드'에서 항목 카드는 대개 같은 목록 구분을 반복한다. '설정 섹션 카드 → 설정 행 카드'도 같은 문제가 있다.

그러나 '독립된 작업면 → 사용자가 채울 입력 칸'은 서로 다른 경계를 설명하므로 중첩을 허용한다. 최대 상자 개수 같은 기계적인 규칙으로 판정하지 않는다. 각 경계가 서로 다른 질문에 답하는지를 본다.

외곽선을 지우고 동일한 둥근 그림자나 채움 면을 남기는 치환은 경계를 줄인 것으로 계산하지 않는다.

### B6. 장식선을 줄여도 조작 계약은 줄이지 않는다

실제 버튼·링크·summary, 최소 44×44 CSS px 입력 영역, 접근성 이름, disabled/aria-current 상태, 눌림 피드백, 포커스, 오류와 위험 행동 설명은 유지한다. 글자만 클릭되게 만들지 않고 투명한 행 전체를 누르게 한다. 정상적인 시각 변경은 기존 A01–A03 회귀 검사를 통과해야 한다.

## 5. 여정 스테이지 번호 — 제안

### 확인한 문제

journey-runtime.js의 makeTimelineItem은 제목, 이야기/스테이지 종류, 단어, 상태를 표시하지만 스테이지 번호를 표시하지 않는다. academic-tower-journey-content.js는 '02와 03은 어느 쪽부터 살펴봐도 좋아'라고 안내하므로, 해당 여정의 번호 없는 행을 안내에서 직접 찾기 어렵다.

번호는 스테이지를 찾고 대화에서 가리키는 주소로 쓴다. 강제 플레이 순서, 난이도, 완료 수, 해금 조건을 대신하지 않는다.

### N1. 지역·연구 묶음 안에서 고정된 번호를 쓴다

게임 전체를 하나의 연속 번호로 매기지 않는다. 길목 02, 장터 02처럼 지역명이 범위를 정한다. 향후 학술탑 연구 묶음이 늘어나면 묶음명도 범위에 포함한다.

기본 사용자 표시는 01, 02처럼 두 자리로 제안한다. 길목 01–07, 장인골 01–07, 장터 01–08, 북쪽 숲 01–08, 현재 학술탑 본선 01–05가 대응한다. 북쪽 숲은 의뢰 하나를 펼쳤다고 다시 01부터 세지 않는다.

튜토리얼은 현재 내부 stage-0…stage-5, 플레이 헤더도 0/5…5/5를 사용한다. 사용자 표기를 01–06으로 정리하려면 여정만 바꾸지 않고 플레이 헤더에도 같은 표시 메타데이터를 적용한다. 내부 ID·진행 조건·저장 키는 변경하지 않는다. 이 표시 정합성은 번호 구현 범위에 포함하되 전술 UI 재설계로 넓히지 않는다.

### N2. 목록을 필터링하거나 잠가도 같은 번호다

이야기는 번호 계산에서 제외한다. 전체/스테이지 필터, 지역 펼침·접힘, 공개·잠금·완료, 재플레이에 따라 번호가 바뀌지 않는다. 공개 조건상 감춰진 콘텐츠는 번호를 위해 미리 출력하지 않는다. 이미 표시되는 잠긴 행에는 기존 제목 비공개를 유지하고 허용된 번호만 표시한다.

STAGES 배열의 전체 index, 현재 화면의 행 index, 필터 뒤 CSS counter, 제목/kicker 문자열의 숫자 추출로 번호를 만들지 않는다. stageId에 연결된 명시적인 표시 메타데이터를 사용한다. 탑의 bundle.rooms[].number 같은 기존 구조를 재사용하거나 공통 조회 함수를 통해 연결해 단일 출처를 유지한다.

### N3. 숫자를 새 배지나 버튼으로 만들지 않는다

제목 앞에 작고 또렷한 숫자를 둔다. 배경·외곽선·원형·캡슐형 배지를 추가하지 않는다. 숫자는 제목보다 약하게, 일반 보조 설명보다는 쉽게 찾을 수 있게 한다. tabular-nums와 03A까지 수용할 폭을 검토한다.

숫자는 클릭 대상이 아니며 행 전체의 일부다. 제목·단어·현재 상태·완료/재플레이 표식과 터치 영역을 보존한다. 시간선의 점에 번호를 덮어써 상태와 참조 번호를 합치지 않는다. 별도 텍스트 행을 늘리지 않는 배치를 우선한다. 긴 제목은 잘라 감추지 않고 자연스럽게 줄바꿈하며, 숫자가 홀로 개행되지 않도록 한다.

접근성 이름에도 지역/묶음 문맥과 단계 번호를 포함한다. 같은 번호를 제목, 부제, 배지에서 반복하지 않는다.

### N4. 선택 연구는 여정과 연구실의 역할을 나눈다

현재 학술탑 가이드는 작은 옆방의 03A 노출을 없애고 이름과 완료 체크만 남긴다. 이 결정은 유지한다.

새 제안은 **여정의 스테이지 행에만** 기존 03A를 참조 번호로 표시하는 예외를 두는 것이다. 예: '03A 색인 옆의 메모', 같은 행의 종류는 '선택 연구'다. 연구실의 옆방에는 번호를 다시 넣지 않는다.

이 예외는 구현 전에 학술탑 가이드의 '전체 여정' 절과 번호 비노출 규칙의 적용 범위에 명시해야 한다. 03A라는 이름을 이유로 03만의 하위 항목으로 이동하거나 선수 조건을 변경하지 않는다. 현재 02·03을 함께 본 뒤 열리는 관계와 본선 5개 집계는 유지한다. 선택 연구를 06번으로 바꾸어 필수 본선처럼 보이게 하지 않는다.

## 6. 후속 구현의 경계와 검증

경계 표현과 번호 표시는 별도 구현 단위로 나눈다. 아래는 각 단위의 범위와 검증 조건이며 전체 실행 순서는 [전체 디자인 감사 §7](DESIGN-AUDIT-v0.1.md)을 따른다.

### 경계 표현 대표 묶음

A09a에서 여행 메뉴·설정 두 화면을 먼저 비교한다. 보조 창의 외곽은 보존하고 내부 행은 목록으로 만든다. 이후 A09b에서 게시판의 개별 종이 면과 내부 행동, 공통 하단 탐색의 표현으로 확장한다. 지도 위치·고정 내비게이션·학술탑 재질·전술판 레이아웃·새 자산 도입은 포함하지 않는다. A04의 탐색 위치 검토는 별도 단계다.

검증할 상태는 일반·눌림·포커스·비활성, 복원 미리보기·오류·초기화 확인이다. 실제 클릭 영역과 인접 영역의 겹침을 확인한다. 외곽을 지운 만큼 아이콘과 상시 설명을 늘려 혼잡도를 다시 높이지 않는다.

### 번호 표시 묶음

번호 메타데이터 → 여정 행 → 필요한 헤더 정합성 → 학술탑 가이드의 화면별 예외 순으로 구현한다. 게임 규칙이나 저장 마이그레이션은 하지 않는다.

회귀 기준:

- 모든 대상 스테이지가 표시 범위 안에서 고유한 번호를 가진다.
- 전체/스테이지 필터 전후 같은 stageId의 번호가 같다. 이야기는 번호가 없다.
- 잠김·완료·진행 중·재플레이 상태에서도 번호가 같다.
- 북쪽 숲의 여러 의뢰와 선택 연구가 각각 잘못 재시작/재번호되지 않는다.
- 학술탑 02·03은 계속 순서 자유이며, 03A는 선택 연구이고 허브의 작은 옆방 외형은 유지한다.
- 기존 비공개 조건, 진행률 집계, 첫 플레이/재플레이 저장 분리와 클릭 목적지가 같다.
- 360×640, 375×640, 375×667, 375×812에서 긴 제목·03A·상태표시가 겹치지 않는다.
- 기존 A01–A03 검사와 전체 콘텐츠/브라우저 검사를 통과한다. iPhone Safari 실기기 승인은 별도로 받는다.

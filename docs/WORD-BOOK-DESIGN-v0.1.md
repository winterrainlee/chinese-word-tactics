# 단어장 설계 v0.1 — 지역별 비교·용례 중심

> 작성일: 2026-09-13  
> 대상: `chinese-word-tactics`  
> 상태: 설계 확정안 / 구현 전  
> 핵심 방향: **지역 → 비교 묶음 → 개별 단어**

---

## 1. 한 줄 정의

**게임에서 단어를 경험하고, 단어장에서는 그 경험들을 서로 연결한다.**

단어장은 퀴즈 화면이 아니다. 이미 전술 스테이지가 단어의 뜻을 상황 속에서 판단하고 적용하는 역할을 한다.

따라서 단어장의 우선순위는 다음과 같다.

1. 비슷하거나 연결된 단어를 한눈에 비교한다.
2. 실제 용례와 게임에서 경험한 장면을 다시 본다.
3. 지역별로 어떤 언어를 배웠는지 여행의 맥락 속에서 정리한다.
4. 필요할 때 개별 단어를 사전처럼 자세히 확인한다.

`전체 단어 → 암기 → 퀴즈`를 기본 흐름으로 삼지 않는다.

---

## 2. 현재 구조의 문제

현재 `GameFlow.showWords()`는 모든 `WORDS`를 모달 시트에 일렬로 나열한다.

이 방식은 단어 수가 적은 프로토타입에서는 작동하지만 세계가 커지면 다음 문제가 생긴다.

- 지역과 스테이지의 맥락이 사라진다.
- `通過 / 經由 / 到達`처럼 비교해야 이해되는 단어가 흩어진다.
- 장인골의 `損壞 → 修復 → 恢復`처럼 과정으로 익힌 의미가 평면 목록으로 바뀐다.
- 긴 목록을 탐색하려면 검색과 정렬에 지나치게 의존하게 된다.
- 빠른 뜻 확인용 모달과 장기 학습용 단어장이 같은 UI에 섞인다.

반면 게임 본편은 이미 `월드맵 / 여정 / 단어장`을 주요 메뉴로 분리해 두었다.

따라서 단어장도 모달이 아니라 독립된 `wordsView`가 되어야 한다.

---

## 3. 역할 분담

### 3.1 플레이 중 단어 시트 — 빠른 확인

현재 `showWord(word)` 계열의 시트는 없애지 않는다.

역할은 다음으로 한정한다.

- 지금 판에 나온 단어의 뜻 확인
- 주음 확인
- 짧은 예문 확인
- `이 판에서는` 무엇을 뜻하는지 확인
- 확인 후 즉시 판으로 복귀

여기에 작은 보조 동작 하나를 추가할 수 있다.

`단어장에서 비교하기 →`

이를 누르면 전체 단어장 해당 단어 상세로 이동한다.

### 3.2 단어장 페이지 — 비교와 연결

메뉴의 `단어장`은 독립 화면을 연다.

역할은 다음과 같다.

- 지역별 단어 탐색
- 비교 묶음 읽기
- 용례 비교
- 다른 지역에서 다시 등장한 단어 추적
- 개별 단어 상세 확인
- 검색

즉 두 UI는 경쟁하지 않는다.

**시트 = 지금 필요한 확인**  
**페이지 = 나중에 다시 보는 학습 공간**

## 4. 정보 구조

기본 계층은 세 단계다.

```text
단어장
└─ 장 / 여행 구간
   └─ 지역
      └─ 비교 묶음
         └─ 개별 단어
```

예:

```text
1장 · 물길마을
├─ 길목
│  ├─ 경계를 드나들기
│  │  ├─ 進入
│  │  └─ 退出
│  ├─ 거리와 범위
│  │  ├─ 距離
│  │  └─ 範圍
│  └─ ...
├─ 장인골
│  ├─ 바꾸기와 유지하기
│  ├─ 늘리고 줄여 맞추기
│  └─ ...
└─ 장터
   ├─ 필요와 부족을 채우기
   ├─ 교환과 획득
   └─ ...
```

### 중요한 원칙

**지역은 단어의 소유자가 아니라 찾아가는 주소다.**

한 단어는 여러 지역과 여러 비교 묶음에서 다시 참조될 수 있다.

예를 들어 `通過`는 숲에서 처음 만나더라도 길목의 `進入 / 退出 / 經由`와 비교할 가치가 있다.

따라서:

- 단어 데이터는 전역에서 하나만 가진다.
- 지역 페이지는 단어를 복제하지 않고 참조한다.
- 비교 묶음은 필요하면 다른 지역의 단어를 `같이 보기`로 연결한다.
- 한 단어가 여러 비교 묶음에 들어가는 것도 허용한다.

비교 묶음은 분류표가 아니라 **학습 관계**이기 때문이다.

## 5. 최상위 단어장 화면

### 5.1 모바일 기본 화면

```text
←  단어장                         검색

1장 · 물길마을                         ▾
길에서 만난 말을 지역별로 다시 살펴봐.

[ 길목 ]
경로 · 위치 · 이동
14개 단어

[ 장인골 ]
변화 · 조건 · 상태
14개 단어

[ 장터 ]
필요 · 거래 · 선택 · 분배
15개 단어

────────────
전체 단어 보기

월드맵   여정   단어장
```

정확한 개수 표시는 런타임에서 계산한다. 하드코딩하지 않는다.

### 5.2 장 선택

지역 수가 늘어날 것을 전제로 최상단에 `장 선택기`를 둔다.

현재에는 다음처럼 시작할 수 있다.

- 여행의 시작 · 숲길
- 1장 · 물길마을

향후:

- 2장 · …
- 3장 · …

지역 20개를 가로 탭 20개로 늘어놓지 않는다.

**장 → 그 장의 지역** 순으로 범위를 좁힌다.

### 5.3 지역 카드

지역 카드는 다음만 보여준다.

- 지역명
- 지역에서 익힌 의미 축을 한 줄로 요약
- 발견한 단어 수

단어 목록 자체를 최상위 화면에 펼치지 않는다.

## 6. 지역 화면

예: `장인골`

```text
←  장인골
1장 · 물길마을

상태를 읽고, 필요한 곳만 바꾼다.

바꾸기와 유지하기
改變  ↔  保持
바꾸어야 하는 것과 그대로 둘 것을 구분한다.

늘리고 줄여 맞추기
增加  ↔  減少  →  調整
개별 변화와 전체 조절의 차이를 본다.

연결하고 떼기
連接  ↔  分開

조건과 맞음
條件  →  符合

나타나고 사라지기
出現  ↔  消失

고장에서 회복까지
損壞  →  修復  →  恢復

────────────
장인골 전체 단어 보기
```

### 6.1 기본값은 비교 묶음

지역 화면의 첫 내용은 가나다순이나 주음순 목록이 아니다.

비교 묶음이 먼저 나온다.

`전체 단어 보기`는 보조 기능으로 아래에 둔다.

### 6.2 비교 묶음의 관계 유형

모든 비교가 반의어는 아니다.

v0.1에서는 다음 관계를 지원한다.

- `contrast`: 대조 — `增加 ↔ 減少`
- `sequence`: 과정 — `損壞 → 修復 → 恢復`
- `perspective`: 같은 사건의 관점 차이 — `買 ⇄ 賣`, `跟隨 ⇄ 帶領`
- `scope`: 상위·하위 또는 범위 차이 — `移動`과 `前進 / 後退`
- `condition`: 기준과 상태 관계 — `需求 → 不足 / 足夠`
- `related`: 직접 대조는 아니지만 같이 보면 좋은 관계

이 `type`은 장식용 분류가 아니다. 묶음 설명을 작성하고 향후 간단한 연결 기호를 고를 때 사용한다.

화면에서 관계 유형 이름 자체를 굳이 표시할 필요는 없다.

## 7. 비교 묶음 상세

비교 묶음을 누르면 단어들을 한 화면에서 직접 비교한다.

예: `늘리고 줄여 맞추기`

```text
←  늘리고 줄여 맞추기
장인골

增加
ㄗㄥ ㄐㄧㄚ
늘리다, 증가시키다
風量增加了一點。

減少
ㄐㄧㄢˇ ㄕㄠˇ
줄이다, 감소시키다
火力減少了一點。

調整
ㄊㄧㄠˊ ㄓㄥˇ
조절하다, 맞추다
把火力和風量調整好。

────────────
비교하면
增加와 減少는 한 값의 방향을 말한다.
調整은 필요한 상태에 맞추는 전체 과정을 말한다.

게임에서
불은 減少하고 바람은 增加했다.
두 상태가 모두 알맞아졌을 때 調整이 완성됐다.
```

### 7.1 비교 화면의 원칙

- 중국어 표기가 가장 먼저 보인다.
- 주음은 바로 아래 둔다.
- 한국어 핵심 뜻은 기본적으로 보여준다.
- 단어마다 최소 한 개의 중국어 예문을 나란히 본다.
- 묶음 마지막에 `차이`를 자연어로 설명한다.
- 가능하면 게임에서 경험한 같은 장면으로 차이를 다시 설명한다.

### 7.2 한국어를 기본으로 숨기지 않는 이유

단어장은 시험 화면이 아니라 참고·비교 공간이다.

따라서 기본 상태에서는 한국어 핵심 뜻을 보여준다.

원한다면 나중에 `뜻 가리기`를 개인 표시 옵션으로 제공할 수 있지만 기본값으로 두지 않는다.

이 옵션이 생기더라도 점수, 정답률, 연속 학습 기록과 연결하지 않는다.

## 8. 개별 단어 상세

예: `通過`

```text
←  通過

通過
ㄊㄨㄥ ㄍㄨㄛˋ
통과하다, 지나가다

일반 용례
我們要通過這個遺跡。
[한국어 뜻 보기]

게임에서
유적의 한쪽 입구로 들어가 다른 쪽 입구로 나왔다.

같이 보면
經由  도중에 어떤 장소를 거침
到達  목적지에 닿음
進入  경계를 넘어 안으로 들어감
退出  안에서 밖으로 나감

처음 만난 곳
여행의 시작 · 폐허를 지나서

다시 나온 곳
길목 · 두 갈래 길에서 到達과 함께 비교 가능
```

### 8.1 정보 우선순위

1. 단어
2. 주음
3. 핵심 한국어 뜻
4. 일반 용례
5. 게임 맥락 용례
6. 비교 단어
7. 등장 기록

사전 정보를 많이 쌓는 것보다 **어디서 어떻게 썼는지**를 먼저 살린다.

### 8.2 예문의 두 층

용례는 두 종류를 구분한다.

- `general`: 게임 밖에서도 자연스러운 일반 예문
- `game`: 실제 게임 장면을 설명하는 맥락 예문 또는 장면 요약

둘을 같은 문장으로 억지로 통합하지 않는다.

## 9. 1장 비교 묶음 초안

### 9.1 여행의 시작 · 숲길

#### 가까워지고 멀어지기

`接近 ↔ 遠離`

- 대상과의 거리 변화
- 위험물과 목표물에 따라 같은 거리 변화가 다른 전략을 만든다.

#### 길에서 일어나는 일

`避開 · 通過 · 到達`

- `避開`: 어떤 대상을 피해 감
- `通過`: 공간이나 구간을 지나감
- `到達`: 목적지에 닿음

향후 길목의 `經由 / 進入 / 退出`으로 연결한다.

---

### 9.2 길목

#### 경계를 드나들기

`進入 ↔ 退出`

같이 보기: `通過`

`進入 / 退出`은 경계를 기준으로 방향을 말한다. `通過`는 공간을 지나 반대편까지 가는 것에 초점이 있다.

#### 거리와 범위

`距離 · 範圍`

- `距離`: 두 대상 사이가 얼마나 떨어졌는가
- `範圍`: 어떤 영향이나 조건이 미치는 영역

#### 길과 경유

`路線 · 經由`

같이 보기: `通過 / 到達`

- `路線`: 출발점에서 목적지까지 이어지는 전체 길
- `經由`: 그 길에서 실제로 거친 지점
- `到達`: 여정의 끝점

#### 위치와 주변

`位置 · 周圍 · 障礙`

- `位置`: 대상이 있는 자리
- `周圍`: 대상 주변의 여러 요소
- `障礙`: 그 주변 요소 중 실제 진행을 막는 것

#### 움직임과 방향

`移動 ⊃ 前進 / 後退`

- `移動`: 위치가 바뀌는 넓은 개념
- `前進`: 바라보는 방향으로 이동
- `後退`: 그 반대 방향으로 이동

#### 같은 행렬, 두 관점

`跟隨 ⇄ 帶領`

같은 움직임을 뒤의 대상에서 보면 `跟隨`, 앞의 대상에서 보면 `帶領`이다.

---

### 9.3 장인골

#### 바꾸기와 유지하기

`改變 ↔ 保持`

모든 것을 바꾸는 것이 아니라 필요한 곳만 바꾸고 이미 맞는 것은 유지한다.

#### 늘리고 줄여 맞추기

`增加 ↔ 減少 → 調整`

`增加 / 減少`는 개별 값의 변화 방향이고 `調整`은 목표 상태에 맞추는 전체 과정이다.

#### 연결하고 떼기

`連接 ↔ 分開`

장치가 함께 작동할 관계를 만들거나 끊는다.

#### 조건과 맞음

`條件 → 符合`

`條件`은 요구되는 기준이고 `符合`는 현재 상태가 그 기준에 맞는다는 판단이다.

#### 나타나고 사라지기

`出現 ↔ 消失`

직접 누르는 조작이 아니라 다른 조건 변화의 결과로 관찰되는 현상이라는 점을 함께 강조한다.

#### 고장에서 회복까지

`損壞 → 修復 → 恢復`

- `損壞`: 손상된 상태
- `修復`: 고치는 행동
- `恢復`: 기능을 되찾은 결과

---

### 9.4 장터

#### 필요에서 충분까지

`需求 → 不足 → 補充 → 足夠`

- `需求`: 필요한 기준량
- `不足`: 현재량이 기준보다 모자란 상태
- `補充`: 부족한 만큼 더하는 행동
- `足夠`: 필요한 만큼 채워진 상태

`補充`은 다른 묶음에도 다시 등장할 수 있다.

#### 수량과 남은 것

`數量 · 剩下`

- `數量`: 어떤 시점의 개수
- `剩下`: 사용하거나 보낸 뒤 현재 남아 있는 것

#### 교환해서 얻기

`交換 → 獲得`

- `交換`: 서로 주고받는 방법
- `獲得`: 그 결과 손에 들어온 것

#### 같은 거래, 두 관점

`買 ⇄ 賣`

같은 거래를 구매자 쪽에서 보면 `買`, 판매자 쪽에서 보면 `賣`다.

#### 가격과 가치

`價格 ↔ 價值`

- `價格`: 지불해야 하는 양
- `價值`: 지금 필요한 일을 얼마나 잘 해결하는가까지 포함한 판단

단순히 싼 것이 더 가치 있다는 식으로 환원하지 않는다.

#### 선택과 이번 차례의 포기

`選擇 ⇄ 放棄`

현재 게임의 `放棄`는 영구 폐기가 아니라 제한된 자원 때문에 이번 차례에 선택하지 않고 미루는 맥락이다.

#### 나누고 채우기

`分配 · 補充`

- `分配`: 여러 목적지에 필요한 자원을 나누어 보냄
- `補充`: 한 목적지의 부족분을 채움

---

## 10. 전체 단어 보기

비교 묶음 외에도 빠른 탐색을 위한 전체 목록은 필요하다.

단, 기본 정렬은 가나다순이나 유니코드순이 아니다.

### 기본 정렬

**처음 만난 순서**

이 순서는 게임의 학습 흐름과 가장 잘 맞는다.

지역 화면에서는 해당 지역에서 처음 만난 순서로 보여준다.

전체 화면에서는:

1. 여행의 시작
2. 1장 길목
3. 1장 장인골
4. 1장 장터
5. 이후 장과 지역

순으로 이어간다.

필요하면 나중에 `가나다 / 주음 / 최근 만남` 같은 보조 정렬을 추가할 수 있다.

v0.1에서는 없어도 된다.

## 11. 검색

세계가 커지면 검색은 반드시 필요하다.

다만 검색창이 단어장의 첫인상이 되어서는 안 된다.

상단 돋보기로 진입한다.

### v0.1 검색 대상

- 번체 중국어 표기
- 한국어 핵심 뜻
- 주음

검색 결과는 단어 카드를 보여주고 해당 상세로 이동한다.

향후에는 비교 묶음 제목도 검색 대상으로 확장할 수 있다.

### 발견 전 단어

스토리 스포일러를 막기 위해 기본 검색은 **플레이어가 만난 단어만** 대상으로 한다.

---

## 12. 발견 상태 — 숙련도와 분리

단어장에 게임 진행 흔적을 넣되 `숙련도 72%` 같은 가짜 정밀도를 만들지 않는다.

게임이 확실히 아는 정보만 저장한다.

v0.1에서 필요한 상태는 하나면 충분하다.

- `discovered`: 실제 플레이 중 한 번 이상 만났는가

향후 필요하면 다음을 추가할 수 있다.

- `firstSeenStage`
- `lastSeenStage`
- `encounterCount`

하지만 이를 시험 점수나 암기 성공률로 해석하지 않는다.

### 발견 시점

스테이지를 처음 화면에 실제로 열었을 때 그 스테이지의 `stage.words`를 발견한 것으로 기록한다.

클리어해야만 등록되게 하지 않는다.

단어를 이미 눈앞에서 읽었는데 실패했다는 이유로 단어장에서 사라지는 것은 부자연스럽기 때문이다.

### 기존 저장 데이터 이행

기존 사용자의 경우 최소한 `completedStages`에 포함된 스테이지의 단어는 발견 상태로 복원할 수 있다.

현재 진행 중인 스테이지도 가능하면 포함한다.

---

## 13. 데이터 구조

현재 `WORDS`는 런타임에서 다음과 같은 작은 구조를 쓴다.

```js
WORDS['通過'] = {
  p: 'ㄊㄨㄥ ㄍㄨㄛˋ',
  k: '통과하다, 지나가다',
  ex: '我們要通過這個遺跡。',
  rule: '...'
};
```

이 데이터는 전술판의 빠른 시트에서 이미 널리 사용하므로 단번에 갈아엎지 않는다.

### 13.1 1차 구현

새 파일을 둔다.

```text
src/lexicon-content.js
src/lexicon-runtime.js
src/lexicon.css
```

`lexicon-content.js`에는 두 종류의 확장 정보만 둔다.

```js
const WORD_META = {
  '通過': {
    pos: 'verb',
    exampleKo: '우리는 이 유적을 지나가야 한다.',
    usageKo: '공간이나 구간을 지나가는 데 초점이 있다.'
  }
};

const LEXICON_GROUPS = [
  {
    id: 'gate-boundary',
    chapterId: 'chapter-1',
    regionId: 'gate-town',
    titleKo: '경계를 드나들기',
    type: 'contrast',
    words: ['進入', '退出'],
    related: ['通過'],
    noteKo: '進入와 退出은 경계를 기준으로 방향을 말한다.'
  }
];
```

### 13.2 단어의 지역·스테이지 등장 정보는 중복 저장하지 않는다

다음 정보는 `STAGES[].words`에서 자동 계산한다.

- 어느 스테이지에서 등장했는가
- 처음 만난 스테이지는 어디인가
- 어느 지역에서 등장했는가
- 몇 번 재등장했는가

이를 위해 `LexiconRuntime`에서 인덱스를 만든다.

```js
buildWordAppearanceIndex(STAGES, JourneyContent)
```

정확한 함수 이름은 구현 시 조정해도 된다.

### 13.3 `p` 필드 정리

현재 `p`에는 병음이 아니라 주음부호가 들어 있다.

장기적으로는 의미가 명확한 `zhuyin` 필드로 바꾸는 것이 좋다.

다만 v0.1 구현에서 기존 `WORDS` 소비 코드를 한꺼번에 깨지 않는다.

우선 정규화 함수에서:

```js
zhuyin: detail.zhuyin || detail.p
```

처럼 호환하고, 이후 콘텐츠 마이그레이션 때 `p → zhuyin`을 정리한다.

### 13.4 대형 외부 단어 데이터는 직접 싣지 않는다

현재 콘텐츠 경계 원칙을 유지한다.

TBCL 등 대형 원천 데이터 전체를 모바일 런타임에 직접 넣지 않는다.

필요한 단어 정보만 생성된 런타임 데이터로 가져온다.

## 14. 화면 상태와 이동

### 14.1 새 메인 뷰

`index.html`에 다음을 추가한다.

```text
main#wordsView
```

`GameFlow.showWords()`는 더 이상 `openSheet()`를 호출하지 않고 `wordsView`를 연다.

### 14.2 단어장 내부 상태

최소 상태:

```js
{
  chapterId,
  regionId,
  groupId,
  wordId,
  mode // root | region | group | word | search | all
}
```

브라우저 새로고침까지 이 내부 위치를 보존해야 하는지는 v0.1 필수는 아니다.

다만 단어 상세에서 뒤로 갔을 때 **단어장 첫 화면이 아니라 직전 비교 묶음/지역으로 돌아가는 것**은 필수다.

### 14.3 주요 메뉴

기존 하단 메뉴의 세 축은 그대로 유지한다.

`월드맵 / 여정 / 단어장`

단어장에서는 `단어장`에 `aria-current="page"`를 준다.

## 15. 모바일 시각 원칙

기준 기기는 계속 iPhone 13 mini 세로 화면으로 둔다.

### 15.1 한 화면에 너무 많은 카드 금지

단어 하나마다 큰 카드 하나를 만들면 세로 스크롤이 과도하게 길어진다.

- 지역은 큰 구획
- 비교 묶음은 얇은 행 또는 낮은 카드
- 개별 단어는 비교 상세에서 텍스트 블록

정도로 위계를 나눈다.

### 15.2 중국어가 시각적 주인공

비교 묶음 행에서는 한자 단어를 제목보다 먼저 읽을 수 있어야 한다.

예:

```text
늘리고 줄여 맞추기
增加  ↔  減少  →  調整
```

제목은 관계를 설명하고 중국어는 실제 학습 대상을 보여준다.

### 15.3 장식보다 여백

기존 디자인 원칙을 따른다.

- 모든 묶음에 두꺼운 테두리와 그림자를 쓰지 않는다.
- 지역 구획은 여백과 약한 면 차이로 나눈다.
- 단어는 일반 앱 버튼처럼 보이지 않게 한다.
- 터치 대상은 최소 44px을 확보한다.

## 16. 접근성과 번역 표시

- 중국어 텍스트에는 가능한 곳에서 `lang="zh-Hant"`를 사용한다.
- 한국어 설명에는 `lang="ko"`를 유지한다.
- 화살표나 색만으로 단어 관계를 설명하지 않는다. 반드시 문장 설명이 따라온다.
- 검색과 지역 선택은 키보드 포커스 순서가 자연스러워야 한다.
- 접힌 번역은 `aria-expanded`를 제공한다.
- 비교 묶음 전체가 하나의 거대한 클릭 영역이 되더라도 내부 텍스트 선택과 스크린리더 읽기가 깨지지 않게 한다.

## 19. 자동 검수 기준

### 구조

- `showWords()`가 단어장 모달을 열지 않는다.
- 월드맵/여정과 같은 수준의 `wordsView`가 존재한다.
- 지역 → 비교 묶음 → 단어 상세 이동이 가능하다.
- 뒤로 가면 직전 단어장 문맥이 유지된다.

### 데이터

- `LEXICON_GROUPS`가 참조하는 모든 단어는 `WORDS`에 존재한다.
- 모든 그룹의 `regionId`는 실제 지역과 연결된다.
- `STAGES[].words`에 존재하는 단어는 등장 인덱스에 빠짐없이 잡힌다.
- 같은 단어가 여러 그룹에 들어가도 중복 단어 레코드를 만들지 않는다.

### 모바일

- 375px 너비에서 가로 스크롤이 생기지 않는다.
- 3개 단어 관계가 필요하면 자연스럽게 줄바꿈된다.
- 주음과 한자가 겹치지 않는다.
- 터치 영역 44px을 지킨다.

### 학습 경험

- 지역 첫 화면에서 전체 단어 평면 목록보다 비교 묶음이 먼저 보인다.
- 한국어 핵심 뜻은 단어장에서는 기본 표시된다.
- 적어도 각 비교 묶음에 관계 설명이 하나 있다.
- 개별 상세에서 일반 용례와 게임 맥락을 구분해 볼 수 있다.
- 퀴즈나 숙련도 퍼센트가 단어장 기본 흐름에 끼어들지 않는다.

## 20. 완료 기준

v0.1 단어장 구현은 다음 경험이 실제로 가능하면 완료로 본다.

> 플레이어가 장터를 끝낸 뒤 단어장을 연다. `1장 · 물길마을 → 장터 → 가격과 가치`로 들어가 `價格`과 `價值`를 같은 화면에서 비교한다. 예문과 게임에서 경험한 차이를 읽는다. `價格`을 눌러 개별 상세를 본 뒤 다시 같은 비교 묶음으로 돌아온다. 이후 검색에서 `가격`을 입력해 `價格`을 다시 찾을 수 있다.

이 흐름에 퀴즈를 풀거나 점수를 얻는 단계는 필요하지 않다.

## 21. 이후 확장 방향

세계가 커져도 기본 구조는 바꾸지 않는다.

```text
장
→ 지역
→ 비교 묶음
→ 단어
```

확장은 다음 방식으로 붙인다.

- 새 장: 장 메타데이터 추가
- 새 지역: 지역 메타데이터 추가
- 새 스테이지: `stage.words`로 등장 기록 자동 반영
- 새 비교 관계: `LEXICON_GROUPS` 추가
- 기존 단어 재사용: 새 단어 레코드 없이 새 그룹에서 참조

따라서 지역과 스테이지가 늘어도 단어장 전체 구조를 다시 설계할 필요가 없다.

## 22. 최종 원칙

1. **단어장은 시험장이 아니라 연결하는 곳이다.**
2. **목록보다 비교가 먼저다.**
3. **비교보다 용례가 뒤처지지 않는다.**
4. **지역은 탐색 축이지만 단어를 가두지 않는다.**
5. **게임이 실제로 아는 진행 정보만 표시한다.**
6. **플레이 중 빠른 시트와 독립 단어장은 서로 다른 일을 한다.**
7. **세계가 커져도 장 → 지역 → 비교 묶음 구조를 유지한다.**

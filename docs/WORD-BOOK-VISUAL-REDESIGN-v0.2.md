# 단어장 시각 리디자인 v0.2 — 카드에서 색인과 노트로

> 작성일: 2026-09-13  
> 대상: `chinese-word-tactics` 단어장  
> 관련 문서: `DESIGN-PRINCIPLES-v0.2.md`, `WORD-BOOK-DESIGN-v0.1.md`  
> 상태: **시각 설계 확정안 / 구현 전**  
> 기준 기기: iPhone 13 mini Safari, 375×812  
> 핵심 방향: **카드를 쌓아 위계를 만들지 않는다. 여백·선·타이포그래피로 위계를 만든다.**

---

## 1. 이번 리디자인의 목적

단어장 v0.1의 정보 구조와 기능은 유지한다.

```text
장 → 지역 → 비교 묶음 → 단어
```

문제는 기능이 아니라 시각 문법이다.

현재 단어장은 다음 요소가 거의 모두 같은 문법을 사용한다.

- 장 선택: 둥근 입력 상자
- 지역: 둥근 흰 카드
- 비교 묶음: 둥근 흰 카드
- 비교 단어: 둥근 흰 카드
- 개별 단어의 각 섹션: 둥근 흰 카드
- 관련 단어: 작은 둥근 버튼
- 전체 보기: 둥근 버튼

각 요소는 개별적으로는 무난하지만, 화면 전체에서는 `흰 배경 + 회색 테두리 + 둥근 모서리`가 반복된다.
그 결과 단어장이 여행 기록이나 어휘 색인보다 일반적인 학습 앱 대시보드처럼 보인다.

v0.2의 목적은 기능을 줄이는 것이 아니라 **같은 정보를 더 자연스럽고 조용하게 보이게 하는 것**이다.

---

## 2. 시각 메타포

단어장은 다음처럼 보여야 한다.

> **여행하면서 만난 말을 사람이 나중에 다시 찾아보기 좋게 정리해 둔 색인과 작은 노트.**

다음처럼 보이지 않는다.

- KPI 대시보드
- SaaS 설정 화면
- 플래시카드 앱
- 모든 항목이 독립 상품인 카드 갤러리
- 생성형 UI가 자동으로 배치한 카드 스택

### 판단 기준

화면을 보았을 때 사용자가 먼저 느껴야 하는 것은

> “어떤 카드를 눌러야 하지?”

가 아니라

> **“어디에서 어떤 말을 배웠고, 이 말들은 어떻게 연결되지?”**

이다.

---

## 3. 유지하는 것

다음은 이번 리디자인에서 바꾸지 않는다.

- `월드맵 / 여정 / 단어장` 하단 주 메뉴
- 장 → 지역 → 비교 묶음 → 단어 정보 구조
- 지역별 탐색
- 발견한 단어만 기본 노출
- 검색
- 비교 중심 학습 구조
- 한국어 핵심 뜻 기본 표시
- 일반 용례 / 게임 맥락 구분
- 빠른 단어 시트와 독립 단어장의 역할 분리
- 44px 최소 터치 영역
- 따뜻한 종이 계열 배경과 현재 기본 색 방향

즉 **레이아웃의 성격을 바꾸되 정보 구조를 갈아엎지 않는다.**

---

## 4. 제거하거나 크게 줄이는 것

### 4.1 반복 카드

다음 요소의 기본 카드 외형을 제거한다.

- 지역 행
- 비교 묶음 행
- 비교 화면의 각 단어
- 개별 단어 상세의 일반 용례 / 게임에서 / 여정 기록

### 4.2 반복 radius

페이지의 모든 블록이 같은 12~16px radius를 갖지 않는다.

둥근 모서리는 다음에만 적극적으로 남긴다.

- 바텀시트 / 모달
- 검색 입력
- 정말 독립된 조작 버튼
- 필요 시 하단 내비게이션

### 4.3 반복 테두리

항목 하나마다 네 면의 테두리를 두르지 않는다.

대신:

- 항목 간 세로 여백
- 약한 수평선
- 타이포그래피 차이
- 정렬

을 사용한다.

---

## 5. 전체 화면의 공통 골격

단어장의 모든 하위 화면은 같은 기본 골격을 공유한다.

```text
←             화면 제목             검색
              작은 맥락

────────────────────────  필요할 때만

본문


월드맵        여정        단어장
```

### 상단

- 높이를 과도하게 키우지 않는다.
- 뒤로가기 44×44.
- 제목은 중앙 또는 좌측 정렬 중 현재 앱 문법에 맞춰 유지한다.
- 부제는 한 줄의 작은 맥락으로만 사용한다.
- 검색은 독립 카드가 아니라 아이콘 행동으로 유지한다.

### 본문

- 전체 폭을 사용하되 좌우 읽기 여백을 유지한다.
- 본문 블록을 카드로 감싸지 않는다.
- 큰 단계 변화에만 비교적 큰 세로 여백을 사용한다.

### 하단

기존 주 메뉴 유지.
단어장 내부 콘텐츠가 하단 메뉴와 겹치지 않도록 충분한 bottom padding을 둔다.

# 화면 1 — 단어장 홈

## 6. 문제

현재 홈은 장 선택 드롭다운보다 지역 카드가 훨씬 크다.

정보 구조는

```text
장
└─ 지역
```

인데, 시각적으로는

```text
작은 설정 컨트롤
└─ 거대한 카드 여러 개
```

처럼 보여 위계가 뒤집힌다.

또 지역 하나에 들어가는 정보가 2~3줄뿐인데 카드 높이가 크고 각 카드 사이에도 간격이 커서 내용 밀도보다 컴포넌트가 과장되어 보인다.

---

## 7. 홈 v0.2 구조

### 권장 시안

```text
←              단어장              ⌕
   게임에서 만난 말을 다시 연결하기

1장 · 물길마을 ⌄
길에서 만난 말을 지역별로 다시 살펴봐.

길목  關口                              4 / 14
경로 · 위치 · 이동
────────────────────────────────
장인골  工坊谷                          3 / 14
변화 · 조건 · 상태
────────────────────────────────
장터  市集                              3 / 15
필요 · 거래 · 선택 · 분배

발견한 단어 전체 보기  ·  10


월드맵            여정            단어장
```

### 장 전환기

`여행 구간`이라는 별도 폼 라벨을 제거하는 방향을 기본안으로 한다.

현재 장은 다음처럼 **페이지 안의 소제목 겸 전환기**처럼 보인다.

```text
1장 · 물길마을 ⌄
```

- 높이 약 44px.
- 전체 폭의 두꺼운 테두리 금지.
- 눌러 바꿀 수 있다는 단서는 `⌄`와 터치 피드백으로 충분하다.
- 장이 하나뿐이어도 장 구조가 있다는 것은 보이되, 빈 설정 필드처럼 보이지 않는다.

### 지역 행

지역 하나의 시각 높이는 **56~64px** 정도를 기본 목표로 한다.

첫 줄:

- 한국어 지역명: 강한 본문 또는 섹션 제목
- 중국어명: 같은 줄, 한 단계 낮은 강도
- 발견 수: 우측 끝, 작은 메타 정보

둘째 줄:

- 의미 축: 작은 회색 설명

행 전체는 44px 이상의 터치 영역을 유지한다.

### 지역 간 경계

우선순위:

1. 일정한 세로 여백
2. 필요하면 1px보다 시각적으로 약한 구분선
3. 카드 배경은 사용하지 않음

마지막 행 아래에는 꼭 선을 넣지 않아도 된다.

### 발견 수

`발견 4 / 14`처럼 문장형으로 크게 쓰지 않는다.

추천:

`4 / 14`

맥락상 발견 수라는 것을 최초 화면의 작은 안내 또는 접근성 레이블에서 충분히 전달한다.

숫자는 참고 정보이지 성취 점수가 아니다.

# 화면 2 — 지역 화면

## 8. 문제

현재 비교 묶음마다 둥근 카드가 하나씩 생긴다.

장터처럼 묶음이 많아지면 아래 패턴이 반복된다.

```text
[ 제목 / 중국어 / 설명 ]
[ 제목 / 중국어 / 설명 ]
[ 제목 / 중국어 / 설명 ]
```

각 묶음이 서로 독립된 상품처럼 보여, 실제 목적 — **한 지역 안의 언어 관계를 훑어보는 것** — 이 약해진다.

---

## 9. 지역 v0.2 구조

### 권장 시안

```text
←              장터               ⌕
                1장 · 물길마을

필요와 거래, 선택과 분배를 배운 곳.

필요에서 충분까지
需求 → 不足 → 補充 → 足夠
필요한 것이 모자라고, 채워져 충분해지는 흐름

────────────────────────────────

수량과 남은 것
數量 · 剩下
처음의 양과 쓰고 난 뒤 남은 것을 구분한다.

────────────────────────────────

買 ⇄ 賣

────────────────────────────────

지불하는 양과 지금의 쓸모는 같은 말이 아니다.

```

### 비교 묶음의 기본 레이아웃

묶음 하나는 **카드가 아니라 짧은 문단/색인 항목**이다.

순서:

1. 관계 제목 — 한국어
2. 중국어 관계식 — 가장 눈에 띄게
3. 설명 — 한 줄 또는 두 줄

중국어 관계식이 묶음의 시각적 중심이다.

### 행 높이

내용에 따라 자연스럽게 결정한다.
고정 높이 카드로 맞추지 않는다.

대략:

- 2단어 묶음: 72~88px
- 3~4단어 묶음: 84~104px

을 목표 범위로 삼되 강제하지 않는다.

### 터치

묶음 전체를 누를 수 있지만 겉으로 버튼처럼 솟게 만들지 않는다.

터치 피드백:

- 아주 약한 배경 wash
- 또는 중국어 관계식 색 변화

중 하나로 충분하다.

# 화면 3 — 비교 상세

## 10. 문제

현재 비교 상세는 단어 하나가 큰 카드 하나씩 차지한다.

예:

```text
[ 買 + 주음 + 뜻 + 예문 ]
[ 賣 + 주음 + 뜻 + 예문 ]
```

정보는 읽히지만 `買`와 `賣`가 서로 비교되는 느낌보다 **독립된 두 카드**처럼 느껴진다.

비교 화면에서는 카드 경계가 오히려 관계를 끊는다.

---

## 11. 비교 상세 v0.2 구조

### 2단어 관계 예시

```text
←         같은 거래, 두 관점          ⌕
                    장터

              買  ⇄  賣

買
ㄇㄞˇ
사다, 구입하다
我買了一份菜。
나는 채소 한 몫을 샀다.

                         ⇅

賣
ㄇㄞˋ
팔다
菜販賣出了一份菜。
채소 상인이 채소 한 몫을 팔았다.

────────────────────────────────

어떻게 다를까?
같은 거래를 구매자 쪽에서 보면 買,
판매자 쪽에서 보면 賣다.

게임에서
…

이것도 참고하자
價格   交換   獲得
```

### 핵심 변화 1 — 관계를 먼저 보여준다

화면 상단에 비교 대상 자체를 한 줄로 보여준다.

```text
買 ⇄ 賣
```

또는

```text
損壞 → 修復 → 恢復
```

사용자는 상세 내용을 읽기 전에 어떤 관계를 보는지 먼저 안다.

### 핵심 변화 2 — 단어 카드를 없앤다

각 단어는 같은 종이 위의 연속된 블록처럼 배치한다.

구분 방법:

- 충분한 세로 여백
- 필요하면 중앙에 작은 관계 기호
- 얇은 선은 단어와 단어 사이보다 **비교 설명 시작 전**에 사용하는 편을 우선한다.

### 핵심 변화 3 — 관계 유형에 따라 레이아웃을 조금 다르게 한다

#### contrast / perspective

두 단어를 거의 같은 무게로 놓는다.

`增加 ↔ 減少`, `買 ⇄ 賣`

#### sequence

수직 흐름을 살린다.

```text
損壞
  ↓
修復
  ↓
恢復
```

단, 화살표가 설명을 대신하지 않는다.

#### scope

포함 관계를 자연어와 들여쓰기로 표현한다.

```text
移動
  ├ 前進
  └ 後退
```

#### condition

원인/상태 흐름을 한 줄 또는 짧은 단계로 표현한다.

```text
需求 → 不足 → 補充 → 足夠
```

관계형 UI를 모두 똑같은 카드 2~4개로 처리하지 않는다.

---

## 12. `어떻게 다를까?` 블록

이 부분은 카드가 아니라 **본문의 다음 섹션**이다.

권장:

- 위쪽에 약한 수평선
- 작은 섹션 제목
- 자연어 설명

```text
────────────────
어떻게 다를까?
같은 거래를 구매자 쪽에서 보면 買,
판매자 쪽에서 보면 賣다.
```

필요하면 제목에 아주 작은 강조색을 사용할 수 있지만 별도 배경 상자는 기본값으로 쓰지 않는다.

---

## 13. `이것도 참고하자`

관련 단어는 pill 버튼 묶음보다 **텍스트 링크 목록**에 가깝게 보인다.

추천:

```text
이것도 참고하자
價格   交換   獲得
```

또는 설명이 필요한 경우:

```text
價格   지불해야 하는 양
價值   지금 상황에서의 쓸모
```

터치 영역은 텍스트 주변에 투명 padding을 줘 44px을 확보한다.

**44px 터치 영역 = 44px짜리 둥근 버튼**은 아니다.

# 화면 4 — 개별 단어 상세

## 14. 문제

현재 상세는 다음이 모두 각각 둥근 카드다.

- 일반 용례
- 게임에서
- 이것도 참고하자
- 여정에서 만난 곳

그래서 문서 하나를 읽는 느낌보다 위젯 여러 개를 세로로 쌓은 느낌이 강하다.

---

## 15. 개별 상세 v0.2 구조

### 권장 시안

```text
←              買                 ⌕
               개별 단어

買
ㄇㄞˇ
사다, 구입하다

一般 용례
我買了一份菜。
나는 채소 한 몫을 샀다.

상대에게 돈이나 값을 지불하고 물건을 얻을 때 쓴다.

────────────────────────────────

게임에서

돈을 내어 물건을 얻는 행동으로 사용했다.

賣      같은 거래의 판매자 쪽
價格    지불하는 양
交換    돈이 아닌 것을 서로 바꿀 때

────────────────────────────────

여정에서 만난 곳
처음   장터 · 오늘 저녁거리
다시   장터 · …
```

### 단어 헤더

단어 자체는 카드에 넣지 않는다.

- 중국어: 가장 큰 텍스트
- 주음: 바로 아래
- 한국어 핵심 뜻: 그 아래

세 요소가 하나의 단어 표제어 블록을 만든다.

### 일반 용례

기본 본문처럼 둔다.
예문은 중국어가 먼저 읽힌다.

한국어 번역을 기본 표시하는 현재 정책은 유지한다.

### 게임에서

일반 용례와 다른 층임을 보여주기 위해 다음 중 하나만 사용한다.

- 얇은 상단선
- 아주 약한 왼쪽 세로선
- 아주 옅은 배경 wash

세 가지를 동시에 쓰지 않는다.

### 여정 기록

작은 2열 기록 형태가 자연스럽다.

```text
처음   장터 · 오늘 저녁거리
다시   장터 · 물건 고르기
```

각 등장 장소를 카드로 만들지 않는다.

---

# 검색 / 전체 단어 보기

## 16. 검색

검색 입력은 실제 입력 컨트롤이므로 둥근 사각형 사용을 허용한다.

다만 검색 결과는 카드가 아니라 목록으로 표시한다.

```text
價格      ㄐㄧㄚˋ ㄍㄜˊ
가격
────────────────
買        ㄇㄞˇ
사다, 구입하다
```

한자 → 주음 → 뜻 위계를 유지한다.

---

## 17. 전체 단어 보기

전체 목록도 `단어 카드 48개`가 되어서는 안 된다.

권장:

```text
接近    ㄐㄧㄝ ㄐㄧㄣˋ     접근하다
遠離    ㄩㄢˇ ㄌㄧˊ        멀어지다
通過    ㄊㄨㄥ ㄍㄨㄛˋ     통과하다
…
```

모바일에서는 열 폭이 부족하면 두 줄로 자연스럽게 바꾼다.

```text
接近      접근하다
ㄐㄧㄝ ㄐㄧㄣˋ
```

단어 하나당 네 면의 테두리는 두지 않는다.

---

# 시각 토큰 방향

## 18. radius 예산

정확한 px은 구현 시 실기기에서 조정하되 역할을 먼저 고정한다.

### 큰 radius

- sheet / modal

### 중간 radius

- 검색 input
- 특별한 독립 조작

### radius 없음 또는 최소

- 지역 행
- 비교 묶음
- 단어 상세 섹션
- 전체 단어 행
- 관련 단어 링크

단어장 본문에서 **radius 0이 예외가 아니라 기본값**이 된다.

---

## 19. 선 예산

수평선은 문서 구조를 보조한다.

- 색: 현재 `--line`보다 한 단계 약해도 좋음
- 두께: 시각적으로 1px 이하
- 모든 블록 사이에 기계적으로 반복하지 않음
- 큰 정보 전환에서만 사용

같은 레벨의 목록에서는 `여백 + 선` 중 하나만으로 충분한지 먼저 확인한다.

---

## 20. 배경 면

기본 배경과 본문 배경을 여러 겹의 흰 카드로 나누지 않는다.

단어장 기본 본문은 하나의 종이 면처럼 느껴지는 것이 좋다.

옅은 면 차이는 다음에만 제한적으로 사용한다.

- 현재 선택
- 게임 맥락처럼 일반 사전 정보와 성격이 다른 층
- 검색 입력
- 비활성/잠김

---

## 21. 타이포그래피 역할

정확한 수치는 구현 때 조정한다.

### 페이지 제목

- 단어장 / 지역명 / 비교 묶음 제목
- 22~24px 범위 검토

### 중국어 관계식

- 지역 비교 묶음: 19~22px
- 비교 상세 상단: 28~32px
- 개별 표제어: 36~40px

### 한국어 관계 제목

- 14~16px
- 중국어 관계식보다 시각적으로 작음

### 한국어 핵심 뜻

- 15~17px

### 예문

- 중국어 16~18px
- 한국어 번역 13~15px

### 메타 정보

- 11~13px

중국어가 가장 중요한 화면에서는 한국어 섹션 제목이 중국어보다 더 크게 보이지 않는다.

# 인터랙션

## 22. 평평한 항목도 누를 수 있어야 한다

카드를 없애도 터치 가능성은 사라지지 않는다.

### 터치 영역

- 각 행 최소 높이 44px
- 텍스트 링크도 padding을 포함해 실질 터치 영역 확보

### 눌림 피드백

다음 중 하나만 사용한다.

- 80~120ms 정도의 약한 배경 wash
- 글자색 또는 관계식 색 변화
- 1px 이내의 아주 작은 위치 변화

큰 scale bounce는 사용하지 않는다.

---

## 23. 뒤로가기와 문맥

기존 동작 유지.

`지역 → 비교 묶음 → 단어`로 들어갔다면 뒤로갈 때 같은 묶음으로 돌아온다.

시각적으로 평평해져도 정보 문맥은 더 명확해야 한다.

# 구현 우선순위

## 24. 한 번에 바꾸는 순서

### Step 1 — 홈

- 장 선택기를 제목형 전환기로 변경
- 지역 카드 → 평평한 색인 행
- 발견 수 축소
- 전체 보기 버튼의 카드성 축소

이 화면만 바꿔도 AI slop 인상이 크게 줄어든다.

### Step 2 — 지역

- 비교 묶음 카드 제거
- 중국어 관계식을 시각 중심으로 이동
- 묶음 간 리듬을 여백/선으로 재구성

### Step 3 — 비교 상세

- 단어별 카드 제거
- 상단 관계식 추가
- 관계 유형별 레이아웃 차이 도입
- `어떻게 다를까?`를 문서형 섹션으로 변경
- `이것도 참고하자` pill 제거

### Step 4 — 단어 상세

- 섹션 카드 제거
- 표제어 중심 문서 레이아웃
- 여정 기록을 행 형태로 정리

### Step 5 — 검색 / 전체 목록

- 결과 카드 → 색인 행

# 자동 / 수동 검수 기준

## 25. 자동 검수

기능 검수는 기존 단어장 v0.1 기준을 그대로 유지한다.

추가 시각 구조 검수 후보:

- 지역 항목 최소 터치 높이 44px
- 지역 행이 80px 이상으로 과대해지지 않음
- 비교 묶음에 네 면 border + radius 조합이 기본 적용되지 않음
- 개별 상세의 모든 section이 카드 border를 갖지 않음
- 관련 단어 링크 최소 터치 영역 44px
- 375px에서 가로 스크롤 없음
- 하단 nav가 콘텐츠를 가리지 않음

CSS 문자열만 검사하는 테스트로 디자인을 과도하게 고정하지 않는다.
실제 브라우저 레이아웃 값을 우선한다.

## 26. 수동 검수

### 홈을 3초 봤을 때

- `1장 · 물길마을`이 현재 범위라는 것을 이해하는가?
- 길목/장인골/장터가 같은 레벨의 세 지역으로 보이는가?
- 지역보다 카드 모양이 먼저 눈에 들어오지 않는가?

### 지역 화면을 3초 봤을 때

- 중국어 관계식이 먼저 눈에 들어오는가?
- 여러 묶음이 한 지역의 색인처럼 느껴지는가?
- 독립 상품 카드 목록처럼 보이지 않는가?

### 비교 상세

- `買 ⇄ 賣` 관계가 단어 두 개보다 먼저 이해되는가?
- 두 단어가 같은 화면에서 비교된다는 느낌이 드는가?
- 카드 경계가 관계를 끊지 않는가?

### 개별 상세

- 한 편의 짧은 사전/노트 항목처럼 읽히는가?
- 여러 위젯이 세로로 쌓인 느낌이 줄었는가?

# 구현하지 않을 것

## 27. 이번 리디자인에서 피할 방향

- 종이 질감을 과하게 넣어 빈티지 노트처럼 꾸미기
- 실제 노트 줄, 테이프, 포스트잇 등 스큐어모픽 장식 남발
- 모든 구분선을 손그림 선으로 만들기
- serif를 과도하게 써 가독성을 희생하기
- 지역마다 다른 색 카드를 부여하기
- 관계 유형마다 별도 배지 만들기
- 관련 단어를 다시 chip cloud로 만들기
- 발견 수를 progress bar로 만들기
- 애니메이션으로 빈 공간을 채우기

목표는 장식적인 “노트 테마”가 아니다.

**구조가 노트처럼 자연스러운 것**이 목표다.

# 완료 기준

## 28. v0.2 시각 완료 기준

다음 경험이 자연스럽게 이어지면 된다.

1. 단어장 홈에서 현재 장을 확인한다.
2. 세 지역을 짧은 색인 행으로 훑는다.
3. 장터에 들어가 중국어 관계식 중심으로 비교 묶음을 읽는다.
4. `買 ⇄ 賣`를 열면 두 카드가 아니라 하나의 비교 장면이 보인다.
5. `買` 상세로 들어가면 여러 카드가 아니라 한 편의 짧은 어휘 노트처럼 읽힌다.
6. 관련 단어와 검색 결과도 같은 평평한 색인 문법을 유지한다.

이때 사용자가 느끼는 화면의 기본 단위는

`카드`

가 아니라

**`행 · 문단 · 관계 · 단어`**

여야 한다.

---

## 29. 최종 문장

**단어장을 예쁘게 꾸미는 것이 아니라, 사람이 정리한 것처럼 자연스럽게 만든다.**

카드를 없애는 것 자체가 목적이 아니다.
카드가 하던 구조적 일을 여백, 선, 정렬, 글자 위계가 더 잘 맡게 만드는 것이 목적이다.

# 1. 이번 기획에서 확정한 사용자 취향

## 스토리 표현

- 지역 그림 또는 간단한 배경 + 작은 캐릭터 이미지 + 대사창을 사용한다.
- 풀스크린 비주얼노벨보다 가볍다.
- 주인공은 짧게 반응하지만 성격과 개인사를 강하게 규정하지 않는다.
- 스토리 선택지는 넣지 않는다. 선택권은 전술판의 작전에서 주는 것을 우선한다.
- 이미 본 이야기는 초기 버전에서 원래 연출 그대로 다시 재생한다.

## 언어

- 번체 중국어가 이야기의 기본 표시다.
- 한국어는 눌러서 확인하는 이해 보조층이다.
- 중국어는 학습 진도에 억지로 맞추기보다 자연스럽고 쉬운 문장을 우선한다.
- 스토리를 읽지 못했다고 진행을 막지 않는다.

## 장면 길이

- 대부분 3~6대사 정도로 짧게 만든다.
- 필요한 장면은 8~15대사까지 허용한다.
- 1차 지역에서는 이야기가 퍼즐을 압도하지 않는다.

## NPC

- 처음에는 `행상인`, `길지기`, `장인`, `장터지기`처럼 역할명으로 등장한다.
- 반복해서 중요해지는 인물에게만 나중에 고유 이름을 붙인다.

## 이야기 비중

- 전체 목표는 A~B 사이: 퍼즐에 이유를 주는 짧은 이야기에서 시작해, 플레이 결과로 세계와 관계가 조금씩 변하는 정도까지 허용한다.
- 특히 1차 지역은 A에 가깝게 잡는다.
- 세계의 큰 비밀은 오래된 석비·명판·글자의 반응 같은 작은 암시만 남긴다.

# 2. 주인공의 성장선

주인공은 처음부터 시스템상 `용사`가 아니다.

## 1단계 — 소년

범위:

- 프롤로그 `고향 마을（出發）`
- 1장 `세 갈래 길`
- 길목 / 장인골 / 장터를 해결하는 동안

소년은 스스로 모험을 떠났지만 아직 세상에서 인정받은 영웅은 아니다.

NPC는 상황에 따라 `소년`, `여행자`, `저기`처럼 부를 수 있다. `여행자`는 시스템 칭호가 아니라 자연스러운 호칭이다.

## 2단계 — 용사

조건:

- 길목 핵심 의뢰 완료
- 장인골 핵심 의뢰 완료
- 장터 핵심 의뢰 완료

세 지역을 모두 해결한 뒤 짧은 전환 장면에서 사람들이 처음으로 그를 `勇者 / 용사`라고 부르기 시작한다.

칭호 수여식이나 레벨 보상처럼 처리하지 않는다.

핵심 감각:

> 강해져서 용사가 된 것이 아니라, 여러 지역의 문제를 자기 힘으로 풀고 사람들의 신뢰를 얻었기 때문에 용사가 된다.

## 3단계 — 대용사

장기 목표다.

여러 지역을 더 해결하고 왕성에 들어갈 즈음 `大勇者 / 대용사`로 불리기 시작한다.

정확한 조건은 왕성 장을 기획할 때 확정한다.

## 구현 원칙

`소년 / 용사 / 대용사`를 저장된 문자열 하나로 관리하지 않는다.

현재 완료한 핵심 여정 조건으로부터 `getHeroRole(progress)`가 계산하도록 한다.

예:

```js
function getHeroRole(progress) {
  if (hasRoyalHeroMilestone(progress)) return 'great-hero';
  if (hasAllTier1CoreMilestones(progress)) return 'hero';
  return 'boy';
}
```

이렇게 해야 저장 데이터와 이야기 진행이 어긋나지 않는다.

# 3. 현재 코드 기준선

현재 구조는 다음과 같다.

- `index.html`: 전술 화면 `tutorialView`와 월드맵 `worldView`를 가진다.
- `src/content.js`: `WORDS`, 튜토리얼 `STAGES`, `WORLD` 데이터를 가진다.
- `src/app.js`: 전술 규칙, 튜토리얼 진행, 저장, 완료 시트, 월드 진입까지 대부분 담당한다.
- `src/world-runtime.js`: 월드 카드의 한국어 이름과 아이콘 표시를 후처리한다.
- 공통 `sheet`는 단어 설명, 스테이지 선택, 완료 화면, 지역 정보 등에 사용한다.

v0.6에서 가장 피해야 할 것은 `app.js`에 스토리와 여정 기능을 계속 직접 덧붙여 하나의 거대한 파일로 만드는 것이다.

따라서 기존 전술 로직은 최대한 보존하고, 새 시스템이 기존 전술 엔진을 호출하는 방향으로 간다.

# 4. v0.6 화면 구조

`appView`를 네 종류로 확장한다.

1. `tacticalView` — 현재 `tutorialView`를 일반 전술 화면으로 점진적으로 이름 정리한다.
2. `worldView` — 월드맵.
3. `storyView` — 짧은 이야기 장면.
4. `journeyView` — 여정 타임라인과 다시 보기/다시 플레이.

`단어장`은 상위 메뉴 자리는 마련하되 v0.6-0에서 완성하지 않아도 된다. 초기에는 기존 단어 카드나 준비 중 화면으로 연결할 수 있다.

## 상위 이동

장기 상위 메뉴:

- 월드맵
- 여정
- 단어장

모바일 공간을 고려해 월드맵/여정 같은 비전투 화면에서는 하단 또는 화면 하부의 간단한 공통 이동을 사용할 수 있다.

전술판과 스토리 장면에서는 항상 상위 메뉴를 노출해 화면을 좁히지 않는다. 현재의 메뉴 버튼을 통해 월드맵/여정으로 나갈 수 있게 한다.

중요 원칙:

> 처음 진행 중인 `story → stage → story` 흐름에서는 메뉴를 거치지 않는다.

상위 메뉴는 탐색과 복습을 위한 탈출구이지, 정상 진행에 필요한 단계가 아니다.

# 5. 파일 책임 분리

v0.6에서 권장하는 최소 파일 구조다.

```text
src/
  content.js               # 기존 WORDS / STAGES / WORLD
  journey-content.js       # STORIES / JOURNEY / milestone 조건
  app.js                   # 전술 엔진 + 기존 호환 어댑터
  story-runtime.js         # storyView 렌더링과 대사 이동
  journey-runtime.js       # 여정 목록, 필터, 재생 연결
  world-runtime.js         # 월드 표시
  story.css
  journey.css
```

처음부터 라우터나 상태관리 라이브러리를 추가하지 않는다.

현재 앱 규모에서는 브라우저 전역 객체를 아주 작은 공개 인터페이스로 연결하는 것으로 충분하다.

예:

```js
window.GameFlow = {
  showWorld,
  showJourney,
  playStory,
  playStage,
  continueFromNode
};
```

새 런타임이 `app.js` 내부 변수에 직접 접근하지 않게 한다.

# 6. 콘텐츠 데이터 구조

## STORIES

스토리 장면의 내용만 가진다.

```js
const STORIES = {
  'chapter1-roadside-merchant': {
    id: 'chapter1-roadside-merchant',
    chapterId: 'chapter-1-three-roads',
    regionId: null,
    titleKo: '길가의 행상인',
    background: 'roadside',
    beats: [
      {
        speaker: '행상인',
        zh: '救命！',
        ko: '사람 살려!',
        expression: 'panic'
      }
    ]
  }
};
```

### beat 최소 필드

- `speaker`
- `zh`
- `ko`

선택 필드:

- `expression`
- `portrait`
- `narration: true`
- `emphasis`

초기 버전에서 대사별 애니메이션, 음성, 선택지, 복잡한 조건문은 넣지 않는다.

## JOURNEY

내용을 복제하지 않고 story와 stage를 순서대로 참조한다.

```js
const JOURNEY = [
  {
    id: 'prologue',
    titleKo: '프롤로그 · 고향 마을',
    tag: '튜토리얼',
    sections: [
      {
        id: 'origin',
        sequence: [
          { type: 'story', id: 'prologue-departure' },
          { type: 'stage', id: 'stage-0' },
          { type: 'stage', id: 'stage-1' },
          { type: 'stage', id: 'stage-2' },
          { type: 'stage', id: 'stage-3' },
          { type: 'stage', id: 'stage-4' },
          { type: 'stage', id: 'stage-5' },
          { type: 'story', id: 'prologue-forest-edge' }
        ]
      }
    ]
  }
];
```

1장에서는 세 지역이 병렬이므로 각 지역을 별도 section으로 둔다.

```text
chapter-1-three-roads
  ├─ shared-intro
  ├─ gate-town
  ├─ workshop-town
  └─ market-town
```

이 구조면 세 지역의 플레이 순서를 자유롭게 두면서도 각 지역 내부 순서는 관리할 수 있다.

# 7. 진행 상태 설계

새 저장 키 가제:

`chinese-word-tactics-journey-v1`

## 최소 저장값

```js
{
  seenStories: [],
  completedStages: [],
  acknowledgedNodes: [],
  lastLocation: null
}
```

가능한 한 상태를 저장하기보다 계산한다.

### 저장하지 않고 계산할 것

- 어떤 노드가 열렸는지
- 지역별 완료율
- 현재 주인공 칭호
- 다음 추천 노드

이 값들은 `JOURNEY + seenStories + completedStages + 월드 milestone`에서 계산한다.

이 방식은 이후 콘텐츠 순서가 조금 바뀌어도 저장 데이터가 쉽게 깨지지 않는다.

## 기존 저장과의 호환

현재 저장:

- `chufa-tutorial-v03`
- `chinese-word-tactics-world-v1`

은 유지한다.

첫 로드에서 기존 `completed` 튜토리얼 stage ID를 새 `completedStages`에 합친다.

새 진행 저장이 생긴 뒤에도 기존 튜토리얼 세부 상태를 당장 삭제하지 않는다.

### 기존 튜토리얼 완료 사용자

- stage-0 ~ stage-5 완료는 여정에서도 완료 처리한다.
- 새로 생긴 프롤로그 story는 자동으로 `seen` 처리하지 않는다.
- 사용자는 새 이야기 장면을 여정에서 읽을 수 있다.
- 이미 완료한 튜토리얼을 강제로 다시 깨게 하지 않는다.

# 8. 전술 엔진과 여정의 연결

현재 전술 엔진은 `stageIndex` 숫자를 중심으로 동작한다.

v0.6에서 전면 교체하지 않는다.

대신 stage ID로 호출할 수 있는 어댑터를 추가한다.

```js
function playStageById(stageId, options = {}) {
  const index = STAGES.findIndex(stage => stage.id === stageId);
  if (index < 0) return false;
  stageIndex = index;
  // 기존 reset/render 경로 재사용
}
```

`options`에는 최소한 다음 출처를 남길 수 있다.

```js
{
  mode: 'first-play' | 'replay',
  returnTo: 'journey' | 'world' | null,
  journeyNodeId: '...'
}
```

## 최초 진행과 다시 플레이를 구분한다

최초 진행:

`story → stage → 다음 story/노드`

여정에서 다시 플레이:

`journey → stage → 완료 화면 → journey`

다시 플레이가 최초 이야기 진행을 다시 열거나 다음 노드를 중복 해금하지 않게 한다.

# 9. 스토리 화면 상세

## 기본 구성

위에서 아래 순서:

1. 작은 장면 제목 / 지역 이름
2. 지역 배경 또는 간단한 장소 실루엣
3. 현재 화자의 작은 캐릭터 이미지
4. 화자 이름
5. 번체 중국어 대사
6. `한국어 뜻 보기` 토글
7. 이전 / 다음

전체 화면을 탭하면 무조건 다음으로 넘어가는 방식은 피한다. 뜻을 보려다 대사를 넘기는 실수를 줄이기 위해 `다음` 영역을 명확하게 둔다.

## 번역

기본 상태는 중국어만 보여준다.

`한국어 뜻 보기`를 누르면 현재 beat의 한국어가 아래에 열린다.

다음 beat로 넘어갈 때 번역 열림 상태는 기본적으로 닫힌 상태로 돌아간다.

뜻을 보는 횟수는 점수나 평가에 영향을 주지 않는다.

## 이전 대사

현재 장면 안에서만 한 단계 이상 뒤로 갈 수 있다.

뒤로 갔다가 다시 앞으로 와도 story 완료 상태에는 영향이 없다.

## 건너뛰기

이미 본 story에만 `장면 건너뛰기`를 제공한다.

처음 보는 story에는 스킵을 강하게 노출하지 않는다. 다만 접근성/중단을 위해 언제든 화면을 나갈 수는 있어야 한다.

## 장면 종료

마지막 beat 다음에는 별도의 메뉴를 요구하지 않는다.

- 다음이 stage이면 바로 스테이지 시작 CTA
- 다음이 story이면 이어서 재생
- 분기 지점이면 월드맵으로 이동

# 10. 여정 화면 상세

## 기본 화면은 혼합 타임라인

스토리와 스테이지를 기본적으로 분리하지 않는다.

실제 여행 순서대로 보인다.

예:

```text
프롤로그 · 고향 마을

📖 고향을 떠나다        ✓
⚔ 出發 · 마을을 떠나다 ✓
⚔ 接近 · 낡은 석비     ✓
⚔ 遠離 · 늑대가 있는 길 ✓
⚔ 通過・到達 · 폐허를 지나서 ✓
⚔ 避開 · 위험한 길      ✓
⚔ 숲을 빠져나가라       ✓
📖 숲 너머의 목소리      ●
```

필터:

- 전체
- 이야기
- 스테이지

이전 논의의 `스테이지 / 이야기` 분리 목록은 필터 기능으로 흡수한다. 기본 화면은 반드시 여정의 시간 흐름을 보여준다.

## 1장 표시

`1장 · 세 갈래 길` 아래에는 공통 도입 뒤 세 지역을 나란히 또는 카드로 보여준다.

- 길목
- 장인골
- 장터

지역 카드에 `스테이지 n/7 · 이야기 n/m` 정도의 진행률을 보여줄 수 있다.

지역을 누르면 그 지역의 혼합 타임라인으로 들어간다.

## 잠긴 노드

- 이미 연 노드는 실제 제목 표시
- 바로 다음 노드는 제목 표시 가능
- 그 이후 중요한 미래 내용은 `???`

전체 콘텐츠 수는 어느 정도 보여주되 스포일러는 줄인다.

## 재생

- 📖 완료 story → 원래 연출로 다시 보기
- ⚔ 열린 stage → 다시 플레이
- 다시 보기/재플레이는 진행 상태를 되돌리지 않는다.

# 12. 길목 첫 에피소드 연결

v0.6-2에서 다음 최소 흐름을 완성한다.

```text
월드맵에서 길목 선택
  ↓
📖 길목에 도착하다
  ↓
📖 길지기의 부탁 (같은 장면에 합쳐도 됨)
  ↓
⚔ 문 안쪽 — 進入 / 退出
  ↓
📖 안팎은 잘 보네
  ↓
다음 스테이지 `종소리가 닿는 곳` 해금
```

이 흐름 하나가 정상 동작하면 이후 지역은 같은 구조를 반복할 수 있다.

`길목에 도착하다`와 `길지기의 부탁`은 장면 길이를 보고 하나의 story로 합치는 것을 기본안으로 한다.

# 13. 소년 → 용사 전환 장면

1차 지역 세 곳의 핵심 의뢰가 모두 완료되면 공통 story를 하나 연다.

가제:

**`세 갈래 길의 끝`**

목적:

- 길목, 장인골, 장터에서 해결한 일을 짧게 되짚는다.
- 행상인 또는 다시 만난 주민이 소년의 소문을 언급한다.
- 누군가 처음으로 `勇者`라고 부른다.
- 이후 내레이션의 기본 호칭이 `소년`에서 `용사`로 바뀐다.

장면은 칭호 획득 팝업보다 이야기 안의 자연스러운 호칭 변화로 처리한다.

`용사 획득!` 같은 게임식 보상 문구는 사용하지 않는다.

# 18. v0.6의 성공 기준

기능 성공은 스토리 화면이 존재하는 것이 아니다.

다음 한 흐름이 끊기지 않고 동작하면 v0.6의 기반이 성공한 것이다.

> **소년의 이야기를 본다 → 왜 움직여야 하는지 안다 → 전술판에서 직접 해결한다 → 해결 결과를 짧게 본다 → 여정에 기록된다 → 나중에 이야기와 판을 각각 다시 찾을 수 있다.**

그리고 1차 지역 세 곳을 모두 해결한 순간, 이 구조가 처음으로 서사적 보상을 만든다.

> **소년은 여러 사람의 문제를 해결했고, 사람들이 그를 `용사`라고 부르기 시작한다.**

이 전환이 향후 `대용사 → 왕성`까지 이어지는 장기 성장선의 첫 기준점이다.

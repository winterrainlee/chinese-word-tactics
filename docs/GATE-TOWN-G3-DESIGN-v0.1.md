# 길목 G3 `두 갈래 길` 설계 v0.1

작성일: 2026-09-11

## 목적

G3는 `路線 / 經由`를 실제 경로 선택과 중간 방문으로 구분해 경험시키는 판이다.

- `路線`: 출발점에서 목적지까지 이어지는 전체 길.
- `經由`: 목적지로 가는 도중 특정 장소를 실제 여정에 포함하는 것.
- `通過`처럼 해당 장소를 한쪽에서 들어가 반대쪽으로 빠져나올 필요는 없다.

핵심 경험은 **좌우 어느 길도 정답이지만, 초소를 경유하려면 본선에서 한 칸 벗어나 의식적으로 들러야 한다**는 점이다.

## 한 줄 플레이 경험

> 왼쪽과 오른쪽 두 路線 중 하나를 골라 걷고, 길가 초소 하나를 經由한 뒤 북쪽 출구에 도착한다.

## 이야기 흐름

### G3-A `두 길 중 하나로`

G2에서 확인한 종소리 조사 결과를 북쪽 초소에도 알려야 한다.

북쪽 출구로 가는 길은 서쪽 길과 동쪽 길 두 갈래다. 어느 쪽으로 가도 목적지에 도착하므로 길지기는 특정 길을 지시하지 않는다.

다만 가는 도중 초소 한 곳에 들러 조사 결과를 전해 달라고 부탁한다.

### G3 `路線・經由 · 두 갈래 길`

목표:

> `選一條路線，經由一個哨站，到達北口。`

서쪽 또는 동쪽 경로 중 어느 쪽도 사용할 수 있다. 도중에 위치한 초소는 본선에서 한 칸 벗어난 샛길 끝에 있어 자동으로 밟히지 않는다.

### G3-B `길은 다시 만난다`

소년은 어느 길을 택해도 북쪽 출구에 도착할 수 있지만, `經由`는 여정에 어떤 장소를 포함했는지를 말한다는 점을 확인한다.

북쪽 길 앞쪽에 멈춰 선 짐수레를 발견하며 G4 `位置 / 周圍 / 障礙`로 연결한다.

## 맵

5×7 세로 맵이다.

```text
##E##
#...#
#.#.#
A.#.B
#.#.#
#...#
##S##
```

- `S`: 소년 시작 위치
- `E`: 북쪽 출구
- `A`: 서쪽 초소
- `B`: 동쪽 초소
- `#`: 이동 불가 지형
- `.`: 길

시작점에서 한 칸 올라간 뒤 서쪽 또는 동쪽으로 갈라진다. 위쪽에서 다시 합류한다.

A/B 초소는 각 경로에서 옆으로 한 칸 빠진 위치에 있다. 따라서 단순히 출구로 이동하는 것만으로는 자동 경유되지 않는다.

## 판정

1. 서쪽 또는 동쪽 전용 경로 칸에 들어가면 `routeObserved = true`가 된다.
2. 어느 쪽을 먼저 골랐는지는 기록하지만 다른 쪽으로 바꾸는 행동을 막지 않는다.
3. A 또는 B 초소 칸에 실제로 들어가면 `via = true`가 된다.
4. 초소에 들어왔다가 같은 길로 되돌아가도 `經由`는 성립한다.
5. `via && at_exit`이면 완료한다.
6. 초소를 거치지 않고 북쪽 출구에 도착해도 실패 처리하지 않는다.
7. 이 경우 `已經到北口，但還沒經由哨站。`이라는 정보만 제공하고 그 자리에서 계속 움직일 수 있다.

## `通過`와의 구분

튜토리얼의 `通過`는 한쪽 입구로 들어가 반대편으로 나가는 경로 관계다.

G3의 `經由`는 목적지까지 가는 전체 여정에 특정 장소가 포함되었는지를 본다.

따라서 초소에 들어갔다가 같은 방향으로 되돌아 나와도 `經由`는 완료된다.

## 해결 경로

최소 두 개의 자연스러운 해법이 있다.

- 서쪽 길 → 서쪽 초소 → 서쪽 길 → 북쪽 출구
- 동쪽 길 → 동쪽 초소 → 동쪽 길 → 북쪽 출구

플레이어가 도중에 반대편 경로로 이동하거나 초소 두 곳을 모두 들르는 것도 허용한다.

최적 루트나 정답 순서를 강제하지 않는다.

## 단어 카드

### 路線

- 주음: `ㄌㄨˋ ㄒㄧㄢˋ`
- 뜻: 노선, 경로
- 예문: `兩條路線都可以到北口。`
- 게임 설명: 출발점에서 목적지까지 이어지는 전체 길을 말한다.

### 經由

- 주음: `ㄐㄧㄥ ㄧㄡˊ`
- 뜻: 경유하다, 거쳐 가다
- 예문: `我們經由哨站，再到北口。`
- 게임 설명: 목적지로 가는 도중 어떤 장소를 실제 여정에 포함한다.

## 재사용/신규 기믹

### 기존 재사용

- 상하좌우 한 칸 이동
- 이동 불가 지형
- `at_exit`
- 되돌리기
- 살펴보기
- 낮은 실패 비용
- story → stage → story
- 재플레이와 본편 진행 분리

### 신규 공통 기믹

`route-runtime.js`에서 다음을 담당한다.

- 위치가 어느 경로에 속하는지 판정
- 경로 선택 경험 기록
- 타일이 중간 경유지인지 판정
- `via` 완료 상태
- `via + at_exit` 완료 조건
- 초소와 경로 살펴보기 정보

경로 찾기 알고리즘, 최단거리 계산, 자동 이동, 정답 노선 추천은 구현하지 않는다.

## 구현 철학 체크

- 학습 단어: `路線 / 經由`
- 실제 관계/변화: 경로 선택 / 중간 장소 방문
- trigger: 경로 전용 칸 진입 / 초소 칸 진입 / 출구 도착
- predicate: route cell / waypoint tile / `via && at_exit`
- state delta: `routeObserved`, `routeChoices`, `via`, `viaIds`
- 즉시 feedback: 선택한 길 이름 / `已經由○○哨站。`
- 잘못된 행동 정보: 초소 없이 출구 도착 시 아직 경유하지 않았다고 알림
- 해결 경로: 좌우 최소 2개, 변경과 왕복 허용
- 모바일: 5×7 전체 판 한 화면
- 색/아이콘 암기: 맵 구조와 실제 이동 자체가 의미를 만든다.

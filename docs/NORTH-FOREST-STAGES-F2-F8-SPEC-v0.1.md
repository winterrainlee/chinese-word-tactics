## 2. 공통 설계 원칙

1. 중국어 단어를 이해하면 판의 상태와 행동 이유가 보이게 한다.
2. 핵심어는 판당 2~3개를 기본으로 한다.
3. 쉬운 색·모양 어휘는 새 단어 카드보다 실제 관찰 정보로 쓴다.
4. 범용 살펴보기 모드를 다시 만들지 않는다.
5. 대상은 직접 탭해 기본 정보를 볼 수 있고, 실제 변화 행동은 필요한 위치에서 상황형 행동으로 연다.
6. 오답은 생명·점수 손실이 아니라 무엇이 달랐는지 보여주는 피드백으로 처리한다.
7. 가능한 판은 되돌리기 또는 자연스러운 재시도로 복구한다.
8. 판 전체는 iPhone 13 mini 세로 화면에서 스크롤 없이 읽히는 크기를 우선한다.
9. 목표 문장은 짧게 유지하고, 정확한 해법 순서는 대사나 규칙문에 미리 쓰지 않는다.
10. F8 이외에는 수레·복잡한 추종 시스템을 억지로 넣지 않는다.

# 3. F2 — 잎에 가려진 표식

핵심어:
- 標記
- 方向
- 確認

재사용:
- 位置
- 路線
- 距離
- 左 / 右

목표:
確認三個標記的方向。

세 표식이 어느 방향을 가리키는지 모두 확인한다.

F2의 목적은 잘못된 표식을 고치는 것이 아니라 정보를 정확히 읽어 기록하는 것이다. 수정은 F3에서 한다.

### 맵

권장 6×6.

개념 배치:

    ######
    #..A.#
    #....#
    #B.S.#
    #...C#
    ##E###

- S: 소년
- A/B/C: 숲길 표식
- E: 돌아가는 출구

세 표식은 서로 떨어져 있어 숲 바깥쪽을 한 바퀴 보게 한다.

### 초기 상태

예:
- A: 右
- B: 上
- C: 左

C는 F3에서 문제로 다룰 표식이며 실제 길과 맞지 않는다.
다만 F2에서는 틀렸다고 자동 표시하지 않는다.

각 표식 상태:
- observed
- confirmed
- direction
- obscured

A 또는 C 한 곳은 잎에 가려져 있어 인접 행동으로 잎을 젖혀야 방향을 읽을 수 있다.

### 플레이

1. 표식을 직접 눌러 외형을 본다.
2. 가려진 표식은 인접 시 잎을 젖혀 방향을 드러낸다.
3. 방향이 보이면 方向確認 행동을 할 수 있다.
4. 확인한 표식에는 작은 확인 표시가 남는다.
5. 세 표식을 모두 확인하면 완료.

### 완료 조건

- markerAConfirmed
- markerBConfirmed
- markerCConfirmed

### 단어 체감

標記:
- 실제 숲길의 나무 표식.

方向:
- 표식이 실제로 가리키는 방향.

確認:
- 단순히 봤다는 것과 확인했다는 것을 구분한다.

### 피드백

가려진 상태:
> 標記被葉子遮住了，還看不清方向。
> 잎에 가려져 아직 방향을 분명히 볼 수 없어.

확인 후:
> 這個標記的方向確認了。
> 이 표식의 방향을 확인했어.

세 개 완료:
> 三個標記的方向都確認了。
> 세 표식의 방향을 모두 확인했어.

### 구현 메모

- 기존 인접 상황형 행동 재사용.
- 새 공통 데이터 후보: 관찰 대상 + 공개 속성 + 확인 flag.
- F3에서 같은 표식 방향 데이터를 일부 재사용한다.

# 4. F3 — 돌아간 표지판

핵심어:
- 正確
- 指示

재사용:
- 標記
- 方向
- 確認
- 路線

목표:
把轉歪的標記調回正確方向。

돌아간 표식을 올바른 방향으로 맞춘다.

### 맵

F2와 같은 장소를 축약 재사용한다.

권장 6×6.

    ######
    #..R.#
    #..|.#
    #A-S-B
    #..|.#
    ##E###

- R: 문제 표식
- A/B: 정상 기준 표식 또는 기준 지점

### 초기 상태

문제 표식:
- currentDirection: wrong
- correctDirection: 실제 길 연결로 추론 가능
- rotationOptions: 4방향

정상 표식과 길 연결은 처음부터 볼 수 있다.
정답 방향 자체를 대사나 목표문에 직접 쓰지 않는다.

### 플레이

1. 정상 표식 또는 실제 길을 확인한다.
2. 문제 표식에 인접한다.
3. 방향을 한 칸씩 회전한다.
4. 현재 指示를 확인할 수 있다.
5. 실제 경로를 올바르게 가리키면 완료.

### 완료 조건

- markerDirection === targetDirection
- routeReferenceObserved === true

### 단어 체감

正確:
- 표식과 실제 길의 관계가 맞는 상태.

指示:
- 표식이 사람에게 어느 쪽으로 가야 하는지 알려주는 기능.

### 피드백

오답:
> 這個方向和實際的路線對不上。
> 이 방향은 실제 길과 맞지 않아.

정답:
> 標記的指示正確了。
> 표식의 안내가 이제 올바르다.

### 구현 메모

- 새 공통 기믹: discrete-state object.
- W2의 단계형 상태 조절 구조를 방향 회전으로 일반화할 수 있다.

# 5. F4 — 닮은 잎

핵심어:
- 特徵
- 相似
- 分辨

재사용:
- 條件
- 符合
- 確認

A1–A2 복습:
- 深綠色 / 淺綠色
- 長
- 圓
- 尖

목표:
比較特徵，分辨出和樣本相同的植物。

특징을 비교해 견본과 같은 식물을 구별한다.

### 맵

권장 5×6.

    ######
    #A..B#
    #....#
    #..S.#
    #C..D#
    ######

상단 목표 아래에는 장인의 견본 특징이 짧게 표시된다.

견본:
- 深綠色
- 長
- 尖

### 후보 속성

A:
- 深綠色
- 長
- 尖
- 정답

B:
- 深綠色
- 長
- 圓

C:
- 淺綠色
- 長
- 尖

D:
- 深綠色
- 短
- 尖

오답은 각각 정확히 한 특징만 다르게 한다.

### 플레이

1. 식물 군락을 직접 누르면 기본 외형이 보인다.
2. 인접하면 特徵確認 행동이 열린다.
3. 확인하면 색·길이·끝 모양이 중국어로 기록된다.
4. 원하는 군락을 견본과 비교한다.
5. 정답 군락을 고르면 완료.

### 완료 조건

- selectedPatch === target
- targetObserved === true

### 단어 체감

特徵:
- 색·길이·끝 모양을 묶는 상위 개념.

相似:
- 일부 특징이 같아도 완전히 같은 것은 아니다.

分辨:
- 여러 특징을 함께 보고 목표를 구별하는 최종 판단.

### 오답 피드백

B:
> 顏色和長度相似，可是葉子的前端不一樣。
> 색과 길이는 비슷하지만 잎 끝이 달라.

C:
> 形狀相似，可是顏色不一樣。
> 모양은 비슷하지만 색이 달라.

D:
> 顏色和葉尖相似，可是長度不一樣。
> 색과 잎 끝은 비슷하지만 길이가 달라.

정답:
> 幾個特徵都符合，可以分辨出來了。
> 여러 특징이 모두 맞아서 구별할 수 있었어.

### 구현 메모

- 새 공통 기믹: attribute comparison.
- 속성은 텍스트 데이터로 구성해 F5/F6/F7에서도 재사용.
- 색만으로 상태를 전달하지 않고 반드시 중국어 텍스트를 함께 표시.

# 6. F5 — 장인이 찾는 재료

핵심어:
- 材料
- 適合
- 生長

재사용:
- 特徵
- 分辨
- 條件
- 符合
- 數量
- 足夠

A1–A2 복습:
- 長 / 短
- 粗 / 細

목표:
找出符合條件、適合做材料的藤條，帶回兩根。

조건에 맞아 재료로 적합한 덩굴 두 개를 가져간다.

### 맵

권장 6×6.

    ######
    #A..B#
    #.~..#
    #..S.#
    #C~.D#
    #..E.#

- ~: 물가
- A/B/C/D: 덩굴 군락
- E: 출구

필요 조건:
- 長
- 細
- 生長在水邊

### 후보

A:
- 長
- 細
- 水邊
- 적합

B:
- 長
- 粗
- 水邊
- 부적합

C:
- 長
- 細
- 水邊
- 적합

D:
- 短
- 細
- 林地
- 부적합

### 플레이

1. 각 군락 特徵을 확인한다.
2. 어디에 生長하는지도 확인한다.
3. 조건에 맞는 군락에서 한 개씩 채집한다.
4. 적합한 材料 2개면 足夠.
5. 출구로 돌아가면 완료.

### 완료 조건

- suitableMaterialCount === 2
- atExit === true

### 잘못 채집한 경우

잘못 고른 재료도 잠시 들 수 있게 한다.

예:
> 這根太粗，不適合做這次的材料。
> 이건 너무 굵어서 이번 재료로 적합하지 않아.

다시 놓기로 원래 군락에 돌려놓을 수 있다.

### 단어 체감

材料:
- 실제로 들고 돌아가는 작업 재료.

適合:
- 같은 식물이어도 용도 조건을 모두 만족하는지의 판정.

生長:
- 식물의 위치를 단순 좌표가 아니라 어디에서 자라는가라는 정보로 읽게 한다.

### 구현 메모

- F4 attribute comparison 재사용.
- 장터 inventory/take-put 구조를 일반화하면 잘못 채집 후 복구 가능.

# 7. F6 — 사라진 꾸러미

핵심어:
- 遺失
- 尋找
- 痕跡

재사용:
- 方向
- 位置
- 周圍
- 確認
- 特徵
- 分辨

A1–A2 복습:
- 藍色

목표:
從最後看到的位置開始，尋找和遺失的包裹有關的痕跡。

마지막으로 본 위치에서 시작해 잃어버린 꾸러미와 관련된 흔적을 찾는다.

### 맵

권장 7×6.

    #######
    #..N..#
    #.....#
    #W.L.E#
    #..S..#
    #######

- L: 꾸러미를 마지막으로 본 지점
- N/W/E: 세 방향의 첫 흔적 후보
- S: 시작

### 알려진 정보

분실물:
- 작은 꾸러미
- 藍色 끈
- 채집인의 손수레에 실려 있었음

### 첫 흔적 후보

북쪽:
- 가지에 걸린 藍色 실
- 관련 있음

서쪽:
- 동물 발자국
- 관련 없음

동쪽:
- 수레바퀴 자국
- 가능성은 있지만 이 길은 수레가 자주 다녀 단독으로는 결정적이지 않음

### 플레이

1. L을 먼저 確認한다.
2. L 周圍의 흔적 후보가 열린다.
3. 후보 特徵을 확인한다.
4. 관련 가능성이 높은 흔적을 따라간다.
5. 북쪽 가지에서 추가 파란 실 + 끌린 자국을 확인한다.
6. 다음 빈터에 도달하면 F6 완료.

꾸러미 자체는 아직 찾지 않는다.

### 완료 조건

- lastSeenConfirmed
- relatedTraceConfirmed
- reachedClearing

### 피드백

동물 흔적:
> 這是動物留下的痕跡，和包裹沒有關係。
> 동물이 남긴 흔적이야. 꾸러미와는 관계없어.

바퀴 자국:
> 有車輪的痕跡，可是這條路常有車經過。只看這個還不能確認。
> 바퀴 흔적은 있지만 이 길은 수레가 자주 지나. 이것만으로는 확인하기 어려워.

파란 실:
> 枝上留下了一小段藍色的線。
> 가지에 파란 실 조각이 남아 있어.

### 단어 체감

遺失:
- 꾸러미가 현재 없어졌다는 사건 상태.

尋找:
- 마지막 위치에서 범위를 좁혀가는 과정.

痕跡:
- 대상 자체가 아니라 지나간 뒤 남은 정보.

### 구현 메모

- 새 공통 기믹: clue graph.
- 기존 stage flag/reveal 조건으로 충분히 표현 가능.

# 8. F7 — 흔적이 멈춘 곳

핵심어:
- 發現
- 附近
- 留下

재사용:
- 痕跡
- 尋找
- 距離
- 範圍
- 特徵
- 分辨

A1–A2 복습:
- 大 / 小
- 圓
- 藍色

목표:
在最後的痕跡附近尋找，發現遺失的包裹。

마지막 흔적 근처를 찾아 잃어버린 꾸러미를 발견한다.

### 맵

권장 5×5.

    A...B
    .....
    ..L..
    .....
    C...D

- L: 마지막 흔적
- A: 큰 나무
- B: 둥근 바위
- C: 낮은 덤불
- D: 작은 물길

실제 꾸러미는 C 덤불 아래에 걸려 있다.

### 핵심 규칙

마지막 痕跡이 중심점이 되고,
그 附近의 1~2칸 범위를 조사한다.

범위 밖 대상을 먼저 누르면:
> 離最後的痕跡有點遠。先看看附近吧。
> 마지막 흔적에서 조금 멀어. 근처부터 살펴보자.

### 오브젝트 정보

L:
- 작은 藍色 실
- 낮은 가지에 긁힌 흔적

A:
- 관련 없음

B:
- 최근 움직인 흔적 없음

C:
- 가지에 藍色 실이 조금 더 留下 있음
- 덤불 아래 무언가 보임
- 꾸러미 發現

D:
- 관련 흔적 없음

### 플레이

1. L을 다시 확인한다.
2. 주변 대상을 조사한다.
3. C에서 추가 파란 실을 발견한다.
4. 아래를 살펴보기 행동이 열린다.
5. 꾸러미를 發現한다.
6. 챙기고 출구로 돌아가 완료.

### 완료 조건

- bundleDiscovered
- bundleCollected
- atExit

### 단어 체감

附近:
- 실제 거리 범위.

留下:
- 지나간 물건이 남긴 파란 실.

發現:
- 탐색 결과로 처음 대상을 찾아낸 상태 변화.

### 구현 메모

- F6 clue graph 재사용.
- 기존 範圍/距離 판정 재사용.
- 附近는 별도 버튼이 아니라 실제 공간 관계로 구현.

# 9. F8 — 오늘의 숲길

핵심어:
- 情況
- 安全
- 危險

대규모 재사용:
- 確認
- 方向
- 路線
- 障礙
- 通過
- 避開
- 帶領
- 後退

A1–A2 복습:
- 乾 / 濕
- 寬 / 窄

목표:
確認每條路的情況，避開危險的地方，帶貨車安全到市集。

각 길의 상태를 확인하고 위험한 곳을 피해 수레를 안전하게 장터까지 데려간다.

### 맵

권장 7×7.

세 경로가 출발점과 장터 쪽 출구를 공유한다.

개념:
- 서쪽 짧은 길
- 가운데 젖고 좁은 길
- 동쪽 긴 길
- 시작점에 소년과 작은 손수레
- 위쪽에 장터 방향 출구

### 경로 상태

서쪽:
- 乾
- 寬
- 쓰러진 가지 1개가 障礙
- 치우면 수레에 安全
- 짧지만 행동 1회 필요

동쪽:
- 乾
- 寬
- 障礙 없음
- 처음부터 수레에 安全
- 더 멀다

가운데:
- 濕
- 窄
- 소년은 통과 가능
- 현재 손수레에는 危險
- 이번 의뢰에서는 복구하지 않음

### 플레이

1. 각 경로 입구에서 情況을 확인한다.
2. 乾/濕, 寬/窄, 障礙가 기록된다.
3. 플레이어가 경로를 선택한다.
4. 서쪽이면 장애물을 치우고 진행.
5. 동쪽이면 바로 진행.
6. 가운데로 수레를 데려가려 하면 위험 피드백 후 수레 진입을 막는다.
7. 소년이 앞서 가면 기존 follower 규칙으로 수레가 따라온다.
8. 장터 출구에 수레와 함께 도달하면 완료.

### 유효 해법

1. 서쪽: 상태 확인 → 障礙 제거 → 짧은 길로 帶領
2. 동쪽: 상태 확인 → 긴 安全 경로로 帶領

둘 중 어느 쪽도 우월하다고 기록하거나 점수화하지 않는다.

### 위험 경로 피드백

> 這段路又濕又窄，現在讓貨車通過太危險。
> 이 구간은 젖고 좁아서 지금 수레를 통과시키기에는 너무 위험해.

소년은 後退해서 다른 경로를 고를 수 있다.

### 단어 체감

情況:
- 각 길의 현재 상태 묶음.

安全:
- 현재 손수레가 실제로 통과 가능한 상태.

危險:
- 대상과 상황에 따라 현재 선택하기 부적절한 경로.

끝마을의 允許 / 禁止 / 限制 같은 규칙 기반 판단과 구별한다.

### 구현 메모

- G6/G7의 수레 추종 규칙 재사용.
- G4/G7의 장애물 직접 선택·제거 패턴 재사용.
- 새로 필요한 것은 route condition metadata와 상태 확인 UI 정도.

# 11. 자동검사 포인트

F2:
- 가려진 표식은 공개 전 확인 불가
- 세 표식 각각 확인 전/후 상태
- 세 개 확인 뒤 완료

F3:
- 오답 방향 완료 불가
- 4방향 회전 가능
- 올바른 방향 + 기준 정보 확인 뒤 완료

F4:
- 오답 세 후보가 각각 정확히 한 특징만 다름
- 색만 맞는 후보로 완료 불가
- 세 특징이 모두 맞는 후보만 완료

F5:
- 정답 후보 2개가 조건 모두 만족
- 굵기/길이/생장 위치 하나라도 다르면 부적합
- 잘못 채집 후 복구 가능
- 적합 재료 2개 + 출구에서 완료

F6:
- 마지막 위치 확인 전 추적 완료 불가
- 동물 흔적은 관련 없음
- 바퀴 자국만으로 확인 완료 불가
- 파란 실 + 후속 흔적으로 올바른 방향 해금

F7:
- 마지막 흔적 기준 주변 범위 판정
- 파란 실 발견 전 꾸러미 확정 불가
- 발견 → 수집 → 출구 순서 확인

F8:
- 서쪽·동쪽 모두 완주 가능
- 가운데는 소년만 통과 가능, 수레 차단
- 서쪽 장애물 제거 후 통과 가능
- 다른 경로로 되돌아갈 수 있음
- 두 유효 경로 어느 쪽도 우열 결과 저장하지 않음

# 길목 G2 `종소리가 닿는 곳` 설계 v0.1

작성일: 2026-09-10

## 한 줄 플레이 경험

**보이지 않는 종소리의 경계를 직접 걸어 다니며, 각 지점의 `距離`를 비교하고 종소리가 닿는 전체 `範圍`의 가장자리를 찾아낸다.**

## 학습 단어

- `距離`: 두 대상 사이가 얼마나 떨어져 있는가.
- `範圍`: 어떤 효과가 미치는 전체 영역.

숫자 암산 문제로 만들지 않는다. 플레이어는 실제로 움직이고, 현재 위치에서 소리가 들리는지 확인하며 두 개념을 구분한다.

## 이야기 흐름

G1 후속 이야기에서 감시탑의 종이 울리고, 길지기가 다음 일이 종소리가 어디까지 닿는지와 관계가 있다고 말한다.

G2를 시작하러 다시 길목을 선택하면 길지기가 길 위에 꽂아둔 확인 표식을 설명한다.

> `請找出還聽得到鐘聲、而且離鐘樓最遠的標記。`
>
> 종소리가 아직 들리면서 종탑에서 가장 먼 표식을 찾아 달라는 부탁이다.

G2를 끝내면 소년은 각 표식의 `距離`는 하나의 지점과 종탑 사이의 관계이고, 들리는 지점들을 모으면 종소리의 `範圍`를 볼 수 있다는 것을 경험으로 정리한다.

## 맵

5×7 세로 맵이다.

```text
#####
#.B.#
..P..
.P#P.
.P.P.
.....
..S..
```

- `S`: 소년 시작 위치
- `B`: 감시탑의 종. 고정된 범위 중심이며 이동 불가
- `P`: 길지기가 꽂아둔 확인 표식. 위에 서면 종탑까지의 거리와 현재 소리 상태를 확인
- `#`: 이동 불가
- `.`: 길

종은 `(1,2)`에 있고 맨해튼 거리 `radius = 3`을 사용한다.

확인 표식의 거리는 다음과 같다.

| 위치 | 거리 | 종소리 |
|---|---:|---|
| `(2,2)` | 1 | 범위 안 |
| `(3,1)` | 3 | 범위의 가장자리 |
| `(3,3)` | 3 | 범위의 가장자리 |
| `(4,1)` | 4 | 범위 밖 |
| `(4,3)` | 4 | 범위 밖 |

왼쪽과 오른쪽 어느 쪽으로도 해결할 수 있다.

중앙의 `(3,2)`는 막혀 있다. 아래에서 접근하면 `(4,2)`에서 종소리가 들리기 시작하지만, 옆의 `(4,1)` 또는 `(4,3)`으로 비켜나가면 다시 범위 밖이 된다. 다시 위의 거리 3 표식으로 올라가면 범위 안으로 돌아온다.

이 움직임을 통해 `範圍`를 단순한 위아래 직선 길이가 아니라 종을 중심으로 퍼지는 공간으로 느끼게 한다.

## 목표

> `找出鐘聲範圍內，距離鐘樓最遠的標記點。`

거리 3의 왼쪽 또는 오른쪽 표식에 도달하면 성공한다.

정답 이동 순서를 제시하지 않는다. 범위 밖 표식을 먼저 확인해도 되고, 안쪽을 둘러봐도 되고, 바로 경계 표식에 닿아도 된다.

## trigger / predicate / state delta / feedback

### 일반 이동

- trigger: 소년이 한 칸 이동한다.
- predicate: 이동 전후가 종소리 범위 안/밖을 가로지르는가.
- state delta: 없음.
- feedback:
  - 밖 → 안: `鐘聲變清楚了。進入鐘聲的範圍。`
  - 안 → 밖: `聽不到鐘聲了。已經離開鐘聲的範圍。`

### 확인 표식

- trigger: 소년이 `P` 위에 선다.
- predicate: 종까지의 맨해튼 거리를 계산한다.
- state delta: `rangeObserved = true`.
- feedback 예:
  - `距離鐘樓：4格。這裡聽不到鐘聲。`
  - `距離鐘樓：1格。這裡聽得到鐘聲。`

숫자는 정답 입력값이 아니라 해당 위치의 관계를 설명하는 정보다.

### 범위의 가장자리

- trigger: 소년이 `P` 위에 선다.
- predicate: `distance === radius`.
- state delta: `rangeSolved = true`.
- feedback: `找到了鐘聲範圍的邊緣。`

## 완료 직후 범위 공개

첫 본편 클리어 직후에만 실제 영향권을 판 위에 한 번 보여준다.

- `distance <= radius`인 칸을 약하게 강조한다.
- `distance === radius`인 가장자리를 조금 더 분명하게 표시한다.
- 이 공개는 정답을 찾은 뒤 `範圍`를 전체 공간으로 묶어 이해시키는 사후 피드백이다.
- 여정에서 다시 플레이할 때는 공개하지 않는다.
- 첫 클리어 완료 화면에서 `다시 해보기`를 눌러도 이미 완료한 판이므로 공개하지 않는다.

즉 범위 시각화가 공략 힌트가 되는 일은 없다.

## 잘못된 행동과 오판

실패나 초기화를 만들지 않는다.

범위 밖 표식에 도착하면 거리와 `들리지 않음` 정보만 준다. 안쪽의 가까운 표식에 도착해도 거리와 `들림` 정보만 준다.

`더 멀리 가라`, `왼쪽으로 가라`, `거리 3을 찾아라` 같은 자동 힌트는 주지 않는다.

## 살펴보기

종을 살펴보면 종소리가 이곳에서 시작된다는 사실만 알려준다. 반경 숫자는 공개하지 않는다.

확인 표식을 살펴보면 위에 서서 거리와 소리를 확인할 수 있다는 도구의 성질만 알려준다.

G2에서는 새 상황형 행동을 만들지 않는다. 실제 사용 행동은 이동이다.

## 신규 공통 range mechanic

G2에서 고정 대상 중심 범위가 두 번째 실제 `radius` 사용처가 되므로 다음 세 판정만 공통화한다.

```js
distanceBetween(a, b)
isWithinRange(target, source, radius)
isRangeBoundary(target, source, radius)
```

스테이지 데이터는 다음 정도로 둔다.

```js
rangeSource: {
  source: 'B',
  radius: 3,
  pointChar: 'P',
  revealOnFirstClear: true
}
```

현재 단계에서 다음은 만들지 않는다.

- 다중 범위 소스
- 유클리드 거리
- 벽에 따른 소리 감쇠
- 시야 차단
- 범용 오라/마법 효과 엔진
- 범위 편집기

늑대의 이동 순환과 미래 위치 위험 판정도 그대로 둔다. 공통 거리/범위 판정을 사용할 수 있는 기반만 만든다.

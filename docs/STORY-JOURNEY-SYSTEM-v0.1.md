# 1. 게임의 세 가지 상위 화면

초기 장기 구조는 다음 세 화면을 기본으로 한다.

## 월드맵

> **앞으로 어디로 갈까?**

- 현재 방문 가능한 지역을 본다.
- 새 의뢰, 추천 목적지, 잠금 상태를 확인한다.
- 지역을 선택해 현재 진행 가능한 이야기나 스테이지를 시작한다.

## 여정

> **지금까지 무엇을 했지?**

- 프롤로그부터 현재까지의 진행을 장과 지역 단위로 돌아본다.
- 본편과 별도로, 발견한 자유 의뢰를 장소별로 돌아본다.
- 이미 열린 스테이지를 다시 플레이한다.
- 이미 본 이야기 장면을 다시 읽는다.
- 튜토리얼도 여정의 첫 번째 에피소드로 포함한다.

## 단어장

> **지금까지 어떤 말을 만났지?**

- 만난 단어를 다시 확인한다.
- 뜻, 주음, 예문, 게임에서 경험한 맥락을 복습한다.

`월드맵 / 여정 / 단어장`은 서로 다른 질문에 답해야 한다. 같은 정보를 세 화면에서 중복해 보여주지 않는다.

# 2. 튜토리얼의 위치

튜토리얼은 게임 밖의 별도 도움말이 아니다.

세계 안에서는 용사가 고향 마을을 떠난 **첫 번째 모험**이고, 사용자 경험에서는 기본 조작과 핵심 단어를 다시 익힐 수 있는 **튜토리얼**이다.

여정에서는 다음처럼 표시한다.

> **프롤로그 · 고향 마을（出發）**  
> 튜토리얼

여기에서 기존 6개 스테이지를 언제든 다시 플레이할 수 있다.

기존 튜토리얼의 사건과 후일담도 점차 이야기 노드로 옮길 수 있다.

튜토리얼 완료 저장 키 `chufa-tutorial-v03`는 기존 사용자 호환을 위해 당분간 유지한다.

# 3. 장과 지역의 관계

## 프롤로그 — 고향 마을

용사가 고향을 떠나 숲을 빠져나오기까지의 첫 모험이다.

- 기본 이동
- `接近`
- `遠離`
- `通過 / 到達`
- `避開`
- 종합 스테이지
- 마지막 `「救命！」`

## 1장 — 세 갈래 길

튜토리얼 마지막의 구조 요청을 따라가 행상인을 만난다.

행상인에게서 세 지역을 소개받고 월드맵이 열린다.

- 길목（關口鎮）
- 장인골（工坊村）
- 장터（市集鎮）

세 지역은 어느 순서로 가도 된다.

이후 자연스러운 연결은 다음과 같다.

- 길목 → 끝마을
- 장인골 → 학술탑(상설 연구, W7 후일담에서 개방)
- 장터 → 회의소

세부 사건은 `TIER1-STORYLINE-v0.1.md`를 기준으로 한다.

## 본편 장과 자유 의뢰의 관계

본편과 자유 의뢰는 같은 여정 화면에 나타나지만 같은 진행선으로 취급하지 않는다.

```text
본편: 장 → 지역 → 이야기·스테이지
자유 의뢰: 자유 의뢰 묶음 → 장소 → 개별 의뢰 → 이야기·스테이지
```

`북쪽 숲（北邊森林）`은 1장의 네 번째 본편 지역이 아니다. `자유 의뢰 · 물길마을 주변` 아래에 두는 영구 장소이며, `북쪽 숲의 버섯（北邊森林的蘑菇）`은 그 장소에 붙는 첫 개별 의뢰다. 이후 북쪽 숲에 채집·조사·던전 의뢰가 생기면 같은 장소 아래에 서로 독립된 형제 의뢰로 추가한다.

본편의 `이어서 여행하기`는 계속 본편 추천 노드만 가리킨다. 진행 중인 자유 의뢰는 해당 의뢰 안에서 별도의 `계속` 위치를 표시하고, 자유 의뢰를 수락하거나 재생해도 본편 추천 위치를 덮어쓰지 않는다.

# 4. 콘텐츠 노드의 두 종류

여정의 기본 단위는 `story`와 `stage` 두 종류다.

## story

대사와 짧은 연출로 사건을 보여준다.

예:

- 고향을 떠나다
- 숲 너머의 목소리
- 길가의 행상인
- 길목에 도착하다
- 북쪽에서 온 소식
- 다시 열린 길

## stage

플레이어가 직접 판을 조작해 사건을 해결한다.

예:

- 관문 안의 길표지
- 종소리가 닿는 곳
- 두 갈래 길

두 종류는 독립된 데이터지만 실제 첫 진행에서는 하나의 순서로 연결한다.

예:

`story → stage → stage → story → stage → story`

이 순서를 **에피소드 순서(sequence)**라고 부른다.

---

# 5. 처음 진행할 때의 흐름

처음 보는 콘텐츠는 목록을 오가게 하지 않는다.

기본 흐름:

> 월드맵 또는 현재 진행 → 이야기 → 스테이지 → 짧은 후일담 → 다음 콘텐츠

예를 들어 길목 첫 방문은 다음처럼 이어질 수 있다.

1. `길목에 도착하다` — story
2. 길지기가 안쪽 뜰의 길표지를 확인해 달라고 부탁한다.
3. `관문 안의 길표지` — stage (`進入 / 退出`)
4. 성공 후 짧은 story 또는 결과 대사
5. `종소리가 닿는 곳`이 열린다.

스토리를 본 뒤 다시 메뉴로 돌아가 스테이지를 찾아 눌러야 하는 구조는 피한다.

# 6. 여정 화면

여정은 **진행 기록 + 다시 보기 + 다시 플레이**를 담당한다.

## 6.1 여정 첫 화면

장 단위로 묶는다.

예:

### 프롤로그 · 고향 마을

`튜토리얼 · 스테이지 6/6 · 이야기 3/3`

### 1장 · 세 갈래 길

- 길목 `스테이지 2/7 · 이야기 2/5`
- 장인골 `스테이지 0/7 · 이야기 1/5`
- 장터 `스테이지 0/7 · 이야기 1/5`

정확한 이야기 수는 실제 장면을 만들며 바꿀 수 있다.

## 6.2 지역 상세

지역 안에서는 최소한 다음 두 목록을 전환할 수 있어야 한다.

### 스테이지

- 이미 열린 판을 다시 플레이할 수 있다.
- 완료 여부를 표시한다.
- 아직 열리지 않은 콘텐츠는 스포일러 정도에 따라 `???` 또는 잠금 표시를 사용한다.
- 다시 플레이해도 이야기 진행 상태를 되돌리지 않는다.

### 이야기

- 이미 본 장면을 다시 읽을 수 있다.
- 읽은 순서가 드러나게 배열한다.
- 아직 보지 않은 중요한 장면의 제목은 필요하면 숨긴다.
- 다시 읽기는 진행도와 보상에 영향을 주지 않는다.

## 6.3 튜토리얼도 동일한 규칙을 사용한다

프롤로그의 6개 기존 스테이지도 `여정 > 프롤로그 > 스테이지`에서 다시 플레이할 수 있게 한다.

튜토리얼을 다시 하는 기능을 별도의 설정이나 도움말 깊숙한 곳에 만들지 않는다.

## 6.4 자유 의뢰는 장소 아래에 누적한다

자유 의뢰는 미래 제목을 `???`로 미리 늘어놓지 않는다. 수락하거나 이야기에서 실제로 발견한 의뢰만 여정에 나타난다.

예:

```text
자유 의뢰 · 물길마을 주변
└─ 북쪽 숲（北邊森林）
   ├─ 북쪽 숲의 버섯（北邊森林的蘑菇）
   │  ├─ 부탁을 수락하다 — story
   │  ├─ 북쪽 숲에서 버섯을 모으다 — stage
   │  ├─ 여관 주인에게 보고하다 — story
   │  └─ 의뢰 게시판이 생기다 — story
   └─ 이후 발견한 북쪽 숲 의뢰
```

- 아직 수락·발견하지 않은 의뢰는 장소와 개수를 포함해 완전히 숨긴다.
- 진행 중인 의뢰는 그 의뢰의 다음 사건을 `계속`으로 표시한다.
- 완료한 의뢰는 같은 장소 아래에 남겨 이야기 재독과 스테이지 연습을 제공한다.
- 한 의뢰의 마지막 사건에서 다음 의뢰로 자동 연결하지 않는다.
- 같은 장소에 진행 가능한 의뢰가 여러 개면 장소 진입 시 하나를 임의 선택하지 않고 의뢰 선택 UI를 먼저 제공한다.

# 7. 스토리 모드 최소 사양

v0.1은 비주얼노벨 엔진을 목표로 하지 않는다.

모바일 세로 화면에서 짧고 빠르게 읽는 연결 장면을 만든다.

필수 기능:

1. 장면 제목
2. 화자 이름
3. 한 번에 1~2개의 짧은 대사 또는 서술
4. 탭하여 다음 대사로 이동
5. 번체 중국어 원문
6. 한국어 뜻 확인
7. 이전 대사 확인
8. 이미 본 장면 건너뛰기
9. 장면 완료 기록
10. 장면 종료 후 다음 스테이지나 월드맵으로 자연스럽게 연결

초기에는 복잡한 선택지, 호감도, 분기 결말, 음성 재생은 만들지 않는다.

---

# 8. 스토리 안의 중국어 원칙

스토리는 중국어 시험 화면이 아니다.

- 번체 중국어를 이야기의 기본 언어로 사용한다.
- 한국어는 이해를 돕는 번역 층으로 제공한다.
- 뜻 확인에 페널티를 주지 않는다.
- 모르는 문장을 읽지 못해도 이야기 진행을 막지 않는다.
- 새 핵심 단어가 등장할 수 있지만, 한 장면에 학습 부담을 몰아넣지 않는다.

전술 스테이지에서 직접 의미를 사용하게 할 단어는 이야기 속에서도 자연스러운 맥락으로 먼저 또는 다시 보여줄 수 있다.

좋은 연결:

> 길지기: 「先進去看看，再從這裡退出來。」  
> 이후 스테이지에서 플레이어가 실제로 `進入 / 退出`을 수행한다.

스토리가 정답 이동 순서를 그대로 설명해서는 안 된다.

# 9. 이야기 장면의 시각 원칙

현재 세계의 밝고 소박한 중세풍 분위기를 유지한다.

v0.1에서 필요한 시각 요소는 최소화한다.

- 지역을 알아볼 수 있는 간단한 배경 또는 배경색/실루엣
- 용사와 NPC의 작은 캐릭터 이미지 또는 초상
- 필요하면 2~3개의 표정 상태
- 대사창

전술 스테이지보다 화려한 연출이 스토리 모드의 목표가 아니다.

같은 지역에서 스토리와 전술판이 **같은 장소에 있다는 느낌**이 나는 것이 더 중요하다.

# 10. 권장 데이터 구조

정확한 자바스크립트 구현은 개발 단계에서 조정할 수 있지만, 콘텐츠 관계는 다음처럼 분리한다.

```js
STORIES = {
  'tier1-roadside-merchant': {
    id: 'tier1-roadside-merchant',
    episodeId: 'chapter-1-three-roads',
    regionId: null,
    titleKo: '길가의 행상인',
    beats: [
      { speaker: '행상인', zh: '救命！', ko: '사람 살려!' }
    ]
  }
}

JOURNEY = [
  {
    id: 'waterway-side-quests',
    kind: 'quest-collection',
    titleKo: '자유 의뢰 · 물길마을 주변',
    sections: [
      {
        id: 'north-forest',
        regionId: 'north-forest',
        nameKo: '북쪽 숲',
        nameZh: '北邊森林',
        quests: [
          {
            id: 'north-forest-mushrooms',
            titleKo: '북쪽 숲의 버섯',
            titleZh: '北邊森林的蘑菇',
            revealRequires: ['story:first-free-quest-accepted'],
            sequence: [
              { type: 'story', id: 'first-free-quest-accepted', entryRegionId: 'inn-first-quest' },
              { type: 'stage', id: 'first-free-quest-forest', entryRegionId: 'north-forest' },
              { type: 'story', id: 'first-free-quest-report', entryRegionId: 'inn-first-quest-report' },
              { type: 'story', id: 'quest-board-installed', entryRegionId: 'inn-first-quest-report' }
            ]
          }
        ]
      }
    ]
  }
]
```

핵심은 `STORIES`, `STAGES`, `JOURNEY sequence`의 역할을 섞지 않는 것이다.

- `STORIES`: 장면 내용
- `STAGES`: 판 규칙과 승리 조건
- `JOURNEY`: 이야기와 판이 어떤 순서로 이어지는지, 자유 의뢰가 어느 장소에 속하는지

자유 의뢰 노드의 `entryRegionId`는 사건이 실제로 시작되는 월드 진입점을 뜻한다. 수락은 여관, 수행은 북쪽 숲, 보고는 다시 여관처럼 한 의뢰 안에서도 달라질 수 있으므로 장소 묶음의 `regionId`와 분리한다.

이렇게 하면 같은 스테이지를 여정에서 다시 실행해도 최초 진행 순서를 훼손하지 않는다.

# 11. 진행 상태

새 저장 상태는 기존 월드 방문 상태와 분리하는 것을 우선한다.

가제:

`chinese-word-tactics-journey-v1`

최소 기록 후보:

- 본 story ID
- 완료한 stage ID
- 현재 열린 story/stage ID
- 장/지역별 최신 진행 위치
- 새로 열린 콘텐츠를 확인했는지 여부

기존 저장 키:

- `chufa-tutorial-v03`
- `chinese-word-tactics-world-v1`

은 즉시 삭제하지 않는다.

## 기존 사용자 마이그레이션 원칙

기존 튜토리얼 완료 사용자는 새 버전에서도 튜토리얼 완료 상태를 잃지 않는다.

새로 추가된 이야기 장면은 **열림 상태**로 만들 수 있지만, 사용자가 실제로 읽지 않았다면 자동으로 `seen` 처리하지 않는다.

즉, 기존 진행을 되돌리지는 않되 새 이야기를 다시 볼 기회는 남긴다.

# 12. 새 콘텐츠 알림

상태 표시는 작고 단순하게 한다.

예:

- 새 이야기: `이야기 ●`
- 새 스테이지: `스테이지 ●`
- 새 지역 의뢰: 월드맵 지역에 작은 표시

알림 자체가 플레이 목적이 되지 않게 한다.

일일 알림, 출석 보상, 놓치면 손해 보는 구조와 연결하지 않는다.

# 15. 최종 경험 목표

처음 플레이할 때:

> **이야기에서 문제가 생긴다 → 내가 판에서 해결한다 → 결과가 다음 이야기로 이어진다.**

며칠 뒤 돌아왔을 때:

> **월드맵을 보고 다음 목적지를 고르거나, 여정에서 지금까지 한 일을 확인한다.**

복습하고 싶을 때:

> **여정에서 예전 스테이지를 다시 하고, 이야기에서 그 단어가 쓰였던 상황도 다시 본다.**

이 구조가 완성되면 스테이지는 독립된 중국어 문제가 아니라 **용사의 여행에서 실제로 해결했던 사건**으로 기억되어야 한다.

# 16. 실제 해금과 이야기 분기 계약 (2026-10-31)

> **현재 구현을 해석하는 우선 기준.** 앞의 2026-09-10 v0.1 예시들은 초기 UI 설계 이력이다. 이 절은 현재 [상위 콘텐츠 분류](GAME-CONTENT-FRAMEWORK-v0.1.md), [학술탑 첫 방문](ACADEMIC-TOWER-OPENING-STORY-v0.1.md), [03B 상세](ACADEMIC-TOWER-RAN-REVISIT-03B-DETAIL-v0.1.md), [큰비 도입](CHAPTER2-RAIN-OPENING-DESIGN-v0.1.md)과 실제 런타임의 선수 상태를 묶는다. 세부 판·대사 원고는 지역 문서를 따른다.

## 16.1 장 소속, 장소 입장, 개별 연구, 공통 사건은 별개다

- **본편의 장:** 1장은 길목·장인골·장터와 여관 결말, 2장은 큰비 도입 이후 회의소·끝마을을 중심으로 확장한다. 월드맵 장 표지는 이야기 시점이지 상설 연구의 완료나 장소 잠금 조건이 아니다.
- **상설 공간의 입장:** 학술탑은 W7 후일담의 수리패·표식 단서를 받은 뒤 지속 개방된다. 이후 장 번호, 1장 결말, 2장 본편 완료와 독립적이다.
- **개별 학습의 선수:** 본선 01~05, 03A, 03B는 각 스테이지와 이야기의 의미를 이해하는 데 실제로 필요한 기록을 조건으로 둔다. 전체 학술탑 완료·격파 milestone은 만들지 않는다.
- **사건의 선수:** 선택 연구 04A는 특정 연구 진도와 *같은 큰비가 이미 지나갔는지*를 모두 확인한다. 아직 일어나지 않은 폭우의 흔적을 조사할 수 없다.
- **분기 대사:** 경험이 있는 경우에만 그 경험을 언급한다. 이야기 분기는 별도 스테이지를 복제하지 않고 공통 story의 일부 beat를 바꾸며, 기본 story ID와 저장 milestone을 유지한다.

## 16.3 코드에서 해금과 표시를 판정하는 방법

- `WORLD.regions[id].requires`는 지도에서 *장소 자체의 진입*을 제한한다. 일반 milestone뿐 아니라 `story:workshop-finale`처럼 정확한 이야기 완료도 인식한다.
- `JOURNEY.sections[].revealRequires` 및 `revealAfterRain`은 여정에서 *항목을 보여줄 시점*을 제어한다. 보인다고 즉시 시작 가능한 것은 아니다.
- `JOURNEY.sections[].sequence[].requires`와 `requiresRainPassed`는 *지금 플레이해도 되는지* 확인한다. 학술탑 허브의 `room.requiresStories`/`room.requiresRainPassed`도 같은 조건을 사용해야 한다. 월드·허브·여정·직접 실행 간 우회가 없어야 한다.
- `JourneyProgress.hasRainPassed`는 `chapter1-complete` 이후 정상 큰비의 `chapter2-rain-passed`/story 완료를 인식한다. **구형 저장**에서 04A 현장 연구나 큰비 이후 자유 의뢰를 이미 진행했다면 그때의 사건을 경험한 것으로 간주한다. 이때 못 본 `chapter2-rain-opening`을 `seenStories`에 허위 기록하지 않는다.
- `JourneyProgress.hasPostRainEvidence`는 **04A 및 1장 이후 의뢰 관련 ID만** 검사한다. 일반 학술탑 연구를 1장 도중 먼저 해도 큰비가 자동으로 건너뛰지 않는다.
- 기존 **03B가 이미 시작된 저장**은 새 M4 조건으로 이용 중인 연구를 회수하지 않는다. 이미 본 도입이나 완료 상태는 유지하고 재개할 수 있다.
- 미완료 `story`의 읽던 위치·기완료 스테이지·첫 inquiry 결과·수리패·관찰 카드는 보존한다. 재열람/재플레이가 원래 진행을 새로 완료 처리하지 않는다. 새 노드를 `STAGES` 중간에 삽입하거나 저장 키/버전을 불필요하게 바꾸지 않는다.

## 16.4 새로운 분기나 연구를 추가할 때 필수 점검

1. **이야기 안의 사실마다 증거 ID를 찾는다.** "지난번", 특정 물건, 특정 사건, 과거에 본 표식·거래를 말한다면 어떤 최초 story가 그 사실을 제공하는지 적는다.
2. **입장 / 표시 / 실행 조건을 구분한다.** 새 연구가 상설 공간 전체를 잠그지 않고, 이미 시작된 내용을 소급 차단하지 않도록 한다.
3. **분기 대사와 주음을 함께 검증한다.** 현재 연구는 `StoryOutcomeContent.resolve`에서 실제 경험에 따라 beat를 치환하며, `tools/story-pronunciation-audit.cjs`로 기본·분기 문장을 모두 확인한다. 별도 story ID를 늘리지 않는다.
4. **저장 이행 반례를 테스트한다.** (a) W7만, (b) W7 후일담 이후 G7 미완료, (c) 03A 후 M4 미완료, (d) 본선 04 후 비 이전, (e) 이전 04A 중단 저장, (f) 1장 중 학술탑 연구 후 1장 결말, (g) 다시 보기·다른 장소 왕복·백업 복원.
5. **G4/G5/G6를 구분한다.** 자동검사·Pages 배포·실제 iPhone Safari 확인은 서로 별개의 완료 단계다.

장인골의 공통 구조는 `현재 장치 상태 → 조작값 → 파생 결과`다. 조작값과 결과를 같은 숫자나 문장으로 중복하지 않고, 행동 가까이에 중국어 결과를 둔다.

| 판 | 핵심 판단 | 반드시 상시 표시 | 사전·상세로 이동 | 중복 정보 | 누락 정보 | 적합한 형태 | 예상 수정 파일 |

## 튜토리얼 회귀 판단

튜토리얼 6판은 공통 셸·44px·판 고정·완료 교체 회귀 대상으로 유지한다. 판과 조작 구조는 바꾸지 않는다. 다만 후속 정보 감사에서 `stage-1 / 3 / 4`의 일반 진입 문구가 목표·판을 반복하는 것을 확인해 비웠다. 첫 이동 선택법이 필요한 `stage-0`과 늑대가 행동마다 움직이는 `stage-2 / 5`의 규칙만 시작 상태에 유지한다.

## 구현·검증 결과

- G7: 판이 이미 보여 주는 경로·행렬을 목표 옆에 반복하지 않고, `via / viaIds`와 `followerPositions / chainStuck`은 실패 이유와 완료 판정에만 사용한다.
- 공통 목표 카드: G7의 전용 규칙 클래스와 F1의 동적 수량 문구를 제거하고, 스테이지 전환마다 `ruleline` 클래스를 초기화한다. 규칙 원문은 책 버튼 상세에 유지한다.
- 공통 상태줄: 일반 진입 문구와 공통 `目標完成`을 제거했다. 결과가 없는 진입·완료는 높이만 예약하고 비우며, 중국어 행동 결과와 실패 이유는 그대로 유지한다.
- 장인골·장터 진입: W1~W7의 장치 상태 재진술과 M1~M8의 목표·자원 재진술을 제거했다. 장인골은 장치판, 장터는 소지·선택 트레이가 첫 판단을 맡는다.
- 완료 피드백: W1~W7·M1~M7의 구체적 상태 변화와 F8의 안전 도착은 유지한다. M8은 일반 완료 설명 대신 마지막 실제 보충·거래 결과를 보존한다.
- 장터 행동 칸: 선택 대상에 현재 생성할 거래·보충 버튼이 없으면 빈칸으로 두고, 버튼 부재를 설명하는 일반 문장은 표시하지 않는다. 구체적인 조건 부족과 실제 행동 실패 피드백은 유지한다.
- W7: `systemRecovered.conditions`에서 중복 장치를 합친 남은 이상 수를 파생하고 연결 행동을 `連接 / 分開`로 표시했다.
- F5: 작업 지시 마지막 칩을 실제 적합 재료 수인 `適合 0/2 → 1/2 → 2/2`로 갱신한다.
- F8: 세 경로의 `confirmedFlag / attributes`에서 판 위 `乾·寬 / 濕·窄 / 乾·寬` 기록과 확인 표식을 함께 파생한다.
- F3·F7: 완료나 다음 판단에 쓰지 않는 `actualRouteObserved / nearbyCompared` 상태를 제거했다.
- 튜토리얼 6판과 길목·장인골·북쪽 숲의 판 구조는 바꾸지 않았다. 상·하 설명의 역할만 정리했다.

Astra medium의 G7·F5·F8 제안은 채택했다. W7의 증상/원인 가시성은 채택했지만 별도 비교 카드는 장치판 자체가 비교 표면이고 세로 예산을 중복 사용하므로 채택하지 않고, 장치판 상단의 파생 요약으로 구현했다.

- `python3 tests/smoke_gate_layout.py`: 84상태 통과
- `python3 tests/smoke_workshop_layout.py`: 224상태 통과
- `python3 tests/smoke_north_forest_layout.py`: 64상태 통과
- 길목·장인골·북쪽 숲 focused Node 테스트: 통과
- `360×640` 가로 overflow 0, 조작 44px 이상, 대표 상태 판 변화 1px 이하

자동 Chromium 통과는 Safari 실기기 승인과 구분한다. 최종 배포 뒤에는 라이브 Pages에서 캐시를 우회해 새 빌드 메타와 변경 자원을 다시 확인한다.

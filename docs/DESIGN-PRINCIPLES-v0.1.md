# 번체 중국어 단어 전술게임 — 디자인 원칙 v0.1

> 기준 버전: v0.5 월드맵
> 작성일: 2026-09-10
> 적용 대상: `chinese-word-tactics`의 월드맵, 전술 스테이지, 단어 정보, 상태 피드백, 이후 지역·의뢰 화면
> 목적: 기능이 늘어나도 화면의 판단 기준이 흔들리지 않도록 시각·상호작용 원칙을 먼저 고정한다.

---

## 1. 한 줄 방향

**조용한 여행 지도 위에서, 단어와 판의 변화만 또렷하게 살아나는 작은 전술게임.**

이 게임의 화면은 학습 앱처럼 정보를 늘어놓는 곳이 아니다.
플레이어가 작은 판을 읽고, 단어의 뜻을 확인하고, 스스로 해법을 찾는 공간이다.

UI는 조용해야 한다.
판과 단어는 분명해야 한다.

---

## 2. 참고 축

### 2.1 tea-timer에서 가져올 것

`tea-timer`의 외형을 복사하지 않는다.
대신 다음 판단 방식을 가져온다.

- UI 자체보다 핵심 경험을 주역으로 둔다.
- 선과 테두리를 남발하지 않고 면과 여백으로 위계를 만든다.
- 같은 역할에는 같은 글자 크기, 간격, 터치 크기를 쓴다.
- 이미 화면에서 알 수 있는 내용을 별도 상자나 설명으로 반복하지 않는다.
- 주요 조작은 엄지 영역을 우선하고 최소 44px 터치 영역을 확보한다.
- 가장 작은 목표 기기에서 실제 화면을 검증한다.
- 시각적 선택은 구현 전에 비교 가능한 시안으로 확인하고, 확정된 원칙은 문서에 남긴다.

### 2.2 전술게임에서 가져올 것

전술판은 장식물이 아니라 플레이 공간이다.

- 맵 전체를 빠르게 읽을 수 있어야 한다.
- 현재 위치, 이동 가능 칸, 위험, 목표, 완료 상태를 즉시 구분할 수 있어야 한다.
- 상태 표시는 판 위에 얹히되 지형 자체를 가리지 않는다.
- 최적 경로를 자동으로 알려주지 않는다.
- 정보는 해법을 대신하지 않는다.

### 2.3 단어 퍼즐에서 가져올 것

단어는 일반 버튼이 아니다.

이 게임에서 중국어 단어는 문제의 보기나 메뉴 항목이 아니라 세계를 이해하는 핵심 규칙이다.
따라서 단어 자체에 일반 UI보다 높은 시각적 존재감을 준다.

## 3. 가장 중요한 구분: 세계와 UI

화면에 있는 모든 요소를 먼저 두 종류로 나눈다.

### 세계

플레이어가 게임 안에서 읽고 판단하는 것.

예:

- 지형
- 길
- 벽
- 유적
- 위험 지역
- 출구
- 용사
- 늑대와 이후 등장할 인물
- 월드맵의 길과 지역
- 단어가 발동하며 생기는 변화

### UI

플레이어가 세계를 이해하거나 조작하기 위해 사용하는 도구.

예:

- 상단 스테이지 제목
- 목표 문장
- 단어 정보 열기
- 기다리기
- 살펴보기
- 되돌리기
- 메뉴
- 설정

**세계는 버튼처럼 보이지 않게 한다.**
**UI는 세계보다 앞에 튀어나오지 않게 한다.**

새 화면을 만들 때 가장 먼저 이 구분을 확인한다.

---

## 4. 판은 카드가 아니다

현재 프로토타입의 격자판은 기능 확인을 위해 각 칸과 외곽에 둥근 모서리, 테두리, 그림자를 많이 사용한다.
이 구조는 읽기는 쉽지만 판 전체가 여러 개의 버튼을 모은 UI처럼 보이게 한다.

앞으로의 원칙은 다음과 같다.

- 격자는 하나의 연속된 공간으로 보이게 한다.
- 각 칸의 둥근 모서리는 없애거나 크게 줄인다.
- 맵 외곽 카드 효과와 그림자는 최소화한다.
- 지형 차이는 색, 질감, 형태로 표현한다.
- 이동 가능, 조사 가능, 위험 범위 같은 상태는 지형 위에 반투명 면·표식·얇은 강조로 겹친다.
- 선택 가능 상태를 표현하기 위해 모든 칸에 테두리를 추가하지 않는다.

판을 보았을 때 먼저 보여야 하는 것은 `버튼 35개`가 아니라 `하나의 장소`다.

## 5. 단어는 주역 정보다

`接近`, `遠離`, `通過`, `到達`, `避開` 같은 단어는 일반 버튼과 다르게 취급한다.

### 기본 원칙

- 단어를 작은 알약 버튼 여러 개로 나열하는 구조를 기본값으로 삼지 않는다.
- 한자 자체가 가장 먼저 읽혀야 한다.
- 한국어 뜻은 필요할 때 열어보는 보조 정보다.
- 병음·주음·예문·게임 안 규칙은 상세 정보에서 제공한다.
- 단어를 확인하는 행동에는 페널티가 없다.

### 시각적 역할

단어는 다음 중 하나처럼 느껴지는 독립 언어를 갖는다.

- 지도에 적힌 표식
- 돌이나 장치에 새겨진 각인
- 여행 노트의 핵심어
- 현재 판을 읽는 명령어

정확한 형태는 이후 시안에서 결정한다.
다만 일반 `button`과 같은 모양을 그대로 쓰는 것은 피한다.

## 6. 정보 위계

한 화면에서 시각적 무게를 다음 순서로 둔다.

1. 현재 판 또는 월드의 공간
2. 플레이어와 중요한 오브젝트
3. 현재 목표와 핵심 단어
4. 지금 가능한 행동
5. 보조 설명과 시스템 정보

모든 정보를 카드로 감싸 같은 무게를 주지 않는다.

### 상단 목표

현재의 큰 `goalbox`처럼 항상 독립 카드 하나를 차지하는 방식은 재검토한다.
목표는 상단에서 짧고 명확하게 읽히면 충분하다.

예:

`通過遺跡 → 到達出口`

완료된 조건은 조용히 상태만 바뀌게 한다.
설명 문단을 계속 붙이지 않는다.

### 상태 메시지

상태 영역을 항상 빈 상자로 유지하지 않는다.
실제로 전달할 정보가 생겼을 때만 나타난다.

예:

- `還沒通過遺跡。`
- `太接近野狼了。`

메시지가 사라지면 그 공간도 다시 판에 돌려준다.

## 7. 색의 의미를 고정한다

색은 장식보다 상태 전달에 먼저 쓴다.

v0.1 기준 역할은 다음과 같이 제안한다.

| 역할 | 기본 방향 | 사용 예 |
|---|---|---|
| 기본 세계 | 따뜻한 종이·흙·돌 계열 | 배경, 길, 일반 지형 |
| 행동 가능 | 녹색 계열 | 이동 가능, 실행 가능 |
| 위험·손실 | 벽돌색·적갈색 계열 | 위험 범위, 실패 가능 상태 |
| 목표·단어 반응 | 금색 계열 | 목표 위치, 단어 발동, 중요한 발견 |
| 정보·조사 | 청색 계열 | 살펴보기, 정보 확인 |
| 비활성 | 낮은 채도의 중성색 | 잠김, 완료 후 비활성 |

이 색을 장식 목적으로 다른 의미에 재사용하지 않는다.

색만으로 상태를 구분하지 않는다.
형태, 밝기, 아이콘, 문구 중 최소 하나를 함께 사용한다.

정확한 색상 값은 별도 시안에서 확정한다.

## 8. 카드와 테두리 사용 규칙

카드는 정보 덩어리를 분리해야 할 때만 쓴다.

### 카드를 써도 되는 경우

- 단어 상세 시트
- 설정
- 메뉴
- 스테이지 선택 정보
- 긴 설명이나 선택지가 실제로 독립된 덩어리일 때

### 기본적으로 카드로 만들지 않는 것

- 월드의 각 지역
- 전술판 자체
- 목표 한 줄
- 항상 떠 있는 상태 영역
- 단순 행동 버튼 주변의 장식 상자

테두리는 요소의 존재를 증명하기 위해 두르지 않는다.
여백, 면 차이, 위치만으로 구분할 수 있으면 선을 생략한다.

그림자는 떠 있는 계층에만 제한적으로 사용한다.

예:

- 바텀시트
- 모달
- 일시적으로 열린 정보층

상시 화면의 모든 요소에 그림자를 쓰지 않는다.

## 9. 월드맵 원칙

월드맵은 지역 선택 메뉴가 아니라 실제 여행 경로처럼 보여야 한다.

### 유지할 것

- `出發`에서 여러 지역으로 갈라지는 현재 3갈래 구조
- 자유 지역, 권장 지역, 잠금 지역의 상태 차이
- iPhone 세로 한 화면에서 전체 구조를 읽을 수 있는 크기

### 바꿀 방향

- 지역 카드를 줄이고 길과 지점을 먼저 보이게 한다.
- 지역 이름과 작은 장소 표식이 지도 위에 놓이게 한다.
- 상세 설명은 지역을 선택했을 때 별도 정보층에서 보여준다.
- `권장`은 강제 경로처럼 보이지 않게 한다.
- `잠김`은 이유를 이해할 수 있게 표시한다.

월드맵 첫인상은 `메뉴 목록`보다 `어디로 갈까?`에 가까워야 한다.

## 10. 타이포그래피 원칙

### 전술 정보와 조작

번체 중국어를 빠르게 읽는 것이 중요하므로 산세리프 계열을 기본으로 한다.

우선 스택:

`Noto Sans TC / PingFang TC / 시스템 CJK 산세리프`

사용 대상:

- 목표
- 단어
- 조작
- 상태
- 전술판 라벨
- 월드 지역 이름

### 이야기와 분위기

명조 계열은 제한적으로 사용한다.

사용 후보:

- 챕터 제목
- 짧은 이야기 장면
- 여행 기록 느낌의 문장

즉, 명조는 분위기이고 산세리프는 판단이다.
둘을 무분별하게 섞지 않는다.

### 숫자와 기호

턴, 수치, 좌표 등 고정 폭이 읽기에 유리한 정보가 실제로 생기면 모노스페이스 계열을 검토한다.
현재 단계에서는 불필요하게 사용하지 않는다.

## 11. 글자 크기와 역할 토큰

화면마다 임의의 px 값을 추가하지 않는다.
역할별 토큰을 먼저 정의하고 같은 역할에는 같은 값을 사용한다.

v0.1에서 최소한 다음 역할을 둔다.

- 페이지·월드 제목
- 스테이지 제목
- 현재 목표
- 핵심 단어
- 본문
- 보조 설명
- 상태 메시지
- 조작 버튼
- 작은 라벨

정확한 rem 값은 디자인 적용 1차 시안에서 현재 iPhone 13 mini 화면을 보며 확정한다.

단, 최소 터치 영역은 지금처럼 44px 이상을 유지한다.

## 12. 공간과 정렬

여백은 예쁘게 비워두기 위한 것이 아니라 관계를 보여주기 위해 쓴다.

- 같은 역할끼리는 같은 간격을 사용한다.
- 관련된 정보는 가까이 둔다.
- 서로 다른 기능 사이에는 한 단계 큰 간격을 둔다.
- 내용이 적다는 이유로 남은 세로 공간을 억지로 균등 분배하지 않는다.
- 판이 중요한 화면에서는 남는 공간을 판에 우선 배정한다.
- 안전 영역을 고려한다.

현재 목표 기기인 iPhone 13 mini Safari 세로 화면을 기준선으로 유지한다.

## 13. 조작 원칙

### 엄지 영역 우선

자주 쓰는 행동은 화면 하단에 둔다.

예:

- 기다리기
- 살펴보기
- 되돌리기

단, 전술판의 칸을 직접 누르는 것이 핵심 조작이므로 별도 방향키를 기본 조작으로 추가하지 않는다.

### 터치 피드백

누를 수 있는 요소는 반응해야 한다.
하지만 모든 요소를 버튼처럼 솟아 보이게 만들 필요는 없다.

- 짧은 밝기 변화
- 아주 작은 이동
- 상태 면 변화

정도로 충분하다.

### 되돌리기

이 게임에서 실수는 학습 과정이다.
되돌리기는 숨기거나 벌을 주지 않는다.

## 14. 모션 원칙

모션은 장식보다 의미 전달에 사용한다.

좋은 모션 예:

- `接近`: 두 대상 사이의 반응이 가까워질수록 커짐
- `遠離`: 위험 범위를 벗어나는 순간 안전 상태로 전환
- `通過`: 영역을 완전히 지나면 흔적이 남음
- `到達`: 목표 지점이 도착을 명확하게 반응
- `避開`: 위험 영역을 건드리지 않은 경로가 결과로 드러남

피할 것:

- 이유 없이 계속 움직이는 배경
- 모든 버튼의 큰 바운스
- 잦은 파티클
- 학습과 무관한 화려한 성공 연출

동작 줄이기 환경에서는 핵심 의미를 잃지 않는 정적 대안을 제공한다.

---

## 15. 아이콘과 일러스트 원칙

아이콘은 단어를 대신하지 않는다.

`接近`을 특정 아이콘 하나로 외우게 만들지 않는다.
단어가 먼저 있고 아이콘은 행동 범주를 보조한다.

오브젝트는 작은 화면에서 한눈에 구분되는 실루엣을 우선한다.

- 용사
- 늑대
- 유적
- 문
- 출구
- 위험물

초기에는 단순한 형태로 유지하고, 아트 스타일을 확정한 뒤 일괄 교체한다.

---

## 16. 학습 UI 원칙

이 게임은 정답률 관리 앱처럼 보이지 않게 한다.

기본 플레이 화면에 다음을 상시 노출하지 않는다.

- 점수
- 별 개수
- 연속 학습일
- 경험치
- 단어 숙련도 퍼센트
- 속도 기록

단어를 모르는 것은 실패가 아니다.
뜻을 확인하는 행동도 실패가 아니다.

플레이어가 느껴야 할 핵심 성취는

> 중국어 문제를 맞혔다.

보다

> **단어를 이해해서 이 판을 풀었다.**

에 가깝다.

---

## 17. 접근성·모바일 기준

- 모든 주요 터치 타깃은 최소 44×44px을 유지한다.
- `env(safe-area-inset-*)`를 고려한다.
- 색만으로 상태를 전달하지 않는다.
- 포커스 표시를 제거하지 않는다.
- 작은 글자를 장식적으로 남발하지 않는다.
- 동작 줄이기 설정을 존중한다.
- 화면 회전을 필수로 요구하지 않는다.
- 확대·축소나 맵 스크롤 없이 기본 판 전체가 보이는 것을 우선한다.

---

## 18. 목표 화면 크기

1차 검수 기준:

- iPhone 13 mini
- Safari
- 세로 화면

개발자 도구의 비슷한 뷰포트만 확인하고 완료로 처리하지 않는다.
실제 배포 화면을 실기기에서 확인한다.

검수할 것:

- 판 전체가 한눈에 보이는가
- 중국어가 너무 작지 않은가
- 엄지로 잘못 누르기 쉬운 요소가 없는가
- 목표와 판이 서로 공간을 빼앗지 않는가
- 바텀시트가 중요한 판 정보를 필요 이상으로 가리지 않는가
- safe area에서 메뉴가 잘리지 않는가

---

## 19. 새 기능을 디자인할 때 묻는 질문

새 UI를 추가하기 전에 다음 순서로 확인한다.

1. 이것은 세계인가, UI인가?
2. 지금 화면에 꼭 계속 보여야 하는가?
3. 이미 다른 요소가 같은 정보를 말하고 있지 않은가?
4. 카드나 테두리가 정말 필요한가?
5. 색이 기존 의미와 충돌하지 않는가?
6. 단어보다 UI가 더 눈에 띄지는 않는가?
7. 해법까지 알려주고 있지는 않은가?
8. 44px 터치 영역을 지키는가?
9. iPhone 13 mini 한 화면에서 판을 방해하지 않는가?
10. 이것을 빼도 플레이가 이해된다면 빼는 편이 낫지 않은가?

## 20. v0.6부터 적용할 우선순위

디자인을 한 번에 전면 교체하지 않는다.
기능 개발을 멈추지 않으면서 공통 규칙부터 적용한다.

### 1차

- 공통 색 역할 토큰 정리
- 글자 역할 토큰 정리
- 카드·테두리·그림자 사용 축소
- 목표 영역 단순화
- 상태 메시지 상시 상자 제거

### 2차

- 전술판을 연속 지형처럼 보이게 수정
- 이동·위험·조사 상태 오버레이 재설계
- 단어 전용 시각 언어 시안 제작

### 3차

- 월드맵을 카드 목록에서 지도·길 중심으로 재설계
- 지역 선택 상세 정보층 분리

### 4차

- 이야기 장면과 장 제목의 보조 타이포그래피 확정
- 아이콘·오브젝트 아트 스타일 정리

## 21. 현재 유지할 것

프로토타입에서 이미 잘 작동하는 다음 기반은 유지한다.

- 따뜻한 밝은 배경 계열
- 짙은 기본 글자색
- 현재의 녹색 중심 행동 강조 방향
- iPhone 13 mini 한 화면 우선
- 44px 이상 터치 영역
- safe area 대응
- 단어 상세 바텀시트
- 기다리기 / 살펴보기 / 되돌리기
- 실패 비용이 낮은 구조
- 뜻 확인에 페널티가 없는 구조

디자인 변경은 이 사용성을 희생하지 않는다.

---

## 22. 아직 확정하지 않는 것

v0.1에서는 다음을 일부러 열어둔다.

- 최종 색상 hex 값
- 최종 폰트 파일과 셀프호스팅 방식
- 단어 전용 컴포넌트의 정확한 모양
- 월드맵 최종 일러스트 스타일
- 캐릭터 최종 아트 스타일
- 지형 텍스처 수준
- 다크 모드
- 태블릿·데스크톱 확장 레이아웃

이 항목은 실제 시안과 실기기 비교 후 확정한다.

## 23. 핵심 문장

**UI는 조용하게, 판은 명확하게, 단어는 특별하게.**

플레이어가 화면을 보고 가장 먼저 느껴야 하는 것은

> “어느 버튼을 눌러야 하지?”

가 아니라

> **“이 판에서 무슨 일이 일어나고 있지?”**

다.

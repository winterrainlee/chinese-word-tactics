# 1. 확정 방향

장인골은 길목처럼 소년을 한 칸씩 움직이는 전술판이 아니다.

> **소년은 현장에 있지만, 플레이어의 핵심 조작 대상은 장치 자체다.**

플레이어는 물길, 불씨, 축, 연결부, 톱니 같은 장치를 직접 건드리고 그 결과가 다른 부분에 어떻게 전파되는지 본다.

기본 경험은 다음과 같다.

> 현재 상태를 본다 → 장치 하나를 조작한다 → 다른 부분의 변화를 본다 → 원인을 추론한다 → 목표 상태를 만든다.

이 구역의 핵심은 빠르게 많이 누르는 것이 아니다.

> **필요한 것만 바꾸고, 건드리지 않아야 할 것은 그대로 둔다.**

# 2. 공통 상태 문법

장인골 1차 구현은 아래 다섯 종류만 공통 엔진으로 지원한다.

## 2.1 3단계 상태값

수치가 필요한 장치는 우선 3단계만 쓴다.

```text
0 = 낮음
1 = 적정 / 중간
2 = 높음
```

예:

- 물의 양
- 불의 세기
- 바람의 세기

정확한 숫자를 읽는 게임으로 만들지 않는다.

화면에서는 실제 모습이 먼저 변한다.

- 물의 높이
- 불꽃의 크기
- 풀무의 움직임

3단계 보조표시는 상태를 다시 확인하는 보조 정보다.

## 2.2 이진 상태

다음 상태는 참/거짓으로 둔다.

- 연결 / 분리
- 작동 / 정지
- 정상 / 손상
- 열림 / 잠김

## 2.3 직접 상태와 파생 상태

플레이어가 직접 조작하는 상태와 결과로 생기는 상태를 구분한다.

직접 상태 예:

- 수문 높이
- 풀무 세기
- 축 연결 여부
- 부품 수리 여부

파생 상태 예:

- 물레방아가 도는가
- 작업대가 열리는가
- 푸른 불꽃이 나타나는가
- 검은 연기가 사라지는가
- 장치 기능이 회복되는가

`出現 / 消失 / 恢復 / 符合`은 기본적으로 파생 상태다.

이 단어용 버튼을 만들지 않는다.

## 2.4 조작 이력

`保持`를 가르칠 때는 최종값만 보지 않는다.

W1에서는 지정된 장치를 한 번도 바꾸지 않았는지를 기록한다.

예:

```text
values.balanceGate = 1
untouched.balanceGate = true
```

플레이어가 잘못 건드리면 즉시 실패 처리하지 않는다.

- 무엇이 달라졌는지 알려준다.
- `되돌리기`로 직전 행동 전 상태를 복원할 수 있다.
- 필요하면 스테이지를 다시 시작할 수 있다.

W7에서는 같은 의미를 재사용하되, 불필요하게 여러 개의 엄격한 `untouched` 조건을 만들지 않는다.

## 2.5 공통 행동 종류

장인골 공통 런타임에서 우선 지원할 행동은 다음 네 가지다.

```text
step-up      3단계 값을 한 단계 높임
step-down    3단계 값을 한 단계 낮춤
toggle       연결/분리 같은 이진값 전환
repair       손상 상태를 정상 상태로 바꿈
```

필요하면 `inspect`는 정보 확인용으로만 둔다.

새 단어마다 새로운 행동 종류를 만들지 않는다.

# 3. 화면 구조

장인골도 기존 스테이지 화면의 상단 제목, 목표, 상태 메시지, 단어 버튼, 되돌리기를 재사용한다.

다만 중앙의 격자 지도는 **장치판**으로 바뀐다.

## 3.1 장치판

`#grid` 영역을 장인골 스테이지에서는 `workshop-board` 렌더러가 사용한다.

격자 칸을 여러 버튼처럼 보이게 만들지 않는다.

- 하나의 수로와 장치가 이어진 그림처럼 보인다.
- 장치 사이의 축, 벨트, 물길은 실제 연결 관계를 보여준다.
- 직접 조작 가능한 부분만 44px 이상의 명확한 터치 영역을 갖는다.
- 상태 변화는 장치 그림 자체가 먼저 보여준다.

## 3.2 이동용 하단 조작 제거

장인골에서는 다음 버튼을 숨긴다.

- 1턴 기다리기
- 이동/살펴보기 모드 전환

`되돌리기`는 유지한다.

정보 확인이 필요한 경우 장치 자체를 탭하거나 별도 작은 정보 표식을 사용한다.

## 3.3 상태 표현

숫자 게이지를 기본값으로 쓰지 않는다.

예:

- 물: 수로의 실제 물 높이
- 불: 불꽃 크기
- 바람: 풀무의 벌어짐과 움직임
- 연결: 벨트/축 선이 이어짐
- 분리: 연결부 사이가 떨어짐
- 손상: 깨진 톱니 형태
- 회복: 멈췄던 장치가 다시 움직임

텍스트는 보조한다.

`적음 / 알맞음 / 많음` 같은 한국어 설명을 판 중앙에 크게 늘어놓지 않는다.

# 4. 공통 런타임 데이터 방향

새 파일 후보:

```text
src/workshop-content.js
src/workshop-runtime.js
src/workshop-runtime.css
```

`workshop-content.js`는 `WORDS`와 `STAGES`에 장인골 데이터를 추가한다.

각 장인골 스테이지는 다음처럼 `workshop` 설정을 가진다.

```js
{
  id: 'workshop-stage-1',
  words: ['改變', '保持'],
  workshop: {
    components: [...],
    predicates: [...],
    derived: [...]
  }
}
```

공통 런타임은 모든 규칙을 JSON으로 옮기는 범용 엔진이 아니다.

아래 정도만 공통으로 처리한다.

- 3단계 값 변경
- 연결 토글
- 수리
- 조작 이력
- 스테이지별 predicate 확인
- 파생 상태 다시 계산
- 상태 메시지
- 완료 판정
- 되돌리기

두 번째 실제 사용처가 생기기 전에는 더 큰 추상화를 만들지 않는다.

# 5. W1 멈춘 물레방아

## 학습어

- `改變`
- `保持`

## 핵심 경험

> 하나는 바꾸고 하나는 그대로 둔다.

## 장치

수로에 나란히 두 조절부가 있다.

- `mainGate`: 주 수문
- `balanceGate`: 균형 수문
- 파생 결과: `wheelRunning`

## 초기 상태

```text
mainGate = 0
balanceGate = 1
balanceGate untouched = true
wheelRunning = false
```

## 목표 상태

```text
mainGate = 1
balanceGate = 1
balanceGate untouched = true
```

이때 물레방아가 정상 속도로 돈다.

## 목표 문구

```text
改變左邊的水門，右邊保持原樣。
```

주변의 쉬운 말:

```text
左邊太低了。
右邊不用動。
```

## 가능한 행동

- `mainGate` 한 단계 올리기/내리기
- `balanceGate` 한 단계 올리기/내리기

## 피드백

주 수문을 알맞게 바꾸면:

```text
水量改變了。
물이 달라졌어.
```

균형 수문을 건드리면:

```text
這邊不用改變，要保持原樣。
이쪽은 바꾸지 않고 그대로 두어야 해.
```

이 상태에서는 완료되지 않는다.

되돌리기로 조작 전 상태를 복구할 수 있다.

## 완료

`mainGate == 1 && balanceGate == 1 && balanceGate untouched`

완료 메시지:

```text
一個改變了，一個保持原樣。水車開始轉了。
하나는 바꾸고, 하나는 그대로 뒀어. 물레방아가 돌기 시작했어.
```

## 구현 목적

장인골의 첫 공통 규칙을 검증한다.

- 장치판 렌더링
- 3단계 상태
- 직접 조작
- 조작 이력
- 파생 상태
- 되돌리기

W1이 실기기에서 편하면 이후 판의 UI 골격을 그대로 유지한다.

# 6. W2 불씨 맞추기

## 학습어

- `增加`
- `減少`
- `調整`

## 핵심 경험

> 크게 만드는 것이 목표가 아니라 알맞은 상태로 맞춘다.

## 장치

- `fire`: 불의 세기
- `air`: 바람의 세기
- 파생 결과: `balanced`

## 초기 상태

```text
fire = 2
air = 0
```

불은 너무 세고 바람은 너무 약하다.

## 목표 상태

```text
fire = 1
air = 1
```

## 목표 문구

```text
調整火力和風量。
```

보조 문구:

```text
火太大了。
風太小了。
```

## 가능한 행동

각 장치에서 한 단계 높이거나 낮춘다.

## 피드백

불을 줄이면:

```text
火力減少了。
```

바람을 늘리면:

```text
風量增加了。
```

둘 다 목표 상태가 되면:

```text
調整好了。現在剛剛好。
조절이 끝났어. 이제 딱 맞아.
```

## 완료

`fire == 1 && air == 1`

## 중요한 구분

`增加 / 減少`는 플레이어가 직접 만든 변화다.

`調整`은 그 변화들을 이용해 목표 상태를 만든 전체 결과다.

따라서 `調整` 전용 버튼은 만들지 않는다.

# 7. W3 함께 도는 도르래

## 학습어

- `連接`
- `分開`

## 핵심 경험

> 연결 상태가 다른 장치의 움직임을 바꾼다.

## 장치

항상 회전하는 주축 하나와 두 개의 작업축을 둔다.

- `workPulleyConnected`
- `idlePulleyConnected`
- 파생 결과: 각 도르래의 회전 여부

## 초기 상태

```text
workPulleyConnected = false
idlePulleyConnected = true
```

필요한 작업 도르래는 멈춰 있고, 쓸모없는 빈 도르래만 같이 돌고 있다.

## 목표 상태

```text
workPulleyConnected = true
idlePulleyConnected = false
```

## 목표 문구

```text
連接工作輪，分開空輪。
```

보조 문구:

```text
這個要一起轉。
那個不用轉。
```

## 가능한 행동

두 연결부를 각각 탭해 연결/분리를 전환한다.

## 시각 변화

- 연결되면 벨트가 이어진다.
- 연결된 도르래는 즉시 같이 돈다.
- 분리되면 벨트가 떨어지고 해당 도르래가 멈춘다.

## 완료

필요한 도르래만 주축과 함께 돈다.

완료 메시지:

```text
需要的輪子連接了，空輪分開了。
필요한 바퀴는 연결되고, 빈 바퀴는 분리됐어.
```

# 8. W4 잠긴 작업대

## 학습어

- `條件`
- `符合`

## 핵심 경험

> 행동 하나가 아니라 여러 상태가 함께 맞아야 한다.

## 장치

작업대 옆에 세 조건을 보여준다.

1. 물의 양이 적정
2. 작업축이 연결
3. 화덕이 꺼짐

직접 조작 대상:

- `water`
- `shaftConnected`
- `furnaceOn`

## 초기 상태

```text
water = 2
shaftConnected = false
furnaceOn = false
```

세 조건 중 하나는 이미 맞아 있다.

## 목표 상태

```text
water = 1
shaftConnected = true
furnaceOn = false
```

## 목표 문구

```text
讓三個條件都符合。
```

보조 문구:

```text
有三個條件。
都符合，工作臺才會打開。
```

## 조건 UI

세 조건을 긴 문장 카드로 만들지 않는다.

작업대 옆 작은 표식 세 개가 현재 상태에 따라 달라진다.

- 맞음: 체크 또는 정돈된 표식
- 안 맞음: 비어 있거나 어긋난 표식

색만으로 구분하지 않는다.

## 파생 상태

세 predicate가 모두 참이면 `benchUnlocked = true`가 된다.

`符合` 버튼은 없다.

## 완료

작업대가 열리고 잠금쇠가 실제로 움직인다.

완료 메시지:

```text
三個條件都符合了。工作臺打開了。
세 조건이 모두 맞았어. 작업대가 열렸어.
```

# 9. W5 푸른 불꽃

## 학습어

- `出現`
- `消失`

재사용:

- `保持`
- `增加`
- `調整`

## 핵심 경험

> 결과를 직접 만드는 버튼이 아니라, 조건을 맞추면 현상이 나타나거나 사라진다.

## 장치

- `fire`: 불의 세기
- `air`: 바람의 세기
- 파생 결과: `blueFlame`, `blackSmoke`

## 초기 상태

```text
fire = 1
air = 0
blueFlame = false
blackSmoke = true
```

불의 세기는 이미 맞다.

## 목표 관계

```text
fire == 1 을 유지
air == 2 로 증가
```

조건이 맞으면 자동으로:

```text
blueFlame = true
blackSmoke = false
```

## 목표 문구

```text
保持火力，調整風量。
```

보조 문구:

```text
火力剛剛好，不要動。
風太小了。
```

## 시각 변화

성공 순간 두 현상이 동시에 보인다.

- 푸른 불꽃이 `出現`
- 검은 연기가 `消失`

따라서 `消失`을 보기 위해 일부러 성공 상태를 망가뜨릴 필요가 없다.

## 완료 메시지

```text
藍色的火焰出現了，黑煙消失了。
푸른 불꽃이 나타나고 검은 연기는 사라졌어.
```

# 10. W6 깨진 톱니

## 학습어

- `損壞`
- `修復`
- `恢復`

보조 표현:

- `壞了`
- `修好了`
- `又能用了`

## 핵심 경험

> 손상된 대상, 수리 행위, 되돌아온 기능을 서로 구분한다.

## 장치

세 개의 톱니가 이어진 작은 기계를 보여준다.

- 정상 톱니 2개
- 눈에 보이게 깨진 톱니 1개
- 파생 결과: 기계 기능 `machineRunning`

## 초기 상태

```text
gearA = normal
gearB = damaged
gearC = normal
machineRunning = false
```

## 목표 문구

```text
找出損壞的齒輪，把它修好。
```

## 플레이

정상 톱니를 눌렀을 때:

```text
這個沒有損壞。
이 톱니는 망가지지 않았어.
```

깨진 톱니를 누르면 손상 상태를 확인할 수 있고, 상황형 `수리하기` 행동이 열린다.

수리 행동 후:

```text
齒輪修復了。
톱니를 수리했어.
```

그 결과 기계가 자동으로 다시 돌기 시작한다.

```text
機器的功能恢復了。現在又能用了。
기능이 회복됐어. 이제 다시 쓸 수 있어.
```

## 완료 관계

```text
gearB repaired -> machineRunning true
```

`恢復`는 플레이어가 직접 누르는 행동이 아니다.

`修復`의 결과로 기능이 되돌아오는 상태다.

# 11. W7 오래된 조절기

## 새 학습어

없음.

종합판이다.

화면의 핵심 재사용 단어는 너무 많이 늘어놓지 않는다.

우선 다음 다섯 개를 대표로 노출한다.

- `保持`
- `調整`
- `連接`
- `分開`
- `修復`

`條件 / 符合 / 出現 / 消失 / 恢復`는 상태 메시지와 결과에서 다시 만난다.

## 핵심 경험

> 여러 장치를 서로 다른 방식으로 다뤄 최종 안정 상태를 만든다.

정답 조작 순서는 하나로 고정하지 않는다.

## 장치

1. `mainGate`: 주 수문
2. `balanceGate`: 균형 수문
3. `mainCoupling`: 필요한 축 연결부
4. `idleCoupling`: 불필요한 축 연결부
5. `regulatorGear`: 손상된 조절 톱니

파생 결과:

- `allConditionsMatch`
- `regulatorStable`
- `indicatorAppears`
- `noiseDisappears`
- `systemRecovered`

## 초기 상태

```text
mainGate = 0
balanceGate = 1, untouched
mainCoupling = disconnected
idleCoupling = connected
regulatorGear = damaged
```

## 목표 상태

```text
mainGate = 1
balanceGate = 1, untouched
mainCoupling = connected
idleCoupling = disconnected
regulatorGear = repaired
```

## 목표 문구

```text
調整舊裝置，讓它恢復正常。
```

장인의 시작 대사:

```text
先別急著修。看看動了這個，哪裡會跟著變。
서둘러 고치지 마. 이걸 움직였을 때 어디가 같이 변하는지 먼저 봐.
```

## 해결 순서

다음 행동은 서로 독립적으로 먼저 수행할 수 있다.

- 주 수문 조정
- 필요한 축 연결
- 불필요한 축 분리
- 손상 톱니 수리

균형 수문은 그대로 둔다.

따라서 여러 행동 순서가 같은 최종 상태에 도달한다.

## 성공 연출

모든 조건이 맞는 순간:

1. 조절기 진동이 잦아든다.
2. 일정하지 않던 물 흐름이 안정된다.
3. 오래된 표시가 `出現`한다.
4. 덜컹거리던 소리가 `消失`한다.
5. 전체 기능이 `恢復`된다.

완료 메시지:

```text
條件都符合了。舊裝置恢復正常。
조건이 모두 맞았어. 오래된 장치가 정상으로 돌아왔어.
```

# 18. 실기기 확인 포인트

장인골은 기존 길목보다 직접 터치 대상이 작아질 위험이 있다.

따라서 iPhone 13 mini Safari에서 특히 다음을 본다.

- 조절 손잡이와 연결부의 실제 터치 영역이 최소 44px인가
- 두 장치가 가까워도 잘못 누르지 않는가
- 불/물/연결 상태가 글을 읽지 않아도 구분되는가
- W7의 5개 조작 대상이 한 화면에서 관계를 잃지 않는가
- 상태 메시지가 장치판을 밀어내거나 화면을 흔들지 않는가
- 단어 버튼이 너무 많아져 판보다 더 강하게 보이지 않는가

W7은 모든 학습어를 버튼으로 늘어놓지 않는다.

대표 재사용 단어만 노출하고, 나머지는 판과 상태 메시지 속에서 다시 만나게 한다.

# 19. 완료 정의

장인골 1차 묶음은 다음이 모두 성립하면 완료다.

1. W1~W7을 처음부터 끝까지 이어서 플레이할 수 있다.
2. 모든 새 목표어가 판의 실제 상태나 변화와 연결된다.
3. `調整 / 符合 / 出現 / 消失 / 恢復`가 단어 전용 버튼 없이 이해된다.
4. 잘못된 조작은 낮은 비용으로 정보를 남기며 되돌릴 수 있다.
5. W7은 하나의 고정 조작 순서만 요구하지 않는다.
6. W7 완료 뒤 `workshop-core`가 저장된다.
7. 수선패와 첫 품삯의 이야기 근거가 생긴다.
8. 학술탑을 나중에 찾아갈 자연스러운 이유가 생긴다.
9. iPhone 13 mini Safari 세로 화면에서 읽고 조작할 수 있다.

한 줄로 요약하면 다음과 같다.

> **장인골에서는 단어를 눌러 효과를 쓰는 것이 아니라, 장치의 상태를 읽고 직접 바꾼 결과로 단어의 뜻을 경험한다.**

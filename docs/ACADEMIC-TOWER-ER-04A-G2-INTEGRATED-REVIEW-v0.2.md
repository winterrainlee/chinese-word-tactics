## 0. 채택 조건과 핵심 결론

04A는 기존 academic-tower 지역의 **전역 스테이지 하나**다. 연구실의 기록 종합(synthesis) 옆방이며 본선 04를 끝내면 선택적으로 들어갈 수 있다. 본선 05, 03A, 03B는 선행 필수가 아니다. 별도 월드 지역/수문 시뮬레이션/유속 엔진을 만들지 않는다.

- 전역 stageId: academic-tower-turn-04a-er-family; 고정 참조 04A. 제목 한국어 《비가 그친 물길》, 중국어 가제 《雨後的水道》.
- 도입/결말 storyId: academic-tower-er-intro / academic-tower-er-result.
- 중간 이야기 안정 ID: academic-tower-er-scene-retrace (I1), academic-tower-er-scene-record (I2).
- 내부 작업 안정 ID(순서): er-rain-01-upstream (T1) → er-rain-02-contrast (T2) → er-rain-03-side-flow (T3) → er-rain-04-scope (T4) → er-rain-05-next (T5).
- 실제 동선: S0 탑 밖 만남 → T1 상류 A → T2 B/C → I1 점검길과 물소리 → T3 숨겨진 D 발견·흐름 판단 → I2 도면 펼치기 → T4 인공 흔적과 판단 범위 → T5 조사 기록·다음 질문 → S1 작은 결말.
- 04A 전역 완료는 **T5에서 한 장의 조사 기록을 확정했을 때**만. 그 뒤 결과 이야기 S1의 열람은 별도 상태이며 중간 종료 시 이어 읽는다. 04A는 본선 다섯 판 집계·05 해금·세계 주요 이야기·여관 관찰 카드를 바꾸지 않는다.
- 첫 완료에는 두 후속 질문 중 **처음 고른 질문 ID 하나만** 영구 보존한다. 실제 도면/하류 출구/제작자/적법성의 답을 이번 04A에서 주지 않는다.

**현장 사실의 엄격한 범위:** A의 높은 물 자국과 풀잎은 지난 큰비의 흔적이며 현재 수위와 시점이 다르다. B는 현재 유입과 조절 기록을 확인한다. C는 소년의 예상보다 약하지, 평소보다 낮다는 비교 측정은 아니다. D에서 인공적인 네모 통로와 현재 수로 밖 유출을 확인하지만, 그 구멍이 C의 차이 전부를 낳았거나 누군가 불법 취수했다는 결론은 아니다. 기존 원래 설계도에 D가 없다는 것은 후대 변경 기록이 존재하지 않는다는 증거가 아니다.

## 1. 다섯 작업의 최종 UX 후보·판정

| 작업 | 화면에서 처음 주는 근거 | 유일하게 필요한 의미 판단 | 확인 뒤 변화 | 피해야 할 중복 조작 |
|---|---|---|---|---|
| T1 而且 | A의 물 자국은 이미 소년의 메모에 적힘 | 같은 지난 큰물의 **별도 관측 흔적**을 추가 | 고수위 자국 + 석틈 풀잎의 합쳐진 관찰 | 물 자국을 다시 탭해 확인 |
| T2 然而 | B 수문 기록·현재 유입, C의 실제 흐름, 소년의 예상 | 둘 다 인정하며 **다음 점검 범위** 선정 | B~C 구간 추가 확인 메모 | 관계 확인 뒤 같은 오답 메모를 또 고치기 |
| T3 反而 | I1의 다른 물소리, 소년의 유입 가설 | **찾을 구간**과 **확인된 유출 방향**을 직접 조사, 예상과 비교 | 발견 D, 유입 가설 ↔ 유출 관측 | 소년에게 먼저 틀린 가설을 정답처럼 선택시키기 |
| T4 不是…而是… / 而已 | T3의 입구·유출, 도구 흔적, 원래 설계도 | 자연 균열 추측을 인공 통로로 정정하고 **원래 도면의 증명 범위** 제한 | 원본 유지 + 인공 흔적·도면 미표시·미확인 분리 | 연구원이 절도라고 확신한 뒤 플레이어가 고치는 연출 |
| T5 從而 / 因而 / 進而 | 이전의 A/B/C/D 출처별 관찰 | 확인한 결과, 필요한 통보, 추가 조사의 질문을 **다른 시제·책임으로** 기록 | 한 장의 공동 조사 기록 + 최초 inquiry ID | 세 단어를 각자 고유 정답인 세 빈칸에 소모 |

### T1 — A / er-rain-01-upstream

- 화면: 원본/관측 면에는 물 자국과 현재 낮아진 수위. 소년의 상류 메모에는 **이미** 「石壁上留著這次大雨的高水位痕跡。」라고 적혀 있다.
- 선택 후보 ID: a-grass-high(높은 틈에 걸린 풀잎; 추가 증거), a-current-level(지금 낮아진 수위; 다른 시점의 참된 관찰), a-gate-failure-theory(수문 고장; 가설).
- trigger: 증거 후보 탭 → 미리보기, confirm → a-grass-high이면 관측 두 가지를 함께 보존하고 T1 완료. 현재 낮아진 수위를 골라도 그 사실 자체를 거짓이라고 하지 않고 **지난 높은 수위의 두 번째 흔적**이 아니라는 점을 피드백한다.
- 완료 표현: 「石壁上留著這次大雨的高水位痕跡，而且高處的石縫裡還卡著草葉。」.
- 기록 작성자: **소년의 상류 관찰 메모**. 짧은 확인 문구만 남기며 반복 성공 카드 없음.

### T2 — B/C / er-rain-02-contrast

- 화면: B 담당자 기록 「管理人員在雨後調整過進水口，現在仍有水流進工坊水道。」와 소년의 C 관찰 「到了工坊附近，水流沒有我原先想的那麼急。」를 각 출처로 보여 준다.
- 질문: "두 기록을 함께 남기면 어디를 더 확인해야 할까?"
- 선택 후보 ID: check-between-b-c(두 사실을 유지하고 사이를 추가 확인; 통과), deny-b-intake(C가 약하므로 B의 유입도 없었다; B와 모순), conclude-gate-broken(수문 고장 확정; 아직 모름).
- confirm 뒤 연구원과 함께 검토한 메모: 「進水口還有水流入工坊水道。然而，到了工坊附近，水流沒有少年預想的那麼急。」. 수문 관리 기록과 C 차이를 인정한 채 안전한 점검길을 되짚는다.
- **한 번의 점검 판단**만 채점한다. 연구원을 근거 없는 수문 고장 보고의 작성자로 만들지 않는다.

### T3 — B~C / er-rain-03-side-flow

I1: 소년은 다른 방향에서 들리는 물소리를 알아차리고 「會不會是草叢裡的雨水流進水道？」라고 **확인 전 가설**을 말한다. I1은 입구 위치·형태·유출·도면 미표시를 누설하지 않는다.

- T3 검색 상태(search): 소리 방향을 참고해 안전한 관측 구역을 탭한다. 세 구역은 top-stone(상류 돌벽), low-bank(낮은 둑/수풀 쪽), near-wheel(수차 쪽). **low-bank**에서 openingFound=true로 바뀐다. 다른 두 지점도 살펴볼 수 있으나 벌점·모든 구역 클릭 의무는 없다.
- T3 방향 관찰(direction): 네모난 틈과 수면에서 틈 쪽으로 움직이는 잎을 **방향 판단에 필요한 원자료**로 보여 준다. 선택 ID는 flow-out(수로→틈→수풀 아래, 통과), flow-in(수풀→틈→수로, 실제와 다름). 선택 순간엔 정답 표시 없이 임시 화살표만 보여 준다.
- confirm에서만 예상(점선)과 실제(실선)를 비교하고 「原以為水會從草叢流進水道，沒想到水反而從水道往草叢下方流去。」라는 메모를 완성한다. 잎이 **어디로 움직이는지**는 접근 가능한 관측 단서지만, 反而의 학습 대상은 **그 관측이 소년의 예상과 다른 결과**라는 의미 판단이다.
- 구멍 찾기만 성공했으면 “물의 실제 방향은 아직 모름”으로 재개한다. flow-in 오답 뒤에는 찾은 구멍이 사라지지 않고 단서만 다시 확인한다. 유출을 확정했어도 누가 만들었는지·인공인지·최종 출구는 T3에서 판정하지 않는다.

### T4 — D와 원래 도면 / er-rain-04-scope

I2: 연구원은 설계도를 꺼내며 대조하자고만 한다. T4의 결론을 미리 말하지 않는다.

- 정정 판단(interpret): **소년의 질문** 「是大雨把石壁沖壞了嗎？」를 관찰로 검토한다. 다듬은 돌면·반복된 도구 자국을 근거로 artificial-passage를 고른다. 자연 균열 natural-crack은 근거와 맞지 않음을 알려 준다. 결과: 「這不是大雨沖出的裂縫，而是有人鑿出的通道。」.
- 범위 판단(scope): **원래 도면에서 말할 수 있는 것**을 선택한다. scope-original-only = 원래 도면에 D 표시가 없고 이후 공사·변경·허가 자료는 이번에 확인하지 않음(통과). scope-all-records-missing = 다른 기록도 존재하지 않음(불가). scope-theft-certain = 불법 취수·제작자 확정(불가).
- 而已는 **원래 도면이라는 출처가 증명할 수 있는 범위**를 한정하지, T3에서 확인한 유출이나 T4에서 확인한 인공 흔적을 삭제하지 않는다. 문장 후보: 「這張原圖只能告訴我們：圖上沒有標這個通道而已。至於後來有沒有施工紀錄，還得再查。」
- 통과하면 출처가 붙은 **연구원의 도면 대조 메모**에 ‘확인: 인공 흔적·현재 유출·원래 도면 미표시 / 미확인: 제작자·용도·허가·유량 기여·출구’를 남긴다. 원래 도면 자체를 고치지 않는다.

### T5 — 다음 질문 / er-rain-05-next

작업 영역은 **소년과 연구원의 현장 조사 기록** 한 장. 이미 확인된 A/B/C/D 근거를 원본/관측 면에 짧게 접어 볼 수 있다. 세 행의 조작 성격을 다르게 한다.

1. method-result: **실제로 수행한 현장 관찰+원래 도면 대조**를 ‘원래 도면에 없는 통로를 현장에서 확인했다’에 연결한다. 확인된 성과만 다룬다. 결과 문장에는 從而를 쓴다.
2. action: 확인된 인공 통로의 유출을 **시설 관리자에게 알리고 변경·관리 기록 확인을 요청**한다. 구멍을 막거나 위험한 수색을 하려는 선택은 통과하지 않는다. 근거에서 필요한 조치로 이어지는 因而를 확인한다.
3. next inquiry: 이미 확인한 D 위치·현재 유출 방향을 출발점으로 inquiry-records(후대 보수·변경 기록을 먼저 확인할 계획) / inquiry-outlet(관리자 안전 확인 후 하류 출구를 관찰할 계획) 중 하나를 선택한다. 둘 다 유효. **進而의 의미는 다음 단계로 발전하는 일**이지 그 결과까지 확보했다는 뜻이 아니다.

세 행은 선택 미리보기만 저장하고 **‘현장 기록 마무리’ 최종 버튼 한 번**으로 확정한다. method-result 또는 action을 정정해도 다른 올바른 행은 지워지지 않는다. 질문 선택은 이후 선택형 탐험을 자동 개방하지 않는다.

## 2. T3 모바일 화면 명세 — 375×640 기준

이 개념도는 **안전한 B~C 구간을 내려다보는 평면 그림**으로, 실제 월드맵의 동서남북이나 좌표가 아니다. 도식 화면상 위쪽은 B, 아래쪽은 C. **하류를 바라볼 때 왼쪽**에 수풀이 놓인다. 캐릭터 이동은 하지 않으며 관찰 가능한 구역만 큰 버튼이다.

### 화면 A: hidden / 처음 들어올 때

    ┌────────── 학술탑 · 04A ──────────┐
    │ 물소리의 방향                    │
    ├──────── 현장 관찰 · B~C ─────────┤
    │      상류 B 방향                 │
    │ [수풀·둑] │ 공방 수로 ↓ │ 점검길 │
    │           │             │        │
    │  (소리)   │   물결      │        │
    │           │             │        │
    │      하류 C 방향                 │
    │ "저쪽에서도 물소리가 나요."      │
    │  [상류 돌벽] [낮은 둑] [수차 쪽]│
    ├────── 소년의 현장 관찰 ──────────┤
    │ 아직 발견한 통로 없음            │
    └──────────────────────────────────┘

실제 앱에서는 고정 폭 ASCII가 아닌 **단순 SVG/HTML 구역 배치**를 사용하되 위 정보 위계를 지킨다. T3 전체 화면에 따로 큰 카드 장식을 추가하지 않는다. **D, hole, hidden, exit, leak** 같은 진상/정답 마커를 발견 전에 시각·접근성 이름·DOM 문구로 노출하지 않는다. 관찰 버튼 이름은 위치를 설명할 뿐 정답 여부를 알려 주지 않는다.

### 화면 B: opening-found / 틈을 찾았을 때

- 같은 도식에서 낮은 둑과 맞닿은 **수로 측벽의 작은 네모 구멍**이 나타난다. 이때 “누군가 팠다”나 “물이 밖으로 나간다”는 **결론 문구·정답 화살표**가 없다.
- 원래 자료가 되는 **수면 잎의 연속된 위치**, 잔물결, 틈 주변 물의 움직임을 보여 준다. 움직임은 미리 계산된 정답 화살표가 아니라 플레이어가 읽을 현장 단서다.
- 그림을 못 봐도 알 수 있게 관측 문장 「水面上的葉子從水道中央，慢慢靠近石壁上的孔口。」를 접거나 읽을 수 있다. 이 단서는 실제 이동의 관찰이지 “따라서 反而를 고르라”는 해설이 아니다.
- 작업 면 제목 ‘소년의 물길 관찰’. 두 선택은 **수로 안 → 틈 → 수풀 아래** / **수풀 아래 → 틈 → 수로 안**. 선택 시에만 예상 방향과 다른 임시 화살표가 나타난다.
- 미선택 때에는 완료 버튼 비활성. 선택 뒤 **물의 방향 기록**을 눌러 실제 관측과 비교한다.
- 오답은 해당 관찰 지점을 다시 가리키고 **openingFound=true는 보존**한다.

### 실제 작은 화면의 공간 예산

현행 academicTowerMvp 화면은 일반 goal/words/status를 숨기고, **상단 전술 헤더 + 내부 스크롤되는 작업대 + 하단 되돌리기/확인**으로 세로를 나눈다. 375×640에서 CSS safe-area는 기기/브라우저에 따라 달라서 정확한 가용 높이를 사전 고정값으로 단정하지 않는다. 다음은 구현 전 목표 범위다.

| 구획 | 375×640 목표 | 제약 |
|---|---|---|
| 공통 헤더 | 약 60~80px | 제목·메뉴, 중복 목표 문단 없음 |
| 현장 도식 | 높이 약 150~190px, 가로 가용 폭 내 | 상류/하류/수풀/점검길, 작은 구멍은 **탭 대상 아님** |
| 한 줄 관측 단서 | 1~3행 | 실제 물 움직임은 미리 감추지 않되 해석은 플레이어 몫 |
| 탐색 구역 버튼 | 44px 이상, 3개 | 3열이 비좁으면 세로 1열 또는 2+1. 타깃 간격 8px 권장 |
| 방향 선택 | 각 최소 48px, 글자 두 줄 허용 | 선택 라벨과 화살표를 함께 표시, 색으로만 뜻을 구분하지 않음 |
| 하단 공통 확인 | 48px 이상 + safe area | 문장/선택지를 가리지 않고 작업대 자체 스크롤 허용 |

**전체 내용이 640px 안에 모두 들어와야 한다는 요구는 하지 않는다.** 최초 진입에서 현장 도식·조사 대상이 발견 가능해야 하며, flow 방향 선택 단계에서는 스크롤을 복원하거나 작업 면으로 자연스럽게 포커스를 옮긴다. 360×640, 375×640, 375×667, 375×812에서 첫 화면·발견 직후·긴 중국어·오답·재진입을 확인한다.

### 접근성·정답 누설·포커스

- 발견 전 구멍·유출 방향 정보는 실제 SVG 텍스트·alt·aria-label에도 존재하지 않게 한다. DOM에 렌더링해 숨기는 방식으로 “정답을 읽어 주는 스크린리더”를 만들지 않는다.
- 발견 후 구멍 위치와 움직이는 잎에 대한 동등한 텍스트 설명을 제공한다. **관측 자체를 장애에 따른 벌점으로 만들지 않는다.**
- 검색 구역 클릭 후 포커스는 새로 생긴 관측 제목/추가 대상에, 방향 선택 확인 후에는 결과 메모에 둔다. 오답 후에는 선택한 방향에 포커스를 복원한다.
- 수로 본류 화살표 **↓**는 첫 화면부터 보여도 되지만, 샛길 **← / →** 유출 화살표는 확인 전 정답 표시로 쓰지 않는다. 추정 미리보기는 점선 + ‘선택 중’ 표기, 확인 사실은 실선 + ‘관측한 실제’ 표기로 분리한다.
- 오디오·자동 애니메이션·정밀 탭·손가락 드래그·시각만의 색 판별은 정답 조건으로 쓰지 않는다. 동작 줄이기 설정을 해도 정적 잎 위치/텍스트만으로 같은 결론을 얻을 수 있어야 한다.

## 3. 번체 원문·풀이의 1차 윤문 후보

아래는 **대만 번체 문맥의 1차 편집 후보**다. 사전 뜻·주음은 확인했으나, 전체 창작 중국어 문장의 최종 원어민 교정/음성 대응을 검증했다고 선언하지 않는다. 처음 원문에 이미 정답 표현이 포함된 **읽기/관측 과제**는 괜찮지만, 답안을 만들어야 할 단계에서는 완성 결과 문장을 확인 **뒤**에만 보여 준다.

| 표현·주음 | 단계의 핵심 문장 후보 | 이 문장에서 판정할 의미 |
|---|---|---|
| 而且 · ㄦˊ ㄑㄧㄝˇ | 石壁上留著這次大雨的高水位痕跡，而且高處的石縫裡還卡著草葉。 | 큰물에 관한 **또 하나의 관측 근거**를 추가. 그리고 단순 나열뿐 아니라 점층도 가능한 단어 |
| 然而 · ㄖㄢˊ ㄦˊ | 進水口還有水流入工坊水道。然而，到了工坊附近，水流沒有少年預想的那麼急。 | B는 사실이지만 C는 소년의 예상과 다름. B가 거짓이라는 뜻은 아님 |
| 反而 · ㄈㄢˇ ㄦˊ | 原以為水會從草叢流進水道，沒想到水反而從水道往草叢下方流去。 | 예상했던 **유입** 대신 실제 **유출**. 反而가 언제나 공간 방향을 뜻하는 것은 아님 |
| 而是 · ㄦˊ ㄕˋ | 這不是大雨沖出的裂縫，而是有人鑿出的通道。 | 근거 있는 **정정**. 제작자·허가·목적에 대한 결론은 아님 |
| 而已 · ㄦˊ ㄧˇ | 這張原圖只能告訴我們：圖上沒有標這個通道而已。至於後來有沒有施工紀錄，還得再查。 | **이 도면의 증명 범위만** 한정; 다른 관측을 지우지 않음 |
| 從而 · ㄘㄨㄥˊ ㄦˊ | 我們對照現場和原圖，從而確認這裡有一條原圖沒有標出的通道。 | 대조한 **방법**으로 얻은 현재의 확인 결과 |
| 因而 · ㄧㄣ ㄦˊ | 現場發現有水從原圖未標出的通道流出，因而需要通知管理人員，請他們核對紀錄。 | 근거를 받아 **지금 필요한 조치** 판단 |
| 進而 · ㄐㄧㄣˋ ㄦˊ | 先記下孔口的位置和水流方向，進而安排查閱後來的修繕紀錄。 | 현재 기록에서 **다음 조사 계획으로 전진**, 조사 결과를 얻었다고 하지 않음 |

**進而의 동등하게 유효한 다른 끝문장:** 「先記下孔口的位置和水流方向，進而規劃在確認安全後觀察下游出口。」. 전자는 변경 자료를 조회할 계획, 후자는 **안전 확인 뒤 출구 관측을 계획**한다. 둘 다 실제 조회/출구 발견 완료를 의미하지 않는다.

**표현 간 중첩 처리:**

- 因而는 앞 내용에 따른 결과를 잇고, 從而는 앞의 원인·방법과 뒤의 결과·목적을 잇는 데 사용한다. 교육부 사전도 **從而를 因而와 겹치는 뜻으로 설명**하므로 어느 표현을 문장 하나에 넣느냐만으로 다른 문법적으로 가능한 표현을 강제 오답 처리하지 않는다. 이 G2에서는 **확인한 결과(현재 성과) / 관리자에게 필요한 조치 / 향후 조사 계획**을 서로 다른 문서 기능으로 묻는다.
- 反而는 예상과 어긋나는 결과이지 물이 항상 반대 방향으로 흐른다는 뜻이 아니다. 현재 사건의 물 흐름은 反而를 경험할 **한 사례**일 뿐이다. 단순한 C의 예상보다 약한 흐름만으로 反而를 의무로 넣지 않는다.
- 而已는 문장 끝에서 범위를 한정하는 성분이다. 다른 而 표현과 같게 앞뒤 절 가운데 접속어 자리에 끼우지 않는다.
- 是/不是와 而是를 단순한 두 단어 대체형으로만 외우게 하지 않고, 현재 문맥의 **不是 A，而是 B** 구문 전체로 보여 준다.
- 해당 표현을 읽는 **원문 독해**에서는 표현이 이미 보이는 것이 정답 누설이 아니다. 반대로 빈칸/문장 복원처럼 **직접 완성**하는 작업에서는 정답 문장을 미리 펼치지 않는다.

**관찰/상태 피드백 예시:**
- T1: 「除了水痕，還有其他被大水沖上去的痕跡。」 / 이번 큰물의 별도 흔적도 남겼어.
- T2: 「進水口有水，不代表中間每一段的情況都清楚了。」 / 수문 기록과 C의 실제를 모두 남기자.
- T3: 「原來水流的方向和剛才想的不一樣。」 / 예상했던 유입과 실제 유출이 달랐어.
- T4: 「原圖沒有標示，不等於一定沒有後來的變更紀錄。」 / 원래 도면이 말하는 범위만 확정해.
- T5: 「下一步要查什麼，已經記下來了；結果還沒查到。」 / 다음 질문을 골랐지, 아직 답은 찾지 않았어.

**사전 교차확인:**

- 然而: https://dict.revised.moe.edu.tw/dictView.jsp?ID=135523
- 反而: https://dict.revised.moe.edu.tw/dictView.jsp?ID=35200&la=0&powerMode=0
- 而已: https://dict.concised.moe.edu.tw/dictView.jsp?ID=39873&la=0&powerMode=0

- 而是: 이번에는 독립 어휘 풀이로 일반화하지 않고 不是……而是…… 구문의 문맥을 출제한다.

## 4. 저장 계약 v1 — 04A 전용, 기존 키 5개 유지

### 4.1 현재 코드로 안 되는 것

- src/app.js의 일반 SAVEKEY는 **마지막 전술 스테이지 스냅샷 한 개**를 저장한다. TacticalGame.playStage는 resetStage를 호출하므로 연구실 옆방에서 미완료 04A에 재진입하면 이전 과제 진행을 잃을 수 있다.
- src/academic-tower-runtime.js의 meaning-links/1에는 taskIndex와 선택, 03B 장면/빈칸 정규화가 있지만 **T3의 구멍 탐색·조사 상태와 04A 독립 영속 저장**이 자동 지원되는 것은 아니다.
- src/journey-progress.js의 normalize는 고정 필드만 반환하므로 새 sideResearchProgress를 그대로 보존하지 못한다.
- src/save-data.js의 validJourney는 lastLocation이 null 또는 world일 때 **중간에 true를 반환**하므로 새 선택 필드의 검증을 그 뒤에 두면 우회된다.
- GameFlow.recordStageComplete는 RouteMechanic.currentOutcome 또는 TacticalGame.stageOutcome을 통해 outcome을 얻는다. **04A의 nextInquiryId를 현재 제공하는 경로는 없다**.
- src/lexicon-runtime.js의 visitStage는 진입한 stage.words[]를 **한 번에 발견 처리**한다. 여덟 표현의 단계별 공개와 충돌할 수 있다.

### 4.2 채택 제안 — journey 내부의 연구별 독립 체크포인트

별도 localStorage 키를 추가하지 않고 기존 chinese-word-tactics-journey-v1의 **선택 필드**에 04A 한 묶음을 저장한다. 신규 G3에서 도입할 구체 스키마의 **설계 예시**는 다음과 같다. 임의 HTML·DOM·사용자 자유 서술형 문구를 저장하지 않는다.

    sideResearchProgress: {
      "academic-tower-turn-04a-er-family": {
        revision: 1,
        contentVersion: "er-rain-g2-v0.2",
        introVariantId: "ordinary",
        cursor: { kind: "task", id: "er-rain-03-side-flow", step: "direction", beat: 0 },
        completedTaskIds: ["er-rain-01-upstream", "er-rain-02-contrast"],
        seenInterludeIds: ["academic-tower-er-scene-retrace"],
        taskDrafts: {
          "er-rain-01-upstream": { evidenceId: "a-grass-high", confirmed: true },
          "er-rain-02-contrast": { decisionId: "check-between-b-c", confirmed: true },
          "er-rain-03-side-flow": {
            inspectedZoneIds: ["low-bank"], openingFound: true,
            flowChoiceId: null, flowConfirmed: false
          }
        }
      }
    }
    stageOutcomes: {
      "academic-tower-turn-04a-er-family": { nextInquiryId: "inquiry-records" }
    }

- cursor.kind는 **intro / task / interlude / result / complete**의 다섯 값만. id는 해당 kind의 알려진 story/task ID만, step은 해당 작업의 허용 단계만, beat는 실제 이야기 beat 범위의 정수만 허용한다. 예시에서 beat는 task에는 사용하지 않도록 최종 serializer가 생략한다.
- completedTaskIds는 **T1~T5 순서의 접두 목록**만 허용. T3 입구만 발견했다면 openingFound=true와 direction step을 저장하고 T3 완료는 기록하지 않는다.
- introVariantId는 S0를 처음 시작할 때 03B 완료 여부에 따라 **ordinary / familiar**로 정해 이후 저장·재생에 유지. 중간에 03B를 새로 완료했다고 이미 읽던 인사말이 바뀌지 않는다.
- seenInterludeIds는 I1/I2 두 ID만, 중복 허용하지 않는다. I1은 T2 완료 뒤, I2는 T3 완료 뒤에만 가능하다. 각 장면 도중에는 cursor.kind=interlude로 정확한 beat를 보존한다.
- taskDrafts는 해당 task의 **허용된 선택 ID와 플래그**만. T4는 artificial-passage/scope-original-only, T5는 methodResultId/actionId/nextInquiryId의 허용 목록을 검사한다. 임의 문장을 저장·복원해 HTML로 렌더링하지 않는다.
- 저장 상한은 **현재 04A 한 연구 엔트리, 작업 초안 최대 다섯, 검사된 짧은 ID 배열**을 원칙으로 한다. 이름을 바꾸거나 새 단계가 생기면 04A 국소 contentVersion 이전 규칙을 마련하고 기존 본편 progress를 지우지 않는다.
- 첫 Inquiry ID는 완료 전 T5 taskDrafts의 **변경 가능한 임시 선택**이고, 완료 뒤에는 stageOutcomes의 **첫 결과**다. 서로 모순되는 값을 영구 결과로 남기지 않는다.

### 4.3 함수 연결·저장 순서 계약

여기서는 **전체 게임 엔진 재작성 대신 04A 경로만 따로 처리**한다. 실제 모듈명은 구현에서 선택 가능하나 책임·호출 순서는 고정한다.

1. src/academic-tower-content.js: 04A room+STAGES 항목을 기존 배열 맨 끝에 등록. 연구별 task/scene/선택 ID/허용답안과 정식 WORDS 편집층 등록.
2. src/academic-tower-journey-content.js: S0, 04A 전역 stage, S1의 이야기·스테이지 여정 노드. I1/I2는 **전역 여정 노드가 아닌 04A 내부 장면**. 기존 05를 04A 선수로 넣지 않는다.
3. src/academic-tower-runtime.js (혹은 작은 04A 전용 reducer): T1~T5의 상태 전이와 읽기 전용 관측 자료, T3의 hidden→opening-found→flow-preview→flow-confirmed를 다룸. 03B 전용 villageResearch 분기를 그대로 복제하지 않는다.
4. src/journey-progress.js: sideResearchProgress 선택 필드를 **normalize에서 보존/검증**하고, 04A 전용 체크포인트 갱신 메서드를 제공한다. 일반 locate/complete와 같은 기존 progress 객체의 데이터로 합친다.
5. src/app.js와 src/flow-runtime.js: 04A에 **기존 SAVEKEY만을 신뢰하지 않는** 진입/이어하기 경로 제공. 연구실·여정에서 미완료 04A의 버튼은 ‘이어서 조사’, 완료+결말 미열람이면 ‘결과 읽기’, 완료+결말 열람이면 ‘다시 연구’로 연결. 가능하면 04A 진행 때문에 다른 스테이지의 마지막 전술 스냅샷까지 불필요하게 덮지 않는 국소 처리.
6. **T5 최종 확정의 원자적 저장:** T5의 유효한 nextInquiryId가 선택되면, **같은 journey 저장 쓰기 한 번 안에서** 04A 다섯 작업 완료·전역 completedStages에 04A 추가·stageOutcomes[04A]={nextInquiryId} 최초 저장·cursor=result/beat=0을 함께 반영한다. 성공했을 때만 ‘완료 저장됨’과 S1 이동을 표시한다. 기존 GameFlow.recordStageComplete를 거쳐야 한다면 04A 전용 outcome 제공 경로 또는 국소 completeSideResearch 브리지 하나를 명시하며 **서로 다른 쓰기로 반쪽 완료 상태를 만들지 않는다**.
7. **재플레이는 스크래치 세션:** stageOutcomes, 본편 milestones, 옛 관찰 카드, 첫 결과, 완료한 03B, 현재 04A 원본 기록을 쓰지 않는다. replay에서 다른 inquiry를 골라도 최초 저장은 불변.
8. **단어장:** 04A stage.words에 여덟 표현을 등록해 감사 가능하게 하되, LexiconRuntime.visitStage의 진입 일괄 발견을 04A에 한해 단계별 **실제 노출 이벤트**로 분리한다. T1 而且, T2 然而, T3 反而, T4 而是/而已, T5 因而/從而/進而의 노출을 기록한다. 기존에 이미 발견된 표현은 그대로 유지. 완료 백업/재진입의 syncProgress도 단계별 발견 기록과 모순되지 않게 한다.
9. 저장 실패 시 **현재 탭에서만 계속할 수 있다**는 경고를 명확히 표시하고, 성공하지 않은 저장을 ‘중단해도 이어서 가능’으로 안내하지 않는다.

### 4.4 백업·초기화 호환성

- 기존 SaveData의 app ID / FORMAT_VERSION 1 / **기존 STORAGE_KEYS 다섯 개**를 유지한다. 새로운 progress 선택 필드는 그중 journey 값에 포함된다.
- 과거 백업처럼 sideResearchProgress가 없는 journey는 정상. 해당 필드가 있다면 **모든 허용 ID·타입·revision·contentVersion·단계의 순서**를 검사한다. lastLocation=null/world/작업/이야기의 모든 경우에 **선택 필드를 먼저 검사**한 뒤 정상 반환해야 한다.
- malformed 04A 필드가 있는 백업은 실제 저장을 바꾸기 전에 검증 실패로 막는다. SaveData.restoreBackup의 기존 백업 검증/롤백을 유지한다. 라이브 저장 손상 시 **04A 국소 오류**로 다루고 본편·03B의 기록까지 리셋하지 않는다.
- 전체 초기화는 기존 journey 키 제거로 04A 체크포인트도 함께 삭제된다. 별도 저장 키를 늘리지 않으므로 설정의 키 목록은 바꾸지 않는다.
- S0/중간 이야기/S1 대사를 읽다가 외부 메뉴로 나간 경우 **04A 커서의 beat가 독립적으로 보존**되도록 한다. journey.lastLocation은 본편의 최근 위치를 계속 나타낼 수 있으며, 별도의 연구 이어하기 버튼은 sideResearchProgress.cursor를 우선한다.
- 첫 결과 이야기 S1을 마치지 않은 상태에서 다른 스테이지를 해도 **이미 완료한 T5를 반복하지 않는다**. 연구실 04A 선택 시 남은 결과 이야기부터 읽는다.
- 첫 결과 이야기 뒤에는 기본적으로 월드맵 귀환을 허용하고, 여정에서 S1 재열람 시 **원래 여정 위치**로 돌아오도록 한다. 결과 재열람/재플레이를 첫 완료와 섞지 않는다.
- 04A 내부 기존 ‘↻ 스테이지 초기화’ 버튼이 연구별 체크포인트를 **묵시적으로 전체 삭제하지 않도록** 동작을 따로 지정한다. 이 연구에서는 ‘현재 작업 다시 보기’ 또는 명시적 재시작 확인을 적용하고 이미 완료된 첫 결과/다른 연구를 보존한다.

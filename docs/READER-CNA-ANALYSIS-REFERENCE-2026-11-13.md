## 3. 평가 대상과 질문

**핵심 질문:** 표현을 강조하면 중국어 텍스트를 되돌아보지 않고 정방향으로 해석하는 데 도움이 되는가?

단순한 문법 분류 성공이나 자동 의미 분할의 정확도를 평가하지 않는다. 사용자가 읽다가 표지어를 인지했을 때 *앞 내용을 유지*, *흐름을 전환*, *결론을 보류*, *근거에서 결과로 진행*, *화제·시간·서술 대상을 갱신*할 수 있는지 본다.

검증 축:

1. **효용:** 해당 위치에서 강조가 독자에게 실제로 다음 정보의 읽기 방향을 예고하는가? (필수 / 도움 / 거의 불필요)
2. **매칭 정확도:** 문자열 검출이 실제 읽기 신호인지? (정확한 감지 / 잘못 감지 / 놓침 / 판단 유보)
3. **밀도:** 강조가 너무 많아 읽기가 오히려 어려워지지 않는가? (문단마다 강조 수, 강조 글자 비율)
4. **안전성:** 문장 안의 다의적 한 글자나 단어 내부 일부를 강조하지 않는가?
5. **두 조건의 차이:** 같은 뉴스의 요약(A)과 원문(B)에서 성능이 달라지는가?

내부 의미 분류(readingAction)는 검토자 메모용이다. 실제 사용자 화면은 사진으로 승인한 것처럼 **흰 바탕·큰 번체 글자·옅은 연녹색 한 종류·설명 없는 비대화형 강조·표지어 표시 켜기/끄기**를 유지한다.

## 4. 비교할 목록과 규칙 — 모두 '후보'이지 채택 확정이 아님

### A0 — 기획서 기준선(표현만)

- [상위 기획 §5](MY-TEXT-READER-PLAN-v0.1.md#5-표지어-목록과-매칭-규칙)의 **기존 초기 후보**를 실험 전 스냅샷으로 고정한다.
- 현재 실행 코드인 matcher·reader-content·정식 표시 사전은 **아직 미구현**이므로 A0 수치는 '기존 엔진 실측'이 아니라, 동일한 문자열 매칭 규칙을 연구 목적으로 재현한 **모의 기준선**이다.
- A0의 임의 한 글자 포함, 긴 표현 우선, 중첩 제외를 그대로 기록하고, 실패를 숨기기 위해 시험 중 A0를 수정하지 않는다.

### A1 — 다글자 우선 보강 시험

- 1차 후보: **至於·其中·此外·接著·隨後·另一方面·針對·對於·儘管·由於·為了·因應·受惠於·首先**.
- 다의성·문맥 위험이 있는 **不過·結果·只是·包括·同時** 등은 별도 후보군으로 시험한다. 두 글자 이상이라고 무조건 안전한 것은 아니다.
- A1은 A0와 동일한 텍스트, 동일한 문단 범위와 같은 판정 기준으로 비교한다. 등장하지 않는 표현을 억지로 등장했다고 기록하지 않는다.

### A2 — 한 글자와 짝·구문은 보류된 독립 실험

- 위험 후보: **若·則·但·仍·並·也·後·再·就·才·得·把** 등. 무조건 일치로 읽기 화면에 적용하지 않는다.
- **雖然…但(是), 先…再, 只有…才, 不是…而是, 不僅…更, 不但…也, 繼…後** 등은 앞뒤 확인이 가능한지 평가하되, v0.1에서는 짝 연결선이나 적용 범위를 확정하지 않는다.
- `原則/規則/準則` 안의 則, `覺得/得到/不得/得易科罰金/勢必得和…` 안의 得 등 부정 사례를 점검한다.
- `說得很清楚/做得不錯/跑得很快` 등 긍정적 **정도·상태 보어** 예문도 별도로 추가한다. 기사에 긍정 사례가 없다는 이유로 탐지율이 높다고 판단하지 않는다. 가능보어 `看得懂`은 별도 판단한다.
- 한 글자나 구문은 **문맥 검증을 통과한 규칙만** 실험 후보로 유지한다. 되레 잘못 강조할 위험이 크면 제외한다.

## 5. 실행 순서 및 산출물

1. 기사 원문 10개와 조간 요약 10개를 열어 제목·주소·열람 시각을 확인한다. 원문 본문만 추출하며 접근 불가 항목은 실패로 적고 멋대로 대체하지 않는다.
2. 텍스트를 보고 먼저 **독립적인 사람 기준 정답(gold)**을 정한다. 각 표현에 위치, 필요한 읽기 행동, 도움이 되는 이유와 확신도를 매긴다. 기획서의 후보 목록 밖에서 유용한 신호도 정답에 추가할 수 있다.
3. 기준선 A0의 순수 매칭을 실행한다. 동일한 텍스트에서 A1 및 A2(안전한 검토 규칙만)를 실행하며 모든 입력·목록 버전을 기록한다.
4. 문단·기사 단위로 오탐(FP), 누락(FN), 정밀도(precision), 재현율(recall), 강조 글자 비율을 계산한다. 요약(A)와 원문(B)을 각각 집계한다. 구현하지 못한 규칙의 성적은 '미측정'이라고 표기한다.
5. 새 후보별로 채택·조건부·보류·제외 권고를 내리며 최소 1개 근거와 1개 오탐 검토를 남긴다. **많이 잡는 것보다 잘못 잡지 않는 것을 우선한다.**
6. 분석 보고서에는 기사별 표와 전체 비교, 대표적인 안전·위험 사례, v0.1에서 실제 활성화할 목록 제안, 미결 사항, 다음 구현 단계 및 검수 범위를 넣는다.

실제 효과 확인은 추후 사용자 독해 실험을 통해야 한다. 문장별 정답이나 정확도 숫자만으로 '되돌아 읽기 감소'를 실증했다고 주장하지 않는다.

### 결과 기록 형식(원문 재배포 금지)

- 기초 정보: corpus ID, 층(A/B), 소스 URL, 기사 제목, 열람 일시, 문단 수·글자 수, 접근 가능 여부.
- 위치: 문단 번호(1부터), 해당 문단 시작 기준 UTF-16 오프셋, 감지한 **짧은 표지어 문자열만**. 오프셋과 HTML 레이아웃 위치를 섞지 않는다.
- 판정: A0/A1/A2 구분, readingAction(내부), 사용 가치, TP/FP/FN/유보, 다의성·부분 문자열 오류 등의 사유.
- 비교표: 전체, 기사별, A/B별 측정치. 분모가 0인 항목은 N/A 처리한다.
- 원문 본문·조간 요약 본문·전체 문단·본문으로 복원 가능한 대량의 조각을 **커밋하지 않는다**. URL·메타데이터·마커·위치·직접 만든 테스트용 예문·극히 짧은 검토 발췌만 남긴다.

## 6. 판정·개발 경계

- **기획 승인과 실제 구현은 별개**다. 분석이 끝나도 자동으로 본편 표지어 사전을 활성화하거나 UI를 변경하지 않는다.
- 평가 스크립트가 필요하면 `tools/` 또는 `tests/` 아래 독립적이고 재현 가능한 실험 코드로 작성할 수 있지만, CNA 본문을 GitHub 저장소에 포함해서는 안 된다.
- CNA 사이트의 재배포 제한을 존중한다. 원문 인용은 최소화하고 URL로 출처를 연결한다. 사이트 접근 제한은 우회하지 않는다.
- 시험 도중 기사 내용이 수정될 수 있으므로 확인 시각과 검증 대상을 기록한다. 비교 시 동일 스냅샷을 사용하되 저장소에는 본문을 공개하지 않는다.
- 이 문서의 후보·가설은 설계·분석을 위한 출발점이다. 실제 발견과 구분해서 보고해야 한다.

# 스토리 단어 강조 설계 v0.1

> 작성일: 2026-09-13
> 적용 대상: 이야기/대화/여정 텍스트
> 관련 문서: `DESIGN-PRINCIPLES-v0.2.md`
> 상태: 시각 규칙 확정 / 익숙함 판정 규칙은 실험 전 보류

---

## 1. 목적

스토리 모드에서도 게임에서 배웠거나 곧 배울 중국어 단어가 자연스럽게 눈에 걸리게 한다.

핵심 경험은 **단어를 공부하기 위해 이야기를 읽는 것**이 아니라,
**이야기를 따라가다 보니 전에 만난 단어가 다시 보이는 것**이다.

따라서 단어 강조는 다음 원칙을 지킨다.

- 스토리 읽기가 항상 먼저다.
- 강조는 발견을 돕지만 문장을 조각내지 않는다.
- 색은 학습 상태를 조용히 전달한다.
- 단어를 눌러 뜻을 확인하는 데 페널티를 두지 않는다.
- 반복 횟수를 숙련도처럼 포장하지 않는다.
- 익숙해진 단어는 언젠가 다시 평범한 문장 속으로 녹아든다.

---

## 2. 기본 상태

스토리 속 단어는 네 가지 상태를 가질 수 있다.

### 2.1 일반 단어 — `normal`

게임 학습 대상으로 관리하지 않는 일반 본문이다.

- 색: `#3F3A34`
- 기본 글자 무게 사용
- 별도 상호작용 없음

### 2.2 곧 배울 단어 — `upcoming`

현재 이야기에서 먼저 보이지만 가까운 스테이지에서 목표어로 등장할 단어다.

- 색: `#8B5E2B` — 탁한 황토
- 일반 본문보다 눈에 걸리되, 이미 배운 단어보다 강하게 보이지 않는다.
- 밑줄, 배경색, 형광펜 효과는 사용하지 않는다.
- 눌렀을 때 `곧 만나게 될 단어`라는 상태를 보여준다.
- 스테이지 해법을 미리 노출할 위험이 있으면 한국어 뜻은 기본 노출하지 않는다.
- 단어 조회가 필요한 맥락에서는 기존의 무페널티 조회 원칙을 우선한다.

초기 시안의 `#A6783D`는 작은 본문에서 대비가 약해, 실제 구현 후보는 더 어두운 `#8B5E2B`로 조정한다.

### 2.3 배운 단어 — `learned`

해당 단어가 목표어로 등장한 스테이지를 플레이어가 완료한 뒤의 기본 상태다.

- 색: `#39736C` — 짙은 청록
- 필요하면 글자 무게를 `550~600` 범위에서 아주 약하게 올린다.
- 굵기 변화가 문장 리듬을 해치면 색만 사용한다.
- 눌렀을 때 뜻, 발음, 처음 배운 위치를 확인할 수 있다.

예:

```text
少年慢慢地走向村口，把行李放下來。
          ^^^^            ^^^^
          learned         upcoming
```

시각적 의도:

- `走向` → 전에 실제로 사용했던 단어라는 회상
- `放下` → 앞으로 다시 만나게 될 단어라는 예고

### 2.4 익숙해진 단어 — `familiar`

충분히 익숙해져 더 이상 색으로 적극적으로 불러낼 필요가 없는 상태다.

최종 시각 상태는 새 색을 추가하는 것이 아니라 **일반 본문색으로 돌아가는 것**을 기본 방향으로 한다.

예상 변화:

```text
#39736C  →  중간 완화 상태  →  #3F3A34
배운 직후                     자연스러운 본문
```

`familiar`은 **숙달, 암기 완료, 마스터**를 의미하지 않는다.
오직 “스토리에서 더 이상 강하게 강조하지 않아도 될 정도로 반복해서 만났다”는 표시 강도의 상태다.

현재 v0.1에서는 판정 로직을 확정하지 않는다.

## 3. 팔레트

| 역할 | 색 | Hex | 의미 |
|---|---|---|---|
| 일반 본문 | 먹빛 회갈색 | `#3F3A34` | 세계의 기본 언어 |
| 배운 단어 | 짙은 청록 | `#39736C` | 이미 만난 지식 |
| 곧 배울 단어 | 탁한 황토 | `#8B5E2B` | 앞으로 만날 단어 |
| 터치/현재 선택 | 짙은 남청 | `#315A70` | 지금 확인 중인 단어 |
| 단어 정보 배경 | 옅은 베이지 | `#F3EBDD` | 종이/여행 노트 |
| 보조선 | 회베이지 | `#CFC4B2` | 조용한 구분 |

`#F3EBDD` 배경 기준으로 일반 본문, 청록, 남청은 작은 본문에서도 충분한 대비를 확보한다.
황토는 초기 시안보다 어둡게 조정해 작은 모바일 본문에서도 읽기 쉽게 한다.

## 4. 강조 강도 규칙

### 하지 않는 것

- 형광펜형 배경 강조
- 단어마다 pill/chip 처리
- 모든 학습어에 굵은 밑줄
- 단어마다 별도 아이콘 부착
- 색 + 굵기 + 밑줄을 동시에 사용
- 문장보다 단어 상태가 먼저 보이는 UI

### 기본 우선순위

1. 색
2. 필요할 때만 아주 약한 글자 무게 차이
3. 터치했을 때 상태 라벨

스토리 본문에서는 **한눈에 단어장처럼 보이지 않는 것**이 중요하다.

---

## 5. 터치 동작

강조된 단어는 누를 수 있다.

### 배운 단어

간단 정보층에서 다음을 보여준다.

```text
走向   zǒuxiàng
~을 향해 가다, ~로 나아가다

이미 배운 단어
처음 배운 곳 · 길목 G?
```

필요하면 단어장 상세로 이어진다.

### 곧 배울 단어

기본 정보는 최소화한다.

```text
放下   fàngxià
곧 만나게 될 단어
```

스토리 문맥상 뜻을 바로 보여줘도 해법을 망치지 않는 경우에는 조회를 허용할 수 있다.
조회 여부에 페널티는 없다.

### 익숙해진 단어

본문에서는 일반 글자처럼 보여도, 단어 데이터 자체는 사라지지 않는다.
필요하면 다시 눌러 단어장 정보로 들어갈 수 있다.

---

## 6. 상태 전환

### 확정 가능한 전환

```text
upcoming
   ↓ 목표어 스테이지 완료
learned
   ↓ 충분한 재등장과 사용 경험
familiar   ← 판정 규칙 미정
```

`normal`은 학습 대상이 아닌 단어이므로 이 흐름 밖에 있다.

### 중요한 원칙

스토리에서 단순히 여러 번 보였다는 이유만으로 `familiar`로 승격하지 않는다.

이 게임에서 단어의 의미를 이용해 실제 행동을 선택하는 경험이 핵심이므로,
**수동 노출보다 실제 사용 경험을 더 강한 증거로 본다.**

---

## 7. ‘익숙함’ 판정에서 아직 결정하지 않은 것

단순한 `3회 노출 = 익숙함` 같은 규칙은 사용하지 않는다.
그것은 실제 언어 학습보다 게임 내부 카운터를 숙련도처럼 보이게 만들기 쉽다.

향후 판정 실험에서는 다음 신호를 검토한다.

### 강한 신호 후보

- 해당 단어를 목표어로 사용하는 스테이지를 완료함
- 이후 다른 스테이지에서 같은 단어를 다시 올바르게 사용함
- 서로 다른 상황/기믹에서 같은 단어를 다시 만남
- 지역이나 이야기 구간이 바뀐 뒤 재등장함

### 약한 신호 후보

- 스토리에서 단순 노출
- 같은 스테이지를 즉시 반복 플레이
- 같은 문장을 여러 번 다시 열어봄

약한 신호만으로는 `familiar` 판정을 하지 않는다.

### 뜻 조회 처리

뜻을 눌러봤다는 사실은 실패로 취급하지 않는다.

- 조회 횟수 때문에 점수를 깎지 않는다.
- `familiar` 상태를 강제로 되돌리지 않는다.
- 필요하다면 강조를 조금 오래 유지하는 보조 신호로만 사용할 수 있다.

이 부분은 실제 플레이 데이터를 본 뒤 결정한다.

---

## 8. 구현 전 미리 저장해둘 수 있는 데이터

판정식은 나중에 정하더라도, 상태 전환 실험을 위해 최소한 다음 사건은 로컬 저장 후보로 남긴다.

```text
wordId
firstLearnedStageId
firstLearnedAt
storyEncounterCount
stageUseCount
stageUseStageIds[]
lastEncounteredAt
meaningOpenCount
visualState
```

단, 이 값들을 사용자에게 `숙련도 73%` 같은 수치로 노출하지 않는다.

구현 초기에 모든 값을 반드시 저장할 필요는 없다.
실제 `familiar` 판정 실험에 필요한 최소 데이터부터 추가한다.

---

## 9. 모바일 검수 기준

기준 기기는 iPhone 13 mini Safari다.

확인할 항목:

- 강조어가 한 문장에 여러 개 있어도 문장이 조각나 보이지 않는가
- 청록과 황토를 모두 작은 글자에서 읽을 수 있는가
- 두 줄 이상 줄바꿈되었을 때 강조가 지나치게 눈에 띄지 않는가
- 강조어 터치 영역은 최소 44px 확보하되 텍스트 레이아웃을 깨지 않는가
- 단어 정보층이 본문을 과도하게 가리지 않는가
- 일반 본문을 먼저 읽고 단어를 나중에 발견할 수 있는가

---

## 10. v0.1 구현 범위 제안

첫 구현에서는 욕심내지 않는다.

1. `upcoming / learned / normal` 세 상태만 적용한다.
2. 위 팔레트로 스토리 본문 강조를 구현한다.
3. 강조 단어를 눌렀을 때 상태와 최소 단어 정보를 보여준다.
4. `familiar` 데이터 구조는 예약하되 자동 전환은 하지 않는다.
5. 실제 스토리 몇 장면에서 읽기 흐름을 먼저 검수한다.

그 뒤 재등장 단어가 충분히 쌓였을 때 `familiar` 판정 규칙을 별도 버전에서 설계한다.
